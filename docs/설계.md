# web-game-builder 설계 명세

> 클로드 코드 플러그인 — 자연어 게임 제작 요청을 감지해 브라우저/모바일 웹뷰용 완성도 높은
> 2D 웹 게임을 Phaser 3 기반으로 자동 생성한다.

## 1. 목표와 범위

- **문제:** 클로드 코드에 "웹 게임 만들어줘"라고 하면 바닐라 JS 수준의 투박한 결과가 나온다.
- **해결:** 게임 제작 의도를 자동 감지 → 검증된 엔진 스택과 템플릿으로 스프라이트 애니메이션·
  HUD·모바일 터치·오디오까지 갖춘 결과를 산출.
- **범위(현재):** **2D 전용.** 플래그십 데모는 슈퍼마리오류 플랫포머(`games/super-runner/`).
- **비범위:** 3D, 멀티플레이어 서버, 네이티브 앱 패키징(향후 과제).

## 2. 기술 선택과 근거

| 결정 | 선택 | 근거 |
|------|------|------|
| 게임 엔진 | **Phaser 3 (v3.90, MIT, vendored)** | 후보 7종(Phaser/Kaplay/PixiJS/melonJS/Excalibur/LittleJS/Cocos) 비교. 플랫포머 필수요소(Arcade 물리·타일맵·스프라이트 애니메이션·카메라·HUD)가 전부 1급 API로 내장 + 예제 코퍼스 최다 → LLM 코드생성 신뢰도 최고. |
| 엔진 버전 | **v3 고정 (v4 아님)** | 학습 데이터 대부분이 v3 API. v3/v4 혼용이 코드생성 실패의 주원인이라 1버전에 핀. |
| 물리 | **Arcade (Matter 아님)** | AABB 기반으로 모바일에서 훨씬 경량 + 플랫포머 표준 튜토리얼 스택이라 코드생성 신뢰도 높음. |
| 에셋 | **CC0 우선 + 절차적 생성 폴백** | 데모는 외부 다운로드 0, `PixelForge`로 코드 생성(CC0·IP-safe). CC0 팩은 `assets.json` 게이트로 CC0만 허용. |
| 사운드 | **절차적 합성(ChipAudio)** | Web Audio로 8비트 SFX/BGM 코드 생성, 오디오 파일 0. BGM은 오리지널 멜로디. |
| 자동 실행 | **Hook + Skill 둘 다** | description 의미 기반(1차) + UserPromptSubmit 훅 결정론적 감지(2차) + 슬래시 커맨드(3차). |
| 모바일 | **MobileHarness** | Scale.FIT+CENTER_BOTH, Tap-to-start 오디오 언락, 멀티터치 컨트롤, 뷰포트/CSS 가드. |
| 결과물 | **웹뷰 최적화 HTML/JS 폴더** | 바로 브라우저·인앱 웹뷰에서 실행. 네이티브 래퍼는 향후. |

## 3. 전체 아키텍처

```
┌─ 트리거 계층 (플러그인) ──────────────────────────────┐
│  1차 SKILL.md description  (의미 기반 자동 트리거)       │
│  2차 hooks.json + detect-game-intent.* (결정론적 넛지)  │
│  3차 commands/make-game.md (명시적 슬래시 폴백)         │
└───────────────────────────────────────────────────────┘
            │ 스킬 발동
            ▼
┌─ 엔진 계층 (engine/) ─────────────────────────────────┐
│  phaser.min.js   Phaser 3.90 (MIT, vendored)          │
│  pixelforge.js   PixelForge — 절차적 픽셀아트          │
│  audio.js        ChipAudio — 절차적 8비트 사운드        │
│  mobile.js       MobileHarness — 모바일 웹뷰 하니스     │
└───────────────────────────────────────────────────────┘
            │ 사용
            ▼
┌─ 게임 계층 (games/<slug>/) ───────────────────────────┐
│  index.html  뷰포트 meta + CSS 리셋 + 스크립트 로드     │
│  game.js     Boot→Title→Game + UI + TouchControls 씬   │
│  CREDITS.txt 라이선스 고지                              │
└───────────────────────────────────────────────────────┘
            ▲
┌─ 에셋 파이프라인 ─────────────────────────────────────┐
│  assets.json  CC0 라이선스 게이트 (CC0만 허용)          │
│  폴백: PixelForge 절차적 생성                           │
└───────────────────────────────────────────────────────┘
```

## 4. 컴포넌트별 책임

- **`.claude-plugin/plugin.json`** — 플러그인 매니페스트(name 필수, version/description/keywords).
  컴포넌트 경로 필드는 생략(기본 디렉터리 자동 탐색).
- **`.claude-plugin/marketplace.json`** — 마켓플레이스 등록(설치 진입점).
- **`skills/` (16종)** — 메인 + 전문 15. 메인 `web-game-builder`가 오케스트레이션하고, 전문
  스킬이 관련 요청에 자동 발동한다(독립 자동발동 + 메인 조율 구조).
  - **`web-game-builder/SKILL.md`** — 자동 트리거의 핵심. 한/영 고밀도 `description`(1차
    트리거 표면) + 빌드 워크플로 + 전문 스킬 라우팅. `reference/`에 엔진 API·모바일 체크리스트.
  - **장르(5):** `platformer-game` `topdown-shooter` `arcade-classic` `puzzle-game`
    `endless-runner` — 장르별 스캐폴드(지침형, 엔진 활용).
  - **제작요소(6):** `sprite-forge`(픽셀) `vector-graphics`(미려한 스무스/벡터) `chip-sound`
    `level-designer` `game-ui-hud` `juice-fx`.
  - **품질·운영(4):** `mobile-webview-tune` `game-qa` `ip-license-guard` `perf-60fps`.
  - 각 전문 스킬은 tight한 description으로 관련 요청에만 발동 → 스킬 listing 예산(컨텍스트 ~1%)
    관리. 너무 많아 truncate 시 `/doctor` 확인 + `skillListingBudgetFraction` 상향 또는 일부를
    name-only 로 조정.
- **`hooks/hooks.json`** — UserPromptSubmit 이벤트에 의도 감지 스크립트 등록(matcher 없음, 매
  프롬프트 실행). `${CLAUDE_PLUGIN_ROOT}` 경로 사용.
- **`scripts/detect-game-intent.js`** — Node(크로스플랫폼) 의도 감지기. stdin JSON `.prompt`를
  정규식 매칭 → `additionalContext` 출력. `.ps1`/`.sh` 변형 동봉.
- **`commands/make-game.md`** — `/web-game-builder:make-game` 슬래시 커맨드(명시적 폴백).
- **`engine/`** — 재사용 런타임 4종(아래 5절).
- **`games/super-runner/`** — 플래그십 데모(아래 6절).
- **`assets.json`** — 외부 에셋 라이선스 게이트. `policy.allow`에 CC0/허용 라이선스, CC-BY는
  attribution 표기 시에만. 데모는 entries 비어있음(전부 절차적 생성).

## 5. 엔진 계층 상세

### PixelForge (`engine/pixelforge.js`)
- 문자 그리드 프레임 → Phaser CanvasTexture(가로 스트립)로 굽기. 외부 이미지 0.
- **라가드 행 자동 패딩**: 행 길이를 안 맞춰도 가장 긴 행 기준 오른쪽 투명 패딩 → 픽셀 작업
  실수 최소화.
- `buildAll(scene)`로 내장 16종 + 애니메이션 등록. `bake()`로 게임별 커스텀.
- IP-safe: 주인공 '빨간 모자 러너'는 빨간 모자 색 단서 1개만 남기고 나머지(초록 멜빵·콧수염
  없음)를 바꾼 오리지널.

### VectorForge (`engine/vectorforge.js`)
- PixelForge의 비-픽셀 짝꿍. `drawFn(ctx,w,h,t,VF)`을 슈퍼샘플(기본 3x) 후 고품질 다운샘플 →
  매끄러운 안티앨리어스 텍스처. 헬퍼 `VF`(rr/circle/blob/star/lin/radial/glow/shadow/glass).
- 4가지 스타일 지원: 플랫/머티리얼+소프트섀도우, 그라데이션/글로우, 글래스모피즘, 카툰 벡터 캐릭터.
- **렌더 스타일은 게임당 하나**: 픽셀(`pixelArt:true`) ↔ 스무스(`pixelArt:false, antialias:true`).
- 외부 HD CC0 아트 로딩 경로도 지원(`this.load.svg`로 벡터를 임의 크기 또렷이 래스터화 +
  `assets.json` CC0 게이트). 쇼케이스: `games/style-preview/`.

### ChipAudio (`engine/audio.js`)
- Web Audio 오실레이터 + 포락선으로 SFX 합성, 스텝 시퀀서로 **오리지널** BGM 루프.
- 모바일 오디오 언락: `unlock()`(resume + iOS 무음버퍼), `resume()`(백그라운드 복귀).

### MobileHarness (`engine/mobile.js`)
- `scaleConfig()`(FIT+CENTER), `installDomGuards()`(iOS 줌/스크롤 차단),
  `TouchControlsClass()`(멀티터치 D-패드+점프, 매 프레임 포인터 위치 재계산으로 견고).

## 6. 게임 계층 상세 (super-runner)
- 씬: `Boot`(에셋 생성) → `Title`(Tap to start, 오디오 언락) → `Game`(플레이) + `UI`(HUD,
  스크롤 X) + `TouchControls`(최상단).
- 디자인 해상도 384×224(≈16:9), TILE 16, `pixelArt:true`.
- 레벨: 바닥 자동 생성 + 피처 목록(코인/블록/적/돌계단) + 파이프/깃발 별도. 폭 132타일.
- 메카닉: 가변 점프(코요테 110ms·버퍼 120ms), 적 밟기/대미지, 코인, 벽돌(큰 상태 파괴)·
  물음표(코인/버섯), 초록 버섯 파워업, 구덩이 추락, 깃발 골인, 목숨·타임·점수, 패럴랙스 배경.

## 7. 자동 트리거 메커니즘 상세

1. **1차 — SKILL.md description (의미 기반):** 세션 시작 시 description이 시스템 프롬프트에
   주입(progressive disclosure). 모델이 요청 의미와 매칭해 스킬 호출. 한/영 키워드 고밀도로
   recall 극대화(1,536자 캡 내). 다국어/패러프레이즈에 강함, 단 비결정적.
2. **2차 — UserPromptSubmit 훅 (결정론적 안전망):** 매 프롬프트에서 정규식 감지 → 매치 시
   `additionalContext`를 `<system-reminder>`로 주입해 스킬 호출을 **넛지**.
   - **왜 `decision:block`이 아닌가:** block은 프롬프트 자체를 컨텍스트에서 지운다. 우리는
     "스킬을 켜라"고 살짝 밀어줄 뿐, 사용자 입력을 취소하면 안 된다.
   - 1차의 recall 공백(특정 어휘 미스)을 결정론적으로 메움.
3. **3차 — 슬래시 커맨드 (명시적 폴백):** 사용자가 직접 `/web-game-builder:make-game`.
   100% 결정론적이지만 자연어로는 발동 안 됨 → 보조 진입점.

두 자동 경로(의미 미스 vs 어휘 미스)의 실패 모드가 상보적이라 함께 쓴다.

## 8. 모바일 웹뷰 베스트프랙티스 (적용 목록)
`reference/mobile-webview.md` 체크리스트를 엔진/템플릿이 구현. 요약: Tap-to-start 오디오 언락,
뷰포트 meta(viewport-fit=cover, user-scalable=no), CSS 리셋(overscroll/touch-action/탭하이라이트),
iOS 제스처 preventDefault, Phaser.AUTO(WebGL→Canvas 폴백), Scale.FIT, 멀티터치 컨트롤,
DPR≤2, 텍스처/풀링/Arcade 물리, visibilitychange 오디오 재개.

## 9. IP / 라이선스 안전 정책
- 닌텐도 등 타사 스프라이트·사운드·폰트·레벨·이름('Mario')·시그니처 조합 절대 미사용.
- 마리오 '느낌'은 색 단서 1개(빨간 모자)만 남기고 나머지 변경한 오리지널로 표현.
- 메카닉/장르(옆스크롤·점프·밟기·코인·깃발 골)는 저작권 대상 아님 → 자유 구현.
- 라이브러리(Phaser MIT 등) 라이선스는 `LICENSE`/`CREDITS.txt`/`engine/phaser.LICENSE.txt`에 명시.
- (참고: 상용 배포 시 캐릭터 디자인은 법률 검토 권장 — 본 문서는 법률 자문 아님.)

## 10. 검증 전략과 결과
- chrome-devtools MCP로 실제 실행 검증: 타이틀/게임 렌더, HUD, 이동/물리/가변점프/카메라/
  애니메이션 정상. 코인(+100)·적 밟기(+100)·물음표블록→코인팝(+200) 메카닉 결정적 검증 통과.
  콘솔 에러 0.
- 검증 중 TouchControls의 `this.input.pointers`(undefined) 버그 발견 → `this.input.manager
  .pointers`로 수정.
- 헤드리스 캡처 한계: WebGL `preserveDrawingBuffer:false` + 비가시 탭 rAF 정지로 라이브
  프레임 캡처가 불안정. `?autostart=1` + `window.SuperRunner.game.step(t,dt)` 수동 전진으로
  결정적 검증을 수행. 실기기/포그라운드 브라우저에서는 60fps로 정상 구동.

## 11. 향후 과제 (오픈 퀘스천)
- 장르 템플릿 확장(러너·슈팅·탑다운·퍼즐·벽돌깨기·테트리스·스네이크·플래피).
- Tiled 맵 에디터(.tmj) 연동 vs 절차적 그리드 레벨.
- Phaser 번들 vendored vs CDN 옵션.
- 가상조이스틱: 자체 구현(현행) vs rexVirtualJoystick 등 서드파티.
- Capacitor/Cordova 네이티브 래퍼(앱스토어 배포) 가이드.
- CC-BY 에셋 자동 attribution 생성 경로(현재 v1은 CC0 전용).
