## 0. 총평

현 구조는 **"게임을 만드는" 축은 두텁고, "만든 게임을 붙잡게 하고(리텐션) 내보내는(배포) 축은 얇다.**
장르 스캐폴드 → 디렉터(서사·능력·아이템·사운드·스타일·레벨·맵) → 품질(QA·성능·라이선스)로 이어지는
제작 파이프라인은 업계 이론까지 코드화된 드문 수준이다. 그러나 게임이 끝나는 순간부터의 설계 —
재도전 루프, 진행 저장, 점수 경쟁, 업적, 데일리 — 와 게임을 세상에 내보내는 설계 —
번들링, 호스팅, PWA, 아이콘, 메타태그 — 는 스킬·엔진·데모 3층 모두에서 비어 있다.

**중독성의 공식 = (재미있는 코어 루프) × (마찰 없는 재도전) × (돌아올 이유).**
첫 항은 잘 갖췄고, 뒤 두 항이 구조적 공백이다.

## 1. P0 — 출시 블로커 (이것 없이는 '출시 가능한 게임'이라 부를 수 없음)

### 1-1. 배포 레인 전무 → 신규 스킬 `wgf-ship`
- **갭**: itch.io·정적 호스팅·Vercel·Capacitor로 가는 스킬/커맨드/체크리스트가 0건. 로드맵에 'Capacitor 가이드'가 미완 항목으로만 존재.
- **치명 결함**: 게임 폴더가 self-contained가 아님 — 모든 데모 index.html이 `../../engine/` 상대경로를 참조해 **게임 폴더만 zip 하면 그대로 깨진다.** itch.io 업로드 자체가 불가능한 구조.
- **제안**: `wgf-ship` 스킬 신설. ① `tools/bundle-game.mjs`(엔진 파일을 게임 폴더로 복사·경로 재작성 → self-contained dist/) ② itch.io/정적호스팅/PWA/Capacitor 4레인 가이드 ③ 버전 스탬프·캐시버스팅 ④ 파비콘·앱 아이콘·OG 카드 생성(절차 생성 — PixelForge로 아이콘 베이크) ⑤ 출시 전 체크리스트.

### 1-2. 재도전 루프가 '2탭 타이틀 경유' → `wgf-retention-architect` + `engine/savekit.js`
- **갭 3종**:
  - 죽음→재도전이 게임오버 → 타이틀 → 탭 2회. **'한판만 더'의 물리 경로(instant retry)가 표준에 없다.**
  - 세이브/진행 영속 인프라 부재. localStorage 래퍼 킷이 없어 BEST 점수·해금·설정이 새로고침마다 증발.
  - BEST 점수 상시 노출·신기록 연출·로컬 리더보드가 아이디어 한 줄로만 존재.
- **제안**: 디렉터 스킬 `wgf-retention-architect` 신설(기존 디렉터들과 동일한 인터뷰→바이블→데이터→린트 패턴).
  산출: `RETENTION.md` + `retention.json`(업적·데일리·메타 진행 정의) + `engine/savekit.js`(버전드 localStorage:
  BEST·해금·설정·streak, 세이브 마이그레이션) 배선. 게임오버 화면 표준에 **RETRY 버튼(1탭) + BEST/신기록 연출** 포함.

### 1-3. 일시정지·설정 씬 부재 → `wgf-game-ui-hud` 보강
- **갭**: 설정(Settings) 씬 패턴이 스킬 29종 어디에도 없음. 일시정지는 '반투명 사각형+탭 재개' 최소 패턴뿐(재개/재시작/타이틀/설정 버튼 없음). 음량 슬라이더·셰이크 끄기·텍스트 크기 등 **모든 접근성 토글이 '살 곳'이 없다.**
- **제안**: game-ui-hud에 일시정지/설정 씬 표준 레시피 추가 + savekit 연동(설정 영속). 모바일 필수: 백그라운드 전환 시 자동 일시정지.

### 1-4. 화면 전환 100% 하드 컷 → `engine/transitionkit.js`
- **갭**: 씬 전환 페이드/와이프가 엔진·스킬·데모 전체에 0건. 모든 scene.start()가 하드 컷 — 상업 게임과 프로토타입을 가르는 가장 값싼 차이.
- **제안**: `transitionkit.js`(페이드·아이리스·와이프 3종, `Transition.go(scene, 'Game', 'fade')` 한 줄 API) + 전 장르 스캐폴드에 기본 배선.

### 1-5. 사운드 유령 스펙 2건 (버그) → 즉시 수정
- `wgf-sound-architect` 문서가 규정한 **`SoundForge.duck()`이 엔진에 미구현** — 스킬을 따르는 LLM이 존재하지 않는 API를 호출하는 코드를 생성한다.
- `wgf-story-architect`가 존재하지 않는 **'ChipAudio stinger'**를 지시.
- **제안**: duck() 실구현(BGM 게인 자동 덕킹) + 스팅어 패턴 추가, 문서-엔진 정합 린트(`lint-audio.mjs`에 API 존재 검증 추가).

### 1-6. 적 AI 패턴 라이브러리 부재 → `wgf-enemy-ai` (또는 `wgf-combat-architect`)
- **갭**: 모든 액션 장르가 적 행동을 매번 즉흥 구현. 패트롤·추적·도약·사격·돌진 같은 검증된 패턴 카탈로그가 없고, 보스전(P1)·웨이브/스폰(P1)도 이론·런타임·데모 3층 모두 0.
- **제안**: 패턴 카탈로그(reference/) + `engine/spawnkit.js`(웨이브·스폰·풀링) + 보스 페이즈 설계 원칙. 데모 1종으로 실증.

### 1-7. 캐릭터 애니메이션 품질 천장 → ✅ **이번 PR로 1차 해소**
- **갭(감사 시점)**: hero 4프레임(run 2)·enemy 2프레임이 사실상 표준 상한이었고, 프레임 수·작화 원칙(외곽선·3톤 셰이딩·바운스)이 체계 어디에도 없었음.
- **해소**: 본 PR에서 PixelForge에 **상업 픽셀아트 원칙 5종 명문화** + hero 9프레임(블링크·4프레임 런 바운스·점프/낙하 분리)·enemy 5프레임(squash&stretch)·장식 스프라이트 10종·다층 패럴랙스·게임필 FX를 super-runner에 실증.
- **남은 일**: 이 원칙을 `wgf-sprite-forge` reference로 승격(작화 가이드 문서화), 패럴랙스 빌더의 엔진 킷 승격 검토.

### 1-8. 파비콘·아이콘·OG 0건 + '파비콘 없음'이 QA 합격 기준으로 제도화
- **갭**: 전 데모에 파비콘 없음(콘솔 404가 '정상'으로 문서화됨). 앱 아이콘·OG 공유 카드 0건 — 링크 공유 시 빈 미리보기.
- **제안**: `wgf-ship`에 포함(1-1) + game-qa의 'favicon 404 제외' 합격 기준 제거.

## 3. P2 — 완성도 (있으면 확실히 달라 보임)

- **공유 기능**: 스코어 카드 이미지 생성(canvas→PNG) + Web Share API + 시드 딥링크. 바이럴 루프의 최소 단위.
- **SEO/소셜 메타태그**: index.html 템플릿에 title/description/OG/twitter 카드 표준.
- **적응형 난이도**: 연속 실패 감지 → 보이지 않는 보정(처방 프로즈는 있으나 런타임 없음).
- **이코노미 시뮬 도구**: 싱크/포셋 이론 14원칙은 충실 — 상비 시뮬 스크립트만 부재.
- **로딩/스플래시 경험**: Boot 무신호 구간에 로고+진행 바(외부 에셋 로드 게임용).
- **좌손 모드**: TouchControls 미러 레이아웃 옵션.
- **BGM 전환 표준**: 씬 간 크로스페이드·스팅어 규약.

## 4. 권장 실행 순서

```
Phase 1 — 출시 가능 (P0 일괄)
  wgf-ship 신설(번들러+4레인+아이콘/OG) → savekit+instant retry+BEST
  → 일시정지/설정 씬 → transitionkit → duck()/stinger 정합 픽스
  → sprite-forge 작화 가이드 승격(본 PR 후속)

Phase 2 — 중독성 (P1 코어)
  wgf-retention-architect(업적·데일리·메타) → wgf-enemy-ai+spawnkit
  → FTUE 원칙 → 파티클 프리셋+SFX 변주+햅틱 → i18n+접근성 토글

Phase 3 — 완성도 (P2)
  공유 카드 → SEO 템플릿 → 적응형 난이도 → 이코노미 시뮬 → 좌손/스플래시
```

신규 스킬은 3개로 압축(ship · retention-architect · enemy-ai), 나머지는 기존 스킬 보강과
엔진 킷 6종(savekit · transitionkit · spawnkit · genkit · i18n · inputkit)으로 흡수하는 것을 권장 —
스킬 수 증가는 컨텍스트 예산을 먹으므로, 디렉터 패턴(인터뷰→바이블→데이터→린트)을 재사용해
기존 골격에 얹는 쪽이 구조적으로 싸다.

## 5. 지금 구조의 강점 — 유지할 것

1. **디렉터-바이블-린트 3층 패턴** (story/item/ability/sound/style/level/map architect): 설계 의도를
   마크다운 바이블 + JSON 데이터로 분리하고 기계 검증(lint-*.mjs)까지 잇는 구조는 업계에도 드물다.
   신규 스킬(retention·enemy-ai)도 반드시 이 패턴으로.
2. **game-dna 라이브러리**: 인기 게임 35종+퍼즐 20종의 재미요소 분해와 조합 레시피 — 명확화 단계의 무기.
3. **100% 절차 생성 CC0 에셋 체계**: PixelForge/VectorForge/SoundForge + 라이선스 게이트.
   외부 의존 0이 배포(1-1)에서도 최대 자산이 된다.
4. **결정론적 QA 하니스**: 헤드리스 step 검증 — 플레이타임 추정(2-12)의 토대가 이미 있다.
5. **Phaser 4 공식 레퍼런스 벤더링**: v3/v4 혼용 오류 원천 차단.
6. **wgf- prefix 단일 네임스페이스**: 피커 검색성.
