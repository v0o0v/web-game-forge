# 게임 서사 인터뷰 (Deep Interview 적응판 · 탑다운 · 의도 주도)

> [`story-architect`](../SKILL.md)의 **'1) 의도 분석 + 서사 인터뷰'** 단계를, **탑다운으로 모호성이 풀릴 때까지
> 끈질기게 묻는 1문1답 인터뷰**로 수행하는 플레이북.
> oh-my-claudecode `deep-interview`(Socratic 1문1답 + 약점 차원 타깃 + 챌린지 모드 + 준비도 게이팅)와
> web-game-builder [game-interview.md](../../web-game-builder/reference/game-interview.md)를 **서사 설계**에 적응시켰다.
> 차이: 게임 인터뷰가 *어떤 게임을*(메카닉·재미) 만들지를 캔다면, 이 인터뷰는 그 위에 *어떤 이야기를·어떤 톤으로*
> 입힐지를 캔다 — 끝낸 플레이어가 무엇을 느끼고 떠나는가.
>
> **언제 쓰나:** "스토리 만들어줘", "분위기 좀 입혀줘", "주인공한테 사연 줘", "여기 반전 넣어줘"처럼 요청이
> 모호하거나, 아래 차원이 비어 있을 때. 요청이 이미 구체적이면(톤·premise·캐릭터·반전·채널이 다 적혀 있으면)
> 인터뷰를 건너뛰고 바로 STORY.md를 설계한다.
>
> 자동 트리거 아님. SKILL.md '1) 의도 분석' 에서 **온디맨드 Read** 로 부른다.

## 0. 이 인터뷰의 3대 정신

1. **톤을 먼저 못 박고 탑다운으로 내려간다.** 스킬 0단계(현재 게임 분석)가 끝난 상태에서 시작한다 — 코어 동사·기존
   텍스트 표면·아트 톤을 이미 안다. 그 위에서 **끝낸 플레이어가 느꼈으면 하는 한 감정(톤)** 부터 못 박고 →
   premise → 전형↔참신 → 프레임워크 → 캐릭터 → 반전 → 대사 → 채널 순으로 *좁혀* 내려간다.
   톤(무드)이 어휘·색·BGM·프레임워크를 전부 프레이밍한다 — 위가 흔들리면 아래를 물어도 소용없다(`WT-MOOD-THROUGHLINE`).
2. **Claude가 먼저 *매우 창의적인* 주제를 제안한다(백지 금지).** 빈 객관식("어떤 이야기 원해요?")을 던지지 않는다.
   매 라운드 game-dna 장르 맥락 + 서사 이론으로 *이 게임의 이 톤에 어울리는 참신한 컨셉*을 구체적인 한 컷으로 먼저
   제시하고 본인 의견을 밝힌다(§4·§5). 사용자는 고르거나 비틀거나 자유 입력. **전형으로 갈지 참신하게 비틀지는 사용자가 주도해 정한다(N3, 반드시 질문).**
3. **모호성이 풀릴 때까지 끈질기게.** 한 라운드 한 질문, 가장 약한 차원을 계속 캔다. 추상적 답("그냥 슬프게", "감동적으로")은
   **구체 사례로 되묻는다**("슬픔 = 잃고 나서 그리운 쓸쓸함? 끝내 못 구한 죄책감? 둘은 전혀 다른 엔딩이 됩니다").
   준비도 게이트(§6)를 통과하기 전엔 STORY.md를 확정하지 않는다. 목표는 *Claude가 쓰기 편한 이야기*가 아니라 **사용자가 원하는, 몰입되는 이야기**다.

## 1. 핵심 원칙 (deep-interview에서 차용)

1. **1문1답.** 한 라운드에 질문 하나. 4개를 한 객관식에 욱여넣지 않는다. (단, N3 전형↔참신의 캐스트 슬롯, N8 채널 배분처럼 *여러 선택지지만 한 질문*인 경우만 multiSelect 허용.)
2. **약점 차원 타깃 + "왜 지금".** 매 라운드 가장 모호하거나 결정적인 차원 하나를 고르고, 왜 지금 이걸 묻는지 한 문장으로.
3. **가정을 드러낸다.** "뭘 원해요?" 대신 "무엇을 전제하나요?"를 묻는다. 추상적 답은 구체 장면/대사로 되묻는다.
4. **Claude가 먼저 참신한 컨셉을 제안(백지 금지).** 서사 이론([story-design/](./story-design/INDEX.md)) + 게임 톤 기반. 첫 옵션에 "(추천)" + 근거. *그림이 그려지는 한 컷*으로(§5).
5. **안티패턴 가드.** [principles.md](./story-design/principles.md)의 '섞지 말 것'(예: 젠 분위기 + 극한 시간압박, 사색형 서사 + 과한 주스, 갈등 없는 톤에 억지 악당)을 내부 가드로. 충돌 의도면 절충 되묻기.
6. **준비도 게이트.** §6 차원이 구체화되기 전엔 STORY.md 확정 금지.
7. **조기 종료 존중.** "알아서/그냥 만들어/충분해"라고 하면 즉시 멈추고, 분석 + 톤 기반 추천 기본값으로 §7 청사진(STORY.md)을 확정해 읽어준 뒤 진행한다고 고지.

## 2. 서사 의도 차원 (탑다운 순서)

위에서부터 캔다(톤 → premise → 전형↔참신 → 프레임워크 → 캐릭터 → 반전 → 대사 → 채널). ✅=구체 확정 · ◻️=미정.

| # | 차원 | 무엇을 확정하나 | 비고 |
|---|---|---|---|
| **N1** | **톤·분위기** ★맨 먼저 | 끝낸 플레이어가 느꼈으면 하는 한 감정을 단어 1~2개로(따뜻함/긴박/쓸쓸함/유쾌/경이/공포) | `ST-TONE-LOCK`·`WT-MOOD-THROUGHLINE`. 어휘·색·BGM·프레임워크를 전부 프레이밍. 흔들리면 아래 무의미. |
| **N2** | **premise / Story Spine 한 문단** | '무엇이 어떻게·왜 변하나'가 든 한 문장 premise + Pixar Story Spine 빈칸 한 문단(옛날…매일…그러던 어느 날…그래서…마침내…그날 이후로) | ★필수. `WT-PREMISE-ONE`·`ST-SPINE-FIRST`. 한 단어 테마('생존')는 인과 문장으로 되받는다. |
| **N3** | **전형(typical) ↔ 참신(novel)** ★★반드시 질문 | 캐스트·세팅·반전을 '전형대로 빠르게' 갈지 '한 군데만 비틀지' 명시 | `AR-EXPECT-FIRST`·`AR-ONE-TWIST`. 장르 전형 캐스트 메뉴 제시 + 슬롯별 '전형 vs 비틀기'. 다 비틀려 하면 게이팅. |
| **N4** | **서사 프레임워크 1개** | 장르·길이·갈등 유무로 메인 구조 1개 자동추천·확인 | `ST-PICK-ONE`·`ST-NO-OVERFIT`. 평화·퍼즐→Kishōtenketsu, 긴박→Fichtean, 루프→Story Circle, 갈등 영웅담→3막/Hero's Journey 압축. |
| **N5** | **입체 캐릭터(의도 + 반전 가능)** | 인물 1명당 7슬롯: Want(겉목표=게임목표)·Lie(한 문장 거짓)·Ghost(상처, 단서1)·Need(엔딩 각성)·Passion 3·노출디테일1~2·아크타입1 | 인물 **1~4명 상한**. 적대자=주인공 Lie의 극단(`AR-SHADOW-MIRROR`), 조연 1명=foil(`CH-FOIL`). Ghost→Lie→Want→Need 인과를 탑다운으로. |
| **N6** | **반전·복선·드러내기** | 엔딩 반전 한 문장을 먼저 확정(역산) → 단서를 인트로·환경에 역배치. 반전 종류 1개 | `TW-PLANT-PAY`·`TW-ONE-CLEAN`·`TW-FAIR-PLAY`. 종류: (A)정체/내 행동의 진짜 의미 깨달음, (B)숨은 빌런/배신, (C)신뢰 못할 인트로 화자. '마지막 클릭=반전 트리거' 기본 제안. |
| **N7** | **대사·캐릭터 보이스** | 인물마다 voice 5축(어휘·자신감·말버릇·내면/외면·비유출처) + catchphrase 1 + 금지 단어 + 문장 리듬 | `DL-VOICEBIBLE`. 모든 대사는 두 가지 일(`DL-DUAL`)·서브텍스트(`DL-SUBTEXT`)·on-the-nose 금지. 막연하면 보기 제시로 구체화. |
| **N8** | **채널 배분 + 분기 깊이** | 각 서사 비트를 4채널(인트로/막간/승패·엔딩/환경 단서)+bark 중 어디로 전달할지 배분 | `TL-CHANNEL-MAP`. 텍스트로 말한 것 중 환경으로 옮길 것 검문(`ST-ENV-CLUE`). 분기 기본=가짜 분기+엔딩만 2~3개(`DL-RECONVERGE`). |

> 갈등 없는 게임이면 N4가 Kishōtenketsu로 거의 자동, N5·N6은 가벼워진다(적 없이 '転'의 시점 전환 하나로 서사 완결).
> 캐릭터·대사 중심 게임이면 N5·N7이 가장 무겁다.

## 3. 라운드 진행 (deep-interview Phase 2 적응)

각 라운드는 `AskUserQuestion` 한 번(질문 1개)으로. 형식:

```
라운드 {n} | 타깃 차원: {N# 이름} | 왜 지금: {한 문장 근거} | 바이블 진행: {✅개수}/8

{Claude의 참신한 제안·관점 1~2문장 — 서사 이론 + 본인 비틀기·의견. 그림이 그려지는 한 컷으로.}

{질문}
```

- 답을 받으면 그 차원을 ✅로, **다음으로 가장 약한 차원**(보통 탑다운 다음 칸)을 타깃해 다음 라운드로.
- 답이 모호하면 같은 차원을 **구체화 질문**으로 한 번 더 판다(추상→구체 장면/대사로 되묻기).
- 안티패턴 충돌이 감지되면 다음 질문은 **절충 되묻기**.

### 라운드 진행 리드아웃 (투명성)

매 라운드 끝에 한 줄로 바이블 상태를 보여준다:

```
바이블: N1 톤 ✅ | N2 premise ✅ | N3 전형↔참신 ◻️ | N4 프레임워크 ◻️ | N5 캐릭터 ◻️ | N6 반전 ◻️ | N7 대사 ◻️ | N8 채널 ◻️
다음 타깃 → N3(전형↔참신): 톤과 premise가 섰으니, 이걸 익숙하게 갈지 한 군데 비틀지가 게임 인상을 가릅니다.
```

## 4. Claude가 창의적 주제를 먼저 제안한다 + 전형↔참신은 사용자가 주도 (★이 인터뷰의 1순위 차별점)

사용자는 "스토리를 어떻게 짜야 할지" 막막할 때가 많다. 그러니 **매 라운드 Claude가 먼저 참신한 컨셉을 한 컷으로 던지고**,
특히 **전형으로 갈지 참신하게 비틀지는 사용자가 고르게** 한다. 사용자의 흐름 그대로:
*"이런 방향들이 있는데(전형/참신 후보) → 이 톤이면 이런 이야기가 됩니다, 괜찮나요? → 혹시 다른 결을 원하세요?"*

### N3 전형↔참신 4단계 루프

1. **전형 캐스트 노출 (expose).** 게임 장르가 정해지면 그 장르의 **전형 캐스트/세팅 메뉴**를 [characters-arcs.md](./story-design/characters-arcs.md)에서 꺼내
   카드로 펼친다(예: 플랫포머=용감한 주인공·잡힌 동료·문지기 보스; 퍼즐=호기심 많은 탐구자·수수께끼의 안내자). "익숙해서 즉시 이해되는 전형은 이렇습니다."
2. **비틀 지점 1개 선택 (one twist).** "이걸 **한 군데만** 참신하게 비틀 수 있어요 — 캐스트/세팅/반전 중 어디를 비틀까요?"
   각 슬롯에 '전형 유지 vs 비틀기' 이지선다 + Claude의 참신한 비틀기 예시 1개. (`AR-ONE-TWIST` — 전부 비틀면 기대가 없어 전복이 안 읽힌다 `AR-EXPECT-FIRST`.)
3. **반영 (reflect).** 사용자가 고르면 → **"그럼 *이런 이야기*가 됩니다"** 하고 구체적인 한 컷으로 되비춘다(막연한 카테고리 금지, 그림이 그려지게).
4. **검증 + 대안 (validate + alternatives).** 곧바로 되묻는다: **"이 방향 마음에 드세요? 아니면 제 다른 아이디어 — [대안 비틀기] — 는 어떠세요?"** 본인 의견·참신함을 적극 개진.

> 비틀기가 톤·코어 동사를 바꿀 만큼 커지면 N1·N2로 거슬러 올라가 갱신한 뒤 다시 내려온다. 탑다운은 *위가 흔들리면 위로 돌아간다*.

## 5. Claude의 제안 의무 — "참신한 주제를 먼저, 구체적으로"

제안 주도권은 Claude에게, 선택권은 사용자에게. **매 라운드 Claude가 먼저 구체적 컨셉/대안을 제시**한다(백지 금지).

- **출처:** [story-design/](./story-design/INDEX.md)의 서사 이론 + game-dna 장르 맥락 + **본인의 창의적 비틀기**.
- **구체적으로.** 카테고리 라벨이 아니라 **그림이 그려지는 한 컷**으로:
  - ❌ "감동적인 스토리는 어떠세요?"
  - ✅ "버려진 등대지기 로봇이 *마지막 전구 하나*를 지키며 폭풍의 밤을 버티는 이야기는 어떨까요 — 매 레벨 전구가 깜빡일 때마다 그가 누굴 기다렸는지 한 줄씩 드러나고, 엔딩에서 *기다리던 배는 오지 않았지만 빛을 본 다른 배가 살았다*로 뒤집히는. 제 추천은 이 쪽인데, 더 밝은 톤도 같이 올릴게요."
- **추천 + 한 컷 + 왜 몰입되나 + 본인 의견.** 첫 옵션에 "(추천)", "제 추천은 X입니다, 왜냐면 ~"으로 관점을 분명히(사용자가 반박·선택하기 쉽게).
- **다양성.** 톤·premise를 묻는 라운드에선 서로 다른 결을 3~4개 섞어 노출.
- 요청에 이미 단서가 있으면 그 부분은 고정하고, 제안은 *그 안에서의 변주*로 좁힌다.

## 5.5. 챌린지 모드 (deep-interview Phase 3 적응 — 서사용)

라운드가 쌓이면 관점을 바꿔 한 번씩 도발한다(각 1회). 이야기를 날카롭게 만든다.

- **3라운드+ · Contrarian(반대로):** 톤·전제를 뒤집는다 — "정말 이 톤이 코어 동사와 맞나요? *쏘는 게임*에 평화로운 톤을 얹으면 메커닉과 이야기가 따로 놀 수도 있는데(`GN-LUDOHARMONY`), 굳이 이 결인 이유가 있나요?"
- **4라운드+ · Simplifier(덜어내기):** 최소 버전을 묻는다 — "이 이야기를 **한 문장**으로 줄이면 뭔가요? 캐릭터·반전을 다 빼고 *그 한 문장*만 남겨도 성립하나요?" (premise 정련)
- **5라운드+ · Signature Beat(자랑할 한 순간):** 정체성을 묻는다 — "플레이어가 *어느 순간*에 '아…' 하고 멈췄으면 하나요? 그 한 컷이 이 게임 서사의 정체성입니다(보통 반전 회수 = `TW-PERI-ANAG`)."

각 모드는 한 번만 쓰고 일반 질문으로 복귀.

## 6. 준비도 체크 (게이트)

STORY.md 확정 시작 조건:
- **N1(톤) 확정** + **N2(premise) 구체화(✅)** + **N4(프레임워크) 1개 확정** + **코어 동사와 주제가 같은 말(`GN-LUDOHARMONY`)** — 각각 한 문장으로 막힘없이 서술 가능.
- N3(전형↔참신)은 **반드시 명시 확정**(전복 0~1개). N5~N8은 ✅이거나, 미정이면 **톤 기반 추천 기본값**으로 확정(사용자에게 "이건 이렇게 기본값으로 갈게요" 고지).
- 안티패턴 충돌이 모두 해소(절충안 확정).

게이트 미달이면 가장 약한 차원으로 라운드를 더 돈다. 보통 **3~6라운드**면 충족된다.

### 라운드 수 가이드 / 조기 종료
- 3라운드+부터 "충분/그냥 만들어"로 조기 종료 가능 — 단, 필수(N1·N2·N4·N3)가 ◻️면 **추천 기본값을 채워 청사진을 완성**한 뒤 진행한다고 고지.
- 8라운드 soft 경고: "벌써 8라운드네요. 지금 바이블로 진행할까요, 더 다듬을까요?"

## 7. 청사진(STORY.md) 확정 & 빌드 라우팅 (deep-interview Phase 4·5 적응)

게이트 충족 시, **청사진을 한 화면으로 정리해 읽어주고 최종 확인**받은 뒤에만 `games/<slug>/STORY.md` 작성을 시작한다.

### 확정 전 반드시 묻는 두 게이트
- **(make-game 적용)** 이 인터뷰가 web-game-builder/make-game 흐름에서 호출됐다면, 시작 전에 이미 **"스토리를 입힐까요?"**로 진입 동의를 받았어야 한다. 받지 않았으면 지금 묻는다.
- **(전형↔참신)** N3에서 **전형으로 갈지 / 한 군데 비틀지**를 명시적으로 확정했는지 청사진에 못 박는다(미정이면 디폴트는 '전형 + 전복 1개 추천').

### 청사진 형식 (응답 안 블록 — STORY.md의 요약본)

```
## 서사 청사진: {제목} (slug: {kebab-slug})

- **톤·무드 (N1):** {단어 1~2개} → 끝낸 플레이어의 한 감정
- **premise (N2):** {무엇이 어떻게·왜 변하나 한 문장} / Story Spine: {옛날…그러던 어느 날…마침내…그날 이후로}
- **전형↔참신 (N3):** {전형 유지 | 전복 1개: 캐스트/세팅/반전 중 어디를 어떻게}
- **프레임워크 (N4):** {Kishōtenketsu | Fichtean | Story Circle | 3막/Hero's Journey 압축} (이유 1줄)
- **캐릭터 (N5):** {이름·원형·Want·Lie·Ghost·Need 1줄씩, 1~4명} (적대자=주인공 Lie의 극단)
- **반전 (N6):** {엔딩 반전 한 문장} ← setup 단서 {1~2개 매설 채널} (종류: A/B/C)
- **대사·보이스 (N7):** {인물별 voice 한 줄 요약 + catchphrase}
- **채널 배분 (N8):** 인트로 {…} · 막간 {…} · 승패/엔딩 {…} · 환경 단서 {…} · bark {…}
- **코어 동사 정합:** {코어 동사}가 {주제}와 같은 말을 한다 (GN-LUDOHARMONY)
- **IP 안전 메모:** 오리지널 인물·이름(Glossary), 상용 작품 미복제
- **빌드 라우팅:** 분위기 → vector-graphics/chip-sound/juice-fx · 카드 UI → game-ui-hud · 환경 단서 → sprite-picker/sprite-forge · 검증 → game-qa
```

확정 후:
1. 톤·장르에 맞는 **story-design 도메인 파일 1~2개를 Read**해 원칙 근거를 반영.
2. `games/<slug>/STORY.md` 를 [consistency-tools.md](./story-design/consistency-tools.md) 스펙으로 작성(단일 진실).
3. 텍스트 표면을 game.js에 매핑(SKILL.md 4단계) → **작성과 분리된 검수 패스**(SKILL.md 5단계 연속성 린트).
4. **확인을 받은 뒤에만** 코드를 짠다.

## 8. 예시 (Good / Bad)

**라운드 1 — 탑다운: 톤부터 (N1)**

```
라운드 1 | 타깃 차원: N1 톤·분위기 | 왜 지금: 끝낸 플레이어가 느꼈으면 하는 한 감정이 어휘·색·BGM·구조를 전부 프레이밍하므로 맨 먼저 정합니다 | 바이블 진행: 0/8

같은 '달리기' 게임도 톤에 따라 완전히 다른 이야기가 됩니다 — *쫓기는 긴박*이냐, *해방의 질주*냐, *떠나간 것을 좇는 쓸쓸함*이냐.
제 추천은 코어 동사(끝없이 달린다)와 가장 잘 맞는 '쫓기는 긴박 + 한 줄기 희망'이지만, 정하기 나름입니다.

이 게임을 끝낸 플레이어가 어떤 한 감정을 안고 떠났으면 하세요?
```

**라운드 3 — 전형↔참신 (사용자 주도 + 비틀기 제안)**

```
라운드 3 | 타깃 차원: N3 전형↔참신 | 왜 지금: 톤(쓸쓸함)과 premise가 섰으니, 익숙하게 갈지 한 군데 비틀지가 게임 인상을 가릅니다 | 바이블 진행: 2/8

이 장르의 전형 캐스트는 [잡힌 동료를 구하러 가는 용감한 주인공 + 길을 막는 문지기]입니다 — 즉시 이해되고 편안하죠.
한 군데만 비틀 수 있어요. 제 추천 비틀기는 '구하러 간 동료가 사실 *떠나고 싶어 했다*'(반전 슬롯)인데, 쓸쓸한 톤과 맞물립니다.

[multiSelect] 전형 유지(빠르게) · 캐스트 비틀기 · 세팅 비틀기 · 반전 비틀기(추천)

어디를 전형대로 두고, 어디를 한 군데 비틀까요?
```
→ (사용자가 고르면) **반영:** "그럼 *구하러 갔더니 동료는 이미 새 삶을 택했고, 주인공이 그걸 받아들이는* 이야기가 됩니다 — 달리는 내내 '왜 안 돌아봤을까'가 깔리는."
→ **검증+대안:** "이 방향 괜찮으세요? 아니면 동료가 *주인공을 지키려 일부러 멀어졌던* 쪽도 같은 톤에서 따뜻해지는데, 어느 쪽이 끌리세요?"

**왜 좋은가:** 탑다운(톤 먼저), 약점 차원 하나만, "왜 지금" 명시, **전형↔참신을 사용자가 직접** 고르게 하고 Claude가 비틀기를 구체적 한 컷으로 *반영*하고 *대안*까지 던짐.

**Bad:** "스토리 어떻게 할까요? 1)감동 2)코믹 3)다크"만 던지기 — 추상 카테고리라 그림이 안 그려지고, 톤(N1)도 안 묻고 바로 점프(정신1 위반), 전형↔참신 주도권도 안 줌(정신2 위반).

## 9. 최종 체크리스트

- [ ] 탑다운: N1(톤·무드)부터 못 박고 아래로 내려갔는가
- [ ] 한 라운드에 질문 하나(1문1답) — N3 캐스트/N8 채널만 multiSelect 한 질문 허용
- [ ] 매 라운드 타깃 차원 + "왜 지금" 명시
- [ ] 매 라운드 Claude가 **참신한 주제를 먼저** 구체적 한 컷으로 제안하고 본인 의견을 밝혔는가
- [ ] **N3에서 전형↔참신을 사용자가 직접 고르게** 했는가(전복 0~1개) — ★반드시
- [ ] 프레임워크는 **하나만** 메인으로 골랐는가(`ST-PICK-ONE`)
- [ ] 캐릭터 7슬롯 + 적대자=주인공 Lie의 극단(`AR-SHADOW-MIRROR`), 인물 1~4명
- [ ] 반전은 엔딩부터 역산하고 단서를 공정하게 심었는가(`TW-PLANT-PAY`·`TW-FAIR-PLAY`), 종류 1개
- [ ] 코어 동사와 주제가 같은 말을 하는가(`GN-LUDOHARMONY`) — 준비도 게이트
- [ ] 추상적 답은 구체 장면/대사로 되물어 구체화
- [ ] 안티패턴 충돌(젠+시간압박, 갈등없는톤+억지악당 등)은 절충 되묻기로 해소
- [ ] 챌린지 모드(Contrarian/Simplifier/Signature Beat)를 적절 라운드에 1회씩
- [ ] **make-game 적용 동의**를 받았는가(이 인터뷰가 make-game에서 호출된 경우)
- [ ] 준비도 게이트(N1 톤 + N2 premise + N4 프레임워크 + 코어 동사 정합) 후에만 STORY.md 확정
- [ ] 청사진을 한 화면으로 읽어주고 최종 확인 후 STORY.md 작성
- [ ] 조기 종료("그냥 만들어") 시 톤 기반 추천 기본값으로 청사진 완성 후 진행
