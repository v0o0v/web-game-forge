# 자원·비용 — 능력에 무게를 주는 기회비용 (`RES-*`)

> 능력이 *공짜*면 그냥 연타 버튼이다. 쿨다운·자원·충전이 **"지금 쓸까, 아낄까"**를 만들어 능력 사용을 *선택*으로 바꾼다.
> 인터뷰 A4. T2+에서 본격. `engine/abilitykit.js`가 이 모델을 런타임으로 굴린다(자원 리젠·쿨다운 틱·충전 회복).

---

## `RES-OPPORTUNITY-COST` — 비용이 선택을 의미있게 한다 (북극성)
모든 발동형 능력에는 비용(쿨다운 또는 자원 또는 둘 다)이 있어야 한다. 비용이 "지금 쓰면 잠시 못 쓴다 / 다른 데 못 쓴다"는 긴장을 만들어 타이밍이 실력이 된다. 비용 0 강력 능력 = 선택 소멸(`principles.md` 안티패턴, lint `cooldown` warn).
- **smallWebGame:** 가장 가벼운 비용은 쿨다운 하나. 자원 풀은 *정말 필요할 때만* 추가한다(`RES-RESOURCE-PICK-ONE`).

## `RES-COOLDOWN-AS-RHYTHM` — 쿨다운은 전투의 리듬을 만든다
쿨다운은 단순 제한이 아니라 *리듬 악기*다. 짧은 쿨(0.5~2s)은 주력기의 박자, 중간(3~8s)은 전술적 한 방, 긴 쿨(10s+)은 궁극의 무게. 쿨다운 길이로 능력의 "체감 무게"를 디자인한다.
- **smallWebGame:** `AbilityKit`의 `cooldownFrac()`로 HUD 스윕을 그린다(`UX-COOLDOWN-VIZ`). 1~3분 세션이면 긴 쿨은 한 판에 1~2회만 돌아온다 — 궁극에 적합.

## `RES-RESOURCE-PICK-ONE` — 자원은 한 종류만
마나·스태미나·에너지·기력·과열·콤보포인트 중 **하나만** 고른다. 두 자원을 동시에 굴리면 짧은 세션·작은 화면에서 인지 과부하. 자원의 *성격*이 게임 느낌을 정한다:
| 자원 | 성격 | 어울리는 게임 |
|---|---|---|
| **마나(고갈형)** | 아끼고 관리, 고갈되면 무력 | 캐스터·전략적 |
| **스태미나(빠른 리젠)** | 연속 행동 제한, 곧 회복 | 액션·회피 중심 |
| **에너지/기(축적형)** | 싸우며 모아 쓴다 | 콤보·궁극 충전 |
| **과열(heat)** | 쓸수록 차오르다 오버히트 | 푸시유어럭 사격 |
| **충전(charges)** | N회 비축, 개별 재충전 | 대시·점멸 |
- **smallWebGame:** 스태미나(빠른 리젠)가 모바일 짧은 세션에 가장 무난 — 고갈 좌절이 적고 리듬만 준다.

## `RES-REGEN-BALANCE` — 리젠 vs 소비 균형
자원 이코노미는 *지속 가능하되 무한하지 않게*. 가장 싼 능력을 계속 써도 자원이 천천히 줄거나 본전이어야 긴장이 산다. 리젠이 소비를 항상 앞지르면 자원은 장식이다(lint `resource` info: 짧은 쿨인데 리젠이 비용 전액 회복 → 기회비용 0).
- **공식 감각:** 주력기 비용 ≈ rechargeDelay 동안 못 모으는 양. `rechargeDelay`(소비 후 리젠 멈춤)로 "쏟아붓고 잠시 마름"의 리듬을 만든다(`AbilityKit` 지원).

## `RES-NO-STARVE` — 고갈 교착 금지
비용 > 자원최대면 영구 사용 불가(죽은 능력, lint `resource` error). 또 모든 능력이 비싸 자원이 늘 바닥이면 플레이어는 아무것도 못 한다 — 항상 *쓸 수 있는 무비용 기본 행동*(코어 동사)을 남긴다.
- **smallWebGame:** 코어 동사(점프·기본 공격)는 자원을 안 먹게 두고, 능력만 자원을 먹게 한다. 자원 0이어도 게임은 계속된다.

## `RES-CHARGES` — 충전형: 비축과 재충전
대시·점멸처럼 "연속으로 몇 번, 그 뒤 재충전"이 어울리는 능력은 `charges`(N충전, 각 cooldown으로 개별 회복)로. 쿨다운 단일보다 *몰아쓰기*의 쾌감과 *비축 관리*를 동시에 준다.
- **smallWebGame:** `AbilityKit`가 충전 회복을 자동 처리(`chargesLeft()`로 HUD 표시). 대시 2충전이 플랫포머·러너에 인기.

## `RES-CAST-COMMIT` — 캐스트·커밋 타임
즉발이 아닌 능력은 선딜(cast)로 "지금 시작하면 잠시 무방비"를 만든다([activation-feel.md](./activation-feel.md) `FEEL-ANTICIPATION`과 연결). 캐스트는 자원과 별개의 *시간 비용*이다 — 큰 능력일수록 길게.

## `RES-GLOBAL-COOLDOWN` — 글로벌 쿨다운(선택)
여러 능력을 한 프레임에 쏟아붓는 걸 막고 싶으면 작은 글로벌 쿨(0.1~0.3s)을 둔다(`balanceConfig.globalCooldown`). 능력 사용 사이에 최소 간격 → 콤보가 "난사"가 아니라 "선택의 연쇄"가 된다.
- **smallWebGame:** 대부분의 작은 게임엔 불필요. 능력이 많고 동시 발동이 문제일 때만.

## `RES-COMBO-AS-RESOURCE` — 콤보가 자원을 만든다
콤보 적중·연계 성공이 자원을 환급/생성하면(`combo.grants`), "잘 쓰면 더 쓸 수 있다"는 숙련 루프가 생긴다([synergy-combo.md](./synergy-combo.md) `COMBO-REWARD-LOOP`). 단 순(純)소모가 0 이하인 자급 루프는 무한콤보(lint `combo-loop` error) — 루프는 항상 순소모가 음수여야 자연 종료.

## `RES-SHARED-VS-SEPARATE` — 공유 자원 vs 분리 쿨다운
여러 능력이 *한 자원풀*을 공유하면(마나 하나로 모든 스킬) "무엇에 쓸까"의 배분 결정이 생긴다 — 능력끼리 경쟁한다. 능력마다 *개별 쿨다운*이면 각 능력이 독립적이라 배분 결정은 없고 타이밍만. 둘을 섞을 수도(쿨다운 + 공유 자원 이중 게이트). 선택이 게임 느낌을 정한다:
- **공유 자원** = 전략적 배분(캐스터·자원 관리 재미), 단 한 자원 고갈 시 전부 막힘(`RES-NO-STARVE` 주의).
- **개별 쿨다운** = 리듬·로테이션(액션 재미), 능력 간 독립이라 밸런스 단순.
- **smallWebGame:** 능력 2~3개면 개별 쿨다운이 단순·명료. 자원풀은 "배분 결정"이 *핵심 재미*일 때만 도입(`RES-RESOURCE-PICK-ONE`).

## `RES-SUSTAIN-VS-BURST` — 지속 vs 폭발 축
능력을 "꾸준히 약하게(sustain)" vs "몰아서 강하게(burst)"로 갈라 빌드 선택을 만든다. 같은 자원을 조금씩 자주 쓰는 빌드와 모아서 한 방 쓰는 빌드가 둘 다 viable이면 `BAL-NO-DOMINANT`가 산다.
- **smallWebGame:** sim-abilities.mjs로 두 빌드의 DPS·자원 고갈률을 비교해 한쪽이 지배하지 않는지 검증.

---

## 기계 검증 훅 (lint-abilities.mjs)
- 비용 > 자원최대 → `resource` error(영구 사용불가).
- 짧은 쿨 + 리젠이 비용 전액 회복 → `resource` info(기회비용 0).
- 고파워 + 무쿨 + 무비용 → `cooldown` warn(스팸).
- cooldownReset 순환 + 순자원수지 ≥ 0 → `combo-loop` error(무한콤보).

## 출처
- 쿨다운·자원 유형(마나/스태미나/에너지/과열/충전)·기회비용·자원 이코노미 균형·글로벌쿨다운을 작은 2D 웹게임용으로 정리. 상세: `.omc/research/ability-system-research-dossier.md`. 도박성·복잡 다자원 통념은 짧은 세션 정합상 단순화.
