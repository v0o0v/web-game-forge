## Sokoban (1982)
**왜 많이 플레이됐나:** 규칙이 단 한 줄("상자를 밀어 모든 목표칸에 올린다")인데, 한 칸 한 칸이 되돌릴 수 없는 결정이라 깊은 수읽기를 요구하는 "쉽게 배우고 평생 못 끝내는" 순수 사고 퍼즐의 원형이기 때문이다. 물리·반사신경·운(RNG)이 전혀 없는 100% 결정론적 공간 추론이라 풀이가 온전히 플레이어의 머리에 달려 있고, 한 수의 실수(벽으로 민 상자)가 명백히 "내 잘못"으로 납득돼 재도전을 부른다. 한 화면짜리 작은 보드만으로 무한에 가까운 난도를 뽑아내는 콘텐츠 효율이 압도적이라 40년간 수만 개의 팬메이드 레벨이 만들어졌다.
**장르 / 시점:** 밀기 퍼즐 (block-pushing / sokoban-type grid puzzle) — 턴제 단일 플레이어 그리드 퍼즐. 모든 후대 밀기 퍼즐(Baba Is You, Stephen's Sausage Roll, Helltaker 등)의 직접 조상. / 탑다운 고정 단일 화면 그리드(top-down grid). 한 레벨 = 한 화면, 스크롤 없음. 정면에서 격자를 내려다보는 2D 평면. 캐릭터(창고지기)·상자·목표칸·벽이 모두 한 셀씩 차지.
**코어 루프:** 화살표/스와이프로 창고지기를 한 칸씩 움직이고, 진행 방향에 상자가 있으면 그 한 칸을 "밀어" 함께 이동시킨다(당기기 불가, 한 번에 상자 하나만). 모든 상자를 목표칸 위에 올리면 클리어 — 매 칸마다 "이 한 수가 상자를 구석/벽에 가둬 교착에 빠뜨리는가"를 머릿속으로 시뮬레이션하는 것이 30초 단위 루프다.
**핵심 재미요소:**
- `FE-PLANNING` 선계획·멀티스텝 — 상자를 목표칸에 올리려면 창고지기가 상자 반대편으로 미리 돌아가 밀 위치를 잡아야 하고, 한 상자를 옮기면 다른 상자의 진입로가 막히는 의존 관계 탓에 올바른 순서·경로를 여러 수 앞서 계획해야 한다. 우리가 게임 DNA에서 Sokoban을 FE-PLANNING의 대표로 명시한 이유.
- `FE-SPATIAL` 공간 추론 — 상자·창고지기·벽의 배치를 머릿속으로 이동시켜 '밀면 어디로 가는지'를 시뮬레이션하는 순수 공간 사고. 회전·반사신경 없이 격자 위 위치 관계만으로 길과 막힘을 읽는다.
- `FE-AHA` 통찰·아하 — 꽉 막혀 보이던 보드에서 '이 상자를 먼저 저 칸으로 빼야 길이 열린다'는 결정적 순서가 떠올라 풀이 전체가 한꺼번에 무너지듯 열리는 순간. 손이 아니라 머리가 푸는 보상.
- `FE-CONSTRAINT` 제약 퍼즐 — 이동 횟수·밀기 횟수가 명시 목표(별 판정)로 작동해, 단순 클리어를 넘어 '최소 push 수'로 푸는 최적화 압박을 만든다. 좁은 보드라는 공간 자원 자체가 제약.
- `FE-FAIRNESS` 공정함 — 운·물리·타이밍이 0이라 실패(상자를 벽 구석에 가둠)가 100% '내 한 수 탓'으로 납득된다. undo/리셋 비용이 0에 가까워 좌절 대신 '다시 한 수'로 즉시 재도전하게 된다.
**핵심 메카닉:**
- 보드 모델: grid[row][col] 2D 배열이 유일 상태원. 정적 레이어(벽 #, 목표칸 .)와 동적 레이어(상자 $, 창고지기 @)를 분리해 두 배열로 관리하거나, 셀 비트마스크(WALL|GOAL|BOX|PLAYER)로 한 배열에 합친다. 렌더는 상태 변경 시점에만 renderBoard() (puzzle-game 핵심 원칙: update 루프에서 그리지 않음).
- 이동 판정(밀기 한 단계): 입력 방향 d에 대해 player 앞 칸 n1을 본다. n1이 벽이면 무효(이동 없음). n1이 상자면 그 다음 칸 n2를 보고, n2가 빈칸/목표칸이면 상자를 n2로, player를 n1로 동시 이동(한 번에 상자 1개만 — 상자 2연속은 밀 수 없음). n2가 벽·다른 상자면 전체 이동 취소. n1이 빈칸/목표칸이면 player만 이동. 당기기(pull)는 규칙상 불가.
- 클리어 판정: 모든 GOAL 셀 위에 BOX가 있으면(또는 모든 BOX가 GOAL 위) 승리. 이동 확정 직후에만 검사. 목표칸 위 상자는 색/하이라이트를 바꿔 'on-goal' 상태를 시각화.
- 교착(deadlock) = 되돌릴 수 없는 한 수: 상자를 벽 코너로 밀거나 목표 아닌 벽면에 붙여 더는 그 상자를 어떤 목표로도 보낼 수 없게 만드는 상태. 게임이 자동 패배를 주지 않으므로(원작 충실), 플레이어가 스스로 교착을 알아채고 undo해야 한다. 선택적 보조: 단순 corner-deadlock 감지(목표 아닌 칸에서 두 인접 벽에 갇힌 상자)로 '되돌리기 권장' 힌트 표시.
- undo 스택 + 리셋: 매 이동마다 grid 깊은 복사(또는 (이동 객체, 이전위치) 델타)를 스택에 push. Z키/버튼으로 무제한 undo, R로 레벨 리셋. 결정론적이라 가설검증 비용이 0에 가까워 FE-AHA·FE-FAIRNESS의 핵심 인프라.
- 이동/밀기 카운터 + 별 판정: moves·pushes를 game-ui-hud에 표시. 레벨별 목표값(예: pushes ≤ N) 대비 별 1~3개로 FE-CONSTRAINT 최적화 동기 부여. localStorage에 레벨별 베스트(최소 push 수) 저장.
- 입력: 키보드 ← → ↑ ↓ + Z(undo)/R(reset). 모바일은 MobileHarness 스와이프 4방향(pointerdown→pointerup delta로 방향 판별), undo/reset은 화면 버튼. 한 스와이프 = 한 칸 이동(연속 슬라이드 아님).
**난이도·진행 곡선:** 외부 가속·타이머 없는 비실시간 진행. 난도는 (1) 보드 크기, (2) 상자 수, (3) 상자-목표 의존 관계의 얽힘(한 상자가 다른 상자의 경로를 막는 정도), (4) 교착 함정 위치의 비직관성으로만 상승한다. 곡선: 도입부는 4~6칸 보드 + 상자 1~2개로 '밀기·되돌리기·당기기 불가'를 손에 익힌다 → 중반은 상자 3~5개로 밀기 순서 의존성과 코너 교착 회피를 도입 → 후반은 좁은 통로·다중 상자 정렬·강제 순서로 멀티스텝 선읽기를 시험. 별도 월드맵 없이 레벨 팩(예: 20~40개 손제작 레벨 + 난도 라벨)을 선형/소분기로 진행, 별 수가 사실상의 진행 지표. level-designer로 각 레벨을 JSON 그리드(# 벽 / . 목표 / $ 상자 / @ 플레이어 / 공백 바닥, 표준 XSB 유사 포맷)로 정의.
**게임필·연출:** 조용하고 또박또박한 '한 수 두는' 손맛이 핵심 — 빠른 액션이 아니라 묵직한 결정의 게임필. 창고지기 한 칸 이동은 60~100ms 격자 스냅 트윈(약간의 오버슈트), 상자는 함께 밀릴 때 살짝 끌리는 느낌의 동시 트윈 + ChipAudio 'bump'(밀기)·발소리 톤. 상자가 목표칸에 안착하는 순간이 핵심 보상: 스쿼시 팝 + 짧은 'coin'류 상승음 + 색 전환(on-goal 하이라이트)으로 '딱 맞았다'를 강조. 벽에 막혀 못 미는 입력은 미세 셰이크 + 둔탁한 'thud'로 '불가'를 즉각 피드백(FE-FAIRNESS의 가시화). 마지막 상자 안착 = 모든 목표 동시 플래시 + 팡파르 + (선택)스크린셰이크로 클리어 카타르시스. undo는 빠른 역재생(50ms)로 '실수 무름'을 가볍게. juice-fx는 '적게, 정확하게' — 사고형 퍼즐이라 과한 연출은 FE-FLOW가 아닌 차분한 집중을 방해한다.
**끈끈함(리텐션):** 막힌 퍼즐이 머릿속을 떠나지 않는 '잠복 효과'가 강력하다 — 끄고 나서도 해법이 번뜩이고, 그 한 수가 맞아떨어졌을 때의 보상이 다음 레벨로 즉시 끌어당긴다. 운이 0이라 실패가 전적으로 '내 판단 탓'(FE-FAIRNESS)으로 귀인돼 '더 잘 둘 수 있었다'는 납득과 재도전 욕구가 동시에 생긴다. undo·리셋 비용이 0에 가까워 부담 없이 실험을 반복하게 되고, '최소 push 수' 별 판정(FE-CONSTRAINT)이 클리어 후에도 '더 짧게 풀기' 최적화 동기를 남겨 한 레벨을 여러 번 다시 켜게 만든다. 짧은 한 화면 단위라 '하나만 더' 진행이 자연스럽다.
**우리 엔진 재현도:** ✅ · 스킬 [`puzzle-game`](../../../../wgf-puzzle-game/SKILL.md) · 엔진 board-model/render 분리 (grid[row][col] 단일 상태원, renderBoard()), PixelForge 또는 VectorForge 절차 스프라이트(창고지기·상자·벽·목표칸), ChipAudio (bump/coin/thud/clear SFX), MobileHarness (스와이프 4방향 입력 + 스케일·DOM 가드), juice-fx (상자 안착 스쿼시·on-goal 플래시·막힘 셰이크, 절제 적용), game-ui-hud (이동/밀기 카운터·별 판정·베스트), level-designer (JSON/XSB 유사 그리드 레벨 팩 정의), localStorage (레벨 클리어·최소 push 베스트 영속) — 순수 결정론 그리드 로직이라 물리(Arcade/Matter)·서버·3D가 전혀 불필요해 우리 puzzle-game 스택과 정합도 최상. 보드 모델: 정적 레이어(WALL/GOAL)와 동적 레이어(BOX/PLAYER)를 분리한 2D 배열, 또는 셀당 비트마스크. 밀기 로직은 '앞칸 n1·그 너머 n2 검사 → 빈칸/목표면 상자+플레이어 동시 이동, 벽/상자면 취소'의 짧은 순수 함수로 구현(2048 슬라이드보다 단순 — 한 칸만 이동, 회전 재사용 불필요). 클리어는 모든 GOAL에 BOX 매칭 검사. undo는 puzzle-game이 이미 권장하는 grid 깊은복사 스냅샷 스택(Baba Is You 재현과 동일 패턴). 핵심 단순화/대체: (1) 교착 자동 패배는 원작에 없으므로 그대로 두되, 선택적 corner-deadlock 감지(목표 아닌 칸 + 두 인접 벽)로 '되돌리기 권장' soft 힌트만 — 일반 교착의 완전 판정은 PSPACE 난도라 시도하지 않음. (2) 원작 자동 솔버/최적해 검증은 작은 보드 한정 BFS로 가능하나 레벨 검증용으로만, 런타임 불필요. (3) 대량 팬메이드 레벨·글로벌 랭킹은 ❌ → 20~40개 손제작 레벨 팩 + localStorage 로컬 베스트로 축소. 모바일은 스와이프=한 칸(연속 슬라이드 아님)으로 명확히. 레벨 풀이 가능성(solvable) 보장은 손제작 + 수동 검증(또는 BFS 솔버 통과)으로 담보 → FE-FAIRNESS 보존.
**조합 훅:** puzzle-game 규칙조작(Baba Is You)과 결합: Sokoban의 '밀기' 위에 'CRATE IS PUSH / GOAL IS WIN' 단어블록을 얹어, 밀어서 규칙을 다시 쓰는 소코반(우리 fun-elements의 '규칙조작 그리드 퍼즐' 레시피 = 밀기 코어 + FE-AHA+FE-EMERGENCE+FE-CONSTRAINT)으로 확장.; arcade-classic 그리드 호퍼/Snake에 이식: 한 칸 이동 + '한 번에 하나만 미는' 밀기 규칙을 더해, 장애물 블록을 밀어 길을 트며 목표에 닿는 밀기형 미로 — FE-SPATIAL+FE-PLANNING을 캐주얼 호퍼에 주입.; 2048/Threes 슬라이드 머지와 결합: 상자에 숫자를 부여하고 같은 수 상자를 밀어 맞닿게 하면 합쳐지는 '밀기형 머지 소코반' — FE-PLANNING(밀기 순서)에 FE-CONSTRAINT(머지 최적화)를 겹친 하이브리드.; endless-runner에 '되돌릴 수 없는 한 수' 긴장 이식: 자동전진 대신 턴제로, 좁아지는 통로에서 블록을 밀어 발판을 만들되 교착에 빠지면 끝나는 FE-FAIRNESS+FE-TENSION 미니 소코반 스테이지.; topdown-shooter에 이식: 엄폐물(상자)을 밀어 적의 사선을 막고 안전지대를 만든 뒤 한 수 안에 통과하는 턴제 '엄폐 밀기' 퍼즐 슈팅 — 실시간 정밀물리를 사고형으로 치환해 신뢰도 확보.
**IP 안전 메모:** 금지: 'Sokoban'(倉庫番)·'창고지기' 명칭을 게임 타이틀/스토어명으로 사용 금지(메카닉 설명 맥락에서만 언급), Thinking Rabbit의 원작 로고·서체·캐릭터 디자인·오리지널 사운드/BGM·특정 원작 레벨 레이아웃(유명 팬/공식 레벨 좌표 그대로 베끼기)도 금지. IP-safe 환기: '밀기 퍼즐(box-pushing puzzle)' 또는 'crate puzzle' 같은 일반 명사로 표기하고 고유 타이틀(예: 'CratePush', 'Warehouse Logic', 'Boxhaul')을 새로 부여. 밀기 규칙(한 번에 하나·당기기 불가·목표 정렬·교착)은 게임 시스템/아이디어라 자유롭게 구현 가능 — 보호 대상은 표현물뿐. 창고지기→VectorForge/PixelForge 자체 마스코트(로봇·블롭 등), 상자→자체 텍스처 큐브, 목표칸→자체 마커, 모든 SFX→ChipAudio 절차 생성(CC0). 레벨은 원작 카피 금지, 동일 규칙 위에서 자작(BFS 솔버로 풀이 가능성·최소해 검증). 최종 ip-license-guard 스킬로 점검.

## Baba Is You (2019)
**왜 많이 플레이됐나:** 규칙 자체가 화면 위 단어블록('BABA IS YOU', 'FLAG IS WIN')으로 물리적으로 존재하고, 그 단어를 밀어 게임의 법칙을 실시간으로 다시 쓴다는 단 하나의 발상이 매 스테이지마다 새로운 "그게 되네?"의 충격을 준다. 좁은 그리드와 적은 요소만으로 무한에 가까운 횡적 사고 퍼즐을 뽑아내며, 막힌 퍼즐이 게임을 끈 뒤에도 머릿속을 떠나지 않는 '잠복 효과'와 무제한 Undo의 0에 가까운 실패 비용이 끝없는 실험을 부른다.
**장르 / 시점:** 규칙 조작(rule-manipulation) 소코반형 그리드 퍼즐 (our_skill: puzzle-game) / 탑다운 격자(top-down grid) 정면 2D, 고정 단일 화면 스테이지. 스크롤 없음, 한 화면에 보드 전체가 들어옴. 한 칸에 여러 객체가 겹칠 수 있어 칸당 객체 스택을 유지한다.
**코어 루프:** 방향키/스와이프로 YOU 객체를 한 칸씩 움직여 박스와 단어블록을 민다. 화면 안 'NOUN IS PROPERTY' 문장을 재배열해 무엇이 나·벽·승리인지를 바꾼 뒤, 새로 만든 규칙으로 WIN 타일에 도달한다. 한 수가 곧 한 단계의 깨달음이라 30초 안에 가설을 세우고 밀어보고 Undo로 되돌리는 실험 루프가 반복된다.
**핵심 재미요소:**
- `FE-RULE-DISCOVERY` 규칙 발견 — 승리 조건·조종 대상·벽 같은 게임의 법칙이 미리 주어지지 않고 화면 위 단어블록으로 노출돼 있어, 'IS'를 옮겨 규칙을 끊거나 'BABA IS WIN'으로 새 규칙을 만드는 것이 곧 해법. 알려주지 않은 규칙 문법(NOUN IS PROPERTY 파싱) 자체를 스스로 깨닫는 순간이 이 게임의 정체성.
- `FE-AHA` 통찰·아하 — 막힌 스테이지를 노려보다 'WALL IS YOU'로 조종 대상을 바꾸거나 'IS'를 끊어 벽을 무력화하는 한 수가 떠오르는 순간, 풀이 전체가 한꺼번에 무너지듯 열리는 강렬한 깨달음. 보드가 작아 해 공간을 음미할 수 있어 아하의 밀도가 매우 높다.
- `FE-EMERGENCE` 창발 — 몇 안 되는 규칙 원자('IS' + 속성)들이 조합되며 설계자도 예상 못 한 풀이가 튀어나온다. 'STOP을 PUSH로 만들어 길을 뚫기' vs '내가 곧 깃발이 되기'처럼 동일 스테이지에서 서로 다른 시스템적 해법·꼼수 해법이 창발한다.
- `FE-PLANNING` 수읽기·계획 — STOP/PUSH 객체가 연쇄로 밀리는 소코반식 캐스케이드와 규칙 갱신 후 파괴·변환 우선순위를 머릿속에서 몇 수 앞까지 시뮬레이션해야 한다. 한 수가 비가역적으로 보일 만큼 보드를 바꾸므로, 밀기 전 규칙 재파싱 결과를 예측하는 사전 계획이 핵심.
- `FE-CONSTRAINT` 제약 퍼즐 — 화면 안 단어블록 수가 곧 사용 가능한 규칙의 전부. 'IS' 한 개, 'WIN' 한 개처럼 제한된 어휘를 어떻게 짜맞춰 목표를 달성할지 최적화하는 폐쇄형 퍼즐. 좁은 그리드와 적은 단어가 해 공간을 손에 잡히게 만든다.
- `FE-TRANSFORM` 변환·되돌리기 — 'NOUN IS NOUN'(ROCK IS BABA)으로 객체 정체성을 통째로 변환하고, 무제한 Undo(Z)와 리셋(R)으로 가설을 0 비용으로 검증한다. 보드 상태를 과감히 비틀었다 되돌리는 탐색 자체가 핵심 사고 도구.
**핵심 메카닉:**
- 보드모델: grid[row][col]에 객체 ID '목록(스택)'을 담는 2D 배열이 유일한 상태원천. 한 칸에 캐릭터+단어블록+바닥이 겹칠 수 있어 칸당 배열(스택)을 유지한다. 객체는 {id, kind:'noun'|'verb'|'prop'|'entity', word?, identity}.
- 규칙 파싱: 매 이동 후 가로·세로로 'NOUN IS PROPERTY' 또는 'NOUN IS NOUN' 연속 3칸을 전수 스캔해 활성 규칙 집합을 재계산. 결과를 entity별 비트마스크/Set(isYou/isWin/isPush/isStop/isSink/isHot/isMelt/isDefeat)으로 캐싱해 판정에 사용. (원작 AND/NOT/조건어(ON/NEAR/LONELY 등) 가변 길이 문장은 3칸 고정 문장으로 단순화.)
- 이동 처리 2단계: (1)입력 방향으로 isYou 객체를 밀려는 시도 → isPush 객체는 연쇄로 한 칸씩 밀고, isStop 또는 경계면을 만나면 그 줄 전체 이동 취소(소코반식 캐스케이드 푸시), (2)이동 확정 후 규칙 재파싱 → WIN 동칸 판정 + SINK/HOT&MELT/DEFEAT 같은 파괴 규칙 적용(같은 칸에서 두 속성이 만나면 둘 다 또는 한쪽 제거).
- 정체성 변환: 'NOUN IS NOUN'(예 ROCK IS BABA)은 해당 종류 객체의 스프라이트·identity를 통째로 교체. 변환 후 다시 규칙 재적용해 연쇄 변화를 처리.
- Undo/리셋: 매 이동 직전 grid 깊은복사(structuredClone 또는 JSON 스냅샷)를 스택에 push → Z키/버튼으로 무제한 pop 복원, R로 스테이지 초기 스냅샷 리셋. isYou가 0개가 돼 조종 불가가 돼도 패배가 아니라 무브만 막혀 Undo로 회복.
- 렌더 분리: update 루프가 아니라 이동·파싱이 끝난 시점에만 renderBoard() 호출 — grid 스택을 순회해 Phaser Image/Rectangle을 갱신, 활성 규칙에 참여 중인 단어블록은 미세 글로우로 '문장이 살아있음'을 표시.
- 레벨 정의: 스테이지를 JSON 레벨맵(grid 배치 + 객체/단어 목록)으로 정의(level-designer). 클리어 시 다음 맵 로드, 월드맵 없이 선형/소규모 분기 진행으로 축소.
**난이도·진행 곡선:** 튜토리얼 스테이지는 'BABA IS YOU / FLAG IS WIN'을 그대로 주고 PUSH·STOP만 도입(규칙이 곧 정답인 단계). → 규칙을 깨뜨려야(IS를 옮겨 끊기) 풀리는 단계 → 정체성 변환(NOUN IS NOUN) → 다중 규칙 상호작용(HOT/MELT, SINK, DEFEAT) → 마지막엔 규칙을 새로 만들어 자기 자신을 승리로 바꾸는 메타 해법. 난도는 '동시에 시뮬레이션해야 할 규칙 상호작용 연쇄 수'로 상승. 우리 재현은 핵심 규칙 8종 + 정체성 변환 + 3칸 고정 문장으로 10~20개 자작 스테이지, 선형 진행 + 개념별 팩(밀기/끊기/변환/상호작용)으로 묶는다.
**게임필·연출:** 조용하고 미니멀한 게임필 — 격자에 딱 맞아떨어지는 한 칸 이동, 단어블록이 밀릴 때의 깔끔한 스냅(짧은 bump SFX + 60~100ms 위치 tween). 핵심 연출은 규칙이 갱신되는 순간 화면 전 객체의 외형·거동이 동시에 바뀌는 '세계 재정의'의 시각적 카타르시스 — 정체성 변환 시 스프라이트 크로스페이드 + 작은 파티클, 활성 문장 단어블록의 펄스 글로우. WIN 달성 시 짧은 반짝임 + 청아한 coin류 톤, 파괴 규칙(MELT/SINK/DEFEAT) 발동 시 객체 디졸브. 빠른 액션이 아니라 '한 수 두는' 또박또박한 손맛이 본질.
**끈끈함(리텐션):** 막힌 퍼즐이 게임을 끈 뒤에도 머릿속을 떠나지 않는 '잠복 효과'가 강력하다 — 출퇴근길에 해법이 번뜩이고, 그 한 수가 맞아떨어졌을 때의 보상이 다음 스테이지로 즉시 끌어당긴다. 무제한 Undo로 실패 비용이 0에 가까워 부담 없이 실험을 반복하게 되고, '이 규칙들로 또 뭘 할 수 있지?'라는 호기심과 창발적 해법의 자기표현 욕구가 리텐션을 만든다. 실패가 시간·목숨이 아니라 '아직 못 깨달음'이라 자기 책임 귀인 + 재도전이 자연스럽다.
**우리 엔진 재현도:** ✅ · 스킬 `puzzle-game` · 엔진 board-model-2d-array(칸당 객체 스택 확장), rule-parser(NOUN IS PROPERTY 3칸 스캔 → entity 비트마스크/Set 캐싱), sokoban-push-cascade(연쇄 밀기 + STOP/경계 취소), undo-stack(grid 깊은복사 스냅샷, R 리셋), PixelForge(단어블록 글리프·객체 스프라이트 절차 생성), ChipAudio(이동 bump·승리 coin·변환/파괴 톤), MobileHarness(스와이프 방향 + 탭, 스케일·DOM 가드), level-designer(JSON 스테이지맵), game-ui-hud(스테이지명·Undo/Reset 버튼·이동수), juice-fx(변환 크로스페이드·규칙 글로우·WIN 반짝임) — 순수 그리드 로직이라 물리(Arcade·Matter) 전혀 불필요 — puzzle-game 스택과 정합도 최상. 보드모델: puzzle-game의 board[row][col] 단일값을 '칸당 객체 ID 스택 배열'로 확장(한 칸에 캐릭터+단어+바닥 겹침). 매 이동 후 (a)규칙 재파싱 → entity별 isYou/isWin/isPush/isStop/isSink/isHot/isMelt/isDefeat 플래그 재계산, (b)밀기 캐스케이드(소코반식), (c)파괴/변환 적용 순서로 처리하고 그 시점에만 renderBoard(). Undo는 매 이동 grid 깊은복사 스냅샷 스택. 단어블록·객체 스프라이트는 PixelForge 단색/픽셀 글리프로 IP-safe 자체 제작. 단순화/대체: 원작의 방대한 스테이지·월드맵·수십 개 숨은 규칙(HAS/MAKE/MOVE/SHIFT/TELE 등)과 AND/NOT/조건어(ON/NEAR/LONELY) 가변 길이 문장 파싱은 전부 재현 시 파서·콘텐츠가 비대 → 핵심 규칙 8종 + 정체성 변환 + 3칸 고정 문장으로 10~20개 자작 스테이지 축소 권장. 서버·멀티·대량 라이브 콘텐츠 ❌(불필요), 진행/클리어 상태는 localStorage 단일 기기 저장. 주의: 규칙 상호작용 조합은 의도 못 한 창발 버그(무한 변환·자기참조)를 낳기 쉬워 game-qa로 변환 연쇄·동시 파괴 우선순위를 반드시 검증.
**조합 훅:** endless-runner: 자동 전진 러너 경로에 'GAP IS SAFE' 'SPIKE IS PASS' 규칙블록이 좌우 레인으로 흘러와, 점프 대신 규칙을 켜고 끄며 장애물을 통과하는 실시간 규칙조작 러너(FE-RULE-DISCOVERY + FE-TIMING).; arcade-classic(브레이크아웃): 벽돌에 PUSH/STOP/WIN 단어가 박혀 있어, 공으로 단어를 떨궈 'WALL IS WIN' 문장을 완성하면 즉시 클리어되는 규칙조작 벽돌깨기(FE-AHA + FE-JUICE).; topdown-shooter: 적·총알·벽의 속성을 'BULLET IS YOU' 'ENEMY IS FRIEND'로 한 칸짜리 규칙 패널을 밀어 전투 도중 교전 법칙을 비트는 아레나 슈터(FE-EMERGENCE + FE-TRANSFORM).; puzzle-game(2048/Threes 결합): 슬라이드 머지 보드에 'EVEN IS MERGE' 'WALL IS STOP' 같은 규칙 타일을 끼워 합산 규칙 자체를 한 수로 바꾸는 메타 머지 퍼즐(FE-RULE-DISCOVERY + FE-CONSTRAINT).
**IP 안전 메모:** 사용 금지: 'Baba'·'Keke'·'Me' 등 원작 캐릭터 이름, 원작 특유의 흰 토끼/벽돌 도트 스프라이트, 굵은 픽셀 폰트와 단어블록 디자인, Hempuli의 BGM·SFX, 'Baba Is You' 로고/상표, 원작의 특정 레벨 레이아웃. IP-safe 환기법: 메카닉(NOUN IS PROPERTY 규칙 파싱, 단어블록 밀기, 정체성 변환, Undo)은 게임 시스템이라 자유롭게 구현하되, 캐릭터·속성 명칭을 자체 어휘로 교체(BABA→자작 마스코트명, FLAG→GOAL, ROCK→CRATE 등). 모든 스프라이트·단어 글리프 폰트·사운드는 PixelForge/ChipAudio로 절차 생성(CC0)하고 CREDITS.txt에 라이브러리 라이선스 명시. 스테이지 레이아웃은 원작 카피 금지, 동일 규칙 문법 위에서 100% 자작. 타이틀도 'Rule Is Game' 같은 일반 명사 신규 명칭 부여, 'Baba Is You'는 메카닉 설명 맥락에서만 표기.

## Monument Valley (2014)
**왜 많이 플레이됐나:** 에셔(Escher)풍 불가능 기하 착시를 손가락으로 직접 비틀어 끊긴 길을 만드는 촉각적 쾌감이 핵심. "게임이라기보다 움직이는 예술품"이라는 입소문 — 말없이 분위기로만 끌고 가는 미니멀한 아름다움과, 실패·죽음·타이머가 없어 비게이머도 부담 없이 만지작거리다 끝까지 완주하는 한 입 크기 챕터 구조. 스크린샷 자체가 자랑거리라 자발적 공유로 퍼졌다.
**장르 / 시점:** 착시·불가능기하 환경 퍼즐 (조작형 디오라마 퍼즐). 우리 스택 매핑: puzzle-game(보드모델=등각 노드 그래프). / 고정 등각투상(isometric) 디오라마 시점. 직교 투영이라 2D 화면에서 "불가능한 연결"이 성립 — 시점 자체가 메카닉. 우리 재현은 가짜 isometric(z=row+col depth sort) 단일 카메라.
**코어 루프:** 디오라마를 훑어 막힌 길을 찾고, 회전 노브·슬라이딩 기둥을 손가락으로 돌려/밀어 등각 화면상 끊긴 두 경로가 시각적으로 맞물리게 만든 뒤, 캐릭터를 탭해 새로 이어진 길로 걷게 한다. 죽음·점수 없이 "맞는 배치냐"만 존재하는 30초~수 분 단위 탐색.
**핵심 재미요소:**
- `FE-AHA` 통찰·아하 — 물리적으로 불가능한 두 경로가 등각 화면에서 '겹쳐 보이면 실제로 이어진다'는 규칙을 스스로 발견하는 순간이 심장. 구조물을 한 번 더 돌리는 순간 막혔던 길이 톡 연결되는 깨달음 — 손보다 머리가 푸는 재미.
- `FE-ELEGANCE` 우아한 해 — 한 레벨에 조작 요소가 회전 노브 1~2개·슬라이더 1개로 극히 적어 보통 정답 배치가 사실상 하나. 군더더기 없는 단 하나의 깔끔한 정답에 미니멀 아트가 겹쳐 '풀었다'가 아니라 '완성했다'는 미적 만족을 준다.
- `FE-SPATIAL` 공간 추론 — 구조물을 머릿속으로 회전·슬라이드시켜 '이렇게 돌리면 저 끝과 저 끝이 화면상 겹치겠다'를 시뮬레이션. 등각 투영의 깊이 모호성을 역이용해 떨어진 노드의 투영 좌표를 맞추는 공간 사고가 퍼즐의 본질.
- `FE-NARRATIVE` 분위기·암시적 서사 — 대사 없이 색·기하·앰비언트 사운드로만 고요하고 신비로운 톤을 형성. 챕터마다 바뀌는 풍경·구조가 다음 방으로의 호기심을 끌고, 명시적 플롯보다 침묵의 정서가 진행 동력.
- `FE-JUICE` 감각 피드백 — 구조물을 돌릴 때의 부드러운 관성·각도 스냅, 길이 연결되는 순간의 미세한 차임·라이트 펄스, 캐릭터의 느리고 우아한 걸음 — 거친 셰이크가 아니라 절제된 미세 피드백이 '만지는' 손맛을 만든다.
**핵심 메카닉:**
- 보드모델=등각 노드 그래프: 각 발판/길 끝을 노드로, board는 nodes[]와 동적 edges[]로 구성. 구조물 상태(회전 각도·슬라이드 위치)가 바뀔 때만 두 노드의 화면 투영 좌표가 임계거리 이내인지 재판정해 edge를 add/remove(연결성 = 유일 상태소스, renderBoard()는 상태 변경 시점에만).
- 회전 노브: 서브구조 노드들을 담은 Phaser Container를 탭/드래그로 0/90/180/270 4상태 스냅 회전(tween). 회전은 실제 3D가 아니라 사전 정의된 4방향 스프라이트 상태 + 회전 후 노드 투영 좌표 재계산 → edge 갱신.
- 슬라이딩 기둥/이동 발판: Container를 등각 축을 따라 보간 이동해 끊긴 길의 위치를 맞춤. 이동 중 캐릭터가 함께 실려 가는 platform-as-elevator(노드 부모를 발판으로 reparent).
- 캐릭터 이동: 탭한 목표 노드까지 현재 edge 그래프에서 BFS 최단경로 탐색 → waypoint tween 체인으로 등각 좌표를 따라 걷는 애니메이션(Arcade 물리 미사용, 순수 좌표 보간).
- 착시 트릭 노드: '실제 거리는 멀지만 화면 투영이 겹치면 연결'을 명시 플래그(impossibleLink:true)로 데이터화해 에셔식 impossible-figure 연결을 표현. 일반 노드는 등각 높이차 1칸까지만 보행 허용(스텝업 규칙).
- 무실패 판정: 죽음·점수·타이머 없음 — '맞는 배치냐'만 검사. 레벨 클리어는 캐릭터가 goal 노드 도달 시. 잘못된 배치는 그냥 길이 안 이어질 뿐 페널티 없음.
**난이도·진행 곡선:** 죽음·점수·타이머 없는 비경쟁 progression. 챕터마다 새 조작 어휘를 1개씩 도입하는 tutorial-by-design: 회전 → 슬라이드 → 착시 연결 → 이동 발판 → (원작 후반) 시점이 동시에 두 구조에 영향. 난도는 '동시에 고려할 조작 요소 수'와 '착시 연결의 비직관성'으로만 상승. 각 레벨 5~10분 한 입 크기. 우리 재현은 6~10개 큐레이션 레벨 + level-designer로 노드/구조물/연결규칙을 JSON 정의, 선형 진행.
**게임필·연출:** 고요하고 명상적. 파스텔/모노톤 컬러 블록, 소프트 섀도우, 미니멀 평면(VectorForge 그라데이션·글로우·소프트섀도우가 정확히 이 톤). 조작은 묵직하되 부드러운 관성과 각도 스냅으로 '정확히 제자리에 맞물리는' 촉감. 길 연결 순간 은은한 차임·라이트 펄스, 캐릭터의 느리고 우아한 걸음. 화면 흔들림·폭발 같은 거친 juice가 아니라 juice-fx를 절제 모드(스냅 스쿼시·미세 글로우 펄스·소프트 트윈)로 써서 '만지는 손맛'을 만든다 — 과한 셰이크·파티클은 분위기를 깬다.
**끈끈함(리텐션):** 실패가 없어 좌절 대신 '풀릴 때까지 만지작거리는' 안전한 탐색 심리가 작동하고, 아하 순간의 도파민이 다음 방으로 끌어당긴다. 짧고 완결된 챕터가 '하나만 더'를 부르며, 스크린샷으로 자랑하고 싶은 시각적 아름다움이 자발적 공유를 유발한다. 핵심은 '내 실수로 죽었다'가 아니라 '내가 아름다운 걸 풀어냈다'는 긍정 귀인 — 재도전이 아니라 다음 발견으로 끌고 간다.
**우리 엔진 재현도:** ⚠️ · 스킬 `puzzle-game` · 엔진 VectorForge(등각 큐브·발판·계단 스프라이트, 파스텔 그라데이션·글로우·소프트섀도우), Phaser Container + tween(구조물 4상태 스냅 회전·슬라이드 보간), 순수 JS 그래프 연결모델(노드 화면투영 거리 임계 판정 → edge add/remove), BFS 최단경로 + waypoint tween 체인(캐릭터 보행), level-designer(노드/구조물/연결규칙 JSON 레벨 정의), juice-fx 절제 모드(스냅 스쿼시·미세 라이트 펄스·연결 차임), MobileHarness(스케일·DOM 가드, 탭/드래그 입력), chip-sound(앰비언트 무드 BGM·연결 차임 SFX) — 보드모델은 nodes[]+동적 edges[] 그래프(칸당 단일값 대신 노드 그래프로 확장)가 유일 상태소스 — 구조물 상태 변경 시에만 두 노드 화면투영 거리를 재판정해 edge add/remove하고 renderBoard()로 갱신, puzzle-game의 '보드모델/렌더 분리' 철학과 정합. 물리(Arcade/Matter) 본질적으로 불필요(순수 좌표 보간·그래프 로직). 단순화/대체: (1)진짜 3D 회전 불가 → VectorForge로 등각 스프라이트 코드생성 + 깊이는 z=row+col 가짜 isometric depth sort, 회전은 사전정의 4방향(0/90/180/270) 상태 + Container tween 스냅으로 페이크. (2)착시 연결은 물리가 아니라 데이터 플래그(impossibleLink + 투영거리 임계)로 명시. (3)원작의 방대한 손제작 레벨·아트는 6~10개 큐레이션 레벨 + level-designer JSON으로 축소. (4)매끄러운 궤도 회전은 tween easing 근사. (5)가장 큰 한계: 원작 후반의 '카메라/시점 의존 착시'(같은 구조물이 보는 각도에 따라 다르게 연결)는 고정 등각 단일카메라 가짜 isometric에서 일반화 매우 어려움 → 임의 시점 회전이 아니라 미리 스크립트된 상태전환·페이크 카메라 연출로만 흉내. 서버·멀티·실시간 3D 메시 회전은 ❌이며 본 게임엔 불필요. 즉 비주얼·기본 연결 메카닉은 충실 재현 가능하나 진정한 임의각 3D 회전·시점의존 착시·대량 콘텐츠는 축소되므로 ⚠️.
**조합 훅:** endless-runner: 자동 전진하는 러너 경로를, 달리는 도중 구조물을 탭 회전해 다음 발판을 즉석에서 연결하는 '리듬형 착시 러너'(FE-TIMING + FE-AHA) — 비경쟁 명상 퍼즐에 압박 리듬을 더한 변주.; arcade-classic: 시간/회전 횟수 제한 안에 최소 조작으로 길을 잇는 스코어어택 모드로, 무실패 명상 퍼즐을 '한 판 더' 기록 갱신 게임으로 전환(FE-CONSTRAINT + FE-JUST-ONE-MORE).; topdown-shooter/탑다운 미로: 적 시야·총알 경로를 등각 착시 연결로 차단·우회시키는 '기하 조작 스텔스' 퍼즐(FE-SPATIAL + FE-CONSTRAINT).; platformer-game: 점프 액션에 회전 가능한 디오라마 룸을 더해, 중력/통행 방향이 룸 회전에 따라 바뀌는 'rotating-room 플랫포머'(FE-SPATIAL + FE-AHA).
**IP 안전 메모:** 금지: 원작명 'Monument Valley', 캐릭터 'Ida(흰 옷의 공주)'·토템·까마귀족, 고유 컬러 팔레트와 특정 레벨 실루엣, 오리지널 앰비언트 음악·로고·서체. 메카닉(등각 착시 길 연결, 구조물 회전·슬라이드, 무실패 디오라마 퍼즐)은 IP 보호 대상이 아니라 자유롭게 차용 가능. IP-safe 환기: 추상적인 무명 기하 정령/오브 같은 자체 마스코트(VectorForge blob 캐릭터)로 교체, 팔레트는 직접 고른 CC0 톤, 사운드는 chip-sound 자체 생성 앰비언트, 레벨 형상은 에셔식 '불가능 도형'이라는 퍼블릭 도메인 미술 개념(impossible figure)에서 직접 설계하되 원작 특정 레벨을 모방하지 않는다. 장르를 '등각 착시 길잇기 퍼즐'로 일반 명사화해 표기하고 고유 타이틀(예: 'Echo Spire', 'Skew Path')을 새로 부여. ip-license-guard 스킬로 최종 점검.

## Lemmings (1991)
**왜 많이 플레이됐나:** 규칙은 "걷는 무리에게 역할을 줘 출구로 보낸다" 한 줄로 즉시 이해되는데, 직접 캐릭터를 조종하지 않고 '환경과 역할 배정'만으로 군집을 간접 제어한다는 발상이 신선했다. 실시간이지만 일시정지·속도조절로 사고 여유를 주고, 한 레벨이 '아하' 하는 단일 해법 퍼즐이라 풀었을 때 쾌감이 크다. 무엇보다 레밍 한 마리가 절벽에서 줄줄이 떨어지는 코믹한 참사와 막판에 다리를 놓아 전원 구출하는 역전이 보는 재미·하는 재미를 동시에 줘 입소문이 폭발했다. 제한된 스킬 개수(자원)와 구출 정족수(N마리 이상)라는 명확한 제약이 완벽주의 재도전을 유발했다.
**장르 / 시점:** 실시간 액션 퍼즐 / 군집(crowd) 간접제어 + 자원배분 퍼즐 (real-time action puzzle, lemming-herding) / 옆스크롤 2D 사이드뷰(중력이 아래로 작용하는 단면). 출구는 화면 어딘가 고정, 입구에서 레밍이 일정 주기로 쏟아진다. 카메라는 좌우 패닝(레벨이 한 화면보다 넓음). 우리 재현은 한 화면~짧은 패닝 레벨로 축소.
**코어 루프:** 자동으로 걷다 벽에 닿으면 돌아서고 낭떠러지에선 떨어지는 레밍 무리를 보며, 제한된 스킬 카운트(파기·계단·다리·막기 등) 중 하나를 골라 특정 레밍을 클릭/탭해 역할을 부여한다. 부여한 역할이 지형을 깎거나 길을 만들어 함정·갭을 통과시키고, 30초 안팎의 이 '관찰→역할 배정→지형 변화 확인'을 반복해 정족수 이상을 출구로 구출한다.
**핵심 재미요소:**
- `FE-CONSTRAINT` 제약 퍼즐 — 레벨마다 스킬별 사용 가능 횟수가 빡빡하게 정해져 있어(예: Digger 3·Builder 2·Blocker 1) '어느 레밍에게 어떤 역할을 몇 번 쓸까'가 자원 최적화 그 자체. 한 번 쓴 Blocker는 회수 못 하므로 한 수의 무게가 크고, 구출 정족수(예: 100% 또는 N마리)가 제약을 더 조인다.
- `FE-AHA` 통찰·아하 — 막힌 레벨을 노려보다 '여기서 한 마리를 Blocker로 세워 무리를 가두고, 선두만 Basher로 벽을 뚫게 한 뒤, Blocker를 Bomber로 터뜨려 풀어준다'는 결정적 순서가 떠오르는 순간 풀이 전체가 한꺼번에 열린다. 직접 조종이 아니라 '환경 설계'로 푸는 퍼즐 해법의 쾌감.
- `FE-PLANNING` 선계획·멀티스텝 — 레밍은 자동으로 계속 전진하므로, 지금 다리를 놓기 시작하면 N초 뒤 어디에 닿을지, 선두가 함정에 닿기 전에 길이 완성될지를 여러 수 앞서 머릿속으로 시뮬레이션해야 한다. 스킬 발동 시점(타이밍)과 위치를 미리 계획하는 멀티스텝 사고가 핵심.
- `FE-TIMING` 타이밍·리듬 — 실시간이라 같은 스킬도 '레밍이 정확히 그 픽셀에 있을 때' 배정해야 의도대로 동작한다. 선두가 절벽에 닿기 직전 Builder를 눌러 갭을 메우거나, 폭발 카운트다운(Bomber)을 정확한 자리에서 터뜨리는 프레임 단위 타이밍이 성패를 가른다.
- `FE-TENSION` 긴장·니어미스 — 무리가 함정·낭떠러지로 줄줄이 빨려 들어가는 와중에 마지막 한 칸의 다리를 가까스로 완성해 전원을 살려내는 아슬아슬한 역전. 정족수를 1마리 차이로 채우거나 놓치는 순간의 조마조마함이 강렬한 보상이 된다.
- `FE-EMERGENCE` 창발·시스템 상호작용 — 소수의 스킬(파기·다리·막기·계단·폭파)과 단순한 레밍 행동규칙(걷기·낙하·회전)이 조합되며 한 레벨에 의도된 정석 외에 우회·복수 해법이 생기곤 한다(상당수는 설계자 의도, 일부는 비의도 트릭). 단 원작은 기본적으로 '단일 의도 해법' 위주 디자인이라 순수 창발 비중은 제한적 — Blocker를 Bomber로 제거해 통로를 여는 것도 잘 알려진 의도 테크닉에 가깝다.
**핵심 메카닉:**
- 보드모델 = 지형 충돌 비트맵(terrain mask). board[y][x] = 0(빈공간)/1(흙·고체)/2(강철=파괴불가) 2D 배열을 단일 상태원으로 둔다. 픽셀당 1셀이 이상적이나 모바일 부하를 위해 coarse 2~4px 셀로 양자화 권장. 렌더는 비트맵을 Phaser CanvasTexture/RenderTexture에 한 번 그리고, 스킬로 지형이 바뀐 셀만 부분 갱신(보드모델/렌더 분리 원칙).
- 레밍 에이전트 = 비트맵과 분리된 객체 배열 lemmings[]: {x,y,dir,state}. 매 고정 스텝(예: 60fps 중 N프레임마다)마다 각 레밍이 비트맵을 샘플링해 행동 결정: 발밑(board[y+1][x])이 고체면 walk, 비면 fall, 진행방향 벽(board[y][x+dir])이 막히면 turn(또는 낮은 턱이면 step-up). 물리엔진 미사용 — 순수 비트맵 샘플링.
- 스킬 = 지형/상태 변이 함수. Digger(아래로 셀을 0으로 파냄), Basher(수평 터널 carve), Miner(대각 carve), Builder(앞 위 대각으로 셀을 1로 채워 계단 N칸 생성·벽돌 카운트 소진), Blocker(자기 위치를 양방향 통행불가 표식으로 만들어 닿는 레밍을 turn시킴), Bomber(카운트다운 후 자기 주변 셀을 0으로 폭파 + 자기 제거), Floater(낙하 데미지 무효), Climber(벽 등반 상태 부여).
- 스킬 카운트 자원: 레벨 데이터에 스킬별 잔여 횟수를 두고, 레밍 클릭 시 1 차감. game-ui-hud 하단 스킬바에 잔여 수 표시. 0이면 비활성. 한 번 부여한 역할은 (Bomber 외) 회수 불가.
- 입력: 데스크톱은 마우스(스킬 선택 후 레밍 클릭). 모바일은 하단 스킬 팔레트 탭으로 선택 → 화면 레밍 탭으로 배정. 군집이 겹쳐 타겟팅이 어려우므로 탭 지점 근처 최근접 레밍 선택 + 일시정지(pause) 버튼·속도조절(1x/2x)·1마리씩 순환 선택 보조를 둔다.
- 클리어 판정: 출구 sensor 영역에 닿은 레밍 카운트가 정족수(saveRequired) 이상이면 성공. 입구에서 spawnInterval마다 정해진 totalLemmings를 순차 스폰. 함정 셀·맵 밖 낙하·과도 낙하높이는 사망 처리. 제한시간(선택)·전원 처리(스폰 완료+잔존 0) 시 결과 정산.
**난이도·진행 곡선:** 초반 레벨은 단일 스킬(예: Digger만)로 길 하나만 뚫으면 풀리는 튜토리얼-바이-디자인으로 스킬 어휘를 하나씩 소개한다. 중반은 Blocker로 무리 가두기 + Builder로 갭 메우기처럼 2~3스킬 조합과 순서를 요구하고, 정족수를 80%→100%로 올려 실수 허용폭을 줄인다. 후반은 빡빡한 스킬 카운트(자원 부족)·강철 지형(파괴불가) 우회·타이밍이 촉박한 멀티스텝 해법으로 난도를 점증. 외부 무한 모드 없이 손제작 레벨 팩(10~20개) 선형 진행 + 별 1~3개(구출률/잔여 스킬/소요시간 기준)로 완벽주의 재도전을 분리. 입구 스폰 주기 단축·총 레밍 수 증가가 보조 압박 노브.
**게임필·연출:** 레밍이 또박또박 걷다 갭에 줄줄이 떨어지는 코믹한 군집 모션이 정체성. 스킬 배정 순간 짧은 확정 SFX와 해당 레밍 위 아이콘 팝, 지형이 깎이거나 벽돌이 한 칸씩 쌓이는 점진적 변형 애니메이션(셀 단위 부분 리드로)이 '내 명령이 세계를 바꾼다'는 손맛을 준다. juice-fx로 Bomber 폭발에 스크린셰이크+파편 파티클, 출구 흡입에 반짝임, 사망에 짧은 파프. 일시정지/속도조절 토글로 사고 여유를 주되 실시간 긴장은 유지. ChipAudio로 걷기·파기·폭발·구출·실패 SFX와 경쾌한 8비트 BGM. 핵심 카타르시스는 막판 다리 완성 후 무리가 줄지어 출구로 빨려 들어가는 '구출 행렬'.
**끈끈함(리텐션):** 실패가 '내 역할 배정·타이밍 실수'로 명확히 납득돼(FE-FAIRNESS적 성격) 좌절보다 '이번엔 Blocker를 한 칸 앞에 세우면 된다'는 확신으로 즉시 재도전을 부른다. 막힌 레벨이 머릿속을 떠나지 않는 '잠복 효과'(아하 퍼즐 특유)와, 클리어는 했지만 정족수 100%·잔여 스킬 최대를 못 채운 완벽주의 후크가 한 레벨을 여러 번 붙들게 한다. 일시정지·undo(또는 즉시 리셋)로 실험 비용이 낮아 가설검증을 반복하게 되고, 코믹한 군집 참사 자체가 다시 보고 싶은 구경거리가 된다.
**우리 엔진 재현도:** ⚠️ · 스킬 `puzzle-game` · 엔진 board model = terrain collision bitmap (board[y][x] coarse-cell 2D 배열), RenderTexture/CanvasTexture 부분 갱신으로 destructible terrain 렌더, 고정 step 루프에서 lemming agent가 비트맵 샘플링(walk/fall/turn) — Arcade/Matter 미사용 순수 로직, 스킬=지형/상태 변이 함수(dig/bash/build/block/bomb), level-designer로 레벨 비트맵·입출구·스킬카운트·정족수 JSON 정의, game-ui-hud 스킬 팔레트(잔여 수)·구출 카운터·일시정지/속도조절, juice-fx 폭발 셰이크·파편·구출 반짝임, ChipAudio SFX/BGM, MobileHarness 탭 타겟팅(최근접 레밍)+스킬바, localStorage 별/진행 저장 — 보드모델: 진짜 픽셀퍼펙트 destructible terrain 대신 coarse-cell(2~4px) 충돌 비트맵 board[y][x](0빈/1흙/2강철)를 단일 상태원으로 두고, 레밍은 이와 분리된 에이전트 배열로 매 고정스텝 비트맵을 샘플링해 걷기·낙하·회전을 결정한다. 스킬은 비트맵 셀을 0/1로 바꾸는 변이 함수(파기·다리·터널·폭파)로 구현 — 핵심이 '비트맵 + 자율 에이전트'라 물리엔진(Arcade/Matter) 불필요, puzzle-game의 보드모델/렌더 분리 철학과 정합. 그래서 ❌가 아니라 ⚠️. ⚠️인 이유: (1) 실시간 자율 군집 시뮬레이션 + 정확한 레밍 AI(낮은 턱 step-up, 벽 turn, 낙하높이 사망, Builder 벽돌 한 칸씩 쌓기, Blocker 회전 판정)는 turn-based 그리드보다 엣지케이스 튜닝이 많아 코드생성 신뢰도가 Tetris/2048보다 낮다 — game-qa 반복 검증 필요. (2) destructible terrain은 RenderTexture에 베이스를 그리고 변형 셀만 부분 리드로하되, 셀 양자화로 픽셀 디테일을 희생(시각 단순화). (3) 모바일은 동시 레밍 수를 20~40체로 제한하고 비트맵 해상도를 낮춰 60fps 확보(perf-60fps). 탭으로 겹친 군집 중 한 마리 타겟팅이 어려워 일시정지·1x/2x 속도·최근접 선택·순환선택 보조가 필수. (4) 원작의 방대한 레벨(120+)·풀 스킬 8종·세밀 픽셀 지형은 콘텐츠 축소: 핵심 스킬 5~6종(Digger/Basher/Builder/Blocker/Bomber/Floater)+손제작 10~20 레벨로 시작. 서버·멀티·온라인 랭킹은 ❌ → localStorage 별/진행·시드 공유로 대체. 즉 코어 루프·메카닉은 충실 재현 가능하나 자율 군집 AI 정밀도·픽셀 지형·대량 콘텐츠는 단순화/축소 → ⚠️.
**조합 훅:** puzzle-game(턴제 변형)에 이식: 실시간 군집을 '한 턴에 스킬 1개 배정 후 N틱 시뮬레이션 일괄 진행'하는 턴제 레밍 퍼즐로 바꿔, FE-PLANNING+FE-AHA를 살리고 실시간 타이밍 난도와 모바일 타겟팅 부담을 제거(undo로 가설검증).; topdown-shooter/PvZ식 레인 디펜스에 이식: 자동 전진하는 아군 군집에 '파기·다리·막기' 대신 '터렛 설치·벽 세우기·길 뚫기' 역할을 제한 횟수로 배정해 출구까지 호위하는 '군집 호위 디펜스'(FE-CONSTRAINT+FE-TENSION).; endless-runner에 이식: 끝없이 흘러오는 레밍 행렬 앞에 다리·계단을 제한 자원으로 즉석 깔아 끊김 없이 통과시키는 '리듬형 길깔기 러너'(FE-TIMING+FE-FLOW), 통과 수로 점수 갱신.; arcade-classic에 이식: 한 화면 단일 레밍을 제한된 스킬 카운트로 최소 횟수 클리어하는 스코어어택 '한 마리 구출 퍼즐'로 압축해 FE-CONSTRAINT+FE-OPTIMIZE(더 적은 스킬·더 빠른 구출) 리더보드화.
**IP 안전 메모:** 금지: 'Lemmings' 명칭·로고, DMA Design/Psygnosis의 시그니처 녹색머리 파란옷 레밍 스프라이트와 걷기/폭발 애니, 'Let's go!'·폭발 'Oh no!' 등 원작 음성, 원작 BGM(민요 편곡 포함)·효과음, 특정 원작 레벨 레이아웃 카피. 메카닉(자율 보행 군집 간접제어, 역할 배정, destructible terrain, 정족수 구출, 제한 스킬 카운트)은 게임 시스템이라 자유롭게 구현 가능. IP-safe 환기: 마스코트를 자체 디자인 생물(둥근 슬라임·개미·로봇 등)로 교체하고 PixelForge/VectorForge로 절차 생성, 스킬은 'Digger/Builder' 같은 역할 일반명 또는 자체 명칭(굴착·교량·차단·폭파)으로, 음성은 ChipAudio 8비트 SFX로 대체. 게임 타이틀은 'Rescue Rush'·'Crowd Path' 같은 오리지널 명칭 부여, 레벨은 동일 규칙 위에서 전부 자작. ip-license-guard로 최종 점검, CREDITS.txt에 Phaser(MIT) 명시.

## Cut the Rope (2010)
**왜 많이 플레이됐나:** 터치 한 번으로 밧줄을 자르면 사탕이 진자처럼 흔들려 떨어지는 물리가 누구나 30초 안에 이해될 만큼 직관적이면서, 별 3개 풀스코어를 노리면 절단 순서·타이밍의 정밀함이 요구되는 깊이를 동시에 가졌다. 짧고 깔끔한 단일 화면 레벨, 귀여운 마스코트, '클리어는 됐지만 별은 못 먹은' 완벽주의 후크가 캐주얼과 코어 양쪽을 모두 흡수해 모바일 캐주얼 폭발기에 수억 다운로드를 만들었다.
**장르 / 시점:** 물리 기반 퍼즐 (physics puzzle) — 밧줄/진자 distance-constraint 시뮬레이션이 곧 퍼즐 규칙 / 고정 화면 옆시점(side-view) 싱글 스크린, 스크롤 없음. 중력 아래 작용, 화면 하단에 먹이 캐릭터 입.
**코어 루프:** 밧줄에 매달린 사탕을 보고 어느 줄을 언제 자를지 판단하고, 탭/스와이프로 줄을 자르면 사탕이 중력·진자·풍선·에어쿠션의 영향으로 움직인다. 도중의 별 3개를 쓸면서 화면 하단 먹이 캐릭터 입에 사탕을 넣으면 클리어 — 한 판 20~40초.
**핵심 재미요소:**
- `FE-AHA` 통찰·아하 — 각 레벨이 '어느 줄을, 어떤 순서로, 언제 자르나'라는 단일 해법을 숨겨둠. 진자 스윙·풍선 부양·에어쿠션 분사의 상호작용을 머릿속에서 시뮬레이션해 풀이를 발견하는 순간이 핵심 쾌감. 물리 결과를 미리 예측(mental simulation)하는 것이 곧 퍼즐 — 규칙 연역(FE-DEDUCTION)이 아니라 물리 직관에 의한 통찰이라 FE-AHA로 분류.
- `FE-TIMING` 타이밍·리듬 — 밧줄 절단은 사탕이 진자 호의 어느 위치(상승/하강/정점)에 있을 때 자르느냐로 궤적이 완전히 달라짐. 별 3개를 한 스윙에 쓸거나 가시를 피하려면 프레임 단위에 가까운 절단 타이밍이 필요 — 같은 '어느 줄'이라도 '언제'가 정답을 가른다.
- `FE-CONSTRAINT` 제약 퍼즐 — 밧줄 개수·풍선 1개·에어쿠션 분사 횟수가 한정돼, 제한 자원 안에서 사탕을 입까지 보내는 최적 경로를 찾는 자원 최적화. 별 3개 풀스코어 조건이 제약을 더 빡빡하게 만들어 '클리어 경로'와 '별 3개 경로'가 갈림. 별 3개 수집·진행도 메타(클리어/별3개 분리 기록)도 이 제약 충족의 누적 보상으로 흡수됨.
- `FE-JUICE` 감각 피드백 — 밧줄이 잘릴 때의 사각사각 절단음과 줄 끝이 탄성으로 튕기는 모션, 별 통과 시 반짝임, 마스코트가 받아먹고 만족하는 표정 변화가 정답 행동에 즉각적·정서적 보상을 줌. 진자의 묵직한 스윙과 밧줄 처짐 자체가 '물리가 살아있다'는 손맛.
- `FE-FAIRNESS` 공정함 — 실패하면 '내가 줄을 한 박자 늦게 잘랐다'처럼 원인이 결정론적 물리로 명확히 납득됨. 랜덤 즉사가 없어 좌절 대신 '이번엔 거기서 자르면 된다'는 확신이 즉시 재도전을 부름 — FE-TIMING의 높은 정밀도를 떠받치는 토대.
**핵심 메카닉:**
- 밧줄(rope): 사탕(원형 강체)을 화면 고정 앵커에 매단 distance-constraint 체인. Matter.js의 stiff Constraint(앵커=pointA, 사탕=bodyB) 또는 작은 세그먼트 chain composite로 구현. 자르면 해당 constraint를 World에서 제거 → 사탕이 관성·중력으로 자유낙하/스윙.
- 절단 입력: 포인터 드래그(스와이프)로 그은 선분이 밧줄 세그먼트와 교차하면 그 줄을 끊음 — 자체 선분-선분 교차 판정. 모바일 단순화로 '밧줄 탭 → 끊김' 모드도 병행.
- 진자 스윙: 한쪽 줄만 끊으면 남은 줄이 피벗이 되어 사탕이 호를 그리며 흔들림. 별 수집·장애물 회피 궤적 제어의 핵심.
- 풍선(balloon): 사탕에 부착하면 중력 무시 + 상향 force로 부양. 탭하면 분리(또는 중력 복원)해 다시 낙하. 비(非)밧줄 경로 제어 수단.
- 에어쿠션/버블(배치형 기믹): 탭하면 정해진 방향으로 사탕을 미는 임펄스(force/velocity) 분사. 버블은 사탕을 가두어 천천히 부양시키다 탭하면 터져 재낙하.
- 별 3개 수집(선택 보너스) + 가시·전기 등 장애물(센서 영역 접촉 시 실패) + 화면 하단 먹이 캐릭터 입(센서 영역) 도달 시 클리어. 별·입·장애물 모두 isSensor 바디 충돌 트리거로 판정.
**난이도·진행 곡선:** 초반 레벨은 밧줄 1~2개의 단순 절단으로 즉시 성공 경험을 줘 조작을 학습시킴. 이후 풍선 → 에어쿠션/버블 → 이동 앵커 → 가시/장애물 순으로 기믹을 한 번에 하나씩 도입(메카닉 점진 소개). 후반은 여러 기믹을 동시 조합해 절단 순서·타이밍이 빡빡한 멀티스텝 퍼즐로 난도 상승. 클리어 자체는 관대하되 별 3개 풀스코어는 별도 숙련 곡선을 형성해 재도전 유발. 원작 박스당 25레벨×여러 박스(수백 레벨) 대신 우리 재현은 8~15개 손제작 레벨에 이 곡선을 압축, '클리어/별3개'를 localStorage에 분리 저장해 진행도 메타로.
**게임필·연출:** 부드럽고 묵직한 진자 운동과 밧줄의 탄성 처짐이 만드는 '물리가 살아있다'는 손맛이 정체성. 절단 순간의 사각사각 가위음, 줄 끝이 탄성으로 튕기는 리코일 연출, 별 통과 시 반짝임 파티클(juice-fx), 마스코트의 표정·먹는 애니메이션이 합쳐져 캐주얼하지만 정성스러운 촉감. 정답 절단 시 사탕 궤적을 카메라가 굳이 따라가지 않고 고정 화면 안에서 모든 게 보이는 것이 핵심 — 한눈에 인과가 읽혀 FE-AHA를 살림. 둥글둥글한 톤에 부드러운 스무스·글로우 렌더가 적합. 셰이크는 입에 닿는 순간 짧게(80ms 이내).
**끈끈함(리텐션):** 레벨이 짧아 '한 번 더' 부담이 없고, 클리어는 됐지만 별 3개는 못 먹은 상태가 강한 재도전 동기를 만듦(완벽주의 후크). 실패가 결정론적 물리라 '내가 한 박자 늦게 잘랐다'로 명확히 납득돼(FE-FAIRNESS) 좌절이 아닌 도전으로 전환. 정답을 발견했을 때의 아하 쾌감(FE-AHA)이 다음 레벨로 끌고 가고, 진자 물리가 매 시도 미세하게 달라 같은 해법도 결과를 구경하는 재미가 있음.
**우리 엔진 재현도:** ⚠️ · 스킬 `puzzle-game` (베이스 — 단 기본 puzzle-game은 그리드·순수 로직 보드모델 중심이라, 본 게임은 연속 좌표 물리 씬이 필수이므로 Phaser + Matter.js 물리(또는 자체 Verlet 밧줄)를 결합한 변형으로 진행. level-designer/juice-fx/game-ui-hud 보조) · 엔진 Matter.js stiff Constraint(앵커 고정 밧줄, 개념), Matter.js chain composite(세그먼트 밧줄, 개념), World에서 constraint 제거(절단), 자체 선분-선분 교차 판정(드래그 절단), circle body(사탕 강체), 중력 무시 토글 + applyForce(풍선/에어쿠션, 개념), isSensor 바디(별·먹이 입·장애물 판정), Matter sleeping + 60fps 타깃(모바일 성능), 대안: 자체 Verlet 적분 밧줄(점 배열+거리제약 반복), 절차 생성 벡터 아트(CC0), 오리지널 SFX(절단음·먹기), 모바일 스케일·터치 하니스, juice-fx(반짝임·튕김), level-designer(8~15 레벨 데이터), game-ui-hud(별 3개·진행도) — 핵심 밧줄 물리는 Arcade로 불가 — Matter.js 물리(⚠️: Arcade보다 무겁고 LLM 코드생성 신뢰도 낮음)가 필수다. 보드모델은 puzzle-game식 2D board[row][col] 배열이 아니라 '연속 좌표 물리 씬'이라 그리드 모델이 성립하지 않음 — 레벨 데이터를 JS 객체 배열로(앵커 좌표·밧줄 연결·별 위치·풍선/에어쿠션 배치·먹이 입·장애물) 선언적 정의하고 Matter 바디/constraint로 빌드. 구현 개념: 밧줄=사탕(circle body)을 stiff Constraint로 앵커에 매단 distance-constraint 체인(또는 chain composite 세그먼트 줄), 절단=포인터 드래그 선분과 세그먼트의 자체 선분교차 판정 후 해당 constraint 제거, 진자=남은 단일 constraint가 피벗, 풍선=중력 무시+상향 force, 에어쿠션=탭 시 방향 임펄스, 별/입/장애물=isSensor. 주의: worldConstraint/getConstraintLength/intersectRay 등은 정확한 Matter.js API명이 아니라 개념 표기이며, 실제로는 Matter.Constraint.create({pointA, bodyB, stiffness})·Matter.Composite/World API·자체 교차함수로 구현해야 한다. 더 안정적인 대안: Matter 없이 자체 Verlet 적분 밧줄(점 배열 + 거리 제약 반복 N회)을 쓰면 절단·스윙이 가볍고 결정론적이라 FE-FAIRNESS·FE-TIMING 재현에 유리(단 사탕-장애물 충돌은 원-AABB 수동 판정 필요). 단순화/대체: 동시 강체·constraint 수를 보수적으로 제한(밧줄 세그먼트 줄이고 sleeping 활성), 레벨은 서버 없이 8~15개 손제작, 풍선/에어쿠션/버블은 단순 임펄스 근사로 축소. 멀티플레이·대규모 라이브 레벨팩·온라인 랭킹은 ❌(단일 플레이 웹 한계) → localStorage 별 기록·시드 공유로 대체.
**조합 훅:** endless-runner에 이식: 자동 전진하는 러너가 천장 앵커에 매달린 그네 밧줄을 타이밍 맞춰 잘라 갭을 점프 통과하는 '밧줄 타잔' 무한 러너 (FE-TIMING + 흐름감).; arcade-classic 벽돌깨기와 결합: 공 대신 밧줄에 매달린 진자 추를 끊어 떨어뜨려 벽돌을 부수는 진자-브레이커 (FE-AHA + 위험보상).; topdown-shooter에 이식: 적을 직접 쏘지 않고 적이 매달린 밧줄을 끊어 함정으로 떨어뜨리는 '환경 처치' 퍼즐 슈터 (FE-CONSTRAINT + FE-AHA).; puzzle-game 그리드와 결합: 절단으로 떨어진 사탕이 아래 그리드에 안착하는 위치를 진자 타이밍으로 조준해 같은 색 3개를 매치하는 '물리 조준 Match-3' 하이브리드 (FE-TIMING + 콤보).
**IP 안전 메모:** 금지: 'Cut the Rope', 'Om Nom' 등 원작 고유명·해당 마스코트 캐릭터 디자인·특유의 사탕 디자인·원작 UI/폰트/효과음/BGM·고유 레벨 레이아웃 일절 사용 금지. 메카닉(밧줄 절단·진자 스윙·풍선·에어쿠션·별 수집·먹이 캐릭터 도달)은 물리 관용구라 자유롭게 구현 가능. IP-safe 환기법: 마스코트를 다른 컨셉(둥근 슬라임·새끼 고양이·로봇)으로 새로 디자인하고 먹이도 사탕 대신 도토리·별사탕·에너지 코어 등으로 치환. 테마를 완전히 교체(예: '로봇에게 에너지 셀 떨어뜨리기'). 모든 스프라이트/벡터 아트는 절차 생성(CC0), 효과음·멜로디는 오리지널, CREDITS.txt에 Phaser(MIT)·Matter.js(MIT) 라이선스 명시.
