## Sudoku (1979(현대형 정착)·2004~2005(글로벌 신문 붐))
**왜 많이 플레이됐나:** 규칙이 한 문장("행·열·3x3 박스에 1~9를 중복 없이")으로 설명되는데 풀이 깊이는 끝이 없는 전형적 "쉽게 배우고 평생 못 끝내는" 퍼즐이다. 운·반사신경·외국어가 일절 필요 없는 순수 논리라 연령·언어·문화를 초월해 접근 가능하고, 신문 지면이라는 일상 매체에 매일 한 판씩 실리며 습관이 됐다. 한 판이 명확한 시작과 끝(유일해)을 가져 완결감이 강하고, 진척이 칸 하나하나로 눈에 보여 '조금만 더 하면 끝난다'가 끊임없이 작동한다. 펜 한 자루로 어디서든 가능한 휴대성과, 난이도 라벨(쉬움~매우어려움)로 자기 수준을 고를 수 있는 폭이 대중화를 완성했다.
**장르 / 시점:** 연역·논리 채우기 퍼즐 (deduction / constraint-satisfaction grid puzzle). 순수 로직, 비실시간 턴제. / 정면 2D 고정 그리드. 9x9 셀(굵은 선으로 3x3 박스 구획)을 한 화면에 표시, 스크롤 없음. 카메라 이동·시점 변화 없음.
**코어 루프:** 빈 칸을 하나 골라, 그 칸이 속한 행·열·3x3 박스에 이미 있는 숫자를 소거하면 남는 후보가 좁혀진다. 후보가 하나로 확정되는 칸(또는 한 영역에서 그 숫자가 들어갈 자리가 하나뿐인 칸)을 찾아 채우고, 그 한 수가 다시 다른 칸의 후보를 줄이는 연쇄를 따라 보드 전체를 유일해로 메운다.
**핵심 재미요소:**
- `FE-DEDUCTION` 연역·소거 — Sudoku의 심장. '이 칸에 9가 들어갈 자리는 이 박스에서 여기뿐'처럼 제약(행/열/박스 중복 금지)을 교차시켜 확실한 한 수를 좁혀가는 순수 논리. 추측 없이 단서만으로 다음 칸이 강제되는 연쇄가 핵심 재미이며, naked single·hidden single·pointing pair 같은 기법 사다리가 그 깊이를 만든다.
- `FE-AHA` 통찰·아하 — 한참 막혔다가 '여기 박스에 6이 들어갈 칸이 하나뿐'임을 발견하는 순간, 막혀 있던 보드가 도미노처럼 풀려나가는 깨달음. 어려운 난이도일수록 한 번의 결정적 통찰이 여러 칸을 연쇄 확정시키는 카타르시스가 크다.
- `FE-ELEGANCE` 우아한 해 — 모든 퍼즐이 단 하나의 정답(유일해)을 보장한다는 점이 만족의 근간. 추측·시행착오 없이 순수 연역만으로 깔끔하게 닫히는 미니멀한 완결감. 좋은 퍼즐일수록 '백트래킹 없이 논리로만 풀린다'는 우아함이 품질 지표다.
- `FE-CONSTRAINT` 제약 퍼즐 — 세 겹의 제약(행 1~9 유일, 열 1~9 유일, 박스 1~9 유일)이 동시에 걸린 제약충족 문제 그 자체. 주어진 단서 수가 적을수록(난이도↑) 한 칸을 확정하는 데 필요한 제약 교차가 깊어져 한 수의 무게가 커진다.
- `FE-HIDDEN-INFO` 숨은 정보 — 각 칸의 '가능한 후보 집합'은 보이지 않는 정보이고, 플레이어가 연필표기(pencil marks)로 이를 드러내 관리한다. 후보를 적고 소거 규칙으로 하나씩 지워 숨은 확정값을 안전하게 표면화하는 과정이 풀이의 작업 흐름이다.
- `FE-JUST-ONE-MORE` 한 판 더 — 한 판이 명확히 끝나고(보드 완성=승리) 새 퍼즐을 즉시 받을 수 있으며, 클리어 타임·난이도라는 자기 기록이 남아 '이번엔 더 빨리/더 어려운 걸'을 부른다. 일일 퍼즐 1판 습관이 장기 리텐션을 만든다.
**핵심 메카닉:**
- 보드 모델 = givens[9][9](고정 단서, 수정 불가 플래그) + board[9][9](플레이어 입력 포함 현재 상태). 0 또는 null = 빈 칸. 이 2D 배열이 유일한 상태 소스이며 상태 변경 시점에만 renderBoard()로 셀 텍스트·색을 갱신(update 루프 미사용).
- 연필표기 레이어 = candidates[9][9]에 셀당 9비트 비트마스크(또는 Set<1..9>)를 두어 후보를 별도 관리. 한 셀에 작은 3x3 그리드로 1~9 마크를 렌더. 자동 후보 모드는 입력 시점에 같은 행/열/박스의 candidates에서 해당 숫자 비트를 일괄 클리어.
- 제약 검증 = 한 칸에 숫자 v를 넣을 때 같은 행·열·3x3 박스(boxIndex = floor(r/3)*3+floor(c/3))에 v가 이미 있으면 충돌. 충돌 칸은 붉게 하이라이트(즉시 피드백 옵션) 또는 완성 시 일괄 검사(엄격 모드).
- 퍼즐 생성기 = (1) 백트래킹 솔버로 완전한 정답 그리드를 무작위 시드로 채우고, (2) 칸을 (대개 180도 대칭으로) 하나씩 비우되 비울 때마다 '유일해 유지' 솔버로 검증해 단서를 제거. 목표 단서 수/요구 기법 난이도에 도달하면 정지. 전부 순수 JS(Phaser.Math.RND.sow 시드 기반)로 클라이언트에서 생성 — 서버 불필요.
- 난이도 등급 = 제거 후 남은 단서 수 + '풀이에 필요한 최고 기법 단계'(naked single만 → 쉬움, hidden single/locked candidate 필요 → 보통, naked/hidden pair·X-Wing 필요 → 어려움)로 라벨링. 논리 솔버가 사람 기법을 모사해 등급을 채점.
- 보조 시스템 = undo/redo 스택(매 입력 board 스냅샷), 힌트(다음 확정 가능한 칸 1개를 논리 솔버로 찾아 하이라이트), 오류 체크(현재 board를 정답과 비교 또는 제약 위반 표시), 클리어 타임 측정, localStorage로 진행 중 퍼즐·기록 영속화.
**난이도·진행 곡선:** 외부 스테이지 진행이 아니라 난이도 라벨로 곡선을 제공한다: 쉬움(단서 ~36, naked single만으로 완주) → 보통(~30, hidden single·박스/행 상호작용 필요) → 어려움(~26, 페어·포인팅·X-Wing급 기법 요구) → 전문가(~22~24, 깊은 체인). 시드 기반 무한 생성으로 각 난이도에서 매 판 새 퍼즐을 받는다. 메타 진행은 일일 퍼즐(시드=날짜) 연속 출석, 난이도별 베스트 타임, 누적 클리어 수 같은 로컬 수집 지표로 구성. 게임 자체의 난도는 '단서 감소 + 요구 기법 단계 상승'으로만 자연 점증하며, 시간 압박은 코어에 없음(선택적 타임어택 모드는 별도).
**게임필·연출:** 조용하고 또박또박한 게임필 — 빠른 반사가 아니라 한 칸 한 칸 채우는 신중한 손맛이 핵심. 칸 선택 시 행·열·박스를 은은히 하이라이트(연관 셀 강조)하고, 같은 숫자를 화면 전체에서 동시 강조해 패턴 읽기를 보조한다. 숫자 입력은 짧은 팝-인(scale Back.out)과 부드러운 'tick' 칩사운드, 확정 시 미세한 색 정착. 한 행/열/박스가 1~9로 완성되는 순간 그 영역에 짧은 플래시·스파클(juice-fx)과 상승 톤으로 작은 성취를 보상. 보드 전체 완성 시 전 셀 순차 웨이브 연출 + 팡파르. 오류는 거친 셰이크가 아니라 붉은 펄스로 절제되게 표현. 연필표기 토글, 숫자 패드(모바일), undo 버튼이 끊김 없이 반응하는 것이 손맛의 본질.
**끈끈함(리텐션):** 실패가 '랜덤'이 아니라 항상 '내 연역 실수'로 100% 귀인되는 순수 논리라 재도전이 납득되고(공정성·자기귀인이 내재), 유일해 보장이 '풀릴 수 있다'는 신뢰를 주어 끝까지 매달리게 한다. 진척이 칸 단위로 가시화돼 '거의 다 왔다'는 완성 임박감이 강하고, 한 번의 통찰이 여러 칸을 연쇄로 푸는 도파민이 다음 막힌 칸으로 끌어당긴다. 난이도 선택이 자기 수준에 맞는 적정 도전(flow)을 보장하고, 일일 퍼즐·베스트 타임이 매일 다시 켜는 습관 고리를 만든다. 막힌 퍼즐이 머릿속에 잠복하다 나중에 해법이 번뜩이는 인지적 잠복(incubation) 효과도 작동한다.
**우리 엔진 재현도:** ✅ · 스킬 [`puzzle-game`](../../../../wgf-puzzle-game/SKILL.md) · 엔진 board model / render 분리 (board[9][9] 2D 배열 단일 상태 소스), candidates[9][9] 비트마스크 연필표기 레이어, 백트래킹 솔버 + 유일해 검증 퍼즐 생성기 (순수 JS), 논리 기법 솔버(naked/hidden single, locked candidate)로 난이도 채점·힌트, undo/redo 스냅샷 스택, Phaser.Math.RND.sow 시드 기반 생성·일일 퍼즐, VectorForge(깔끔한 셀·숫자) 또는 PixelForge(픽셀 테마), ChipAudio(입력 tick·완성 chime·오류 펄스), MobileHarness(세로 스케일 + 숫자패드 탭 입력), juice-fx(영역 완성 플래시·완주 웨이브), game-ui-hud(타이머·난이도·힌트/연필 토글), localStorage(진행 저장·베스트 타임) — 순수 그리드 로직이라 물리(Arcade/Matter)·서버·3D가 일절 불필요해 puzzle-game의 '보드모델/렌더 분리' 철학과 정합도 최상. 보드모델: givens[9][9](고정 단서 플래그) + board[9][9](현재 입력)을 단일 상태 소스로 두고, 연필표기는 candidates[9][9]에 셀당 9비트 비트마스크(또는 Set)로 별도 레이어 관리. 렌더는 9x9 Phaser Text/Rectangle 그리드 + 굵은 박스 구획선, 셀당 작은 3x3 후보 마크. 입력은 셀 탭→숫자패드 탭(모바일) / 셀 선택+1~9·방향키(데스크톱), 연관 행·열·박스·동일숫자 하이라이트. 핵심 엔지니어링은 콘텐츠가 아니라 '생성기': 백트래킹 솔버로 정답 그리드를 시드 생성 후, 대칭으로 칸을 비우며 매 단계 유일해를 솔버로 검증해 단서를 제거 — 이 전 과정이 클라이언트 순수 JS로 충분히 빠르고(9x9 백트래킹은 ms급), 시드 공유로 '같은 퍼즐 도전'까지 가능. 난이도는 사람 기법을 모사하는 논리 솔버로 채점. 단순화/대체: (1) 대량 라이브 콘텐츠(수천 고정 스테이지)·글로벌 일일 랭킹은 ❌ → 무한 생성 + 로컬 베스트/일일 시드(=날짜)·로컬 출석으로 축소, (2) 변종(Killer/Diagonal/Samurai 등)은 제약 검증 함수만 추가하면 동일 스택에서 확장 가능하나 생성기 검증 난도가 올라가므로 클래식 9x9를 1순위로. IP-safe는 사실상 무위험 — 규칙이 수학·퍼블릭 도메인이라 메카닉 100% 자유.
**조합 훅:** puzzle-game(Tetris/낙하): 떨어지는 숫자 블록을 9x9 라인에 배치하되 같은 행/열/박스에 중복이 생기면 페널티, 한 영역을 1~9로 완성하면 소거되는 'Sudoku-Tetris' 하이브리드 — FE-DEDUCTION에 FE-FLOW·FE-ESCALATION을 얹어 실시간화.; arcade-classic(그리드 호퍼/Snake): 9x9 칸을 이동하며 빈 칸에 후보가 하나뿐인 셀만 '안전'하게 채울 수 있고, 잘못된 연역으로 채우면 데미지 — 연역을 액션 그리드 탐색으로 변환(FE-DEDUCTION + FE-TENSION).; topdown-shooter: 적이 1~9 번호를 달고 등장, 같은 행/열/박스 제약을 만족하는 번호 순서로만 처치하면 콤보가 터지는 '제약 사격' — FE-CONSTRAINT를 전투 표적 선택으로 이식.; endless-runner: 3레인에 흐르는 숫자 게이트 중 '현재 줄에 아직 없는 숫자'만 통과 가능한 라인-제약 러너로, Sudoku의 중복금지 규칙을 리듬형 즉시 판단(FE-TIMING + FE-CONSTRAINT)으로 변주.; Threes/2048(머지): 같은 행/열에 같은 수가 모이면 충돌 대신 다음 단계로 병합되는 변종 제약 머지 — FE-DEDUCTION의 '중복금지'를 FE-AHA 병합 전략과 결합.
**IP 안전 메모:** Sudoku의 규칙(9x9, 행·열·3x3 박스 1~9 유일, 유일해, 연필표기)은 수학적 제약충족 문제이자 퍼블릭 도메인 개념이라 메카닉·명칭 사용에 IP 위험이 거의 없다 — 'Sudoku'라는 단어 자체도 일반 명사화되어 자유롭게 쓸 수 있다(특정 출판사 'Su Doku' 로고/상표·특정 앱 브랜딩만 피하면 됨). 금지/주의: 특정 상용 Sudoku 앱·신문의 고유 로고·서체·UI 스킨·아이콘, 특정 출판물에 실린 개별 퍼즐 레이아웃(저작권 주장 사례 존재)을 그대로 복제하지 말 것 — 우리는 자체 생성기로 퍼즐을 절차 생성하므로 원천적으로 회피된다. IP-safe 환기법: 셀·숫자·하이라이트 컬러는 VectorForge/PixelForge로 자체 CC0 팔레트 디자인, 숫자 폰트는 오픈/자체 폰트, 효과음·BGM은 ChipAudio 절차 생성, 모든 퍼즐은 시드 기반 자체 생성(외부 퍼즐 임포트 금지). 변종(Killer 등)을 넣을 때도 규칙은 자유롭게 차용하되 특정 제품의 표현물(아트/사운드/명칭)만 100% 자체 제작하면 안전. ip-license-guard 스킬로 최종 점검 권장.

## Picross (Nonogram) (기원 1987~1988 (논어반/Nonogram 형식: Non Ishida 'Window Art Puzzles' 및 Tetsuya Nishio 독립 고안, 1990년대 신문 연재로 확산). 닌텐도 'Mario's Picross' 1995로 대중화)
**왜 많이 플레이됐나:** 규칙은 1분이면 배우지만(행·열 숫자대로 칸을 칠한다) 한 칸 한 칸이 순수 논리 연역이라 운이 개입하지 않는다. '확실한 한 수'를 찾을 때마다 작은 성취가 쌓이고, 다 풀면 의미 없던 격자가 하나의 도트 그림으로 돌변하는 리빌 보상이 강력하다. 펜·종이로도, 폰으로도 똑같이 즐길 수 있고 한 퍼즐이 짧아(5x5는 1분, 15x15는 10~20분) 출퇴근·자투리 시간에 딱 맞다. 스도쿠처럼 '논리로만 풀린다'는 공정성과, 그림이 드러나는 시각적 수집욕이 결합돼 장수 캐주얼 장르가 됐다.
**장르 / 시점:** 연역형 그리드 논리 퍼즐 (deduction / picture-logic puzzle) / 정면 고정 2D 그리드. 보드 좌측에 행 단서, 상단에 열 단서를 배치한 한 화면 표시(스크롤 없음, 큰 보드만 핀치/팬 보조).
**코어 루프:** 행·열의 숫자 단서를 읽고 '여기는 무조건 칠해진다 / 무조건 비었다'가 논리적으로 확정되는 칸을 찾아 채움(fill) 또는 X표를 찍는다. 한 칸을 확정하면 교차하는 줄의 단서가 새로 풀려 다음 확정 칸이 연쇄적으로 보이고, 모든 칸을 맞추면 숨겨진 도트 그림이 리빌된다.
**핵심 재미요소:**
- `FE-DEDUCTION` 연역·소거 — 운·추측 없이 '이 줄은 합이 너무 커서 가운데 N칸은 무조건 채워진다(overlap)', 'X로 막혔으니 이 블록은 여기만 가능' 같은 확실한 한 수를 단서로 좁혀가는 것이 게임의 전부. Sudoku·Minesweeper와 같은 계열의 핵심 재미이며, 이 게임에서는 행 단서와 열 단서가 서로를 제약하는 2축 교차 연역으로 발현된다.
- `FE-HIDDEN-INFO` 숨은 정보 리빌 — 칠해진 칸들이 모이면 무의미했던 격자가 고양이·하트·과일 같은 도트 그림으로 '드러난다'. 풀이 중에도 윤곽이 점점 보이기 시작하는 점진적 reveal이 Picross 특유의 시각 보상으로, 마지막 칸을 채우는 순간 전체 그림이 색을 입고 등장하는 연출이 클라이맥스.
- `FE-AHA` 통찰·아하 — 막혀 보이던 보드에서 'overlap으로 이 행 가운데가 확정되네' 또는 한 칸 X 덕분에 교차 열 전체가 와르르 풀리는 결정적 한 수를 발견하는 순간. 한 번의 확정이 연쇄 해소를 부르는 깨달음이 도파민 루프.
- `FE-FAIRNESS` 공정함 — 유일해(unique solution) 퍼즐은 추측 없이 논리만으로 끝까지 풀린다. 막혔다면 그건 RNG가 아니라 '내가 아직 못 본 단서'라는 자기 책임 귀인이 성립해, 실패(오답 패널티)도 납득되고 재도전을 부른다. 생성기가 unique-solution 보장을 해야 이 재미가 깨지지 않는다.
- `FE-COLLECT` 수집·성장 — 퍼즐 하나를 풀 때마다 도트 그림 한 장이 갤러리에 모인다. 5x5→10x10→15x15 크기 상승과 테마 팩(동물·음식·우주) 해금이 진행 동기. 완성한 그림 컬렉션 자체가 가시적 진행 지표.
**핵심 메카닉:**
- 보드 모델은 두 개의 2D 배열을 분리 유지: solution[row][col](0/1, 정답 — 비공개)과 player[row][col](0=미정, 1=fill, 2=X마킹, 플레이어 상태). renderBoard()는 player 변경 시점에만 호출해 Phaser Rectangle/Image 셀을 칠/X/빈칸으로 갱신(update 루프 미사용).
- 단서(clue) 생성: solution의 각 행·열을 런렝스 인코딩해 연속 1의 길이 목록을 만든다(예: 0,1,1,0,1,1,1 → [2,3]). rowClues[r], colClues[c]를 HUD 라벨로 좌측·상단에 렌더.
- 입력 판정: 셀 탭/클릭 → fill 토글(좌클릭·짧은 탭), X마킹 토글(우클릭·롱프레스 또는 모드 토글 버튼). 모바일은 드래그로 연속 칠하기(pointermove 동안 같은 동작 페인트), 칠/X 모드 토글 버튼을 HUD에 배치.
- 오답 패널티: 셀을 fill했는데 solution이 0이면 라이프 1 감소 + 셀 플래시·셰이크. 라이프 0이면 게임오버. (대안 모드: 패널티 없는 free 모드, 또는 시간 가산 페널티). 정답 셀을 fill하거나 빈 셀을 올바르게 X표 하면 정답 확정으로 잠금.
- 승리 판정: 모든 solution==1 셀이 player==1로 채워지면 클리어(X 칸의 정합은 보지 않음 — 채워야 할 칸만 다 채우면 됨). 매 fill 후 'solution의 1 개수 == 맞게 칠한 개수'로 O(1) 비교.
- 줄 완성 자동 표시: 한 행/열의 단서가 player 상태로 완전히 만족되면 그 단서 라벨을 회색 처리(dim)해 '이 줄 끝남'을 시각 피드백 — 인지 부담 감소.
**난이도·진행 곡선:** 크기 곡선: 5x5(튜토리얼, overlap 규칙 학습) → 10x10(중반, 단서 조합 추론) → 15x15(후반, 다단계 연역·장시간 집중). 팩 단위 진행: 테마별(동물·음식·기호) 8~15개 퍼즐 묶음을 localStorage로 해금. 난이도 파라미터는 (보드 크기, 채움 밀도, 단서 모호도=한 수만 보고 확정 가능한 칸 비율, 라이프 수, 시간 제한 유무). 초반엔 overlap만으로 확정되는 칸이 많은 '친절한' 퍼즐, 후반엔 X마킹 경유 다단계 추론이 필요한 퍼즐. 별점은 노힌트·노미스·시간으로 1~3성 부여.
**게임필·연출:** 칠하기는 즉각적이고 또박또박한 손맛 — 셀을 채울 때 작은 scale 팝(Back.out)과 짧은 'tick' 칩사운드, X마킹은 다른 톤의 짧은 'tap'. 한 행/열 단서가 완성되면 그 줄을 따라 빠른 sweep 플래시 + dim 처리로 '닫혔다'를 알린다. 오답은 셀 적색 플래시 + 가벼운 셰이크(0.004)+낮은 'buzz'로 자기 실수를 명확히. 클라이맥스는 reveal: 마지막 칸을 채우는 순간 회색 도트들이 색을 입으며(틴트 트윈) 행 단위 wipe로 그림이 등장하고, 상승 아르페지오 + 부드러운 파티클 스파클. 풀이 중에도 칠한 셀이 점점 그림 윤곽을 이루는 점진적 만족이 핵심. juice-fx로 '적게, 정확하게' — 칠하기 리듬을 가리지 않을 만큼만.
**끈끈함(리텐션):** 한 퍼즐이 짧고(작은 보드 1~3분) 즉시 다음 퍼즐로 넘어가 'just one more'가 자연 발생. 막혔을 때 'RNG가 아니라 내가 못 본 단서'라는 공정성 귀인이 좌절 대신 재집중을 부른다. 완성한 도트 그림이 갤러리에 모이는 수집욕과 '다음 팩엔 뭐가 숨어있을까'의 호기심이 장기 동기. 명상적·무압박(시간 제한 끄기 가능)이라 휴식용으로 다시 켜기 쉽고, 막힌 퍼즐이 머릿속에 남는 '잠복 효과'도 약하게 작동한다.
**우리 엔진 재현도:** ✅ · 스킬 `puzzle-game` · 엔진 Phaser 4 Rectangle/Image grid 렌더, board 모델/렌더 분리 (renderBoard), PixelForge(셀·도트 그림 절차 생성), VectorForge(스무스 셀·단서 폰트 대안), ChipAudio(tick/tap/buzz/reveal SFX), MobileHarness(스케일·DOM 가드·드래그 페인트 입력), juice-fx(셀 팝·줄 완성 sweep·reveal 컬러 트윈·셰이크), game-ui-hud(라이프·타이머·진행률·단서 라벨·칠/X 모드 토글), level-designer(퍼즐/팩 데이터 정의·난이도 곡선), localStorage(갤러리·별점·해금 저장) — puzzle-game 스택과 구조적 정합도 최상. 물리 불필요한 순수 그리드 로직이라 Arcade/Matter 모두 미사용. 보드모델은 solution[row][col](정답 0/1, 비공개)과 player[row][col](0미정/1fill/2X) 두 배열로 분리하고, renderBoard()는 player 변경 시점에만 호출(보드모델/렌더 분리 원칙 그대로). 단서는 solution의 행·열 런렝스 인코딩으로 생성해 HUD 라벨로 표시. 퍼즐 콘텐츠 생성 두 방식: (1) 손제작 — 도트 그림을 PixelForge 그리드로 디자인하면 solution이 곧 그림, level-designer로 팩 JSON 관리(IP-safe·품질 보장, 권장·기본 경로). (2) 절차 생성 — 랜덤 밀도로 채운 뒤 solver로 unique-solution(추측 없이 풀림) 검증, 비유일하면 재생성. 단, 이 unique-solution solver+재생성 루프는 비자명한 추가 구현(논리 단계 시뮬레이션·검증 비용)이라 ✅ 유지의 전제는 '손제작 팩 우선'이며, 절차 생성은 검증 신뢰도가 확보된 뒤 무한 모드로 확장하는 것이 안전(이 리스크는 손제작 시작으로 회피됨). 컬러 Picross(다색)도 player/solution을 색 인덱스 배열로 확장하면 동일 패턴으로 가능. 축소·대체: 서버 랭킹·일일 글로벌 챌린지는 ❌ → localStorage 베스트 시간 + 시드 공유(URL로 퍼즐 시드 전달)로 축소. 수천 스테이지 라이브 동기화 대신 팩당 8~15개 손제작 + 절차 생성 무한 모드 혼합. 도트 그림·폰트·SFX 전부 PixelForge/ChipAudio 코드 생성(CC0).
**조합 훅:** topdown-shooter에 'Picross 장전': 단서를 보고 적 격자에서 칠할 칸을 연역해 fill하면 그 패턴대로 광역 공격이 발동 — 사고형 연역(FE-DEDUCTION)을 실시간 슈팅 보상으로 변환; endless-runner에 'reveal 페이스 게이트': 자투리 구간마다 미니 5x5 Picross를 한 줄 풀면 대시·실드를 주는, 달리기 흐름에 짧은 연역 휴식(FE-HIDDEN-INFO)을 끼우는 하이브리드; arcade-classic Minesweeper와 결합: 칸을 칠할 때 인접 단서가 '폭탄/안전'을 동시에 알려주는 이중 단서 보드로, FE-DEDUCTION+FE-HIDDEN-INFO를 한 격자에서 교차; level-designer + 매치3: 다 푼 Picross 그림이 그대로 매치3 보드의 막힘/구멍 마스크가 돼, 연역으로 '판을 깎아내고' 그 판에서 캐스케이드를 노리는 2단 퍼즐; 2048식 컬렉션 메타: 완성한 도트 그림을 도감 타일로 모으고 같은 테마끼리 합쳐 상위 일러스트를 해금하는 FE-COLLECT 강화 메타루프
**IP 안전 메모:** 금지: 'Picross'·'Nonogram'·'논어반'을 게임 타이틀/스토어 명칭으로 사용 금지(메카닉 설명 맥락에서만 언급). 닌텐도 'Mario's Picross' 등 특정 제품의 고유 도트 일러스트(원작 퍼즐의 정확한 solution 그림 배열은 저작물)·로고·폰트·BGM/SFX·캐릭터(마리오 등) 일체 미사용. 원작 퍼즐 팩의 그림 데이터를 그대로 복제 금지. IP-safe 환기: 메카닉(행·열 런렝스 단서, 칠/X 마킹, 유일해 연역, 그림 리빌)은 신문 퍼즐 유래의 퍼블릭 도메인 규칙이라 자유 구현 가능. 도트 그림은 PixelForge로 100% 자체 디자인(동물·음식·도형 등 일반 모티프, 원작 특정 그림 모방 금지), 단서 숫자 폰트·UI는 자체/오픈 폰트, SFX는 ChipAudio 생성. 타이틀은 'Pixel Logic', 'Gridraw', 'Logic Reveal' 같은 일반 명칭 부여. ip-license-guard 스킬로 최종 점검.

## Minesweeper (1990~1992 대중화 (Microsoft Entertainment Pack 1 수록 1990, Windows 3.1 OS 기본 번들 1992로 수억 명 노출). 직계 선조는 1985년 'Relentless Logic'/'Mine Out' 계열 등 1980년대 초중반 홈컴퓨터·교육용 게임으로 거슬러 올라간다.)
**왜 많이 플레이됐나:** 규칙이 한 문장("숫자는 인접 8칸의 지뢰 수")인데 그 숫자만으로 지뢰 위치를 논리로 연역하는 깊이가 있다. Windows에 무료 동봉돼 수억 명이 강제 노출됐고, 한 판이 짧으며 "방금 그건 내 오판"이라는 자기 책임 귀인이 즉시 재도전을 부른다. 마우스만으로 즉시 시작·즉시 종료되는 접근성, 그리고 끝에 가면 단서가 모자라 확률에 베팅해야 하는 "운 vs 실력"의 긴장이 끝없는 재플레이를 만든다.
**장르 / 시점:** 숨은 정보 연역 그리드 퍼즐 (logic deduction / hidden-information grid puzzle) / 정면 고정 2D 그리드 뷰 (탑다운 격자). 스크롤 없는 단일 화면 보드(초급 9×9, 중급 16×16, 고급 16×30 등). 카메라 이동 없음.
**코어 루프:** 숫자가 드러난 칸 주변을 훑어, 인접 지뢰 수와 이미 깃발 꽂은 수를 비교해 "여긴 100% 안전" 또는 "여긴 100% 지뢰"인 칸을 한 칸씩 확정한다. 안전칸은 열고(0이면 빈 영역이 연쇄로 펼쳐짐) 지뢰칸엔 깃발을 꽂으며, 단서가 끊기면 확률로 베팅한다 — 한 번의 오판이 곧 즉사.
**핵심 재미요소:**
- `FE-DEDUCTION` 연역·소거 — "이 3 주변 미공개 칸이 정확히 3개면 전부 지뢰", "이 1의 지뢰는 이미 깃발 1개로 충족됐으니 나머지 인접칸은 전부 안전" 같은 국소 제약을 풀어 확실한 한 수를 좁혀가는 것이 게임의 본체. 인접한 두 숫자의 제약을 겹쳐 빼는 1-2-1·1-2-2-1 패턴 추론이 숙련의 핵심이며, 손이 아니라 머리가 푸는 순수 논리 퍼즐.
- `FE-HIDDEN-INFO` 숨은 정보 — 보드 전체가 가려진 상태에서 시작해, 한 칸을 열 때마다 인접 지뢰 수라는 부분 정보가 새로 드러나고 그 정보로 가려진 나머지를 추론한다. "안전이 확실한 칸만 골라 정보를 안전하게 캐낸다"는 정보 수집 자체가 메카닉. 0칸 연쇄 공개(flood reveal)로 한 번에 넓은 영역이 펼쳐지는 정보 폭발의 쾌감이 절정.
- `FE-AHA` 통찰·아하 — 막혀 보이던 보드에서 두 숫자 제약을 겹쳐 보면 "저 칸은 무조건 안전"이 톡 튀어나오는 순간, 그리고 그 한 칸을 열자 0 연쇄로 보드 절반이 와르르 열리며 막힌 줄 알았던 판이 한꺼번에 풀리는 카타르시스.
- `FE-RISK-REWARD` 위험-보상 — 확실한 수를 다 소진하면 단서가 끊겨 50:50 또는 가중 확률 칸에 베팅해야 한다. 더 안전한 구석을 찍을지, 시간을 줄이려 모험적인 칸을 찍을지의 저울질. 깃발을 생략하고 속도로 밀어붙이는 'no-flag' 고수 플레이도 위험-보상 선택.
- `FE-FAIRNESS` 공정함 — 첫 클릭은 항상 지뢰가 아니게 보장(first-click safe)하고, 단서(숫자)가 대체로 충분히 노출돼 죽었을 때 "논리로 풀 수 있었는데 내가 성급히 찍었다"는 자기 책임 귀인이 성립하는 경우가 많아 즉시 재도전을 부른다. (단, 원작은 단서가 부족한 진짜 50:50 강제 상황도 빈번해 불공정으로 느껴질 수 있으므로, 우리 재현에선 무추측 보드 생성으로 이를 선택적으로 보완.)
**핵심 메카닉:**
- 보드 모델: board[row][col] 셀 객체 2D 배열이 유일 상태원. 각 셀 = { mine:bool, adj:int(인접 지뢰 수 0~8), state:'hidden'|'revealed'|'flagged'|'question' }. 렌더는 상태 변경 시점에만 renderBoard()로 Phaser Rectangle/Image 갱신(update 루프 미사용) — puzzle-game 보드모델/렌더 분리 원칙 그대로.
- 지뢰 배치 + 숫자 사전계산: 총 M개 지뢰를 빈 칸에 무작위 살포(시드 PRNG로 재현/공유 가능) 후, 각 비지뢰 칸의 adj를 8방향 이웃 지뢰 수로 1회 계산해 캐싱. 단서는 추론 시점에 즉석 계산하지 않고 board에서 읽음.
- first-click safe: 첫 클릭 칸(과 그 8이웃)에는 지뢰가 안 가게 배치 또는 재배치. 첫 수가 즉사가 되는 불공정 제거 → FE-FAIRNESS 충족.
- 열기(reveal): 클릭 칸이 지뢰면 게임오버. 지뢰가 아니고 adj>0이면 그 칸만 공개. adj==0이면 flood fill(BFS/DFS 스택)로 인접 0칸과 그 경계 숫자칸까지 연쇄 공개 — 한 번의 입력이 넓은 영역을 펼치는 FE-AHA 모먼트의 엔진.
- 깃발(flag): 우클릭(데스크톱)·길게 탭/모드 토글(모바일)로 hidden↔flagged↔question 순환. 깃발은 지뢰 추론 메모일 뿐 정답 검증을 안 함(틀린 깃발 허용) — 깃발 수가 곧 정답은 아님.
- 코드 보조(chord/양클릭): 공개된 숫자칸에서 인접 깃발 수 == 그 숫자면 나머지 인접 hidden 칸을 한 번에 일괄 공개. 숙련자의 속도 핵심 입력. 잘못 꽂은 깃발이 있으면 이 동작이 지뢰를 열어 즉사 → 위험.
- 승리/패배 판정: 비지뢰 칸을 전부 공개하면 승리(깃발 여부 무관). 지뢰칸을 공개하면 패배(전체 지뢰 공개 + 잘못된 깃발 X 표시). 타이머·지뢰 잔여 카운터(=M - 깃발 수)를 HUD에 표시.
- (선택) no-guess 보드 생성: 배치 후 자체 solver(제약 전파 + 부분집합 소거, 필요 시 국소 전수 탐색 보강)로 '추측 없이 풀리는가' 검증, 실패 시 재배치 — FE-FAIRNESS를 한 단계 끌어올리는 대체 룰.
**난이도·진행 곡선:** 원작은 외부 레벨 진행 없이 난이도 프리셋(보드 크기 × 지뢰 밀도)과 클리어 타임 기록이 유일한 지표. 우리 재현 곡선: (1) 튜토리얼 보드(작고 저밀도, no-guess 보장)로 숫자 의미·flood·깃발·chord를 단계 도입 → (2) 초급 9×9/10지뢰(~12%) → 중급 16×16/40(~16%) → 고급 16×30/99(~21%)로 보드 확대 + 지뢰 밀도 상승 → (3) 무추측 모드 / 추측 허용 하드 모드 분기. 진행 지표는 난이도별 best-time(localStorage), 클리어 별점(시간/추측 횟수 기반), 일일 시드 챌린지(같은 판 공유). level-designer로 밀도·크기·no-guess 여부를 파라미터 테이블로 관리.
**게임필·연출:** 손맛의 핵심은 두 가지 리빌 연출 — (1) 단일 숫자 공개의 또박또박한 'tick' 사운드 + 칸 눌림(베벨→평면) 트윈, (2) 0칸 flood reveal이 중심에서 바깥으로 물결치듯 퍼지는 스태거드 reveal(juice-fx: 셀마다 5~15ms 지연 스케일/페이드 + 상승 피치 칩사운드 스택)이 정보 폭발의 카타르시스를 청·시각화. 깃발 꽂기는 작은 squash 팝 + 'plant' SFX. 지뢰 클릭=즉사는 짧고 강한 셰이크(120ms) + 폭발 파티클 + 'die' 사운드 + 전체 지뢰 순차 공개 + 보드 그레이아웃. 승리는 남은 hidden 칸을 자동 깃발로 채우는 스윕 연출 + 팡파르 + 타이머 정지 플래시. chord 일괄 공개도 미니 flood 연출로 손맛을 준다.
**끈끈함(리텐션):** 한 판이 수십 초~수 분으로 짧고, 패배 원인이 많은 경우 "논리로 풀 수 있었는데 내가 성급히 찍었다"는 자기 책임으로 귀인돼(FE-FAIRNESS) 즉시 재도전을 부른다. 단일 숫자(클리어 타임)로 환산되는 기록은 자기 경신·비교가 쉬워 숙련 동기(패턴 즉독·no-flag 스피드·chord 속사)를 만든다. 시드 기반이라 매 판 배치가 달라 외움이 안 통하고, 막판의 확률 베팅(FE-RISK-REWARD)이 "이번엔 운 좋게 풀릴까"의 변주를 더한다. 0 연쇄로 보드가 와르르 열리는 도파민(FE-AHA)이 "한 칸만 더"를 끝없이 잇는다. (자기기록 자랑·시드 공유 등 소셜 환기는 fun_elements 확정 태그가 아닌 리텐션 보조 요소로 다룬다.)
**우리 엔진 재현도:** ✅ · 스킬 `puzzle-game` · 엔진 board[row][col] 2D 배열 단일 상태원 + renderBoard() (상태 변경 시점만, update 루프 미사용), Phaser Rectangle/Image 또는 Container 그리드 셀 렌더(숫자는 text/bitmaptext), flood fill reveal (BFS/DFS 스택, 0칸 + 경계 숫자칸 연쇄 공개), 입력: 좌클릭=열기 / 우클릭=깃발 (데스크톱), 모바일은 탭=열기 + 길게누름 or 깃발모드 토글 버튼 (MobileHarness, input pointerdown/up), PixelForge(레트로 픽셀 셀/숫자) 또는 VectorForge(둥근 셀·플랫 숫자) 절차 에셋, ChipAudio(reveal tick / flag plant / flood 상승 피치 스택 / die 폭발), juice-fx(flood 스태거드 reveal, 깃발 squash 팝, 즉사 셰이크+파티클, 승리 스윕), game-ui-hud(타이머·지뢰 잔여 카운터(M-깃발수)·best-time·난이도 셀렉터), localStorage(난이도별 best-time, 시드 공유(?seed=), 통계), Phaser.Math.RND.sow 시드 PRNG로 재현/공유 가능한 배치, time-and-timers·tweens·data-manager — puzzle-game 스택과 정합도 최상, 오히려 Tetris보다도 쉽다. 실시간 낙하 루프조차 없는 완전 턴제(입력 시에만 상태 변화)라 보드모델/렌더 분리 철학이 100% 들어맞고, 물리(Arcade/Matter) 전혀 불필요한 순수 로직. 보드모델: board[row][col]에 {mine,adj,state} 셀 객체 2D 배열을 유일 상태원으로 두고, 지뢰 살포→adj 8방향 사전계산→first-click safe 재배치→reveal(단일/flood)→깃발 토글→chord→승패 판정만 구현하면 충실 재현 끝. flood fill은 명시적 스택 BFS로 (재귀 깊이/스택오버플로 회피, 대형 보드 16×30도 안전). renderBoard는 셀 state→스프라이트/텍스트 매핑 1:1. 타이머는 time.addEvent 또는 game-ui-hud 경과시간. 축소/대체: (1) 글로벌 일일 랭킹·서버 세이브는 ❌ → localStorage best-time + 시드 문자열/URL 공유로 '같은 판 도전'으로만 축소(서버 의존 소셜 기능은 제외). (2) 원작의 진짜 50:50 강제 불공정은 자체 solver(제약 전파+부분집합 소거, 필요 시 국소 전수 탐색 보강) 기반 no-guess 보드 생성으로 선택적 보완 — 다만 단순 제약전파만으로 풀리지 않는 보드가 남을 수 있어 추론기 강화/검증 루프 비용이 생각보다 더 들 수 있으므로, 기본 재현엔 넣지 않아도 무방(feasibility ✅에 영향 없음). (3) 대형 보드는 셀 수천 개라 Rectangle 개별 객체 대신 RenderTexture/단일 텍스처 아틀라스 + 좌표 매핑으로 모바일 perf 확보 권장(perf-60fps). 서버·멀티·3D 요소가 전무해 축소 없이 사실상 100% 재현 가능.
**조합 훅:** topdown-shooter에 이식: 시야 가려진 격자 맵에서 적이 매복한 칸의 인접 수가 정찰로 드러나고, '확실히 안전한 칸'만 전진해 매복을 회피·역습하는 연역형 스텔스 슈터(FE-DEDUCTION+FE-HIDDEN-INFO).; arcade-classic 그리드 호퍼에 이식: 한 칸씩 건너는 호퍼가 인접 위험 수(지뢰=함정)를 단서로 안전 경로를 연역해 반대편에 닿는 '논리 건너뛰기' 퍼즐(FE-DEDUCTION+FE-RISK-REWARD).; endless-runner에 이식: 자동 전진 중 앞쪽 3레인의 '인접 장애물 수' 숫자를 보고 안전 레인을 즉석 연역해 좌우 한 칸 이동하는 리듬형 숨은정보 러너(FE-HIDDEN-INFO + 타이밍 압박).; puzzle-game 매치3/Picross와 결합: 연역으로 '지뢰가 아님이 확정된' 칸만 색이 부여돼 그것으로 매치/네모로직을 푸는, 숨은정보 해제가 곧 매치 보드를 짓는 2단 퍼즐(FE-DEDUCTION + 연쇄/콤보).; Baba Is You식 규칙조작과 결합: 'N IS SAFE' 같은 규칙블록을 밀어 숫자의 의미(인접 지뢰→인접 보물)를 재정의하며 푸는 규칙조작 마인스위퍼(규칙 발견형 결합 가설).
**IP 안전 메모:** 메카닉(인접 지뢰 수 표시, 8방향 카운트, flood reveal, 깃발, chord, first-click safe, 승패 판정)은 1980년대로 거슬러 올라가는 공개 게임 규칙·수학이라 자유롭게 구현 가능 — IP 위험이 가장 낮은 부류. 금지: 'Minesweeper' 명칭을 타이틀/스토어명으로 사용 금지(메카닉 설명용 언급만), Microsoft Windows판 고유 자산 — 노란 스마일리 페이스 버튼(평상/긴장/사망 3종 표정), 특유의 회색 3D 베벨 셀 디자인, 정확한 숫자 색 코드(1=파랑·2=초록·3=빨강… 그 색표), 원작 폭발·삑 효과음·win.com 비트맵·로고/폰트 일체 미사용. IP-safe 환기: 타이틀은 'Logic Field', 'Safe Squares', 'Deduce' 등 일반 명칭으로 새로 부여; 지뢰는 추상 위험 토큰(가시·크리스털·별)으로 테마화; 셀·숫자·깃발은 PixelForge/VectorForge 자체 CC0 팔레트(원작과 다른 색표)로, 스마일 버튼 대신 자체 마스코트/추상 아이콘으로 재시작 버튼 디자인; 모든 SFX는 ChipAudio 절차 생성. 난이도 프리셋 숫자(9×9/10 등)는 사실상 관용 규격이라 무방하나 표현물(아트/사운드/명칭)만 100% 자체 제작하면 안전. ip-license-guard로 최종 점검.

## Wordle (2021 (Josh Wardle 공개; 2022년 1월 바이럴 폭발 후 NYT 인수))
**왜 많이 플레이됐나:** 규칙이 한 문장(5글자 단어를 6번 안에 맞히기)인데 매 추측이 정보가 되어 논리로 후보를 좁히는 깊이가 있다. 하루 1퍼즐이라 과몰입 없이 짧게 즐기고, 모두가 같은 정답을 풀어 "오늘 몇 번에 맞혔나"를 비교·공유하는 사회적 의식이 됐다. 스포일러 없이 색 이모지 격자만 공유하는 포맷이 SNS 바이럴을 폭발시켰다. 설치 불필요·무료·1분 컷이라 진입장벽이 거의 0.
**장르 / 시점:** 단어 연역 퍼즐 (word deduction puzzle) — 글자 단위 피드백으로 후보를 좁히는 마스터마인드(Mastermind)형 논리 추리. / 정면 고정 2D 그리드. 6행 × 5열의 추측 보드(위→아래로 추측 기록 누적) + 하단 가상 QWERTY 키보드. 스크롤 없음, 카메라 고정. 보드 자체는 움직이지 않고 셀의 글자·색 상태만 변한다.
**코어 루프:** 5글자 단어를 입력해 제출하면 각 글자가 색으로 채점된다(정답위치=초록 / 단어엔 있지만 위치다름=노랑 / 없음=회색). 이 단서로 다음 추측의 후보를 머릿속에서 좁혀 6번 안에 정답을 연역한다.
**핵심 재미요소:**
- `FE-DEDUCTION` 연역·소거 — 매 추측의 초록/노랑/회색 피드백이 가능한 단어 집합을 논리적으로 줄인다. 회색 글자는 후보에서 완전 배제, 노랑은 '있지만 그 자리 아님', 초록은 위치 확정 — 단서를 누적 적용해 확실한 한 수로 수렴하는 것이 게임의 본질.
- `FE-CONSTRAINT` 제약 퍼즐 — 추측 기회가 단 6번. 한 번의 추측을 '확정 정보를 최대한 캐는 정찰'에 쓸지 '정답 베팅'에 쓸지 자원처럼 배분해야 한다. 기회가 줄수록 한 추측의 무게가 커진다.
- `FE-AHA` 통찰·아하 — 흩어진 노랑 글자들의 위치 제약과 회색 배제를 종합하다 '그럼 답은 이 단어밖에 없다'가 머릿속에서 딱 맞아떨어지는 순간. 손이 아니라 머리가 푸는 쾌감.
- `FE-FAIRNESS` 공정함 — 정보가 전부 보드에 공개돼 있어 실패가 항상 '내가 단서를 덜 활용했다'로 납득된다. 운이 아니라 추론의 책임이라 다음 날 재도전을 부른다.
- `FE-JUST-ONE-MORE` 한 판 더 — 원작은 하루 1판으로 절제하지만 재현판에서는 무제한/연습 모드로 즉시 새 단어를 뽑아 '다음 단어'를 끝없이 돌릴 수 있다. 한 판이 1~2분이라 기록 갱신 루프가 자연스럽다.
- `FE-SOCIAL` 경쟁·공유 — 정답을 노출하지 않는 색 이모지 격자(🟩🟨⬜)를 클립보드로 복사·공유. 원작은 같은 날짜에 모두가 동일 정답을 풀어 '몇 번에 맞혔나'를 스포일러 없이 자랑하는 것이 바이럴의 핵심(재현판은 날짜 시드/공유 URL로 같은 판을 전달).
**핵심 메카닉:**
- 보드모델: board[row][col]에 글자 문자 저장 + status[row][col]에 채점 코드(0=빈칸, 1=회색/absent, 2=노랑/present, 3=초록/correct) 저장. 이 두 2D 배열이 유일 상태원. 상태 변경(글자 입력·삭제·제출 채점) 시점에만 renderBoard()로 셀 글자·배경색 갱신(update 루프 미사용).
- 채점 알고리즘(중복 글자 정확 처리 2-pass): 1패스 — 정답과 같은 위치·같은 글자는 초록(3)으로 확정하고 정답 글자 카운트에서 소모. 2패스 — 남은 글자에 대해 정답에 아직 남은 카운트가 있으면 노랑(2), 없으면 회색(1). 단순 includes() 방식은 중복 글자(예: 정답에 E 1개인데 추측에 E 2개)를 틀리게 칠하므로 반드시 카운트 차감식으로 구현.
- 단어 사전: CC0/오픈 영어 단어 리스트를 2개로 분리 — answers[](정답 풀, 수백~천 단어)와 allowed[](제출 허용 사전, 정답 풀의 상위집합). 입력이 allowed에 없으면 제출 거부 + 행 흔들기(invalid shake) 피드백. 사전은 코드/JSON 에셋으로 동봉(서버 불필요).
- 가상 키보드 상태: keyState[letter]에 그 글자의 최선 채점 결과(초록>노랑>회색 우선순위)를 누적 저장해 키 색을 칠한다 — 이미 회색이 된 글자는 흐리게, 확정 초록은 강조해 플레이어의 연역을 시각 보조.
- 입력: 물리 키보드(A~Z, Enter 제출, Backspace 삭제) + 모바일은 화면 내 가상 QWERTY 탭. MobileHarness 스케일·DOM 가드로 모바일웹뷰 대응. 한 행이 5글자 다 차야 Enter 활성.
- 일일 퍼즐 + 시드 공유: 정답 인덱스 = (오늘 날짜를 epoch-day로 환산) % answers.length 로 결정론적 산출 → 같은 날 모두 같은 단어. localStorage에 오늘 진행/결과·연속일(streak)·통계 저장. URL ?seed=YYYYMMDD 또는 ?w=인덱스로 특정 판 공유(서버 없이 시드만 전달).
- 결과 공유: 클리어/실패 시 status 격자를 🟩🟨⬜ 이모지 문자열로 변환(글자 미노출) + 시도 횟수 헤더를 navigator.clipboard로 복사. game-ui-hud 토스트로 '복사됨' 안내.
**난이도·진행 곡선:** 원작은 외부 레벨 없는 '하루 1퍼즐' 구조 — 난이도는 그날 단어의 빈도·글자 패턴에서 자연 변동. 재현판 진행 곡선: (1) 데일리 모드(하루 1판, 통계·연속일 추적) + (2) 무제한 연습 모드(즉시 새 단어). 난이도 팩으로 확장 — 흔한 단어 위주 EASY 풀 → 드문 단어/이중 글자 많은 HARD 풀, 글자 수 변주(4·5·6글자) 팩, '하드 모드'(드러난 초록/노랑 글자를 다음 추측에 반드시 사용하도록 제약 = FE-CONSTRAINT 강화). level-designer로 단어 풀을 난이도별 테이블로 구성.
**게임필·연출:** 제출 시 한 행의 5타일이 좌→우로 순차 플립(flip reveal) 트윈으로 색이 드러나는 것이 핵심 손맛 — 한 번에 칠하지 말고 50~80ms 간격으로 한 글자씩 뒤집어 '판정이 차오르는' 긴장을 만든다. 글자 입력 시 셀 팝(scale yoyo), 제출 불가(미완성·사전에 없음)는 행 좌우 흔들림(shake) + 짧은 buzz SFX. 초록 확정엔 살짝 바운스 + 상승 톤, 전체 정답 시 행 점프 웨이브 + 컨페티/팡파르. 키보드 키도 같은 타이밍에 색이 물든다. ChipAudio: 입력 tick, 플립마다 짧은 톤(색별 피치), 클리어 coin/win, 실패 die. juice-fx로 플립·셰이크·컨페티 구성. 절제된 연출이 논리 게임의 차분한 톤과 맞는다.
**끈끈함(리텐션):** 하루 1판이라는 인위적 희소성이 '오늘 거 풀었나?'를 일과로 만들고, 연속일(streak) 카운터가 끊기기 아까워 매일 재방문하게 한다(손실 회피). 정답이 전 세계 동일이라 '나만 어려웠나/쉬웠나'를 비교하는 사회적 동기 + 스포일러 없는 이모지 공유가 자랑을 안전하게 만들어 바이럴이 리텐션으로 환류. 실패가 운이 아닌 추론 탓이라 자기 책임 귀인(FE-FAIRNESS)이 다음 날 복수전을 부른다.
**우리 엔진 재현도:** ✅ · 스킬 `puzzle-game` · 엔진 board[row][col] 글자 + status[row][col] 채점코드 이중 2D 배열(보드모델/렌더 분리), PixelForge 또는 VectorForge로 타일·글자 글리프·키보드 키 절차 생성(CC0), ChipAudio(입력 tick·플립 톤·win/die SFX), MobileHarness(스케일·DOM 가드 + 화면 내 가상 QWERTY), juice-fx(플립 리빌·invalid shake·초록 바운스·정답 컨페티), game-ui-hud(시도 카운터·통계·연속일·토스트(공유 복사)), level-designer(난이도별 단어 풀 테이블 EASY/HARD/글자수 팩), localStorage(진행·통계·streak 영속화 + 날짜 시드 일일 퍼즐), navigator.clipboard(이모지 격자 공유 + ?seed= URL 공유) — 순수 로직 그리드라 물리(Arcade/Matter) 전혀 불필요, puzzle-game의 '보드모델/렌더 분리' 철학과 정합도 최상. 핵심 상태는 board[row][col](입력 글자)와 status[row][col](채점 0~3) 두 2D 배열이며, renderBoard()가 변경 시점에만 셀 텍스트·배경색을 갱신. 채점은 중복 글자를 정확히 처리하는 2-pass 카운트 차감 알고리즘이 유일한 까다로운 부분(includes 단순구현 금지). 단어 사전은 CC0/오픈 영어 워드리스트를 정답 풀+허용 풀로 분리해 JSON 에셋으로 동봉(서버 불필요, 완전 오프라인). 일일 퍼즐·연속일·통계는 날짜→epoch-day 시드 + localStorage로 100% 로컬 재현. 결과 공유는 색 이모지 문자열 클립보드 복사 + URL 시드 파라미터로 서버 없이 충족. 축소/대체 포인트: (1) 글로벌 실시간 리더보드·계정 동기화·친구 비교는 ❌ → 로컬 통계 + 이모지/시드 공유로 축소(FE-SOCIAL은 '자랑'까지 보존). (2) 원작의 큐레이션된 일일 단어 시퀀스(편집자가 정한 순서)는 재현 불가 → 날짜 시드 결정론 셔플로 대체. (3) 한글 자모 조합(초성·중성·종성 분해 채점)은 별도 IME·자모 보드 모델이 필요해 ⚠️ — 1차는 영어/로마자 기준으로 ✅ 재현하고 한글은 확장 과제로 분리. 모바일은 OS 키보드 대신 화면 내 가상 키보드를 그려 입력 일관성 확보.

## Flow Free (2012)
**왜 많이 플레이됐나:** 규칙이 한 줄로 끝난다 — "같은 색 점을 잇고 보드를 다 채워라". 5초면 배우는데, 보드가 커지면 한붓그리기식 공간 최적화 난도가 급상승해 "쉽게 배우고 끝없이 깊은" 퍼즐 공식을 완성한다. 한 판이 10초~수 분으로 짧고, 손가락으로 선을 쭉 긋는 촉각적 쾌감이 즉각적이라 "한 판 더"가 끊기지 않는다. 실패가 없고(언제든 선을 지우고 다시) 정답이 명확히 존재해 "내가 풀 수 있다"는 통제감이 강하며, 보드 크기별 수천 스테이지를 무료/광고로 풀어 캐주얼층을 대규모로 흡수했다.
**장르 / 시점:** 경로 연결 퍼즐 (path-connecting / unicursal flow puzzle) — 보드 충전(board-filling) 논리 퍼즐 / 정면 2D 정사각 그리드 고정 시점 (스크롤 없음). 보드 전체를 한 화면에 표시, 셀에 색 점(엔드포인트)과 흐르는 파이프 선을 렌더.
**코어 루프:** 색 점 하나를 손가락/마우스로 누른 채 인접 셀을 따라 드래그해 같은 색 짝 점까지 선을 잇는다. 선끼리 겹치지 않게 짜맞춰 모든 색 쌍을 연결하고 보드의 모든 빈칸을 선으로 채우면 클리어 — 막히면 선을 되짚거나 지우고 다시 긋는 30초 루프.
**핵심 재미요소:**
- `FE-SPATIAL` 공간 추론 — 각 색 경로가 보드 위에서 어떤 곡선을 그려야 다른 색을 막지 않으면서 빈칸을 다 메울지 머릿속으로 시뮬레이션해야 한다. 한 색의 경로 모양이 다른 색의 통로를 결정하는 상호 구속이 핵심 — 한붓그리기 + 영역 분할의 공간 감각이 이 게임의 심장.
- `FE-OPTIMIZE` 최적화 — 단순 연결만으로는 부족하고 '모든 빈칸을 채워야' 클리어. 더 나아가 원작의 perfect(최소 이동 수로, 같은 색 경로를 되짚거나 낭비 없이 한 번에 채우는 무낭비 풀이) 보너스처럼, 정답을 넘어 '더 효율적인 경로'를 노리는 최적화 압박이 재도전을 만든다.
- `FE-AHA` 통찰·아하 — 꽉 막혀 보이던 보드에서 '이 색을 벽 따라 우회시키면 가운데가 뚫린다'는 결정적 경로가 머릿속에 딱 떠오르는 순간, 나머지 색이 연쇄적으로 자리를 찾으며 풀이 전체가 한 번에 완성되는 깨달음의 쾌감.
- `FE-FLOW` 몰입 흐름 — 손가락으로 선을 쭉 긋고, 막히면 되짚고, 다시 긋는 입력이 끊김 없이 이어진다. 드래그 한 번에 경로가 살아나듯 그려지는 촉각 리듬이 무아지경 몰입을 만든다.
- `FE-ELEGANCE` 우아한 해 — 보드가 빈칸 하나 없이 색색의 곡선으로 빈틈없이 메워지는 완성 상태 그 자체가 미니멀하고 만족스러운 그림 — 정답이 시각적으로 '딱 맞아떨어진' 우아함을 준다.
**핵심 메카닉:**
- 보드모델: board[row][col] 2D 배열을 단일 상태원으로 두고 각 셀에 {colorId, endpoint?:bool}을 저장. 별도 path 상태로 colorId→경로 셀 시퀀스([[r,c],...]) 배열을 유지(엔드포인트 2개를 양끝으로). 렌더는 상태 변경 시점에만 renderBoard()로 점·파이프 세그먼트 갱신(update 루프 미사용).
- 엔드포인트 = 한 색당 정확히 2개의 고정 점. 레벨 데이터는 각 색의 두 좌표 + 보드 크기로 정의(level-designer JSON). 클리어 조건은 (a)모든 색 쌍 연결 AND (b)모든 셀 점유(빈칸 0개) 둘 다 충족.
- 입력(경로 그리기): 엔드포인트나 기존 경로 끝에서 pointerdown → pointermove로 인접(상하좌우 4방향, 대각 불가) 셀로 진입할 때마다 경로에 push. screenToGrid(pointer.x,y)로 현재 셀 산출, 직전 셀과 인접·미점유면 연장. 모바일 스와이프 드래그가 곧 그리기 입력이라 별도 키 불필요(MobileHarness pointer delta).
- 겹침·되짚기 규칙: 다른 색이 이미 점유한 셀로 들어가면 그 색의 경로를 그 지점부터 잘라내고(자동 양보) 새 색이 차지 — 원작의 '덮어쓰기' 손맛. 같은 색 경로 위를 거꾸로 드래그하면 그 지점까지 경로를 truncate(되짚기 = 부분 지우기). 짝 엔드포인트에 닿으면 그 색 연결 완료 플래그.
- 승리 판정: 매 경로 변경 후 connectedColors === totalColors && filledCells === ROWS*COLS 검사. 부분 충족(전부 연결됐지만 빈칸 남음)은 미클리어로 처리해 '빈칸 채우기' 제약을 강제 — 이것이 단순 길찾기와의 차별점.
- 무손실 실험: 실패 개념 없이 언제든 경로를 지우고 다시. Undo는 경로 단위 스택(색별 경로 스냅샷) 또는 셀 단위 truncate로 충분. 이동 수(moves) 카운터와 perfect 판정(보드 완전 충전 시 이동 수가 최소 = 같은 색 경로를 되짚거나 낭비 없이 채웠는지)으로 별점 산출.
**난이도·진행 곡선:** 보드 크기로 자연스러운 난도 곡선: 5x5(튜토리얼, 색 3~4개) → 6x6 → 8x8 → 9x9 → 10x10+ 로 셀 수와 색 수가 늘며 경로 상호구속이 기하급수로 복잡해진다. 같은 크기 안에서도 엔드포인트 배치(모서리 vs 중앙·인접 vs 대각)로 난도를 미세 조절. 팩 단위 진행: 크기별 10~30개 손제작/검증 레벨 묶음을 level-designer로 정의하고 클리어 시 다음 잠금 해제, 별점(연결만/완벽=최소 이동·무낭비)으로 재도전 동기. 선택적 타임 트라이얼 팩으로 FE-ESCALATION 변주 가능.
**게임필·연출:** 파이프 선이 손가락을 따라 셀 단위로 톡톡 연장되는 스냅감 + 둥근 캡으로 이어지는 매끈한 선(VectorForge 라운드 캡·조인). 경로가 짝 점에 닿아 연결 완료될 때 그 색 전체가 짧게 펄스/글로우 + 'ding' 칩사운드(ChipAudio). 다른 색을 덮어쓸 때 잘려나간 선이 살짝 페이드(juice-fx). 보드가 100% 채워져 클리어되는 순간 모든 선이 동시에 밝게 차오르는 sweep 연출 + 상승 팡파르 + 마지막 빈칸이 메워지는 '딱' 맞물림 피드백. 되짚기/지우기는 즉각·무비용이라 부담 없이 실험하는 손맛.
**끈끈함(리텐션):** 실패가 없어 좌절 대신 '풀릴 때까지 만지작'하는 안전한 탐색 심리가 작동하고, 막힌 보드는 머릿속에 잠복해 다시 켜게 만든다(잠복 효과). 정답이 반드시 존재해 '내가 풀 수 있다'는 통제감 + 한 판이 짧고 즉시 다음 레벨로 넘어가는 구조가 FE-JUST-ONE-MORE를 만든다. perfect/별점·다음 보드 크기 해금이라는 가시적 수집 progression이 장기 동기. 보드가 색색으로 빈틈없이 채워진 완성 그림의 시각적 만족이 클리어마다 보상으로 작동한다.
**우리 엔진 재현도:** ✅ · 스킬 `puzzle-game` · 엔진 보드모델/렌더 분리(board[row][col] + colorId별 경로 시퀀스), Phaser Graphics/VectorForge 라운드캡 선분 렌더(파이프·엔드포인트 점), pointerdown/pointermove 드래그로 셀 경로 연장(input-keyboard-mouse-touch 레퍼런스), screenToGrid/gridToScreen 좌표 변환, MobileHarness 스와이프 드래그 입력 + 스케일·DOM 가드, ChipAudio 연결/클리어/지우기 SFX, juice-fx 연결 펄스·클리어 sweep·덮어쓰기 페이드, level-designer 크기별 레벨 팩 JSON 정의, game-ui-hud 이동 수·연결 진행도·별점, localStorage 진행·별점·perfect 기록 저장 — 순수 그리드 로직 + 드래그 입력이라 물리(Arcade/Matter) 전혀 불필요, puzzle-game 스택과 정합도 최상. 보드모델: board[row][col]에 {colorId, isEndpoint} 저장 + 색별 path 시퀀스 배열을 병행 상태로 유지(파이프 렌더·되짚기·덮어쓰기의 단일 소스). 입력은 Tetris/2048식 방향 단발이 아니라 연속 드래그라, pointerdown(엔드포인트 또는 경로 끝에서 시작)→pointermove마다 screenToGrid로 인접 4방향 셀 진입 시 path.push, 같은 색 위 역드래그는 truncate, 타 색 셀 진입은 그 색 경로 잘라내고 양보하는 규칙으로 구현(레퍼런스의 input.on('pointermove') 패턴 그대로). 선은 VectorForge Graphics로 셀 중심 잇는 라운드캡 폴리라인 + 엔드포인트 원, IP-safe 자체 팔레트. 승리 판정은 매 변경 후 '전 색 연결 && 빈칸 0' 동시 검사로 '보드 채우기' 제약을 코드로 강제(이게 단순 미로 길찾기와 차별점). 대체/축소: (1)원작의 수천 라이브 스테이지·일일 챌린지·글로벌 랭킹은 ❌ → 크기별 손제작/검증 레벨 팩(level-designer) + 시드 공유·localStorage 베스트로 단일 플레이 축소. (2)레벨 자동 생성은 가능하나 '유일 풀이 보장 + 빈칸 완전 충전'을 만족하는 보드 합성은 검증 비용이 커, 초기엔 손제작/사전검증 레벨 권장(절차생성은 후속 확장으로, 생성 후 솔버로 풀이 가능성·유일성 검증 필요). (3)perfect 별점은 경로 길이 합 = ROWS*COLS(즉 빈칸 0) 충족 시 이동 수(낭비 없는 최소 풀이)인지로 순수 JS 재현 — '방향전환 수'가 아니라 '되짚기·낭비 없는 최소 이동'이 기준. 서버·멀티 없음 → 단일 플레이 웹 기준 축소 없이 ✅.
**조합 훅:** endless-runner: 달리는 도중 화면 하단 미니 그리드에 색 점이 떠오르고, 손가락으로 경로를 그어 잇는 데 성공하면 대시·실드가 발동하는 '경로 잇기로 가속하는' 하이브리드(FE-SPATIAL+FE-FLOW).; topdown-shooter: 적을 처치하면 같은 색 노드 쌍이 보드에 박히고, 두 노드를 선으로 연결하면 그 라인을 따라 관통 레이저/연쇄 번개가 발사되는 '경로 무기 장전' 슈터(FE-AHA+FE-COMBO).; puzzle-game(Match-3): 같은 색 3개 이상을 인접 잇기로 연결하면 소거되고 중력 낙하·리필이 도는 'connect-to-clear' 변주 — Flow의 드래그 잇기 입력 + 매치3 캐스케이드 결합(FE-COMBO).; arcade-classic: 제한 시간 안에 최소 이동으로 모든 색을 잇는 스코어어택 모드로, 무실패 명상 퍼즐을 'perfect 경로 + best-time 갱신' 한 판 더 게임으로 전환(FE-OPTIMIZE+FE-JUST-ONE-MORE).; platformer-game: 발판 사이를 색 파이프로 직접 그어 연결하면 그 경로가 이동 가능한 길이 되는 '길을 그려 건너는' 1인 퍼즐 플랫포머(FE-SPATIAL+FE-ELEGANCE).
**IP 안전 메모:** 금지: 'Flow Free' 게임명·로고·서체, Big Duck Games의 고유 색 팔레트·시그니처 네온 파이프 룩과 효과음·BGM, 원작의 특정 레벨 레이아웃(좌표 배치)을 그대로 복제하는 것. 메카닉(색 점 잇기, 선 비겹침, 보드 빈칸 완전 충전, 드래그로 그리기, 되짚기/덮어쓰기, perfect 보너스)은 게임 규칙/아이디어라 자유롭게 구현 가능. IP-safe 환기법: 게임명을 'Pipe Link', 'Connect Flow', 'Wire Up' 등 일반 명사화하고, 파이프 색·캡 스타일·점 디자인은 VectorForge로 자체 CC0 팔레트 새로 디자인(예: 보석·별자리·전선 테마). 사운드는 ChipAudio 자체 생성, 레벨은 원작 카피 없이 자작/절차생성(생성 시 솔버로 유일 풀이 검증). 장르를 '경로 연결 퍼즐'로 일반 표기하고 ip-license-guard 스킬로 최종 점검.
