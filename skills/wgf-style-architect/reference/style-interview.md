# 스타일 설계 인터뷰 (Deep Interview 적응판 · 탑다운 · 복잡도·매체 먼저 · 의도 주도)

> [`style-architect`](../SKILL.md)의 **'1) 의도 분석 + 스타일 인터뷰'** 단계를, **탑다운으로 모호성이 풀릴 때까지
> 끈질기게 묻는 1문1답 인터뷰**로 수행하는 플레이북.
> oh-my-claudecode `deep-interview`(Socratic 1문1답 + 약점 차원 타깃 + 챌린지 모드 + 준비도 게이팅)와
> [ability-interview.md](../../wgf-ability-architect/reference/ability-interview.md)·[item-interview.md](../../wgf-item-architect/reference/item-interview.md)를
> **비주얼 아트 디렉션 설계**에 적응시켰다.
> 차이: 능력 인터뷰가 *캐릭터가 무엇을 하는가*, 아이템 인터뷰가 *무엇을 습득·사용하는가*를 캔다면, 이 인터뷰는
> *게임이 어떻게 보이는가(매체·색·폼·셰이딩·무드)* 를 캔다 — 그리고 **얼마나 자세히 정해야 하는가**를 먼저 가른다.
>
> **용어:** "스타일"은 게임의 **비주얼 아트 디렉션**(팔레트·폼·무드). Claude 스킬과 무관.
>
> **언제 쓰나:** "예쁘게 해줘", "픽셀아트로", "던전 분위기로", "통일감 있게"처럼 요청이 모호하거나 아래 차원이 비어
> 있을 때. 요청이 이미 구체적이면(매체·팔레트·무드가 다 정해졌으면) 인터뷰를 건너뛰고 바로 STYLE.md·style.json 을 설계한다.
>
> 자동 트리거 아님. SKILL.md '1) 의도 분석'에서 **온디맨드 Read** 로 부른다.

## 0. 이 인터뷰의 3대 정신

1. **복잡도·매체를 먼저 못 박고 탑다운으로 내려간다.** 스킬 0단계(현재 게임 분석)가 끝난 상태에서 시작한다 — 코어 동사·
   장르·기존 에셋·톤·플랫폼을 이미 안다. 그 위에서 **얼마나 자세히 스타일을 정할까(티어 0~3)** 와 **픽셀 vs 벡터**부터
   못 박고 → 무드 → 팔레트 → 폼·라인 → 셰이딩·조명 → 포스트FX → 응집·검증 순으로 *좁혀* 내려간다.
   티어·매체가 어휘·범위·이후 모든 질문을 프레이밍한다(`STY-SCOPE-DEFAULT-MINIMAL`·`STY-SCOPE-MEDIUM-GATE`).
2. **Claude가 먼저 *구체적인* 룩을 제안한다(백지 금지).** 빈 객관식("무슨 색 원해요?")을 던지지 않는다. 매 라운드
   game-dna 장르 맥락 + 아트 이론으로 *이 게임의 이 톤에 어울리는 구체적 룩*을 한 컷으로 먼저 제시하고 의견을 밝힌다.
   **단순하게 갈지(팔레트만) 깊게 갈지(풀 스타일가이드+무드)는 사용자가 주도해 정한다(S1, 반드시 질문).**
3. **모호성이 풀릴 때까지 끈질기게 — 단, 단순함을 부끄러워하지 않는다.** 한 라운드 한 질문, 가장 약한 차원을 계속 캔다.
   추상적 답("예쁘게", "분위기 있게")은 **구체 사례로 되묻는다**("'분위기 있게' = 어두운 던전에 따뜻한 횃불(T3 라이팅)인가요,
   아니면 차분한 파스텔 팔레트(T0)인가요? 1~3분 모바일이면 후자도 충분히 예쁩니다"). 목표는 *Claude가 그리기 편한 룩*이
   아니라 **이 게임에 맞는, 한 세계로 보이는 룩**이다 — 그게 제한 팔레트 하나일 수도 있다(`STY-SCOPE-DEFAULT-MINIMAL`).

## 1. 핵심 원칙 (deep-interview에서 차용)

1. **1문1답.** 한 라운드에 질문 하나. 여러 개를 한 객관식에 욱여넣지 않는다.
2. **약점 차원 타깃 + "왜 지금".** 매 라운드 가장 모호하거나 결정적인 차원 하나를 고르고, 왜 지금 이걸 묻는지 한 문장으로.
3. **가정을 드러낸다.** "뭘 원해요?" 대신 "무엇을 전제하나요?"를 묻는다. 추상적 답은 구체 색/매체/무드로 되묻는다.
4. **Claude가 먼저 구체적 룩을 제안(백지 금지).** 아트 이론([INDEX](./INDEX.md)) + 게임 장르 기반. 첫 옵션에 "(추천)" + 근거. *손에 그려지는 한 컷*으로.
5. **안티패턴 가드.** 과설계·매체 혼용·render 불일치·팔레트 폭발·가독성 희생 무드·Canvas 폴백 누락을 내부 가드로(각 파일 ## 안티패턴). 충돌 의도면 절충 되묻기.
6. **준비도 게이트.** §6 차원이 구체화되기 전엔 STYLE.md·style.json 확정 금지.
7. **조기 종료 존중.** "알아서/그냥 만들어/충분해"라고 하면 즉시 멈추고, 분석 + 장르 기반 추천 기본값으로 §7 청사진을 확정해 읽어준 뒤 진행한다고 고지.

## 2. 스타일 의도 차원 (탑다운 순서 = S1~S7)

위에서부터 캔다. ✅=구체 확정 · ◻️=미정.

| # | 차원 | 무엇을 확정하나 | 비고 |
|---|---|---|---|
| **S1** | **매체·복잡도** ★맨 먼저 | 픽셀 vs 벡터(`medium`) + 티어(0 팔레트만·1 +폼·2 +셰이딩·3 풀가이드+무드) | `STY-SCOPE-DEFAULT-MINIMAL`·`STY-SCOPE-MEDIUM-GATE`. 디폴트 T0·픽셀. **T0이면 인터뷰 대부분 스킵, 팔레트만 정하고 청사진.** |
| **S2** | **무드·레퍼런스** | 한 문장 무드(밝은 야외/아늑한 던전/네온 밤/파스텔…) + 톤·STORY 정합. 사용자 레퍼런스 이미지 있으면 인제스트 | `STY-MOOD-MOOD-FROM-PALETTE`·`STY-SCOPE-GENRE-FIT`. IP 안전: 상용 게임 룩 복제 아닌 무드 관습만. |
| **S3** | **팔레트** | 재질 램프 키 + 역할색(player/enemy/danger/pickup) + 온도 대비 + 팔레트 크기 | `STY-PAL-RAMP`·`STY-PAL-ROLE-COLORS`·`STY-PAL-LIMITED`·`STY-SCOPE-PALETTE-BUDGET`. |
| **S4** | **비율·라인** | head_to_body(chibi/리얼)·실루엣·아웃라인 규칙·min_feature_px·display_px | `STY-FORM-PROPORTION`·`STY-FORM-OUTLINE-RULE`·`STY-FORM-SILHOUETTE-FIRST`. T1+. |
| **S5** | **셰이딩·조명** | 셰이딩 모델(cell/soft/flat)·ramp_steps·NW 광원·AO·림라이트 | `STY-SHADE-MODEL-PICK-ONE`·`STY-SHADE-LIGHT-DIR-NW`. T2+. |
| **S6** | **포스트FX·무드** | 동적 라이팅(ambient/point/fog) + 포스트FX(bloom/vignette/grade) + **Canvas 폴백** + FX 절제 | `STY-MOOD-LIGHTING-PRESET`·`STY-MOOD-POSTFX-PRESET`·`STY-MOOD-CANVAS-FALLBACK`·`STY-MOOD-FX-RESTRAINT`. T3만. |
| **S7** | **응집·검증** | 한 게임 한 스타일 확인 · 상속 체인(item/ability/HUD/juice) · lint-style 채택 · 작은 크기 가독 · render 정합 | `STY-SCOPE-ONE-STYLE`·`STY-PAL-SHARED-INHERIT`·`STY-FORM-READABLE-SMALL`·`STY-SCOPE-MEDIUM-RENDER-MATCH`. |

> **Tier 0이면 S1 직후 청사진으로 점프**(S2 무드 한 줄 + S3 팔레트만, S4~S6 스킵). Tier 1~2는 S3·S4·S5 가 핵심. Tier 3이면 S6(무드·라이팅·Canvas 폴백)이 가장 무겁다.

## 3. 라운드 진행 (deep-interview Phase 2 적응)

각 라운드는 `AskUserQuestion` 한 번(질문 1개)으로. 형식:

```
라운드 {n} | 타깃 차원: {S# 이름} | 왜 지금: {한 문장 근거} | 청사진 진행: {✅개수}/7

{Claude의 구체적 룩 제안·관점 1~2문장 — 아트 이론 + game-dna 장르 맥락 + 본인 비틀기·의견. 손에 그려지는 한 컷으로(매체 + 무드 + 핵심 색).}

{질문}
```

- 답을 받으면 그 차원을 ✅로, **다음으로 가장 약한 차원**(보통 탑다운 다음 칸)을 타깃해 다음 라운드로.
- 답이 모호하면 같은 차원을 **구체화 질문**으로 한 번 더 판다(추상→구체 매체/색/무드로 되묻기).
- 안티패턴 충돌이 감지되면 다음 질문은 **절충 되묻기**.

### 라운드 진행 리드아웃 (투명성)

매 라운드 끝에 한 줄로 청사진 상태를 보여준다:

```
청사진: S1 매체·복잡도 ✅(픽셀·T2) | S2 무드 ✅(아늑한 던전) | S3 팔레트 ◻️ | S4 비율·라인 ◻️ | S5 셰이딩·조명 ◻️ | S6 포스트FX ◻️ | S7 응집·검증 ◻️
다음 타깃 → S3(팔레트): 매체(픽셀)와 무드(아늑한 던전)가 섰으니, 어떤 색 램프·역할색이 그 무드를 만드는지가 다음입니다.
```

## 4. Claude가 구체적 룩을 먼저 제안한다 + 복잡도·매체는 사용자가 주도 (★이 인터뷰의 1순위 차별점)

사용자는 "어떤 스타일로 해야 할지" 막막하거나, 반대로 "리얼하게 화려하게"로 과설계·작은 화면 부적합을 부르기 쉽다.
그러니 **매 라운드 Claude가 먼저 구체적 룩을 한 컷으로 던지고**, 특히 **단순하게 갈지(팔레트만) 깊게 갈지(풀 가이드+무드)는
사용자가 고르게** 한다. 사용자의 흐름 그대로:
*"이 게임엔 이 정도 스타일이 맞아 보입니다(매체·티어 제안) → 이런 톤이면 이렇게 예뻐집니다(무드·핵심 색 한 컷), 괜찮나요?
→ 더 단순/화려한 결도 보여드릴까요?"*

### S1 매체·복잡도 루프 (가장 중요)

1. **디폴트 최소 제시.** "이 게임은 *제한 팔레트 하나*(T0)만 깔끔하게 잡아도 통일돼 예뻐 보입니다. 폼·셰이딩은 엔진 기본으로 충분할 수 있어요. 정말 더 필요할까요?" — 과설계를 먼저 막는다(`STY-SCOPE-DEFAULT-MINIMAL`).
2. **매체 가른다.** "픽셀(레트로·도트)로 갈까요, 벡터(매끈·그라디언트)로 갈까요? 작은 웹게임·이 장르엔 픽셀이 디폴트로 잘 맞습니다(생성·가독·응집)." game.js render 와 1:1 정합도 짚는다(`STY-SCOPE-MEDIUM-RENDER-MATCH`).
3. **장르 디폴트 한 칸 제안.** 필요하면: "이 장르(예: 던전 슈터)면 보통 *픽셀 + 셀 셰이딩 + 따뜻한 던전 무드*(T2~T3)가 잘 맞습니다. 한 칸 내려 팔레트+폼(T1)만 잡을 수도 있어요."
4. **반영 + 검증 + 대안.** 고르면 **"그럼 *이런 룩*이 됩니다"** 하고 구체 한 컷으로 되비춘 뒤 되묻는다: **"이 정도 깊이 괜찮으세요? 더 단순(팔레트만)하게도, 더 화려(라이팅+포스트FX T3)하게도 갈 수 있는데 어느 쪽이 끌리세요?"**

> 티어·매체가 바뀌면 이후 차원(팔레트·폼·셰이딩·무드)의 무게가 통째로 달라진다. T0이면 S2 무드 한 줄 + S3 팔레트만 채우고 바로 청사진으로 점프.

## 5. Claude의 제안 의무 — "구체적 룩을 먼저, 손에 그려지게"

제안 주도권은 Claude에게, 선택권은 사용자에게. **매 라운드 Claude가 먼저 구체적 매체/색/무드/대안을 제시**한다(백지 금지).

- **출처:** [INDEX](./INDEX.md)의 아트 이론 + game-dna 장르 맥락 + **본인의 창의적 비틀기**.
- **구체적으로.** 카테고리 라벨이 아니라 **손에 그려지는 한 컷**으로:
  - ❌ "무슨 분위기 원해요?"
  - ✅ "던전 탐험이니까 *아늑하지만 긴장되는* 톤은 어떨까요 — 차가운 보랏빛 돌 배경(stone 램프)에 따뜻한 횃불 광원(warm_light 램프)이 대비되는 'cozy-dungeon'. 어둠은 깊지만 횃불 주변은 포근하고, 위험은 붉게(danger) 떠 보입니다(`STY-PAL-WARM-COOL-CONTRAST`). 픽셀·셀 셰이딩·NW 광원으로 깔끔하게요. 제 추천은 이 쪽인데, 더 단순한 '밝은 파스텔 던전'(라이팅 없이도 예쁨)도 같이 올릴게요."
- **추천 + 한 컷 + 왜 좋은가(무드·가독·응집) + 본인 의견.** 첫 옵션에 "(추천)", "제 추천은 X입니다, 왜냐면 ~"으로 관점을 분명히.
- **다양성.** 매체·복잡도를 묻는 라운드에선 서로 다른 결(단순/중간/화려)을 섞어 노출.
- 요청에 이미 단서가 있으면 그 부분은 고정하고, 제안은 *그 안에서의 변주*로 좁힌다.

## 5.5. 챌린지 모드 (deep-interview Phase 3 적응 — 스타일용)

라운드가 쌓이면 관점을 바꿔 한 번씩 도발한다(각 1회). 룩을 날카롭게 만든다.

- **2라운드+ · Contrarian(반대로):** 과설계를 친다 — "정말 라이팅+포스트FX가 다 필요할까요? 작은 화면·짧은 세션에선 *제한 팔레트 + 실루엣*만으로도 충분히 예쁘고, WebGL 안 켜진 기기에선 무드가 통째로 사라집니다(R4). 무드를 빼면 뭐가 남나요?"(`STY-SCOPE-DEFAULT-MINIMAL`·`STY-MOOD-CANVAS-FALLBACK`)
- **4라운드+ · Simplifier(덜어내기):** 최소 팔레트를 묻는다 — "이 게임을 **딱 12색**으로 그린다면 어떤 램프들인가요? 그 제한이 오히려 응집을 줍니다(`STY-PAL-LIMITED`)."
- **5라운드+ · Signature Look(자랑할 한 룩):** 정체성을 묻는다 — "플레이어가 스크린샷을 봤을 때 *무엇 하나*로 '이 게임이다'를 알아챘으면 하나요? 그 한 룩(핵심 색 대비 + 실루엣 + 무드)이 이 게임의 정체성입니다."

각 모드는 한 번만 쓰고 일반 질문으로 복귀.

## 6. 준비도 체크 (게이트)

STYLE.md·style.json 확정 시작 조건:
- **S1(매체 + 티어) 확정** + **S2(무드 한 줄 + 톤 정합)** + **S3(master_palette 램프 + role_colors)** — 각각 한 문장으로 막힘없이 서술 가능.
- S4~S6 은 ✅이거나, 미정이면 **분석·장르 기반 추천 기본값**으로 확정(사용자에게 "이건 이렇게 기본값으로 갈게요" 고지).
- 안티패턴 충돌이 모두 해소(절충안 확정 — 매체 일관·render 정합·팔레트 크기·가독 무드·Canvas 폴백·과설계 축소).
- **Tier 0이면 "팔레트만"으로 즉시 완결**(STYLE.md 불필요, style.json `master_palette`·`role_colors`·`render` 만).

게이트 미달이면 가장 약한 차원으로 라운드를 더 돈다. 보통 **Tier 0~1은 1~3라운드, Tier 2는 3~5라운드, Tier 3은 5~7라운드**면 충족된다.

### 라운드 수 가이드 / 조기 종료
- 2라운드+부터 "충분/그냥 만들어"로 조기 종료 가능 — 단, 필수(S1·S2·S3)가 ◻️면 **추천 기본값을 채워 청사진을 완성**한 뒤 진행한다고 고지.
- 7라운드 soft 경고: "벌써 7라운드네요. 지금 청사진으로 진행할까요, 더 다듬을까요?"

## 7. 청사진(STYLE.md) 확정 & 빌드 라우팅 (deep-interview Phase 4·5 적응)

게이트 충족 시, **청사진을 한 화면으로 정리해 읽어주고 최종 확인**받은 뒤에만 `games/<slug>/STYLE.md` + `style.json` + `assets/palette.master.json` 작성을 시작한다.

### 확정 전 반드시 묻는 두 게이트
- **(make-game 적용)** 이 인터뷰가 web-game-builder/make-game 흐름에서 호출됐다면, 시작 전에 이미 **"스타일을 정할까요?"**로 진입 동의를 받았어야 한다. 받지 않았으면 지금 묻는다.
- **(복잡도·매체)** S1에서 **매체와 티어**를 명시적으로 확정했는지 청사진에 못 박는다(미정이면 디폴트는 픽셀 + 가장 낮은 합리적 티어).

### 청사진 형식 (응답 안 블록 — STYLE.md의 요약본)

```
## 스타일 청사진: {제목} (slug: {kebab-slug})

- **매체·복잡도 (S1):** medium {pixel|vector} · Tier {0~3} · game.js render 정합(pixelArt={..})
- **무드 (S2):** "{한 문장 무드}" ↔ STORY/톤·코어 동사와 같은 결(STY-MOOD-MOOD-FROM-PALETTE)
- **팔레트 (S3):** 램프 {키들} · role_colors{player/enemy/danger/pickup/ui_accent} · 온도 대비 · 총 {N}색
- **비율·라인 (S4):** head_to_body {1:x} · silhouette · outline {none|selective|full} · min_feature_px · display_px (T1+)
- **셰이딩·조명 (S5):** model {cell|soft|flat} · ramp_steps {2~3} · NW 광원 · AO 접지 (T2+)
- **포스트FX·무드 (S6):** lighting{ambient/point/fog} · postfx{bloom/vignette/grade} · **Canvas 폴백{overlay+pre_shade}** · FX 절제 (T3)
- **응집·상속 (S7):** 한 게임 한 스타일 · master_palette → palette.master.json → item §7/ability §8/HUD/juice 상속 · lint-style 채택 · 작은 크기 가독
- **IP 안전 메모:** 상용 게임 룩·이름·시그니처 미복제, 무드 관습만 차용, lintConfig.ip_redwords 검증
- **빌드 라우팅:** 런타임 → engine/stylekit.js · 에셋 생성 → (pixel)sprite-forge/sprite-picker (vector)vector-graphics · 라이팅 → lighting-mood · 포스트FX → screen-fx · HUD 색 → game-ui-hud · 파티클 색 → juice-fx · 검증 → lint-style.mjs + game-qa(Canvas 폴백)
```

확정 후:
1. 복잡도·매체에 맞는 **reference 도메인 파일 1~3개를 Read**해 원칙 근거를 반영(항상 style-scope.md 먼저).
2. `games/<slug>/STYLE.md` + `style.json` + `assets/palette.master.json` 을 [cohesion-tools.md](./cohesion-tools.md) 스펙으로 작성(단일 진실).
3. style.json → stylekit 배선(`StyleKit.load`·`applyLighting`/`applyPostFX`/`applyCanvasFallback`) + 에셋 visual.* 핸드오프 + 상속 체인 emit → **작성과 분리된 검수 패스**(`lint-style.mjs` + game-qa Canvas 폴백 + 작은 크기 수동 점검).
4. **확인을 받은 뒤에만** 코드를 배선하고 에셋을 생성한다.

## 8. 예시 (Good / Bad)

**라운드 1 — 탑다운: 매체·복잡도부터 (S1)**

```
라운드 1 | 타깃 차원: S1 매체·복잡도 | 왜 지금: 매체(픽셀/벡터)와 티어가 이후 모든 질문(색·폼·셰이딩·무드)의 어휘를 정하므로 맨 먼저 정합니다 | 청사진 진행: 0/7

분석해보니 이 게임은 *옆스크롤 점프* 플랫포머입니다. 사실 *제한 팔레트 하나 + 깔끔한 실루엣*(T0~T1)만으로도 통일돼 예뻐 보여요 — 라이팅/포스트FX는 던전·밤처럼 무드가 정체성일 때만 필요합니다. 매체는 작은 웹게임·이 장르엔 픽셀이 디폴트(생성·가독·응집)고, game.js render.pixelArt:true 와 맞춰야 뭉개지지 않습니다. 제 추천은 픽셀 + T1입니다.

스타일을 어느 정도로 정할까요? (매체: 픽셀(추천)/벡터 · 티어: 0 팔레트만 / 1 +폼·라인 / 2 +셰이딩 / 3 풀가이드+무드)
```

**라운드 4 — 추상답을 구체 팔레트/무드로 되묻기 (S3, 던전 무드 선택 시)**

```
라운드 4 | 타깃 차원: S3 팔레트 | 왜 지금: 매체(픽셀)와 무드(아늑한 던전)가 섰으니, 어떤 색 램프가 그 무드를 만드는지가 다음입니다 | 청사진 진행: 3/7

'아늑한 던전'이라고 하셨는데 그게 핵심입니다 — 다만 색을 아무거나 늘리면 응집이 깨집니다(STY-PAL-LIMITED). 제 추천은 차가운 stone 램프(보랏빛 돌, dark→light 4단) + 따뜻한 warm_light 램프(횃불, 주황→크림)의 온도 대비고, 역할색은 player=청록·danger=빨강으로 어둠 위에 떠 보이게요(STY-PAL-WARM-COOL-CONTRAST). 총 ~18색이면 통일되면서 충분합니다. hue-shift로 그림자는 차갑게·하이라이트는 따뜻하게 굽고요(STY-PAL-HUE-SHIFT).

팔레트를 어떻게 갈까요 — (a) 차가운 돌 + 따뜻한 횃불 대비, ~18색(추천) (b) 단색 모노톤(가장 단순) (c) 컬러풀 다채(밝은 톤)?
```
→ **반영:** "그럼 *stone(보라 4단) + warm_light(주황 4단) + flesh + 중립 2색 + 역할색 5색 ≈ 18색*으로, 어둠 속 횃불이 포근하게 떠 있는 던전이 됩니다. 이 master_palette가 아이템·능력·HUD·파티클 색의 단일 진실이 되고요(STY-PAL-SHARED-INHERIT)."
→ **검증+대안:** "이 정도 색 수 괜찮으세요? 더 줄여 12색 모노로도 멋지게 갈 수 있는데, 어느 쪽이 끌리세요?"

**왜 좋은가:** 탑다운(매체·복잡도 먼저), 약점 차원 하나만, "왜 지금" 명시, **단순/화려를 사용자가 직접** 고르게 하고 Claude가 구체 한 컷으로 *반영*하고 *대안*까지, 안티패턴(팔레트 폭발·render 불일치) 가드, 상속 체인 환기.

**Bad:** "스타일 어떻게 할까요? 1)픽셀 2)벡터 3)셀 4)소프트"만 던지기 — 추상 카테고리라 손에 안 그려지고, 복잡도·매체(S1)와 무드(S2)도 안 묻고 바로 셰이딩으로 점프(정신1 위반), 단순해도 된다는 안내도 없음(정신3 위반), 4문항 한 객관식(1문1답 위반).

## 9. 최종 체크리스트

- [ ] 탑다운: S1(매체·복잡도)부터 못 박고 아래로 내려갔는가
- [ ] **디폴트 최소(팔레트만 T0)를 먼저 제시**하고, 단순해도 된다고 적극 안내했는가(`STY-SCOPE-DEFAULT-MINIMAL`)
- [ ] **매체(픽셀/벡터)를 명시 확정**하고 game.js render 정합을 짚었는가(`STY-SCOPE-MEDIUM-RENDER-MATCH`)
- [ ] 한 라운드에 질문 하나(1문1답)
- [ ] 매 라운드 타깃 차원 + "왜 지금" 명시
- [ ] 매 라운드 Claude가 **구체적 룩(매체+무드+핵심 색)을 먼저** 한 컷으로 제안하고 본인 의견을 밝혔는가
- [ ] **S1에서 매체 + 티어를 사용자가 직접 확정**했는가 — ★반드시
- [ ] 한 게임 한 스타일(`STY-SCOPE-ONE-STYLE`), 매체·셰이딩·광원 방향을 섞지 않았는가
- [ ] 무드가 팔레트를 따르는가(`STY-MOOD-MOOD-FROM-PALETTE`), 무드가 가독성을 해치지 않는가(`STY-MOOD-FX-RESTRAINT`)
- [ ] 추상적 답("예쁘게/분위기 있게")은 구체 매체·색·무드로 되물어 구체화
- [ ] T3 라이팅/포스트FX를 쓰면 **Canvas 폴백을 반드시 확정**했는가(`STY-MOOD-CANVAS-FALLBACK` — R4)
- [ ] 안티패턴 충돌(과설계·매체 혼용·render 불일치·팔레트 폭발·가독 희생 무드)은 절충 되묻기로 해소
- [ ] 챌린지 모드(Contrarian/Simplifier/Signature Look)를 적절 라운드에 1회씩
- [ ] **make-game 적용 동의**를 받았는가(이 인터뷰가 make-game에서 호출된 경우)
- [ ] 준비도 게이트(S1 매체·티어 + S2 무드 + S3 팔레트) 후에만 STYLE.md·style.json 확정
- [ ] 청사진을 한 화면으로 읽어주고 최종 확인 후 STYLE.md + style.json + palette.master.json 작성, 상속 체인 emit
- [ ] 조기 종료("그냥 만들어") 시 장르 기반 추천 기본값으로 청사진 완성 후 진행
- [ ] **IP 안전:** 상용 게임 룩·이름·시그니처 미복제, 무드 관습만 차용(`lintConfig.ip_redwords` 검증)
