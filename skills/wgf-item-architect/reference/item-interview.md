# 아이템 설계 인터뷰 (Deep Interview 적응판 · 탑다운 · 복잡도 먼저 · 의도 주도)

> [`item-architect`](../SKILL.md)의 **'1) 의도 분석 + 아이템 인터뷰'** 단계를, **탑다운으로 모호성이 풀릴 때까지 끈질기게
> 묻는 1문1답 인터뷰**로 수행하는 플레이북.
> oh-my-claudecode `deep-interview`(Socratic 1문1답 + 약점 차원 타깃 + 챌린지 모드 + 준비도 게이팅)와
> [story-interview.md](../../wgf-story-architect/reference/story-interview.md)·[game-interview.md](../../wgf-web-game-builder/reference/game-interview.md)를
> **아이템 시스템 설계**에 적응시켰다.
> 차이: 게임 인터뷰가 *어떤 게임을*(메카닉) 만들지, 서사 인터뷰가 *어떤 이야기를* 입힐지를 캔다면, 이 인터뷰는
> *플레이어가 무엇을 습득·사용하고, 그것이 얼마나 복잡한가*를 캔다 — 그리고 **얼마나 단순해도 되는가**를 먼저 가른다.
>
> **언제 쓰나:** "아이템 넣어줘", "장비/포션 만들어줘", "빌드 짜는 재미 주고 싶어", "전리품 시스템"처럼 요청이 모호하거나
> 아래 차원이 비어 있을 때. 요청이 이미 구체적이면(복잡도·범주·획득·시너지·비주얼이 다 적혀 있으면) 인터뷰를 건너뛰고
> 바로 ITEMS.md를 설계한다.
>
> 자동 트리거 아님. SKILL.md '1) 의도 분석'에서 **온디맨드 Read** 로 부른다.

## 0. 이 인터뷰의 3대 정신

1. **복잡도를 먼저 못 박고 탑다운으로 내려간다.** 스킬 0단계(현재 게임 분석)가 끝난 상태에서 시작한다 — 코어 동사·장르·
   기존 아이템·톤·플랫폼을 이미 안다. 그 위에서 **이 게임에 아이템이 정말 필요한가, 얼마나 복잡한가(복잡도 티어 0~4)** 부터
   못 박고 → 정합 → 범주 → 이코노미 → 희귀도 → 시너지 → 특수기능 → 비주얼 → 밸런스 순으로 *좁혀* 내려간다.
   복잡도 티어가 어휘·범위·이후 모든 질문을 프레이밍한다 — 위가 흔들리면 아래를 물어도 소용없다(`SCOPE-DEFAULT-ZERO`).
2. **Claude가 먼저 *참신한* 아이템을 제안한다(백지 금지).** 빈 객관식("어떤 아이템 원해요?")을 던지지 않는다. 매 라운드
   game-dna 장르 맥락 + 아이템 이론으로 *이 게임의 이 코어 동사에 어울리는 참신한 아이템*을 구체적인 한 컷으로 먼저 제시하고
   의견을 밝힌다(§4·§5). 사용자는 고르거나 비틀거나 자유 입력. **단순하게 갈지 깊게 갈지는 사용자가 주도해 정한다(I1, 반드시 질문).**
3. **모호성이 풀릴 때까지 끈질기게 — 단, 단순함을 부끄러워하지 않는다.** 한 라운드 한 질문, 가장 약한 차원을 계속 캔다.
   추상적 답("좋은 아이템", "RPG처럼")은 **구체 사례로 되묻는다**("'RPG처럼' = 슬롯 장비 + 등급 + 인벤토리(T4)인가요,
   아니면 줍는 파워업 몇 개(T2)인가요? 1~3분 모바일 세션이면 후자가 훨씬 잘 맞습니다"). 목표는 *Claude가 만들기 편한 시스템*이
   아니라 **이 게임에 맞는, 몰입되는 아이템**이다 — 그게 0개일 수도 있다(`SCOPE-PROGRESSION-MIN`).

## 1. 핵심 원칙 (deep-interview에서 차용)

1. **1문1답.** 한 라운드에 질문 하나. 4개를 한 객관식에 욱여넣지 않는다. (단, I3 활성 범주, I6 시너지 archetype처럼 *여러 선택지지만 한 질문*인 경우만 multiSelect 허용.)
2. **약점 차원 타깃 + "왜 지금".** 매 라운드 가장 모호하거나 결정적인 차원 하나를 고르고, 왜 지금 이걸 묻는지 한 문장으로.
3. **가정을 드러낸다.** "뭘 원해요?" 대신 "무엇을 전제하나요?"를 묻는다. 추상적 답은 구체 아이템/수치로 되묻는다.
4. **Claude가 먼저 참신한 아이템을 제안(백지 금지).** 아이템 이론([item-design/](./item-design/INDEX.md)) + 게임 장르 기반. 첫 옵션에 "(추천)" + 근거. *그림이 그려지는 한 컷*으로(§5).
5. **안티패턴 가드.** [principles.md](./item-design/principles.md) §3 '섞지 말 것'(과설계·곱연산 폭발·지배전략·함정템·호딩함정·도박구조·softlock·등급 색단독·ludo 불협)을 내부 가드로. 충돌 의도면 절충 되묻기.
6. **준비도 게이트.** §6 차원이 구체화되기 전엔 ITEMS.md 확정 금지.
7. **조기 종료 존중.** "알아서/그냥 만들어/충분해"라고 하면 즉시 멈추고, 분석 + 장르 기반 추천 기본값으로 §7 청사진(ITEMS.md)을 확정해 읽어준 뒤 진행한다고 고지.

## 2. 아이템 의도 차원 (탑다운 순서)

위에서부터 캔다(복잡도 → 정합 → 범주 → 이코노미 → 희귀도 → 시너지 → 특수기능 → 비주얼 → 밸런스). ✅=구체 확정 · ◻️=미정.

| # | 차원 | 무엇을 확정하나 | 비고 |
|---|---|---|---|
| **I1** | **복잡도·범위** ★맨 먼저 | 아이템이 필요한가, 필요하면 복잡도 티어(0 무아이템·1 단일픽업·2 소수파워업·3 빌드시너지·4 인벤토리경제)와 **핵심 모델 1개** | `SCOPE-DEFAULT-ZERO`·`SCOPE-ONE-CORE`. 디폴트 0에서 한 칸씩 정당화. **여기서 T0/T1이면 인터뷰 대부분 스킵하고 바로 청사진.** |
| **I2** | **서사·장르·플랫폼 정합** | STORY.md 톤·코어동사·스캐폴드(platformer/shooter/arcade/puzzle/runner)·세션 길이에 핵심 모델이 맞는가 | `IDENT-LUDO-HARMONY`·`SCOPE-GENRE-FIT`·`SCOPE-PLATFORM-BUDGET`. ludonarrative 조화 게이트. |
| **I3** | **활성 범주** | 6범주(소모품·장비·키·재화·재료·코스메틱) 중 켤 2~3개 + 각 상한(슬롯·통화·등급·재료 종 수) | `CAT-SIX-BUCKET`·`CAT-SCOPE-FIT`. "RPG처럼 다 넣자" 가드. 7번째 misc 금지. multiSelect 한 질문 허용. |
| **I4** | **이코노미 & 획득** | faucet/sink·파워커브·통화 1종·드랍 결정성 vs 가변비율·천장 필요 여부 | `ECON-FAUCET-SINK`·`ECON-CURVE`·`ECON-VARIABLE-RATIO`·`ECON-PITY`. 랜덤드랍/수집/가챠 신호 잡히면 몬테카를로 툴 온디맨드 예고. |
| **I5** | **희귀도 & 등급** | 등급 수(3~4)·등급=슬롯폭인가 수치인가·legendary 수작업 개수·다채널 시각 신호 | `AFX-RARITY-LADDER`·`AFX-RARITY-MEANS-MORE`·`AFX-LEGENDARY`. 표준 색 상속(학습비용 0). T≥3에서만. |
| **I6** | **시너지 & 빌드** | archetype 몇 개·곱산 소스 몇 종·슬롯 수·진화/세트 유무·지배전략/함정 가드 | `SYN-ENABLER-PAYOFF`·`SYN-ADD-VS-MULT`·`SYN-SLOT-SCARCITY`. **T≥3에서만 깊게.** multiSelect 허용. |
| **I7** | **특수기능 & 진행 게이트** | 키/능력 아이템·새 동사 부여·소모품 모델(재충전 vs 쿨다운 vs 소모)·게이트 그래프·softlock 방지 | `UTIL-VERB-NOT-STAT`·`UTIL-COOLDOWN-GATE`·`UTIL-LOCK-KEY`·`UTIL-NO-SOFTLOCK`. |
| **I8** | **비주얼 & 정체성** | signature 아이템 4요소(이름·실루엣·flavor·동사)·테마 패밀리·스타일가이드 헤더 상수·**비주얼 슬롯 채움(이미지 핸드오프 준비)** | `IDENT-MICRO-CHARACTER`·`UX-SILHOUETTE-FIRST`·`UX-DESC-SLOTS`·`IDENT-THEME-FAMILY`. |
| **I9** | **밸런스 & 검증** | validator linter 채택·EV/몬테카를로 필요 여부·"안써도/항상써도 클리어 가능?" 수동 테스트·픽률 카운터 | `SYN-NO-DOMINANT`·`SYN-NO-TRAP`·`SYN-METRICS`. |

> **Tier 0~1이면 I1 직후 청사진으로 점프**(I3~I9 대부분 추천 기본값). Tier 2는 I3·I7·I8이 핵심. Tier 3~4면 I6·I8이 가장 무겁다.
> 갈등·전투 약한 게임이면 I5·I6은 가벼워지고 I8(코스메틱·수집 로어)이 주가 될 수 있다.

## 3. 라운드 진행 (deep-interview Phase 2 적응)

각 라운드는 `AskUserQuestion` 한 번(질문 1개)으로. 형식:

```
라운드 {n} | 타깃 차원: {I# 이름} | 왜 지금: {한 문장 근거} | 청사진 진행: {✅개수}/9

{Claude의 참신한 제안·관점 1~2문장 — 아이템 이론 + game-dna 장르 맥락 + 본인 비틀기·의견. 그림이 그려지는 한 컷으로.}

{질문}
```

- 답을 받으면 그 차원을 ✅로, **다음으로 가장 약한 차원**(보통 탑다운 다음 칸)을 타깃해 다음 라운드로.
- 답이 모호하면 같은 차원을 **구체화 질문**으로 한 번 더 판다(추상→구체 아이템/수치로 되묻기).
- 안티패턴 충돌이 감지되면 다음 질문은 **절충 되묻기**.

### 라운드 진행 리드아웃 (투명성)

매 라운드 끝에 한 줄로 청사진 상태를 보여준다:

```
청사진: I1 복잡도 ✅(T2) | I2 정합 ✅ | I3 범주 ◻️ | I4 이코노미 ◻️ | I5 희귀도 ◻️ | I6 시너지 ◻️ | I7 특수기능 ◻️ | I8 비주얼 ◻️ | I9 밸런스 ◻️
다음 타깃 → I3(활성 범주): 복잡도(T2 소수 파워업)와 정합이 섰으니, 6범주 중 무엇을 켜느냐가 카탈로그 크기를 정합니다.
```

## 4. Claude가 참신한 아이템을 먼저 제안한다 + 복잡도는 사용자가 주도 (★이 인터뷰의 1순위 차별점)

사용자는 "아이템을 어떻게 짜야 할지" 막막하거나, 반대로 "RPG처럼 다 넣어줘"로 과설계를 부르기 쉽다. 그러니 **매 라운드 Claude가
먼저 참신한 아이템을 한 컷으로 던지고**, 특히 **단순하게 갈지 깊게 갈지는 사용자가 고르게** 한다. 사용자의 흐름 그대로:
*"이 게임엔 이 정도가 맞아 보입니다(복잡도 제안) → 이런 아이템이면 이렇게 재밌어집니다, 괜찮나요? → 더 단순/복잡한 결도 보여드릴까요?"*

### I1 복잡도 4단계 루프 (가장 중요)

1. **디폴트 0 제시 (default zero).** "이 게임은 코어 동사가 *{동사}*라 아이템 없이 점수·해금만으로도 완결됩니다(T0). 정말 아이템이 필요할까요?" — 과설계를 먼저 막는다(`SCOPE-DEFAULT-ZERO`·`SCOPE-PROGRESSION-MIN`).
2. **장르 디폴트 한 칸 제안 (one step).** 필요하다면 장르 정합 디폴트를 제시: "이 장르(예: 러너)면 보통 *순간 픽업(자석·실드) + 코인*(T2)이 가장 잘 맞습니다. 한 칸 더 올려 빌드 시너지(T3)까지 갈 수도 있어요."
3. **반영 (reflect).** 사용자가 고르면 → **"그럼 *이런 아이템들*이 됩니다"** 하고 구체적인 한 컷으로 되비춘다(막연한 카테고리 금지, 그림이 그려지게 — 예: "달리며 줍는 *자석 코어*(코인 흡인 6초) + *깃털 부적*(다음 1회 추락 무효)").
4. **검증 + 대안 (validate + alternatives).** 곧바로 되묻는다: **"이 정도 복잡도 괜찮으세요? 더 단순(코인 1개)하게도, 더 깊게(줍는 것마다 빌드가 바뀌는 T3)도 갈 수 있는데 어느 쪽이 끌리세요?"** 본인 의견·참신함을 적극 개진.

> 복잡도가 바뀌면 이후 차원(범주·시너지)의 무게가 통째로 달라진다. T0/T1이면 §6 게이트만 채우고 바로 청사진으로 점프한다.

## 5. Claude의 제안 의무 — "참신한 아이템을 먼저, 구체적으로"

제안 주도권은 Claude에게, 선택권은 사용자에게. **매 라운드 Claude가 먼저 구체적 아이템/대안을 제시**한다(백지 금지).

- **출처:** [item-design/](./item-design/INDEX.md)의 아이템 이론 + game-dna 장르 맥락 + **본인의 창의적 비틀기**.
- **구체적으로.** 카테고리 라벨이 아니라 **그림이 그려지는 한 컷**으로:
  - ❌ "장비 시스템 어떠세요?"
  - ✅ "탑다운 슈터니까 *무기=색*으로 묶는 빌드는 어떨까요 — *불꽃 칩*(탄에 화상 도트) + *불쏘시개 부적*(화상 대상 처치 시 폭발)이 만나면 화면을 태우는 연쇄가 터지는. payoff(불 빌드) 1개 + enabler 2~3개 구조라 '한 판 더'가 자연스럽고(`SYN-ENABLER-PAYOFF`), 색=무기 매핑이라 아이콘도 명료합니다. 제 추천은 이 쪽인데, 더 단순한 '주우면 즉시 강해지는 패시브'도 같이 올릴게요."
- **추천 + 한 컷 + 왜 재밌나/몰입되나 + 본인 의견.** 첫 옵션에 "(추천)", "제 추천은 X입니다, 왜냐면 ~"으로 관점을 분명히.
- **다양성.** 복잡도·범주를 묻는 라운드에선 서로 다른 결(단순/중간/깊음)을 섞어 노출.
- 요청에 이미 단서가 있으면 그 부분은 고정하고, 제안은 *그 안에서의 변주*로 좁힌다.

## 5.5. 챌린지 모드 (deep-interview Phase 3 적응 — 아이템용)

라운드가 쌓이면 관점을 바꿔 한 번씩 도발한다(각 1회). 아이템 시스템을 날카롭게 만든다.

- **2라운드+ · Contrarian(반대로):** 과설계를 친다 — "정말 이 아이템들이 다 필요할까요? 1~3분 세션에 등급+접사+제작을 넣으면 한 판에 다 못 보고 끝납니다. *핵심 모델 하나*로 줄이면 뭐가 남나요?"(`SCOPE-ONE-CORE`)
- **4라운드+ · Simplifier(덜어내기):** 최소 버전을 묻는다 — "이 시스템에서 **딱 3개 아이템**만 남긴다면 뭔가요? 그 셋만으로도 '획득하는 재미'가 서나요?"(카탈로그 정련, `SYN-MINIMAL-CATALOG`)
- **5라운드+ · Signature Item(자랑할 한 아이템):** 정체성을 묻는다 — "플레이어가 *어떤 아이템*을 주웠을 때 '오!' 하고 멈췄으면 하나요? 그 한 아이템(이름+실루엣+flavor+부여 동사)이 이 시스템의 정체성입니다(`IDENT-MICRO-CHARACTER`)."

각 모드는 한 번만 쓰고 일반 질문으로 복귀.

## 6. 준비도 체크 (게이트)

ITEMS.md 확정 시작 조건:
- **I1(복잡도 티어 + 핵심 모델 1개) 확정** + **I2(ludo·장르·플랫폼 정합)** + **I3(활성 범주 2~3개 명시)** — 각각 한 문장으로 막힘없이 서술 가능.
- I4~I9는 ✅이거나, 미정이면 **분석·장르 기반 추천 기본값**으로 확정(사용자에게 "이건 이렇게 기본값으로 갈게요" 고지).
- 안티패턴 충돌이 모두 해소(절충안 확정 — 곱연산 캡·지배전략 가드·과설계 축소 등).
- **Tier 0이면 "아이템 시스템 없음"으로 즉시 완결**(ITEMS.md 불필요, 점수·해금으로 진행감).

게이트 미달이면 가장 약한 차원으로 라운드를 더 돈다. 보통 **Tier 0~1은 1~2라운드, Tier 2는 3~4라운드, Tier 3~4는 4~7라운드**면 충족된다.

### 라운드 수 가이드 / 조기 종료
- 2라운드+부터 "충분/그냥 만들어"로 조기 종료 가능 — 단, 필수(I1·I2·I3)가 ◻️면 **추천 기본값을 채워 청사진을 완성**한 뒤 진행한다고 고지.
- 8라운드 soft 경고: "벌써 8라운드네요. 지금 청사진으로 진행할까요, 더 다듬을까요?"

## 7. 청사진(ITEMS.md) 확정 & 빌드 라우팅 (deep-interview Phase 4·5 적응)

게이트 충족 시, **청사진을 한 화면으로 정리해 읽어주고 최종 확인**받은 뒤에만 `games/<slug>/ITEMS.md` + `items.json` 작성을 시작한다.

### 확정 전 반드시 묻는 두 게이트
- **(make-game 적용)** 이 인터뷰가 web-game-builder/make-game 흐름에서 호출됐다면, 시작 전에 이미 **"아이템 시스템을 만들까요?"**로 진입 동의를 받았어야 한다. 받지 않았으면 지금 묻는다.
- **(복잡도)** I1에서 **복잡도 티어와 핵심 모델 1개**를 명시적으로 확정했는지 청사진에 못 박는다(미정이면 디폴트는 장르 정합 모델 + 가장 낮은 합리적 티어).

### 청사진 형식 (응답 안 블록 — ITEMS.md의 요약본)

```
## 아이템 청사진: {제목} (slug: {kebab-slug})

- **복잡도 (I1):** Tier {0~4} · 핵심 모델 1개 {상태파워업 | 누적픽업+빌드 | 보드부스터 | 순간픽업 | 인벤토리경제} (+표현/메타층 0~2개)
- **정합 (I2):** 코어 동사 {동사} ↔ 효과가 같은 말을 한다(GN/IDENT-LUDO-HARMONY) · 플랫폼·세션 적합
- **활성 범주 (I3):** {소모품/장비/키/재화/재료/코스메틱 중 2~3개} + 각 상한(슬롯 N·통화 1·등급 N·재료 N종)
- **이코노미 (I4):** faucet/sink {…} · 파워커브 {곡선식} · 드랍 {결정성|가변비율(+천장 N)}
- **희귀도 (I5):** 등급 {N단계, 색} · 등급=슬롯폭|수치 · legendary {수작업 N개} (T≥3만)
- **시너지 (I6):** payoff {1~2} + enabler {2~3} archetype · 곱산 소스 {0~2 격리} · 슬롯 {N} · 진화/세트 {유무} (T≥3만)
- **특수기능 (I7):** 키/능력 {부여 동사} · 소모품 모델 {재충전|쿨다운|소모} · 게이트 그래프 {유무} · softlock 방지
- **비주얼 (I8):** signature 아이템 {이름·실루엣·flavor·동사} · 테마 패밀리 {…} · 스타일가이드 헤더 상수 · visual.* 슬롯 채움
- **밸런스 (I9):** lint-items.mjs 채택 · 수동 "안써도/항상써도 클리어?" · 픽률 카운터
- **IP 안전 메모:** 오리지널 아이템 이름·외형(Glossary), 상용 게임 미복제, loot box/gacha 차용 안 함
- **빌드 라우팅:** 아이콘 → sprite-forge/vector-graphics/sprite-picker · 인벤·툴팁 → game-ui-hud · 획득 연출 → juice-fx/chip-sound · flavor → story-architect · 검증 → lint-items.mjs + game-qa
```

확정 후:
1. 복잡도·장르에 맞는 **item-design 도메인 파일 1~3개를 Read**해 원칙 근거를 반영(항상 principles.md + scope-complexity.md 먼저).
2. `games/<slug>/ITEMS.md` + `items.json` 를 [consistency-tools.md](./item-design/consistency-tools.md) 스펙으로 작성(단일 진실, visual.* 슬롯 채움).
3. items.json → game.js 연결 + 아이콘 핸드오프(SKILL.md 4단계) → **작성과 분리된 검수 패스**(SKILL.md 5단계: `lint-items.mjs` + 수동).
4. **확인을 받은 뒤에만** 코드를 짜고 아이콘을 생성한다.

## 8. 예시 (Good / Bad)

**라운드 1 — 탑다운: 복잡도부터 (I1)**

```
라운드 1 | 타깃 차원: I1 복잡도·범위 | 왜 지금: 아이템이 필요한지·얼마나 복잡한지가 이후 모든 질문(범주·시너지·인벤)을 프레이밍하므로 맨 먼저 정합니다 | 청사진 진행: 0/9

분석해보니 이 게임은 *끝없이 달리는* 러너입니다. 사실 아이템 없이 코인+점수만으로도 충분히 완결돼요(T0~T1). 다만 '획득하는 재미'를
주고 싶다면 *순간 픽업*(자석 코어·깃털 부적 같은 짧은 버프)이 러너의 즉시성과 가장 잘 맞습니다(T2). 더 가면 줍는 것마다 빌드가
바뀌는 불릿헤븐형(T3)도 가능하지만, 1~3분 세션엔 T2가 안전합니다. 제 추천은 T2입니다.

이 게임에 아이템을 어느 정도로 둘까요? (0: 없음·점수만 / 1: 코인 한 종류 / 2: 줍는 파워업 몇 개(추천) / 3: 빌드 시너지 / 4: 인벤토리·장비·등급)
```

**라운드 4 — 추상답을 구체 시너지로 되묻기 (I6, T3 선택 시)**

```
라운드 4 | 타깃 차원: I6 시너지·빌드 | 왜 지금: 복잡도(T3 빌드)와 범주(장비+패시브)가 섰으니, 무엇이 무엇과 곱해지느냐가 '한 판 더'를 만듭니다 | 청사진 진행: 4/9

'조합하면 강해지게'라고 하셨는데, 그게 핵심입니다 — 다만 곱연산을 아무 데나 풀면 빌드가 폭발합니다(`SYN-ADD-VS-MULT`). 제 추천은
payoff 1개(*얼음 빌드*: 적을 얼림) + enabler 2~3개(이동속도 시 냉기 방출 / 얼린 적 처치 시 파편 확산)로 묶고, 곱산은 *한 종*(빙결 피해 ×)만
희소하게 두는 구조입니다. 그러면 "얼음 빌드를 노리고 모으는" 동기가 생기죠.

시너지를 어떻게 둘까요 — (a) payoff 1 + enabler 2~3, 곱산 1종 격리(추천) (b) 가산 스택만(단순·안전) (c) 세트 보너스(특정 N개 모으면 발동)?
```
→ **반영:** "그럼 *얼음 payoff 1개 + 냉기 enabler 3개 + 빙결피해 곱산 1개(캡 있음)*로, 한 판에 얼음 빌드를 완성하는 맛이 납니다. 슬롯은 4개로 둬서 기회비용을 만들고요(`SYN-SLOT-SCARCITY`)."
→ **검증+대안:** "이 깊이 괜찮으세요? 부담되면 (b) 가산만으로도 충분히 재밌게 만들 수 있는데, 어느 쪽이 끌리세요?"

**왜 좋은가:** 탑다운(복잡도 먼저), 약점 차원 하나만, "왜 지금" 명시, **단순/깊음을 사용자가 직접** 고르게 하고 Claude가 구체적 한 컷으로 *반영*하고 *대안*까지 던짐, 안티패턴(곱연산 폭발) 가드.

**Bad:** "아이템 어떻게 할까요? 1)장비 2)포션 3)등급 4)제작"만 던지기 — 추상 카테고리라 그림이 안 그려지고, 복잡도(I1)도 안 묻고 바로 범주로 점프(정신1 위반), 단순해도 된다는 안내도 없음(정신3 위반), 4문항 한 객관식(1문1답 위반).

## 9. 최종 체크리스트

- [ ] 탑다운: I1(복잡도·범위)부터 못 박고 아래로 내려갔는가
- [ ] **디폴트 0을 먼저 제시**하고, 단순해도 된다고 적극 안내했는가(`SCOPE-DEFAULT-ZERO`)
- [ ] 한 라운드에 질문 하나(1문1답) — I3 범주/I6 시너지만 multiSelect 한 질문 허용
- [ ] 매 라운드 타깃 차원 + "왜 지금" 명시
- [ ] 매 라운드 Claude가 **참신한 아이템을 먼저** 구체적 한 컷으로 제안하고 본인 의견을 밝혔는가
- [ ] **I1에서 복잡도 티어 + 핵심 모델 1개를 사용자가 직접 확정**했는가 — ★반드시
- [ ] 핵심 모델은 **하나만**(`SCOPE-ONE-CORE`), 한 게임에 모델 중복 안 했는가
- [ ] 효과가 코어 동사·주제와 같은 말을 하는가(`IDENT-LUDO-HARMONY`) — 준비도 게이트
- [ ] 추상적 답("좋은 아이템/RPG처럼")은 구체 아이템·티어·수치로 되물어 구체화
- [ ] 안티패턴 충돌(과설계·곱연산 폭발·지배전략·호딩함정·softlock·도박구조)은 절충 되묻기로 해소
- [ ] 챌린지 모드(Contrarian/Simplifier/Signature Item)를 적절 라운드에 1회씩
- [ ] **make-game 적용 동의**를 받았는가(이 인터뷰가 make-game에서 호출된 경우)
- [ ] 준비도 게이트(I1 복잡도+핵심모델 + I2 정합 + I3 범주) 후에만 ITEMS.md 확정
- [ ] 청사진을 한 화면으로 읽어주고 최종 확인 후 ITEMS.md + items.json 작성, visual.* 슬롯 채움
- [ ] 조기 종료("그냥 만들어") 시 장르 기반 추천 기본값으로 청사진 완성 후 진행
