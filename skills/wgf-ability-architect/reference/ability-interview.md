# 능력 설계 인터뷰 (Deep Interview 적응판 · 탑다운 · 복잡도 먼저 · 의도 주도)

> [`ability-architect`](../SKILL.md)의 **'1) 의도 분석 + 능력 인터뷰'** 단계를, **탑다운으로 모호성이 풀릴 때까지 끈질기게
> 묻는 1문1답 인터뷰**로 수행하는 플레이북.
> oh-my-claudecode `deep-interview`(Socratic 1문1답 + 약점 차원 타깃 + 챌린지 모드 + 준비도 게이팅)와
> [item-interview.md](../../wgf-item-architect/reference/item-interview.md)·[story-interview.md](../../wgf-story-architect/reference/story-interview.md)를
> **캐릭터 능력 시스템 설계**에 적응시켰다.
> 차이: 게임 인터뷰가 *어떤 게임을*(메카닉), 서사 인터뷰가 *어떤 이야기를*, 아이템 인터뷰가 *무엇을 습득·사용하는가*를
> 캔다면, 이 인터뷰는 *캐릭터가 무엇을 할 수 있고, 그 능력이 어떻게 자라고(획득) 조합되고(시너지) 쓰이는가(사용)*를 캔다
> — 그리고 **얼마나 단순해도 되는가**를 먼저 가른다.
>
> **용어:** "스킬/능력"은 **게임 캐릭터의 능력**(대시·파이어볼·궁극기). Claude 스킬과 무관. 사용자와 헷갈릴 여지가 있으면 "능력"으로 부른다.
>
> **언제 쓰나:** "스킬 넣어줘", "대시 만들어줘", "스킬트리 짜줘", "콤보로 잇는 재미", "조합하면 강해지는 빌드"처럼 요청이
> 모호하거나 아래 차원이 비어 있을 때. 요청이 이미 구체적이면(복잡도·킷·자원·시너지·비주얼이 다 적혀 있으면) 인터뷰를
> 건너뛰고 바로 ABILITIES.md를 설계한다.
>
> 자동 트리거 아님. SKILL.md '1) 의도 분석'에서 **온디맨드 Read** 로 부른다.

## 0. 이 인터뷰의 3대 정신

1. **복잡도를 먼저 못 박고 탑다운으로 내려간다.** 스킬 0단계(현재 게임 분석)가 끝난 상태에서 시작한다 — 코어 동사·장르·
   기존 입력/능력·톤·플랫폼·버튼 예산을 이미 안다. 그 위에서 **이 게임에 능력이 정말 필요한가, 얼마나 복잡한가(티어 0~4)** 부터
   못 박고 → 정합 → 킷 → 자원 → 발동 → 진행 → 시너지 → 게이트 → 정체성 → 밸런스 순으로 *좁혀* 내려간다.
   복잡도 티어가 어휘·범위·이후 모든 질문을 프레이밍한다 — 위가 흔들리면 아래를 물어도 소용없다(`SCOPE-DEFAULT-MINIMAL`).
2. **Claude가 먼저 *참신한* 능력·콤보를 제안한다(백지 금지).** 빈 객관식("어떤 스킬 원해요?")을 던지지 않는다. 매 라운드
   game-dna 장르 맥락 + 능력 이론으로 *이 게임의 이 코어 동사에 어울리는 참신한 능력*을 구체적인 한 컷으로 먼저 제시하고
   의견을 밝힌다(§4·§5). 사용자는 고르거나 비틀거나 자유 입력. **단순하게 갈지 깊게 갈지는 사용자가 주도해 정한다(A1, 반드시 질문).**
3. **모호성이 풀릴 때까지 끈질기게 — 단, 단순함을 부끄러워하지 않는다.** 한 라운드 한 질문, 가장 약한 차원을 계속 캔다.
   추상적 답("멋진 스킬", "RPG처럼")은 **구체 사례로 되묻는다**("'RPG처럼' = 스킬트리 + 다자원 + 리스펙(T4)인가요, 아니면
   쿨다운 액티브 3개(T2)인가요? 1~3분 모바일 세션이면 후자가 훨씬 잘 맞습니다"). 목표는 *Claude가 만들기 편한 킷*이 아니라
   **이 게임에 맞는, 쓰는 맛이 나는 능력**이다 — 그게 대시 1개일 수도 있다(`SCOPE-PROGRESSION-MIN`).

## 1. 핵심 원칙 (deep-interview에서 차용)

1. **1문1답.** 한 라운드에 질문 하나. 4개를 한 객관식에 욱여넣지 않는다. (단, A3 킷 구성, A7 시너지 archetype처럼 *여러 선택지지만 한 질문*인 경우만 multiSelect 허용.)
2. **약점 차원 타깃 + "왜 지금".** 매 라운드 가장 모호하거나 결정적인 차원 하나를 고르고, 왜 지금 이걸 묻는지 한 문장으로.
3. **가정을 드러낸다.** "뭘 원해요?" 대신 "무엇을 전제하나요?"를 묻는다. 추상적 답은 구체 능력/수치/콤보로 되묻는다.
4. **Claude가 먼저 참신한 능력을 제안(백지 금지).** 능력 이론([ability-design/](./ability-design/INDEX.md)) + 게임 장르 기반. 첫 옵션에 "(추천)" + 근거. *손에 그려지는 한 컷*으로(§5).
5. **안티패턴 가드.** [principles.md](./ability-design/principles.md) §3 '섞지 말 것'(과설계·곱연산 폭발·무한콤보·지배능력·죽은능력·무비용 스팸·버튼 폭발·softlock·가짜 선택·ludo 불협)을 내부 가드로. 충돌 의도면 절충 되묻기.
6. **준비도 게이트.** §6 차원이 구체화되기 전엔 ABILITIES.md 확정 금지.
7. **조기 종료 존중.** "알아서/그냥 만들어/충분해"라고 하면 즉시 멈추고, 분석 + 장르 기반 추천 기본값으로 §7 청사진(ABILITIES.md)을 확정해 읽어준 뒤 진행한다고 고지.

## 2. 능력 의도 차원 (탑다운 순서)

위에서부터 캔다. ✅=구체 확정 · ◻️=미정.

| # | 차원 | 무엇을 확정하나 | 비고 |
|---|---|---|---|
| **A1** | **복잡도·범위** ★맨 먼저 | 능력이 필요한가, 필요하면 티어(0 없음·1 단일·2 소수액티브·3 빌드/콤보·4 스킬트리)와 **핵심 모델 1개** | `SCOPE-DEFAULT-MINIMAL`·`SCOPE-ONE-CORE`. 디폴트 0~1에서 한 칸씩. **T0/T1이면 인터뷰 대부분 스킵하고 바로 청사진.** |
| **A2** | **서사·장르·플랫폼 정합** | STORY.md 톤·코어동사·스캐폴드·세션·버튼예산에 핵심 모델이 맞는가 | `IDENT-LUDO-HARMONY`·`SCOPE-GENRE-FIT`·`SCOPE-PLATFORM-BUDGET`·`UX-BUTTON-BUDGET`. |
| **A3** | **킷·역할 구성** | 활성 kind(액티브/패시브/이동기/궁극기/리액션) + 역할 분담(주력/생존/이동/CC/버프) + 입력 타입 | `KIT-FIVE-KIND`·`KIT-ROLE-SPREAD`·`KIT-INPUT-TYPE`. "다 넣자" 가드. multiSelect 한 질문 허용. |
| **A4** | **자원·비용** | 쿨다운만/마나·스태미나/충전 중 한 종 · 기회비용 · 리젠 균형 | `RES-RESOURCE-PICK-ONE`·`RES-OPPORTUNITY-COST`·`RES-REGEN-BALANCE`. T2+. |
| **A5** | **발동·게임필** | 즉발 vs 차지/조준 · 선딜/후딜 · 텔레그래프 · 캔슬/콤보 윈도 · 모바일 입력 | `FEEL-ANTICIPATION`·`FEEL-TELEGRAPH`·`FEEL-BUFFER`·`FEEL-COYOTE-CANCEL`. |

| **A8** | **능력 게이트** | 새 동사로 잠긴 곳 열기(메트로배니아) · 게이트 그래프 · 자물쇠 먼저 · softlock 방지 | `GATE-VERB-KEY`·`GATE-SHOW-LOCK-FIRST`·`GATE-NO-SOFTLOCK`. 탐험/진행 게이트 있을 때만. |

## 3. 라운드 진행 (deep-interview Phase 2 적응)

각 라운드는 `AskUserQuestion` 한 번(질문 1개)으로. 형식:

```
라운드 {n} | 타깃 차원: {A# 이름} | 왜 지금: {한 문장 근거} | 청사진 진행: {✅개수}/10

{Claude의 참신한 제안·관점 1~2문장 — 능력 이론 + game-dna 장르 맥락 + 본인 비틀기·의견. 손에 그려지는 한 컷으로(능력 + 어떻게 콤보/시너지가 터지나).}

{질문}
```

- 답을 받으면 그 차원을 ✅로, **다음으로 가장 약한 차원**(보통 탑다운 다음 칸)을 타깃해 다음 라운드로.
- 답이 모호하면 같은 차원을 **구체화 질문**으로 한 번 더 판다(추상→구체 능력/수치/콤보로 되묻기).
- 안티패턴 충돌이 감지되면 다음 질문은 **절충 되묻기**.

### 라운드 진행 리드아웃 (투명성)

매 라운드 끝에 한 줄로 청사진 상태를 보여준다:

```
청사진: A1 복잡도 ✅(T2) | A2 정합 ✅ | A3 킷 ◻️ | A4 자원 ◻️ | A5 게임필 ◻️ | A6 진행 ◻️ | A7 시너지 ◻️ | A8 게이트 ◻️ | A9 정체성 ◻️ | A10 밸런스 ◻️
다음 타깃 → A3(킷·역할): 복잡도(T2 소수 액티브)와 정합이 섰으니, 어떤 kind·역할을 켜느냐가 킷 크기를 정합니다.
```

## 4. Claude가 참신한 능력을 먼저 제안한다 + 복잡도는 사용자가 주도 (★이 인터뷰의 1순위 차별점)

사용자는 "스킬을 어떻게 짜야 할지" 막막하거나, 반대로 "디아블로처럼 다 넣어줘"로 과설계를 부르기 쉽다. 그러니 **매 라운드 Claude가
먼저 참신한 능력을 한 컷으로 던지고**, 특히 **단순하게 갈지 깊게 갈지는 사용자가 고르게** 한다. 사용자의 흐름 그대로:
*"이 게임엔 이 정도가 맞아 보입니다(복잡도 제안) → 이런 능력이면 이렇게 재밌어집니다(콤보/시너지 한 컷), 괜찮나요? → 더 단순/복잡한 결도 보여드릴까요?"*

### A1 복잡도 4단계 루프 (가장 중요)

1. **디폴트 최소 제시.** "이 게임은 코어 동사가 *{동사}*라 능력 없이/대시 하나로도 깊게 완결됩니다(T0~T1). 정말 더 필요할까요?" — 과설계를 먼저 막는다(`SCOPE-DEFAULT-MINIMAL`).
2. **장르 디폴트 한 칸 제안.** 필요하면 장르 정합 디폴트: "이 장르(예: 트윈스틱 슈터)면 보통 *쿨다운 액티브 2~3개 + 대시*(T2)가 가장 잘 맞습니다. 한 칸 더 올려 빌드 드래프트(T3)까지 갈 수도 있어요."
3. **반영.** 사용자가 고르면 → **"그럼 *이런 능력들*이 됩니다"** 하고 구체적인 한 컷으로 되비춘다(막연한 카테고리 금지 — 예: "쿨다운 *그림자 대시*(0.4초 무적 이동) + *기력 폭발*(주변 적 넉백) + 충전형 *조준 사격*. 대시로 적 사이를 파고들어 폭발로 모으고 조준샷으로 정리하는 흐름").
4. **검증 + 대안.** 곧바로 되묻는다: **"이 정도 복잡도 괜찮으세요? 더 단순(대시 1개)하게도, 더 깊게(주울 때마다 빌드가 바뀌는 T3)도 갈 수 있는데 어느 쪽이 끌리세요?"** 본인 의견·참신함을 적극 개진.

> 복잡도가 바뀌면 이후 차원(킷·자원·시너지·진행)의 무게가 통째로 달라진다. T0/T1이면 §6 게이트만 채우고 바로 청사진으로 점프한다.

## 5. Claude의 제안 의무 — "참신한 능력·콤보를 먼저, 구체적으로"

제안 주도권은 Claude에게, 선택권은 사용자에게. **매 라운드 Claude가 먼저 구체적 능력/콤보/대안을 제시**한다(백지 금지).

- **출처:** [ability-design/](./ability-design/INDEX.md)의 능력 이론 + game-dna 장르 맥락 + **본인의 창의적 비틀기**.
- **구체적으로.** 카테고리 라벨이 아니라 **손에 그려지는 한 컷**으로:
  - ❌ "스킬 시스템 어떠세요?"
  - ✅ "탑다운 슈터니까 *원소=능력*으로 묶는 빌드는 어떨까요 — *불씨 대시*(지나간 자리에 화염 장판) + *발화*(화염에 닿은 적 점화, payoff) + *폭심*(점화된 적 처치 시 연쇄 폭발)이 만나면 화면을 태우는 연쇄가 터지는. enabler(대시·발화) + payoff(폭심) 구조라 '한 판 더'가 자연스럽고(`SYN-ENABLER-PAYOFF`), 대시 캔슬로 폭심을 앞당기는 숙련 천장도 생깁니다(`COMBO-CHAIN`). 제 추천은 이 쪽인데, 더 단순한 '쿨다운 액티브 3개 독립'도 같이 올릴게요."
- **추천 + 한 컷 + 왜 재밌나(획득·조합·사용) + 본인 의견.** 첫 옵션에 "(추천)", "제 추천은 X입니다, 왜냐면 ~"으로 관점을 분명히.
- **다양성.** 복잡도·킷을 묻는 라운드에선 서로 다른 결(단순/중간/깊음)을 섞어 노출.
- 요청에 이미 단서가 있으면 그 부분은 고정하고, 제안은 *그 안에서의 변주*로 좁힌다.

## 5.5. 챌린지 모드 (deep-interview Phase 3 적응 — 능력용)

라운드가 쌓이면 관점을 바꿔 한 번씩 도발한다(각 1회). 킷을 날카롭게 만든다.

- **2라운드+ · Contrarian(반대로):** 과설계를 친다 — "정말 이 능력들이 다 필요할까요? 1~3분 세션에 스킬트리+다자원+콤보를 넣으면 한 판에 다 못 쓰고 끝납니다. *핵심 능력 하나*로 줄이면 뭐가 남나요?"(`SCOPE-ONE-CORE`)
- **4라운드+ · Simplifier(덜어내기):** 최소 버전을 묻는다 — "이 킷에서 **딱 능력 3개**만 남긴다면 뭔가요? 그 셋만으로도 '쓰는 맛·조합하는 맛'이 서나요?"(킷 정련, `SYN-MINIMAL-KIT`/`KIT-MINIMAL-KIT`)
- **5라운드+ · Signature Ability(자랑할 한 능력):** 정체성을 묻는다 — "플레이어가 *어떤 능력*을 처음 썼을 때 '오!' 하고 멈췄으면 하나요? 그 한 능력(이름+실루엣+발동 동사+'이걸 쓸 때 나는 누구')이 이 킷의 정체성입니다(`IDENT-SIGNATURE-ABILITY`)."

각 모드는 한 번만 쓰고 일반 질문으로 복귀.

## 6. 준비도 체크 (게이트)

ABILITIES.md 확정 시작 조건:
- **A1(복잡도 티어 + 핵심 모델 1개) 확정** + **A2(ludo·장르·플랫폼·버튼예산 정합)** + **A3(킷·역할 명시)** — 각각 한 문장으로 막힘없이 서술 가능.
- A4~A10은 ✅이거나, 미정이면 **분석·장르 기반 추천 기본값**으로 확정(사용자에게 "이건 이렇게 기본값으로 갈게요" 고지).
- 안티패턴 충돌이 모두 해소(절충안 확정 — 곱산 캡·무한콤보 차단·지배 가드·버튼 예산·과설계 축소 등).
- **Tier 0이면 "능력 시스템 없음"으로 즉시 완결**(ABILITIES.md 불필요, 코어 동사로 진행).

게이트 미달이면 가장 약한 차원으로 라운드를 더 돈다. 보통 **Tier 0~1은 1~2라운드, Tier 2는 3~5라운드, Tier 3~4는 5~8라운드**면 충족된다.

### 라운드 수 가이드 / 조기 종료
- 2라운드+부터 "충분/그냥 만들어"로 조기 종료 가능 — 단, 필수(A1·A2·A3)가 ◻️면 **추천 기본값을 채워 청사진을 완성**한 뒤 진행한다고 고지.
- 8라운드 soft 경고: "벌써 8라운드네요. 지금 청사진으로 진행할까요, 더 다듬을까요?"

## 7. 청사진(ABILITIES.md) 확정 & 빌드 라우팅 (deep-interview Phase 4·5 적응)

게이트 충족 시, **청사진을 한 화면으로 정리해 읽어주고 최종 확인**받은 뒤에만 `games/<slug>/ABILITIES.md` + `abilities.json` 작성을 시작한다.

### 확정 전 반드시 묻는 두 게이트
- **(make-game 적용)** 이 인터뷰가 web-game-builder/make-game 흐름에서 호출됐다면, 시작 전에 이미 **"능력 시스템을 만들까요?"**로 진입 동의를 받았어야 한다. 받지 않았으면 지금 묻는다.
- **(복잡도)** A1에서 **복잡도 티어와 핵심 모델 1개**를 명시적으로 확정했는지 청사진에 못 박는다(미정이면 디폴트는 장르 정합 모델 + 가장 낮은 합리적 티어).

### 청사진 형식 (응답 안 블록 — ABILITIES.md의 요약본)

```
## 능력 청사진: {제목} (slug: {kebab-slug})

- **복잡도 (A1):** Tier {0~4} · 핵심 모델 1개 {이동능력 | 쿨다운 액티브 | 드래프트 빌드 | 콤보 킷 | 스킬트리} (+표현/메타층 0~2개)
- **정합 (A2):** 코어 동사 {동사} ↔ 능력이 같은 말을 한다(IDENT-LUDO-HARMONY) · 플랫폼·세션·버튼예산 적합
- **킷·역할 (A3):** {액티브/패시브/이동기/궁극기/리액션 중} + 역할 분담{주력·생존·이동·CC·버프} + 입력타입
- **자원 (A4):** {쿨다운만 | 마나 | 스태미나 | 충전} 한 종 · 기회비용 · 리젠 균형 (T2+)
- **게임필 (A5):** 선딜/발동/후딜 · 텔레그래프 · 버퍼 · 캔슬/콤보 윈도 · 모바일 입력
- **진행 (A6):** {시작보유 | 드래프트 3택 | 스킬트리(형태) | 능력게이트} · 메타 vs 런내 · 파워커브 (T3+)
- **시너지·콤보 (A7):** payoff {1~2} + enabler {2~3} archetype · 콤보 연계 {A→B} · 곱산 {0~2 격리} · 진화/세트 (T3+)
- **능력 게이트 (A8):** 새 동사 {부여 동사} · 게이트 그래프 {유무} · 자물쇠 먼저 · softlock 방지 (있을 때)
- **정체성 (A9):** signature 능력 {이름·실루엣·발동 동사·판타지} · 테마 패밀리 · 스타일가이드 헤더 상수 · visual.* 슬롯 채움
- **밸런스 (A10):** lint-abilities.mjs 채택 · (복잡 킷) sim-abilities · 수동 "안써도/항상써도 클리어? 콤보 터지나? 손맛?" · 카운터플레이
- **IP 안전 메모:** 오리지널 능력 이름·외형(Glossary), 상용 게임 미복제, 도박형 능력해금 차용 안 함
- **빌드 라우팅:** 런타임 → engine/abilitykit.js · 아이콘 → sprite-forge/vector-graphics/sprite-picker · 스킬바·쿨다운·스킬트리 UI → game-ui-hud · 발동 연출 → juice-fx/sound-architect · flavor → story-architect · 능력부여 아이템 → item-architect(grantsAbility) · 검증 → lint-abilities.mjs + game-qa
```

확정 후:
1. 복잡도·장르에 맞는 **ability-design 도메인 파일 1~3개를 Read**해 원칙 근거를 반영(항상 principles.md + scope-complexity.md 먼저).
2. `games/<slug>/ABILITIES.md` + `abilities.json` 를 [consistency-tools.md](./ability-design/consistency-tools.md) 스펙으로 작성(단일 진실, visual.* 슬롯 채움).
3. abilities.json → abilitykit 배선(`AbilityKit.attach`·`onActivate` 효과 dispatch) + 입력 바인딩 + 아이콘 핸드오프(SKILL.md 4단계) → **작성과 분리된 검수 패스**(SKILL.md 5단계: `lint-abilities.mjs` + 수동).
4. **확인을 받은 뒤에만** 코드를 짜고 아이콘을 생성한다.

## 8. 예시 (Good / Bad)

**라운드 1 — 탑다운: 복잡도부터 (A1)**

```
라운드 1 | 타깃 차원: A1 복잡도·범위 | 왜 지금: 능력이 필요한지·얼마나 복잡한지가 이후 모든 질문(킷·자원·시너지)을 프레이밍하므로 맨 먼저 정합니다 | 청사진 진행: 0/10

분석해보니 이 게임은 *옆스크롤 점프* 플랫포머입니다. 사실 점프(코어) + *대시* 하나만으로도 Celeste처럼 깊게 완결돼요(T1) — 대시 1개가 회피·이동·콤보의 축이 됩니다. 더 가면 능력으로 잠긴 곳을 여는 메트로배니아(T3~T4)도 가능하지만, 짧은 세션엔 T1이 안전합니다. 제 추천은 T1입니다.

이 게임에 능력을 어느 정도로 둘까요? (0: 없음·코어 동사만 / 1: 능력 1개(대시 추천) / 2: 쿨다운 액티브 몇 개 / 3: 빌드·콤보 / 4: 스킬트리·능력게이트)
```

**라운드 5 — 추상답을 구체 시너지/콤보로 되묻기 (A7, T3 선택 시)**

```
라운드 5 | 타깃 차원: A7 시너지·콤보 | 왜 지금: 복잡도(T3 빌드)와 킷(액티브+패시브)이 섰으니, 무엇이 무엇과 곱해지고 이어지느냐가 '한 판 더'를 만듭니다 | 청사진 진행: 5/10

'조합하면 강해지게'라고 하셨는데 그게 핵심입니다 — 다만 곱연산을 아무 데나 풀면 빌드가 폭발합니다(`SYN-ADD-VS-MULT`). 제 추천은 payoff 1개(*빙결 폭발*: 얼린 적 처치 시 파편 확산) + enabler 2~3개(대시 시 냉기 장판 / 피격 시 빙갑) 구조에, 곱산은 *빙결 피해 ×* 한 종만 캡 걸어 격리하는 겁니다. 그러면 "얼음 빌드를 노리고 모으는" 동기가 생기고, 대시→빙결→폭발로 잇는 콤보 천장도 생깁니다(`COMBO-CHAIN`).

시너지를 어떻게 둘까요 — (a) payoff 1 + enabler 2~3, 곱산 1종 격리(추천) (b) 가산 스택만(단순·안전) (c) 콤보 연계 중심(A→B 캔슬로 잇기)?
```
→ **반영:** "그럼 *빙결 payoff 1개 + 냉기 enabler 3개 + 빙결피해 곱산 1개(캡 있음)*로, 한 판에 얼음 빌드를 완성하는 맛이 납니다. 대시→폭발 콤보 윈도는 0.5초로 둬서 숙련 보상을 만들고요(`COMBO-WINDOW`)."
→ **검증+대안:** "이 깊이 괜찮으세요? 부담되면 (b) 가산만으로도 충분히 재밌게 만들 수 있는데, 어느 쪽이 끌리세요?"

**왜 좋은가:** 탑다운(복잡도 먼저), 약점 차원 하나만, "왜 지금" 명시, **단순/깊음을 사용자가 직접** 고르게 하고 Claude가 구체적 한 컷으로 *반영*하고 *대안*까지 던짐, 안티패턴(곱연산 폭발·무한콤보) 가드.

**Bad:** "스킬 어떻게 할까요? 1)액티브 2)패시브 3)궁극기 4)스킬트리"만 던지기 — 추상 카테고리라 손에 안 그려지고, 복잡도(A1)도 안 묻고 바로 킷으로 점프(정신1 위반), 단순해도 된다는 안내도 없음(정신3 위반), 4문항 한 객관식(1문1답 위반).

## 9. 최종 체크리스트

- [ ] 탑다운: A1(복잡도·범위)부터 못 박고 아래로 내려갔는가
- [ ] **디폴트 최소를 먼저 제시**하고, 단순해도 된다고 적극 안내했는가(`SCOPE-DEFAULT-MINIMAL`)
- [ ] 한 라운드에 질문 하나(1문1답) — A3 킷/A7 시너지만 multiSelect 한 질문 허용
- [ ] 매 라운드 타깃 차원 + "왜 지금" 명시
- [ ] 매 라운드 Claude가 **참신한 능력·콤보를 먼저** 구체적 한 컷으로 제안하고 본인 의견을 밝혔는가
- [ ] **A1에서 복잡도 티어 + 핵심 모델 1개를 사용자가 직접 확정**했는가 — ★반드시
- [ ] 핵심 모델은 **하나만**(`SCOPE-ONE-CORE`), 한 게임에 모델 중복 안 했는가
- [ ] 능력이 코어 동사·주제와 같은 말을 하는가(`IDENT-LUDO-HARMONY`) — 준비도 게이트
- [ ] 추상적 답("멋진 스킬/RPG처럼")은 구체 능력·티어·콤보로 되물어 구체화
- [ ] 안티패턴 충돌(과설계·곱연산 폭발·무한콤보·지배능력·무비용 스팸·버튼 폭발·softlock)은 절충 되묻기로 해소
- [ ] 챌린지 모드(Contrarian/Simplifier/Signature Ability)를 적절 라운드에 1회씩
- [ ] **make-game 적용 동의**를 받았는가(이 인터뷰가 make-game에서 호출된 경우)
- [ ] 준비도 게이트(A1 복잡도+핵심모델 + A2 정합 + A3 킷) 후에만 ABILITIES.md 확정
- [ ] 청사진을 한 화면으로 읽어주고 최종 확인 후 ABILITIES.md + abilities.json 작성, visual.* 슬롯 채움
- [ ] 조기 종료("그냥 만들어") 시 장르 기반 추천 기본값으로 청사진 완성 후 진행
- [ ] **용어 혼동 주의:** 사용자가 헷갈릴 여지가 있으면 "능력(ability)"으로 부른다(Claude 스킬과 구분)
