# 사운드 설계 인터뷰 (Deep Interview 적응판 · 탑다운 · 무드 먼저 · 의도 주도)

> [`sound-architect`](../SKILL.md)의 **'1) 의도 분석 + 사운드 인터뷰'** 단계를, **탑다운으로 모호성이 풀릴 때까지 끈질기게
> 묻는 1문1답 인터뷰**로 수행하는 플레이북.
> oh-my-claudecode `deep-interview`(Socratic 1문1답 + 약점 차원 타깃 + 챌린지 모드 + 준비도 게이팅)와
> [story-interview.md](../../wgf-story-architect/reference/story-interview.md)·[item-interview.md](../../wgf-item-architect/reference/item-interview.md)·[game-interview.md](../../wgf-web-game-builder/reference/game-interview.md)를
> **사운드(BGM·SFX) 설계**에 적응시켰다.
> 차이: 게임 인터뷰가 *어떤 게임을*(메카닉), 서사 인터뷰가 *어떤 이야기를*, 아이템 인터뷰가 *무엇을 습득하는가*를 캔다면,
> 이 인터뷰는 **이 게임이 어떤 소리가 나야 하는가 — 어떤 감정을 귀로 전하는가**를 캔다. 그리고 **무드를 가장 먼저** 못 박는다.
>
> **언제 쓰나:** "사운드/BGM/효과음 넣어줘", "분위기 있는 음악", "긴박한 느낌의 사운드"처럼 요청이 모호하거나 무드·음색이 비어 있을 때.
> 요청이 이미 구체적이면(무드·장르음색·BGM구조·SFX·적응형 여부가 다 적혀 있으면) 인터뷰를 건너뛰고 바로 AUDIO.md를 설계한다.
>
> 자동 트리거 아님. SKILL.md '1) 의도 분석'에서 **온디맨드 Read** 로 부른다.

---

## 0. 이 인터뷰의 3대 정신

1. **무드를 먼저 못 박고 탑다운으로 내려간다.** 스킬 0단계(현재 게임 분석)가 끝난 상태에서 시작한다 — 코어 동사·장르·STORY.md 톤·아트·플랫폼을 이미 안다. 그 위에서 **이 게임이 끝낸 플레이어에게 남길 한 감정(무드 토큰)** 부터 못 박고(`MOOD-LOCK-FIRST`) → 장르 음색 정합 → BGM 구조 → SFX 팔레트 → 적응형 → 믹스·모바일 순으로 *좁혀* 내려간다. 무드가 스케일·BPM·악기·진행·이펙트를 전부 프레이밍한다 — 위가 흔들리면 아래를 물어도 소용없다.
2. **Claude가 먼저 *구체적인 소리*를 제안한다(백지 금지).** 빈 객관식("어떤 음악 원해요?")을 던지지 않는다. 매 라운드 게임의 코어 동사·STORY.md 톤 + 사운드 이론으로 *이 게임에 어울리는 구체적 사운드*를 **귀에 그려지는 한 컷**으로 먼저 제시하고 의견을 밝힌다(§4·§5). 사용자는 고르거나 비틀거나 자유 입력. **단순(T1)하게 갈지 적응형(T3)까지 갈지는 사용자가 주도해 정한다.**
3. **모호성이 풀릴 때까지 — 단, 작은 게임엔 단순함이 정답.** 한 라운드 한 질문, 가장 약한 차원을 계속 캔다. 추상적 답("멋진 음악", "분위기 있게")은 **구체 사례로 되묻는다**("'분위기 있게' = 쓸쓸한 단조 패드(앰비언트)인가요, 긴박한 슈퍼소우 추격(신스웨이브)인가요? 명상 퍼즐이면 전자가 잘 맞습니다"). 목표는 *Claude가 만들기 쉬운 사운드*가 아니라 **이 게임이 진짜로 내야 할 소리**다.

## 1. 핵심 원칙 (deep-interview에서 차용)

1. **1문1답.** 한 라운드 질문 하나. (단, S4 SFX 이벤트 팔레트처럼 *여러 선택지지만 한 질문*인 경우만 multiSelect 허용.)
2. **약점 차원 타깃 + "왜 지금".** 매 라운드 가장 모호하거나 결정적인 차원 하나를 고르고, 왜 지금 이걸 묻는지 한 문장으로.
3. **가정을 드러낸다.** "뭘 원해요?" 대신 "무엇을 전제하나요?". 추상적 답은 구체 사운드/무드로 되묻는다.
4. **Claude가 먼저 구체적 사운드를 제안(백지 금지).** 사운드 이론([sound-design/](./sound-design/INDEX.md)) + 게임 맥락 + STORY.md 톤 기반. 첫 옵션에 "(추천)" + 근거. *귀에 그려지는 한 컷*으로(§5).
5. **안티패턴 가드.** [principles.md](./sound-design/principles.md) §4 '섞지 말 것'(무드 불협·음색 잡탕·보이스 폭발·SFX 마스킹·긴 리버브 남발·적응형 과설계·시그니처 곡 인용)을 내부 가드로. 충돌 의도면 절충 되묻기.
6. **준비도 게이트.** §6 차원이 구체화되기 전엔 AUDIO.md 확정 금지.
7. **조기 종료 존중.** "알아서/그냥 만들어/충분해"라고 하면 즉시 멈추고, 분석 + 장르 기반 추천 기본값으로 §7 청사진(AUDIO.md)을 확정해 읽어준 뒤 진행한다고 고지.

## 2. 사운드 의도 차원 (탑다운 순서)

위에서부터 캔다(무드 → 음색 정합 → BGM 구조 → SFX → 적응형 → 믹스). ✅=구체 확정 · ◻️=미정.

| # | 차원 | 무엇을 확정하나 | 비고 |
|---|---|---|---|
| **S1** | **무드 · 음악 정체성** ★맨 먼저 | 끝낸 플레이어가 느낄 한 감정(무드 토큰: 유쾌/따뜻/쓸쓸/긴박/긴장/평온/장엄/신비) + 복잡도 티어(0 chip~3 적응형) | `MOOD-LOCK-FIRST`·`MOOD-LUDO-HARMONY`. 무드가 모든 걸 프레이밍. **T0/chip이면 대부분 스킵.** |
| **S2** | **장르 음색 패밀리** | 무드를 어떤 음색으로(칩튠/신스웨이브/앰비언트/로파이/16비트FM/아케이드/오케스트라풍) — 한 게임 한 패밀리 | `TIMBRE-ONE-FAMILY`·`TIMBRE-FIT`. 아트(픽셀/스무스)·코어 동사와 정합. |
| **S3** | **BGM 구조** | 스케일/모드·키·BPM·코드 진행·트랙 수·레이어(악기 프리셋) | `MOOD-SCALE-MAP`·`MOOD-TEMPO`·`MOOD-PROGRESSION`. 멜로디는 절차 생성(오리지널). |
| **S4** | **SFX 팔레트** | 게임 이벤트(점프·피격·획득·폭발·UI...)별 SFX 톤(또렷/말랑/묵직) + 레이어드 정도 | `SFX-CATEGORY`·`SFX-LAYER-3`·`SFX-FEEDBACK-CLARITY`·`SFX-COMPAT`. multiSelect로 이벤트 셋 확인. |
| **S5** | **적응형 / 전환** | 인텐시티(전투 격화 등)로 레이어를 쌓을지, 섹션(탐험/전투/보스) 전환할지 — 또는 정적 BGM | `ADAPT-VERTICAL`·`ADAPT-HORIZONTAL`·`ADAPT-MINIMAL`. **T3에서만 깊게. 짧은 게임엔 정적이 정답.** |
| **S6** | **믹스 · 모바일 예산** | 동시 보이스 캡·리버브/딜레이 정도·음소거·언락/suspend(거의 자동) | `MIX-VOICE-BUDGET`·`MIX-SEND-FX`·`MIX-MUTE`. 보통 기본값으로 자동 확정. |

> **T0(chip)이면 S1 직후 종료**(ChipAudio 8비트로). T1은 S1·S2·S3·S4가 핵심, S5는 "정적". T2는 S2·S3가 무겁다. T3이면 S5(적응형)가 가장 무겁다.

## 3. 라운드 진행 (deep-interview Phase 2 적응)

각 라운드는 `AskUserQuestion` 한 번(질문 1개)으로. 형식:

```
라운드 {n} | 타깃 차원: {S# 이름} | 왜 지금: {한 문장 근거} | 청사진 진행: {✅개수}/6

{Claude의 제안·관점 1~2문장 — 사운드 이론 + 게임 코어 동사·STORY.md 톤 + 본인 의견. 귀에 그려지는 한 컷으로.}

{질문}
```

- 답을 받으면 그 차원을 ✅로, **다음으로 가장 약한 차원**(보통 탑다운 다음 칸)을 타깃해 다음 라운드로.
- 답이 모호하면 같은 차원을 **구체화 질문**으로 한 번 더 판다(추상→구체 사운드로 되묻기).
- 안티패턴 충돌이 감지되면 다음 질문은 **절충 되묻기**.

### 라운드 진행 리드아웃 (투명성)

```
청사진: S1 무드 ✅(긴박/T2) | S2 음색 ◻️ | S3 BGM ◻️ | S4 SFX ◻️ | S5 적응형 ◻️ | S6 믹스 ◻️
다음 타깃 → S2(음색): 무드(긴박)가 섰으니, 그걸 어떤 음색 패밀리로 칠하느냐가 게임 인상을 정합니다.
```

## 4. Claude가 구체적 사운드를 먼저 제안 + 무드/복잡도는 사용자가 주도 (★이 인터뷰의 1순위)

사용자는 "사운드를 어떻게 짜야 할지" 막막하거나, 반대로 "웅장한 오케스트라 풀로!"로 과설계를 부르기 쉽다. 그러니 **매 라운드 Claude가 먼저 귀에 그려지는 한 컷을 던지고**, 특히 **무드와 복잡도(단순 T1 ↔ 적응형 T3)는 사용자가 고르게** 한다. 사용자의 흐름 그대로:
*"이 게임엔 이런 소리가 어울려 보입니다(무드 제안) → 이러면 이런 느낌이 됩니다, 괜찮나요? → 더 단순/풍부한 결도 보여드릴까요?"*

### S1 무드 4단계 루프 (가장 중요)

1. **코어 동사·톤에서 무드 추론 (infer).** "이 게임은 코어 동사가 *{동사}*이고 STORY.md 톤이 *{톤}*이라, 끝낸 플레이어에게 *{무드}* 감정을 남기는 소리가 어울립니다." — 분석에서 출발(`MOOD-LUDO-HARMONY`).
2. **복잡도 디폴트 제안 (one step).** "대부분의 작은 게임은 *한 무드 BGM + SFX 팔레트(T1)*면 충분합니다. 전투 강약이 중요하면 *인텐시티로 레이어가 쌓이는 적응형(T3)*까지 갈 수 있어요." — 과설계를 먼저 막는다(`ADAPT-MINIMAL`).
3. **반영 (reflect).** 사용자가 고르면 → **"그럼 *이런 소리*가 됩니다"** 하고 귀에 그려지는 한 컷으로(막연한 카테고리 금지 — 예: "낮게 깔리는 phrygian 패드 위로, 달리기 시작하면 4-on-floor 킥이 들어오고 추격 절정엔 슈퍼소우 훅이 터지는").
4. **검증 + 대안 (validate + alternatives).** 곧바로 되묻는다: **"이 무드 괜찮으세요? 더 차분(앰비언트 패드만)하게도, 더 밝게(칩튠 경쾌)도 갈 수 있는데 어느 쪽이 끌리세요?"** 본인 의견·참신함을 적극 개진.

> 무드가 바뀌면 이후 차원(음색·BGM·적응형)의 결이 통째로 달라진다. T0(chip)이면 S1 직후 바로 청사진으로 점프.

## 5. Claude의 제안 의무 — "구체적 사운드를 먼저, 귀에 그려지게"

제안 주도권은 Claude에게, 선택권은 사용자에게. **매 라운드 Claude가 먼저 구체적 사운드/대안을 제시**한다(백지 금지).

- **출처:** [sound-design/](./sound-design/INDEX.md)의 사운드 이론(무드 매핑·장르 음색·합성 레시피) + 게임 코어 동사·STORY.md 톤 + **본인의 비틀기**.
- **구체적으로.** 카테고리 라벨이 아니라 **귀에 그려지는 한 컷**으로:
  - ❌ "BGM은 어떤 스타일로 할까요?"
  - ✅ "탑다운 슈터의 긴장감을 *신스웨이브*로 칠하면 어떨까요 — E phrygian, 148BPM, 낮은 saw 베이스가 추진하고 4-on-floor 킥 위로 슈퍼소우 리드가 아르페지오로 달리는. 적이 몰리면(인텐시티↑) 리드 레이어가 페이드 인해 *체감 난이도가 귀로* 올라갑니다. 제 추천은 이쪽인데, 더 미니멀한 '드론+퍼커션'도 같이 올릴게요."
- **추천 + 한 컷 + 왜 어울리나 + 본인 의견.** 첫 옵션에 "(추천)", "제 추천은 X입니다, 왜냐면 ~"으로 관점을 분명히.
- **다양성.** 무드·음색을 묻는 라운드에선 서로 다른 결(차분/중간/강렬)을 섞어 노출.
- 요청에 이미 단서가 있으면 그 부분은 고정하고, 제안은 *그 안에서의 변주*로 좁힌다.

## 5.5. 챌린지 모드 (deep-interview Phase 3 적응 — 사운드용)

라운드가 쌓이면 관점을 바꿔 한 번씩 도발한다(각 1회).

- **2라운드+ · Contrarian(반대로):** 과설계를 친다 — "정말 적응형(T3)이 필요할까요? 한 판 40초면 정적 루프 하나로도 충분하고, 레이어가 많을수록 모바일에서 끊길 위험만 커집니다. 한 무드 BGM이면 뭐가 부족할까요?"(`ADAPT-MINIMAL`)
- **4라운드+ · Simplifier(덜어내기):** 최소 버전을 묻는다 — "BGM 없이 **SFX만**으로도 이 게임이 성립할까요? 아니면 BGM이 분위기의 핵심인가요? 둘 중 하나만 공들인다면?"
- **5라운드+ · Signature Sound(자랑할 한 소리):** 정체성을 묻는다 — "플레이어가 *어떤 소리* 하나로 이 게임을 기억했으면 하나요? 그 한 소리(시그니처 SFX나 메인 훅)가 사운드의 정체성입니다."

각 모드는 한 번만 쓰고 일반 질문으로 복귀.

## 6. 준비도 체크 (게이트)

AUDIO.md 확정 시작 조건:
- **S1(무드 토큰 + 복잡도 티어) 확정** + **S2(음색 패밀리)** + **S3(스케일·BPM·진행 또는 추천 기본값)** — 각각 한 문장으로 막힘없이 서술 가능.
- S4~S6은 ✅이거나, 미정이면 **분석·장르 기반 추천 기본값**으로 확정(사용자에게 "이건 이렇게 기본값으로 갈게요" 고지).
- 안티패턴 충돌이 모두 해소(무드 불협·보이스 폭발·음색 잡탕 등).
- **Tier 0(chip)이면 "ChipAudio 8비트로 진행"으로 즉시 완결**(AUDIO.md 불필요, 무드만 기록).

게이트 미달이면 가장 약한 차원으로 라운드를 더 돈다. 보통 **T0~T1은 1~2라운드, T2는 2~4라운드, T3은 4~6라운드**면 충족된다.

### 라운드 수 가이드 / 조기 종료
- 2라운드+부터 "충분/그냥 만들어"로 조기 종료 가능 — 단, 필수(S1·S2)가 ◻️면 **추천 기본값을 채워 청사진을 완성**한 뒤 진행한다고 고지.
- 8라운드 soft 경고: "벌써 8라운드네요. 지금 청사진으로 진행할까요?"

## 7. 청사진(AUDIO.md) 확정 & 빌드 라우팅 (deep-interview Phase 4·5 적응)

게이트 충족 시, **청사진을 한 화면으로 정리해 읽어주고 최종 확인**받은 뒤에만 `games/<slug>/AUDIO.md` + `audio.json` 작성을 시작한다.

### 확정 전 반드시 묻는 두 게이트
- **(make-game 적용)** 이 인터뷰가 web-game-builder/make-game 흐름에서 호출됐다면, 시작 전에 이미 **"사운드를 설계해 적용할까요?"**로 진입 동의를 받았어야 한다. 받지 않았으면 지금 묻는다.
- **(무드·복잡도)** S1에서 **무드 토큰 + 복잡도 티어**를 명시적으로 확정했는지 청사진에 못 박는다(미정이면 디폴트는 장르 정합 무드 + T1).

### 청사진 형식 (응답 안 블록 — AUDIO.md의 요약본)

```
## 사운드 청사진: {제목} (slug: {kebab-slug})

- **무드 (S1):** 무드 토큰 {유쾌|따뜻|쓸쓸|긴박|긴장|평온|장엄|신비} · 복잡도 Tier {0~3} · 엔진 {soundforge|chip}
- **음색 패밀리 (S2):** {칩튠|신스웨이브|앰비언트|로파이|16비트FM|아케이드|오케스트라풍} (한 게임 한 패밀리)
- **BGM 구조 (S3):** {스케일/모드} {키} {BPM} · 진행 {로마숫자} · 트랙 {N} · 레이어 {프리셋 목록}
- **SFX 팔레트 (S4):** {이벤트→톤} · 레이어드 {단일|3겹} · ChipAudio 호환 키 유지
- **적응형 (S5):** {정적 | 인텐시티 수직 레이어 | 섹션 전환(탐험/전투/보스)} (T3만)
- **믹스·모바일 (S6):** maxVoices {16} · 리버브/딜레이 {정도} · 음소거·언락·suspend(자동)
- **정합 메모:** 코어 동사 {동사} ↔ 음악이 같은 말(MOOD-LUDO-HARMONY) · STORY.md 톤 상속
- **IP 안전:** 절차 합성 오리지널(오디오 파일 0) · 시그니처 곡 인용 안 함(CC0-ORIGINAL)
- **빌드 라우팅:** 엔진 engine/soundforge.js(또는 chip=audio.js) · index.html 로드순서 tone.js→soundforge.js · 검증 lint-audio.mjs + 청취 + game-qa
```

확정 후:
1. 무드·장르에 맞는 **sound-design 도메인 파일 1~3개를 Read**해 원칙 근거 반영(항상 principles.md + mood-music-theory.md 먼저).
2. `games/<slug>/AUDIO.md` + `audio.json` 를 [consistency-tools.md](./sound-design/consistency-tools.md) 스펙으로 작성(단일 진실).
3. audio.json → game.js 연결(`new SoundForge(AUDIO_SPEC)`) + index.html 로드순서(SKILL.md 4단계) → **작성과 분리된 검수 패스**(SKILL.md 5단계: `lint-audio.mjs` + 청취).
4. **확인을 받은 뒤에만** 코드를 짠다.

## 8. 예시 (Good / Bad)

**라운드 1 — 탑다운: 무드부터 (S1)**

```
라운드 1 | 타깃 차원: S1 무드 | 왜 지금: 무드가 스케일·BPM·악기·이펙트를 전부 프레이밍하므로 맨 먼저 정합니다 | 청사진 진행: 0/6

분석해보니 이 게임은 *끝없이 달리며 장애물을 피하는* 러너에, STORY.md 톤이 '쫓기는 긴박함'입니다. 그럼 끝낸 플레이어에게
*긴박/추격* 감정을 남기는 소리가 어울려요 — 제 추천은 신스웨이브(빠른 BPM·추진 비트)입니다. 다만 더 차분히(달리는 명상감, 앰비언트)
갈 수도 있어요. 복잡도는 대부분 *한 무드 BGM(T1)*이면 충분하지만, 가속할수록 음악이 격해지는 *적응형(T3)*도 러너에 잘 맞습니다.

이 게임은 어떤 감정을 귀로 남기면 좋을까요? (긴박/추격(추천) · 차분한 몰입 · 경쾌한 질주) 그리고 음악이 게임 강도를 따라가길 원하세요?
```

**라운드 3 — 추상답을 구체 BGM으로 되묻기 (S3)**

```
라운드 3 | 타깃 차원: S3 BGM 구조 | 왜 지금: 무드(긴박)와 음색(신스웨이브)이 섰으니, 스케일·BPM·진행이 곡의 뼈대를 정합니다 | 청사진 진행: 2/6

'긴장감 있게'라고 하셨는데, 신스웨이브에서 그건 보통 *어두운 모드 + 빠른 BPM*으로 만듭니다. 제 추천은 E phrygian(이국적 긴장),
148BPM, i–♭II–i–VII 진행(♭II가 불안을 줍니다)이에요. 멜로디는 스케일에서 절차 생성해 오리지널을 보증하고요(어떤 곡도 인용 안 함).

BGM 뼈대를 이렇게 갈까요? (a) E phrygian 148BPM 추진(추천) (b) 더 느리고 무겁게(A 하모닉마이너 120BPM) (c) 알아서 추천대로?
```
→ **반영:** "그럼 *불안한 phrygian 위를 슈퍼소우가 달리는* 추격 트랙이 됩니다 — 패드 베드가 항상 깔리고, 그 위로 베이스·드럼·리드가 강도에 따라 쌓이게요."
→ **검증+대안:** "이 뼈대 괜찮으세요? 보스 구간만 하모닉마이너로 바꿔 더 드라마틱하게 만들 수도 있는데, 그건 적응형(S5)에서 정할게요."

**왜 좋은가:** 탑다운(무드 먼저), 약점 차원 하나만, "왜 지금" 명시, **무드·복잡도를 사용자가 직접** 고르게 하고 Claude가 귀에 그려지는 한 컷으로 *반영*하고 *대안*까지 던짐, 안티패턴(보이스 폭발·과설계) 가드, CC0 보증 명시.

**Bad:** "BGM 칩튠/오케스트라/EDM 중 뭐로 할까요? SFX는 8비트로?"만 던지기 — 추상 카테고리라 귀에 안 그려지고, 무드(S1)도 안 묻고 바로 음색으로 점프(정신1 위반), 단순해도 된다는 안내도 없음(정신3 위반).

## 9. 최종 체크리스트

- [ ] 탑다운: S1(무드)부터 못 박고 아래로 내려갔는가(`MOOD-LOCK-FIRST`)
- [ ] **무드 토큰 1개 + 복잡도 티어(0~3)를 사용자가 직접 확정**했는가 — ★반드시
- [ ] 한 라운드에 질문 하나(1문1답) — S4 SFX 이벤트 셋만 multiSelect 허용
- [ ] 매 라운드 타깃 차원 + "왜 지금" 명시
- [ ] 매 라운드 Claude가 **구체적 사운드를 먼저** 귀에 그려지는 한 컷으로 제안하고 본인 의견을 밝혔는가
- [ ] 음악이 코어 동사·STORY.md 톤과 같은 말을 하는가(`MOOD-LUDO-HARMONY`) — 준비도 게이트
- [ ] 한 게임 한 음색 패밀리(`TIMBRE-ONE-FAMILY`) — 잡탕 금지
- [ ] 추상적 답("멋진 음악/분위기 있게")은 구체 무드·스케일·음색으로 되물어 구체화
- [ ] 안티패턴 충돌(무드 불협·보이스 폭발·음색 잡탕·적응형 과설계·시그니처 곡 인용)은 절충 되묻기로 해소
- [ ] 챌린지 모드(Contrarian/Simplifier/Signature Sound)를 적절 라운드에 1회씩
- [ ] **make-game 적용 동의**를 받았는가(이 인터뷰가 make-game에서 호출된 경우)
- [ ] 준비도 게이트(S1 무드+티어 + S2 음색 + S3 BGM 뼈대) 후에만 AUDIO.md 확정
- [ ] 청사진을 한 화면으로 읽어주고 최종 확인 후 AUDIO.md + audio.json 작성
- [ ] 조기 종료("그냥 만들어") 시 장르 기반 추천 기본값으로 청사진 완성 후 진행
