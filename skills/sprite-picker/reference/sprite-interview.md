# 스프라이트 인터뷰 — 끈질긴 1문1답으로 의도를 캔다 (SP-*)

화면에 보이는 이미지·애니메이션은 게임의 재미를 가장 크게 좌우한다. 그래서 **사용자가 직접
고르게** 하되, 의도가 모호하면 **구체적·적극적·끈질기게** 질문해 스프라이트 구성을 확정한다.
[`world-map-architect`](../../world-map-architect/reference/map-interview.md)·`deep-interview` 와 같은
탑다운 1문1답 철학.

## 3대 정신
1. **탑다운으로 내려간다.** 넓은 결정(SP1 출처 → SP2 스타일)부터 묻고 → 에셋 목록 → 애니 → 라이선스 → 적용 매핑으로 좁힌다.
2. **매 라운드 Claude 가 먼저 구체안을 제안한다(백지 금지).** "어떤 스프라이트 원해요?"라고 던지지 말고,
   요청·장르에서 추론한 **구체적 후보 묶음**을 제시하고 본인 추천을 밝힌 뒤 고르거나 바꾸게 한다.
3. **모호성이 풀릴 때까지.** 4문항을 한 번에 묶지 않는다. 가장 약한 차원 하나씩, 매 라운드 "지금 왜 이걸 묻는지"를 붙인다.

## 준비도 게이트
**SP1(출처) + SP2(스타일) + SP3(에셋 목록)** 가 구체화되기 전에는 피커를 띄우거나 다운로드하지 않는다.
세 축이 서면 후보를 추려 피커로 넘어간다([picker-protocol.md](./picker-protocol.md)).

## 차원 (탑다운 순서)

### SP1 — 출처 결정 ★맨 먼저·핵심 게이트
"이 스프라이트들을 **(a) 내가 코드로 만들까**, **(b) 실제 CC0 에셋에서 골라줄까**?" 를 가른다.
화면 인상을 좌우하므로 명시가 없으면 **반드시** 묻는다(자동으로 결정하지 않는다 — 단, 사용자가
"알아서/대충"이라고 명시하면 추천 기본값으로 진행).

- 보기를 `AskUserQuestion` 으로 제시:
  - **실제 에셋 소싱** — 큐레이션된 CC0 카탈로그(Kenney 등)에서 시각적으로 골라 적용.
  - **로컬 파일** — 사용자가 가진 이미지/시트를 골라 적용.
  - **이전 사용분 재사용** — `assets-library/` 에 쌓인 것에서 고름.
  - **절차 생성(Claude 제작)** — 글로 설명 → `sprite-forge`/`vector-graphics` 로 코드 생성.
- 게임 생성 흐름 안에서 호출됐다면(오케스트레이터 위임), 이 질문이 곧 "실제 에셋 vs 절차 생성" 결정 게이트다.

### SP2 — 아트 스타일/룩 ★필수
- **픽셀아트** vs **미려한 스무스/벡터** — 게임당 **한 스타일**로 통일(렌더 설정이 다름).
- 픽셀이면: 해상도/타일 크기(16·18·32px), NES풍 vs 모던 픽셀, 팔레트 톤.
- 스무스면: 플랫/머티리얼·네온글로우·글래스·카툰벡터 중 어느 결.
- 기존 게임에 추가하는 거면 **현재 게임 스타일을 먼저 읽어** 충돌을 막는다(섞지 않는다).

### SP3 — 에셋 목록 ★필수
필요한 화면 요소를 **빠짐없이** 나열하게 한다. Claude 가 장르 기반으로 먼저 초안을 제시:
- 캐릭터: 플레이어, 적(종류별), NPC, 보스
- 월드: 타일셋(지형·플랫폼), 배경(원경/근경), 장식
- 아이템: 코인·파워업·열쇠·픽업
- UI: 버튼·게이지·하트·아이콘·HUD 프레임
- 이펙트: 폭발·타격·먼지·반짝임
→ 우선순위(필수/있으면 좋음)도 함께.

### SP4 — 애니메이션
캐릭터마다 어떤 상태가 움직여야 하는가:
- 상태: idle / walk / run / jump / fall / attack / hit / die
- 프레임 수(보통 2~6), 방향(횡스크롤=좌우 플립, 탑다운=4·8방향)
- 스프라이트시트 형식(가로 스트립 / 그리드 / 아틀라스 JSON) — 소스마다 다름.

### SP5 — 라이선스 제약
- CC0만? 표기(CC-BY) 허용? 상용 배포 예정?
- 기본은 `cc0` 우선. 표기 허용 시 `permissive-attribution` 까지 풀되 `CREDITS.txt` 약속.
- 판정·게이트는 [`ip-license-guard`](../../ip-license-guard/SKILL.md) 와 정합.

### SP6 — 적용 매핑
- 어느 스프라이트를 어느 게임 객체/씬에 — 플레이어=X, 적=Y, 코인=Z.
- 크기/스케일(원본 px → 게임 표시 배율), 색 보정/틴트, 충돌 박스 영향.
- 이건 보통 피커 선택 후 `note` 와 함께 확정한다.

## 진행 규칙
- **1문1답·탑다운**: SP1부터 아래로, 가장 약한 차원을 깊게. 4문항을 한 질문에 묶지 않는다(SP3 목록 multiSelect 한 질문은 허용).
- **매 라운드 Claude 선제안**: 요청·장르에서 추론한 구체 후보를 *먼저* 제시하고 추천을 밝힌다.
- **추상답은 구체로 되묻는다**: "멋있게" → "픽셀 16px 네온 톤 vs 스무스 카툰벡터 중 어느 쪽?"
- **충돌 가드**: 기존 게임 스타일과 다른 스타일을 고르면 "한 게임 한 스타일" 원칙으로 되묻는다.
- **막다른 길 금지**: 끝내 못 정하면 추천 기본값(보통 현재 게임 스타일 + 절차 생성)으로 폴백.
- 준비도 게이트(SP1·SP2·SP3) 충족 → 후보를 추려 **피커로** → 선택 회수 → SP6 매핑 → 적용·검증.
