# 플랫포머 레벨 디자인

> 옆스크롤 차징 점프 플랫포머(저장소 예시 = **super-runner**)의 레벨을 `LD-*` 원칙으로 설계하기 위한 처방전이다. 공통 이론은 [./principles.md](./principles.md), 빌드 구현 패턴은 [`level-designer`](../../../level-designer/SKILL.md), 재미요소(`FE-*`) 사전은 [game-dna/fun-elements.md](../../../web-game-builder/reference/game-dna/fun-elements.md)·[INDEX.md](../../../web-game-builder/reference/game-dna/INDEX.md) 참고.
> 핵심: 횡스크롤에서 **레벨의 가로 좌표(`col`)가 곧 시간축**이다 — 난이도 곡선·페이싱·4비트·시선 유도가 전부 `col` 순서로 인코딩된다. `features`/`pits`/`pipes`를 `col` 오름차순으로 읽으면 그게 플레이어가 겪는 시간순 경험이다.

이 문서는 [INDEX.md](./INDEX.md) 라우팅 표의 **옆스크롤 플랫포머** 칸에 대응한다. 빌드 위임 대상은 `platformer-game` + [`level-designer`](../../../level-designer/SKILL.md).

## 0. 대상 게임 스키마 — super-runner LEVEL

먼저 설계 대상의 `game.js` 상단 레벨 선언을 그대로 분석한다(새 포맷 발명 금지). super-runner는 `games/super-runner/game.js`에서 전역 `LEVEL` 하나를 선언하는 단일 스테이지 플랫포머다.

```js
var TILE = 16, DESIGN_W = 384 /* 24타일 */, DESIGN_H = 224 /* 14타일 */, GRAVITY = 1100;

var LEVEL = {
  width: 132,        // 전체 가로 타일 수 (= 시간축의 길이)
  rows: 14,          // 세로 타일 수 (0..13)
  groundTop: 12,     // 바닥 상단 행 (row 12=잔디, 13=흙 자동 생성)
  pits: [[27, 29], [58, 60], [88, 90], [104, 105]], // [시작열,끝열] 바닥 없음
  features: [        // t=종류, c=열, r=행 — col 오름차순으로 작성
    { t: '?', c: 8,  r: 9 },              // 물음표 블록
    { t: 'o', c: 6,  r: 9 },              // 코인
    { t: 'B', c: 14, r: 9 },              // 벽돌
    { t: 'M', c: 17, r: 9 },              // 버섯(파워업) 블록
    { t: 'S', c: 39, r: 11 },             // 돌 블록(고정 발판)
    { t: 'e', c: 21, r: 11 }              // 적
  ],
  pipes: [ { c: 23, top: 10, h: 2 }, { c: 54, top: 8, h: 4 } ], // 파이프
  goal:  { c: 124 }, // 깃대
  start: { c: 2, r: 11 } // 플레이어 시작
};
```

**난이도 노브(이 스키마로 조절 가능한 변수):** 구덩이 폭/연속 수(`pits`), 공중 발판 간격·높이(`features`의 `c`/`r`), 적 밀도(`t:'e'` 수와 간격), 발판 길이(`S`/`B` 연속 수), 파이프 높이(`pipes.h`). 모든 노브는 결국 **점프 아크** 안에 들어와야 공정하다(아래 §1 참조).

> 좌표 헬퍼: `cx(col)=col*TILE+TILE/2`, `cy(row)=row*TILE+TILE/2`. 화면 1폭 = `DESIGN_W/TILE = 24타일`이므로 "한 화면"은 곧 24열이다 — 페이싱·체크포인트 간격의 기본 단위로 쓴다.

## 1. 점프 아크 — 모든 메트릭의 기준

플랫포머 레벨의 모든 거리 수치(구덩이 폭, 공중 발판 간격, 코인 호 높이)는 **플레이어의 점프 아크 안에** 들어와야 한다. 아크 밖이면 "닿을 수 없는 배치"가 되어 LD-FAIR가 무너진다. 따라서 레벨을 그리기 전에 엔진의 점프 메트릭을 먼저 계측한다.

**정의.** 점프 최대 높이·거리는 `GRAVITY`(super-runner=1100)와 점프 임펄스 속도, 그리고 수평 이동 속도로 결정되는 포물선이다. 물리 공식으로 근사 계측한다.

**구체 규칙(아크 계측 → 배치 한계 도출).**

```js
// 점프 아크 계측 (Arcade, 단위: px·s). engine/ 점프 임펄스 vJump, GRAVITY 기준.
var GRAVITY = 1100, vJump = 380 /* setVelocityY(-vJump) */, vRun = 150 /* px/s 최대 수평 */;
var tApex   = vJump / GRAVITY;                 // 정점까지 시간 ≈ 0.345s
var hMax    = (vJump * vJump) / (2 * GRAVITY); // 최대 높이 ≈ 65.6px ≈ 4.1타일
var tAir    = 2 * tApex;                        // 평지 체공 ≈ 0.69s
var dMax    = vRun * tAir;                      // 최대 수평 도달 ≈ 103px ≈ 6.5타일
// → 안전 한계: 구덩이/간극은 dMax의 70%(≈4.5타일) 이내가 '도입~전개'용,
//   dMax의 90%(≈5.8타일)는 '정점 챌린지' 전용. 100%는 쓰지 않는다(입력 오차 여유).
```

| 배치 항목 | 점프 아크 기준 한계 | super-runner 환산(≈) |
|---|---|---|
| 구덩이 폭(도입·전개) | `dMax × 0.7` 이내 | ≤ 4~5타일 |
| 구덩이 폭(정점 챌린지) | `dMax × 0.9` 이내 | ≤ 5~6타일 |
| 공중 발판 수직 간격 | `hMax` 이내 | ≤ 4타일 |
| 코인 호 정점 높이 | 점프 정점 `r` = `groundTop − hMax/TILE` | 바닥 row12 → 정점 ≈ row8 |

> super-runner의 실제 구덩이는 `[27,29]`(폭3), `[58,60]`(폭3), `[88,90]`(폭3), `[104,105]`(폭2)로 전부 4타일 미만 — 점프 아크 70% 안쪽의 보수적 배치다. 새 구덩이를 추가할 때도 이 한계를 넘기지 않는다.

**우리 엔진 적용.** 점프 임펄스/중력은 [`level-designer`](../../../level-designer/SKILL.md)가 빌드하는 컨트롤러 층의 값이다. 레벨 데이터(`pits`/`features`)는 이 계측값을 상수로 받아 배치 한계를 도출한다. Arcade 물리는 가변 dt라 완전한 결정성이 없으므로 한계치에 여유(70/90%)를 둔다. 정밀 강체가 필요 없으니 Matter는 ⚠️ — 단순 임펄스(`body.setVelocityY`)로 충분하다.

**주의/안티패턴.** ❌ 아크 100%를 요구하는 픽셀-프레임 점프(억울한 죽음). ❌ 수직 간극이 `hMax`를 넘는 발판(닿을 수 없음). ❌ 가속(관성)을 무시한 거리 계산 — super-runner는 마리오류라 약간의 관성이 있으므로 정밀 점프 구간은 발판을 한 칸 넓게.

## 2. 게임필 관용 — 레벨 디자인의 전제 조건

코요테 타임과 점프 버퍼는 **레벨 디자인이 아니라 컨트롤러 층의 일**이지만, 이게 없으면 아무리 공정하게 배치해도 "억울한 죽음"이 생겨 LD-FAIR(§7)가 통째로 무너진다. 그래서 레벨을 그리기 전에 이 관용 장치부터 확보한다.

**정의.** 코요테 타임 = 발판을 벗어난 직후 짧은 시간 동안 점프 입력을 받아주는 관용. 점프 버퍼 = 착지 직전에 미리 누른 점프를 착지 순간 자동 발동.

**왜 통하나.** GMTK 'Improve Your Game Feel With Coyote Time and Jump Buffering'에서 정리된 통념 — 인간의 입력은 항상 몇 프레임 어긋나므로, 이 관용이 없으면 "분명 눌렀는데 안 뛴" 좌절이 누적된다. 통상 인용값은 코요테 ≈0.1s, 버퍼 ≈0.12s이지만 게임마다 다르므로 **권장 시작값**일 뿐 표준은 아니다(정밀 플랫포머는 더 짧게).

**구체 규칙(체크리스트).**
- [ ] 코요테 타임 ≈0.1s(super-runner GRAVITY=1100 기준 약 6프레임) 확보.
- [ ] 점프 버퍼 ≈0.12s 확보.
- [ ] 구덩이 직전 발판 끝에서 한 프레임 늦게 뛰어도 살 수 있어야 한다(코요테로 흡수).
- [ ] 관용값은 컨트롤러 상수로 분리해 한 곳에서 튜닝.

**우리 엔진 적용.** [`level-designer`](../../../level-designer/SKILL.md)의 hero 컨트롤러에서 `lastGroundedAt`/`jumpBufferedAt` 타임스탬프로 구현. 레벨 데이터는 이 값을 전제로 구덩이/발판 끝 위치를 잡는다.

**주의/안티패턴.** ❌ 관용 없이 픽셀-프레임 정밀을 요구해 억울한 죽음 양산. ❌ 코요테를 0.3s+로 과하게 줘 "공중에서 뛰는 버그"처럼 보임.

## 3. LD-4BEAT — 4단 비트로 한 메카닉 전개 (도입→전개→비틀기→마무리)

**정의.** 한 레벨(또는 구간)을 하나의 메카닉을 위한 4부 구조로 짠다. (1) **도입**: 안전한 곳에서 메카닉을 처음 보여주고 만지게 한다. (2) **전개**: 같은 메카닉을 약간 더 복잡한 시나리오로 늘린다. (3) **비틀기**: 메카닉을 예상치 못한 방식으로 뒤집어 다시 생각하게 한다. (4) **마무리**: 숙련을 증명하는 정점 챌린지를 준 뒤 그 메카닉을 버리고 다음으로 넘어간다.

**왜 통하나.** 이 도입→전개→비틀기→마무리(introduction/development/twist/resolution) 4단 구조는 닌텐도식 레벨 설계 방법론이다. 키쇼텐케츠(kishōtenketsu, 起承轉結 — 만화 4컷 서사 구조, Miyamoto의 어린 시절 만화 경험에서 유래)를 레벨에 명시적으로 적용한 것은 닌텐도 디렉터 Koichi Hayashida로, 그가 1차로 정식화·진술한 출처는 GDC 2012 발표와 Christian Nutt의 2012년 Gamasutra/Game Developer 인터뷰(대상 게임은 Super Mario 3D Land)다. Mark Brown의 Game Maker's Toolkit 'Super Mario 3D World's 4 Step Level Design'(2015)은 이 개념을 4단계로 정리해 **대중화·해설**한 2차 자료이며, 영상 스스로도 구조를 Hayashida에게 귀속한다. 약 5분짜리 자기완결 쇼케이스로 메카닉을 가르치고→전개하고→비틀고→버린다는 게 핵심이다.

**구체 규칙(체크리스트).**
- [ ] 한 레벨을 가로 4구간으로 등분(super-runner `width=132` 기준 ≈ 33타일/구간, 경계 `0–33 / 33–66 / 66–99 / 99–132`).
- [ ] 구간1 도입부에는 절대 적/구덩이를 두지 않는다(현 super-runner는 col 6~10에 코인/물음표만 두고 첫 적 `e`를 col 21에 둠 — 올바른 패턴).
- [ ] 구간3 비틀기에는 그 레벨에서 **단 한 번만** 쓰는 변형 배치(예: 폭3 구덩이를 연속 2개로, 또는 발판 간격을 점프 한계 직전까지).
- [ ] 마무리 정점은 도입~전개에서 가르친 요소만 조합 — 새 요소를 정점에 처음 등장시키지 않는다.

**우리 엔진 적용 — super-runner를 4비트 타임라인으로 주석화.**

```js
// LEVEL을 4분할 경계(0–33 / 33–66 / 66–99 / 99–132)에 맞춰 비트 주석
// ───── 도입(0–33): 위협 0, 기믹 첫 등장 ──────────────────────────
{ t: 'o', c: 6, r: 9 }, { t: '?', c: 8, r: 9 }, { t: 'o', c: 10, r: 9 }, // 코인·물음표만
{ t: 'e', c: 21, r: 11 },                                              // 첫 적(안전 거리 뒤)
// pits[0]=[27,29] 위 코인 아치 → 점프 메카닉 첫 시험
// ───── 전개(33–66): 기믹 + 적/구덩이 결합 ────────────────────────
// 돌계단(39~42) 오르기 + 공중 발판(45~49) + 그 위 적(47,r5)
// pits[1]=[58,60] + 적 무리(66,68)
// ───── 비틀기(66–99): 변형 1회 ──────────────────────────────────
// 물음표 3연속(70~72) → 더 높은 계단(75~79, 5단) → pits[2]=[88,90]
// ───── 마무리(99–132): 정점 후 골 ───────────────────────────────
// pits[3]=[104,105] + 적(99,101) → 보상 코인 길(108~110) → 골계단(113~116) → goal c124
```

다른 스키마로의 일반화: **is-rule**은 `LEVELS[]` 각 항목을 한 비트로 보고 4개 레벨이 한 메카닉의 도입→전개→비틀기→정점이 되게 `par`를 점증. **runeburst**는 한 스테이지 묶음(4개 `LEVELS`)을 새 블로커 1종의 4비트로(ice 도입→ice+이동수 압박→ice+spreader 비틀기→종합).

**주의/안티패턴.** ❌ 한 레벨에 메카닉 2개 이상을 가르치려다 4비트 붕괴(LD-ONE-IDEA 위반). ❌ 비틀기를 그냥 "더 많이/더 빨리"로만 처리(양적 증가일 뿐 개념 전복이 아님 → 놀라움 상실). ❌ 마무리 정점이 도입보다 쉬워 카타르시스 없음.

## 4. LD-TEACH — 무텍스트로 가르치기 (안전한 첫 등장 공간)

**정의.** 새 메카닉/기믹은 죽음 위험이 없는 '안전 공간'에서 처음 등장시켜, 텍스트 튜토리얼 없이 직접 만지며 규칙을 체득하게 한다. 첫 등장은 항상 실패해도 손해가 없는 맥락에 둔다.

**왜 통하나.** Maddy Thorson의 GDC 2017 'Level Design Workshop: Designing Celeste'의 핵심 원칙 — 각 새 메카닉은 죽음을 두려워하지 않고 익힐 수 있는 안전 공간에서 도입된다. 닌텐도 4단계의 1단계(도입)도 "안전한 곳에서 가르친다"가 명시적 전제다. Miyamoto/Hayashida 철학과 Celeste가 독립적으로 같은 결론에 도달했다. 이는 TV Tropes에서 'Antepiece'(레벨이 앞으로 올 기믹을 자기 디자인으로, 흔히 위험 없는 형태로 미리 예고·연습시키는 'Instructive Level Design'의 sub-trope)로도 정리된 기법으로, 자주 인용되는 예시는 Mega Man X1의 안전한 구덩이 Wall Jump 연습이다.

**구체 규칙(체크리스트).**
- [ ] 기믹 첫 등장 타일 아래에는 반드시 바닥(`groundTop`)이 있고 구덩이/적이 없어야 한다.
- [ ] 첫 등장은 '선택적'으로 시작 — 밟지 않아도 통과 가능하게 해 관찰만으로 학습 가능하게.
- [ ] 치명적 변형(구덩이 위 점프 발판, 적이 올라탄 발판)은 동일 기믹을 안전 맥락에서 1회 이상 본 다음에만.
- [ ] 도입 구간 길이는 최소 4~6타일 확보해 "한 번 만져보고 실수해도 회복"할 여유.

**우리 엔진 적용.** super-runner에서 새 `feature` 타입(예: 움직이는 발판)을 추가하면, 첫 인스턴스를 `pits` 바깥의 `groundTop` 위 `col`에 배치하고 같은 화면(24타일) 안에서 두 번째 인스턴스부터 구덩이/적과 결합. is-rule: 새 `'X IS Y'` 규칙 레벨은 `par`를 낮게(2~3) 잡고 격자에 함정(`w`물, 떨어지는 길) 없이 규칙 변형만으로 풀리게 `ent` 구성. runeburst: 새 블로커는 첫 등장 레벨에서 `moves`를 넉넉히(goal 대비 +30%) 줘 실험 여유.

**주의/안티패턴.** ❌ 텍스트 팝업으로 가르치고 안전 공간 생략(체화 안 됨). ❌ 첫 등장과 동시에 처벌(구덩이 위)을 줘 관찰 학습 박탈. ❌ 안전 공간이 너무 길어 지루(LD-PACING 충돌 → 한 화면 내로 제한).

## 5. LD-ONE-IDEA — 한 레벨 한 개념

**정의.** 레벨(또는 명확히 구분된 구간)마다 새 아이디어/메카닉을 단 하나만 도입한다. 4비트로 소진한 뒤 버리고, 다음 레벨에서 새 개념 하나를 다시 도입한다.

**왜 통하나.** Hayashida: 각 레벨은 "처음에 명확한 컨셉을 잡고 그걸 끝까지 일관되게 끌고 간다." 4단계는 '하나의 새 아이디어를 위한 자기완결 쇼케이스'이므로, 한 번에 하나만 가르쳐야 4비트가 성립하고 학습 부하가 관리된다. Celeste도 각 챕터가 한 메카닉(점프, 대시 패널, 바람, 거울 등)을 중심으로 구성된다.

**구체 규칙(체크리스트).**
- [ ] 한 레벨에서 '플레이어가 처음 보는 것'은 1종으로 제한 — 나머지는 이미 가르친 요소의 재조합.
- [ ] 익힌 메카닉 A + 새 메카닉 B 조합은 B를 단독으로 한 레벨 가르친 뒤에만.
- [ ] 수집물/장식은 '새 개념'으로 세지 않음 — 새 개념 = 새 행동을 요구하는 규칙/기믹/적 타입.
- [ ] 게임 전체의 메카닉 등장 순서를 명시적 표로 관리(레벨별 신규 1개).

**우리 엔진 적용.** is-rule에 가장 직접적이다 — `LEVELS[]` 각 레벨은 `texts[]`로 단 하나의 새 `'X IS Y'` 규칙만 도입(예: 레벨N은 `WALL IS PUSH` 하나). super-runner는 단일 레벨이므로 `features` 종류를 도입 순서대로 — `col` 오름차순으로 새 타입이 한 번에 하나씩만 처음 등장. runeburst: 한 `LEVELS` 항목당 신규 블로커 1종 또는 `win.type` 변경 1개만.

**주의/안티패턴.** ❌ 초반에 욕심내 여러 기믹을 몰아넣음(무엇을 배우는지 불명확). ❌ '개념'을 너무 잘게 쪼개 거의 같은 레벨 반복(LD-VARIETY 위반). ❌ 새 개념과 변형 혼동 — 같은 메카닉의 변형은 같은 레벨 안 전개/비틀기로 처리.

## 6. LD-CURVE & LD-FLOW-CHANNEL — 톱니형 난이도와 몰입 채널

### 6.1 LD-CURVE — 톱니형 난이도 곡선(sawtooth)

**정의.** 난이도를 단조 상승이 아니라 톱니형으로 짠다: 챌린지 제시 → 마스터(승리감) → 곧바로 약간 더 어려운 변형 → 다시 마스터. 전체 추세는 우상향이되 각 봉우리 뒤에 완화가 들어가 상승-하강을 반복한다.

**왜 통하나.** Flow 이론(Mihaly Csikszentmihalyi)의 게임 적용 — 도전>실력이면 불안, 실력>도전이면 지루함. 톱니형은 매 봉우리에서 실력을 끌어올린 뒤 잠깐 낮춰 성장을 체감(승리감)하고 다음 봉우리로 진입하게 한다. 매크로플로우(난이도 곡선)와 마이크로플로우(짧고 강렬한 반복 성취)의 결합(Jenova Chen, 'Flow in Games' MFA 논문). 'sawtooth'라는 구체 표현 자체는 Csikszentmihalyi 원전이 아니라 게임 디자인 2차 문헌의 해석이다.

### 6.2 LD-FLOW-CHANNEL — 불안과 지루함 사이

**정의.** 플레이어를 도전(challenge)과 실력(skill)이 균형 잡힌 좁은 '몰입 채널' 안에 머물게 한다. 채널 위(도전>실력)는 불안, 아래(실력>도전)는 지루함.

**왜 통하나.** 도전과 실력의 균형이 불안과 지루함을 가르는 flow(몰입) 채널 개념은 Csikszentmihalyi가 1970년대에 정식화한 flow 이론(1975년 'Beyond Boredom and Anxiety: Experiencing Flow in Work and Play'에서 처음, 1990년 'Flow: The Psychology of Optimal Experience'에서 체계화·대중화)에 기반한다. 원본 1975년 도식은 challenge-skill 평면을 anxiety / flow / boredom의 단순 3구역으로 나누었고, 1987년 Massimini·Csikszentmihalyi·Carli가 이를 8가지 정서 상태로 세분한 'Eight Channel Model(8채널 모델)'로 발전시켰다 — 즉 흔히 인용되는 정식 도식은 8채널 모델이다. Jesse Schell은 'The Art of Game Design: A Book of Lenses'에서 이 flow를 도전 상승→보상→완화가 반복되는 'tense and release(긴장과 이완)' 사이클로 설명하며 진동을 통해 플레이어를 채널 안에 유지하라고 처방했다(이는 flow의 대안이 아니라 flow를 실현하는 같은 개념의 표현이다).

**구체 규칙(체크리스트).**
- [ ] 각 봉우리(고난도 챌린지) 직후 1~2개의 쉬운 비트를 넣어 곡선을 잠시 내린다.
- [ ] 다음 봉우리는 직전보다 '한 단계만' 높게 — 점프 거리/적 밀도/구덩이 폭 중 **한 변수만** 증가.
- [ ] 레벨 시작 난이도는 직전 레벨 정점보다 낮게 리셋(톱니의 하강 시작점).
- [ ] 예상 클리어 시도 횟수를 채널 지표로 — 한 챌린지가 3~10회 시도 내 클리어되게(즉시 통과=지루, 20회+=불안).
- [ ] 쉬운 우회로(저위험 경로)와 선택적 고난도 경로를 병행해 여러 실력대를 한 채널에 수용.

**우리 엔진 적용.** super-runner는 `col` 순서가 곧 시간축이므로 봉우리(연속 구덩이/좁은 발판) 뒤에 평지+코인 구간을 넣어 하강을 만든다 — `pits` 폭을 점증하되 정점 뒤엔 폭을 줄이거나(예: `[104,105]` 폭2는 후반 완화) 평지를 둔다. 메인 통로는 채널 중앙, 위쪽 공중 발판(`col 45~49 row6` + 코인 `row4`)은 고위험(채널 상단·코인 보상), 아래 평탄 통로는 저위험으로 한 레벨이 여러 실력대를 수용. runeburst: `moves` 여유로 채널 폭 조절(어려운 `goal`엔 `moves`를 약간 더). is-rule: `par`보다 많은 이동으로도 클리어 가능하게(`par`는 별점 목표일 뿐 통과 조건 아님).

**난이도 곡선 표 — super-runner 132타일 적용.**

| 구간(col) | 4비트 | 강도 | 배치 처방(LD-*) |
|---|---|---|---|
| 0–33 | 도입 | 낮음→약간↑ | 위협 0(LD-TEACH) · 코인/물음표 · 첫 적 col21 · 첫 구덩이 위 코인 아치(LD-SIGNPOST) |
| 33–66 | 전개 | 중간(↑↓ 1파동) | 계단+공중 발판(LD-RISK-PATH) · 구덩이+적 무리 · 직후 코인 평지 쉼표(LD-REST) |
| 66–99 | 비틀기 | 높음(정점 진입) | 5단 계단·물음표 3연속·연속/근접 구덩이 1회 변형(LD-CURVE 봉우리) |
| 99–132 | 마무리 | 정점→완화→골 | 정점 챌린지(폭2 구덩이+적) → 보상 코인 길 → 골계단 완화(LD-PACING) → goal |

**주의/안티패턴.** ❌ 단조 우상향(매 레벨 무조건 더 어려움 → 누적 피로로 이탈). ❌ 하강을 너무 깊게 줘 지루(실력≫도전). ❌ 여러 변수를 동시에 올려 난이도 점프가 통제 불능. ❌ 채널 폭이 너무 좁아(정밀 입력만 허용) 약간의 실수로 곧장 불안.

> 모바일 주의: '난이도 스파이크가 최근 성공과 정합되지 않으면 이탈률이 최대 34% 상승' 같은 수치가 블로그류로 떠돌지만, 검증 가능한 1차 출처가 없는 미검증 통계다 — 의사결정 근거로 인용하지 말고, 곡선은 위 LD-CURVE 원칙과 실제 LD-PLAYTEST로 잡는다.

## 7. LD-FAIR & LD-CHECKPOINT — 공정성과 실패 비용

### 7.1 LD-FAIR — 공정성·안티프러스트레이션 + 즉시 재시도

**정의.** 실패는 항상 회피 가능하고 납득되어야 한다 — 기습/즉사 함정 금지, "내 실수였다"가 즉시 납득되게. 동시에 죽음→재시작 마찰을 거의 0으로(즉시 리스폰).

**왜 통하나.** Super Meat Boy(Edmund McMillen, Tommy Refenes) 'Why So Hard?' — "당신이 한 실수는 당신이 한 실수다." 죽음→리스폰이 거의 즉각적이라 페이스가 끊기지 않고 '한 번 더' 심리가 유지된다. 좌절의 원인은 난이도가 아니라 불공정(기습)과 재시도 마찰이므로 이 둘을 제거하면 고난도도 즐겁다.

**구체 규칙(체크리스트).**
- [ ] 보이지 않는 즉사 요소 금지 — 모든 위험은 화면에 보이고 반응 시간이 있어야 한다.
- [ ] 죽음 후 리스폰은 0.5초 이내, 입력 잠금 최소화(즉시 다시 조작 가능).
- [ ] 구덩이/적은 카메라 진입 후 최소 점프 반응 거리(≈수평속도×0.4s ≈ 2~3타일) 확보 후 도달.
- [ ] 코요테 타임(≈0.1s)·점프 버퍼(≈0.12s)로 아슬아슬한 입력을 살려 억울한 죽음 제거(§2).

### 7.2 LD-CHECKPOINT — 체크포인트·청크 분할

**정의.** 긴/어려운 레벨을 작은 청크로 나누고 각 청크 끝에 체크포인트를 둔다. 죽으면 직전 체크포인트에서 즉시 재개해 어려운 정점에서 죽어도 처음부터 다시 하지 않게 한다.

**왜 통하나.** Super Meat Boy Forever(Refenes)의 진화 — 레벨을 청크로 쪼개 각 청크 클리어 시 체크포인트를 두고 다음 청크에서 죽으면 그 지점에서 즉시 리스폰. 원작 SMB는 짧은 레벨이라 무체크포인트가 가능했지만, 길어지면 체크포인트가 톱니 봉우리마다 '저장점'을 만들어 좌절 누적을 끊는다. 재시도 비용이 낮을수록 고난도에 더 오래 도전한다.

**구체 규칙(체크리스트).**
- [ ] 어려운 정점(연속 구덩이/정밀 점프) **직전**에 체크포인트를 둔다 — 정점에서 죽어도 정점만 재시도.
- [ ] 체크포인트 간격은 '평균 실패 1~3회로 통과 가능한 분량'(대략 한 화면~두 화면 = 24~48타일).
- [ ] 체크포인트는 깃발/빛으로 명확히 표시해 도달 사실을 알린다.
- [ ] 레벨이 한 화면 수준으로 짧으면 체크포인트 없이 즉시 전체 재시작도 허용(SMB 원작식).

**우리 엔진 적용 — super-runner는 width 132로 Mario식 긴 레벨이라 내부 체크포인트가 필수.**

```js
// LEVEL에 체크포인트 배열 추가(스키마 확장) — 4비트 경계 직전에 배치
LEVEL.checkpoints = [{ c: 37 }, { c: 66 }, { c: 99 }]; // 전개/비틀기/마무리 진입 직전

// level-designer 패턴: 비가시 physics zone, 닿으면 리스폰 col 갱신
LEVEL.checkpoints.forEach(function (cp) {
  var zone = this.add.zone(cx(cp.c), cy(10), TILE, LEVEL.rows * TILE);
  this.physics.add.existing(zone, true);
  this.physics.add.overlap(this.hero, zone, function () {
    if (cp.c > (this.run.spawnCol || LEVEL.start.c)) this.run.spawnCol = cp.c;
  }, null, this);
}, this);
// 사망 시: this.hero를 cx(this.run.spawnCol || LEVEL.start.c)에서 리스폰(scene.restart 대신 위치 복원)
```

is-rule: 레벨 단위가 짧아 레벨=체크포인트(죽음 시 해당 레벨만 재시작), undo 제공으로 실수 비용 최소화. runeburst: `moves` 소진=실패 시 같은 레벨 재시작이 곧 체크포인트, 진행한 별/점수 유지(교착 자동 셔플도 안티프러스트레이션 — 플레이어 탓 아닌 실패 제거).

**주의/안티패턴.** ❌ 화면 밖에서 튀어나오는 적/발사체로 기습사(가장 큰 좌절). ❌ 리스폰 시 긴 페이드/연출로 '한 번 더' 흐름 차단. ❌ 체크포인트가 너무 드물어 정점 둘을 한꺼번에 다시(좌절 폭증) 또는 너무 잦아 긴장 희석. ❌ 체크포인트가 위험 직후가 아니라 리스폰 즉시 또 죽는 함정 위치.

## 8. LD-PACING & LD-REST — 페이싱과 쉼표

**정의.** 레벨의 강도(intensity)를 일정하게 두지 않고 상승·하강 파동으로 짠다. 고강도 챌린지 뒤에 쉼표(완화 구간)를 넣어 호흡을 고르고 다시 끌어올린다.

**왜 통하나.** 톱니 곡선(§6)과 짝을 이루는 시간축 리듬 — 마이크로플로우(짧고 강렬한 반복 성취) 사이에 회복을 끼워야 매크로플로우가 지속된다(Jenova Chen). The Level Design Book에 따르면 Valve 디자이너들은 Half-Life 2: Episode Two/Left 4 Dead 페이싱을 위해 비트를 Explore/Combat/Choreo/Puzzle 4종으로 분류하고 X축=시간(분)·Y축=강도(intensity)로 그래프를 그렸다(강도 척도는 0-100% / 0-5 / 0-10 중 선택, 값은 플레이테스트 관찰에서 나오는 '직관' — Valve 내부 실무 관행이 GDC China 2014 'Level Design Workshop: Pacing' 발표로 소개된 것). Left 4 Dead AI Director의 'Relax(이완)' 단계는 GDC 2009 'The AI Systems of Left 4 Dead'(Michael Booth) 1차 슬라이드 기준 '30-45초'(또는 다음 세이프룸까지) 지속한다. 강도 상대성 원리 "항상 11로 틀어놓으면 11이 새로운 5가 된다"는 Mike Stout의 'Trinity, Part 6 - Intensity Ramps'(2015) Principle #5다 — 정점을 살리려면 그 앞뒤를 반드시 낮춰야 한다.

**구체 규칙(체크리스트).**
- [ ] 고강도 구간(연속 구덩이/적 무리) 길이는 ≈한 화면(24타일) 이하로 제한하고, 직후 평지+코인 쉼표를 ½화면(≈12타일) 배치.
- [ ] 강도 파동 주기를 4비트와 정렬 — 비틀기 구간이 강도 정점, 마무리 직전 짧은 쉼표.
- [ ] 쉼표 구간엔 위협 0, 보상(코인/비밀 단서)만 둬 능동적 휴식으로.
- [ ] 골 직전엔 약한 마무리(쉬운 계단)로 안도감 → 클리어 카타르시스 강화.

**우리 엔진 적용.** super-runner의 `features`/`pits` `col` 타임라인을 '강(구덩이군·적 무리) → 약(코인 평지) → 강' 파동으로 편집. 현재 골 직전 돌계단(`col 113~116`)이 마무리 완화 역할이므로 의도적으로 유지. runeburst: 어려운 블로커 레벨 뒤 한 레벨은 `win.type`을 단순 `score`로 풀어 쉼표. is-rule: `par` 높은 퍼즐 뒤 `par` 낮은 '아하' 레벨로 리듬.

**주의/안티패턴.** ❌ 강도를 끝까지 올리기만 해 탈진(쉼표 부재). ❌ 쉼표가 너무 길거나 보상 없어 지루. ❌ 강약 주기가 불규칙해 리듬을 못 만들고 예측 불가 피로.

## 9. LD-SIGNPOST — 코인·색·구도로 길 안내

**정의.** 다음에 어디로 가고 무엇을 할지를 텍스트 없이 시각 신호로 안내한다. 코인을 점프 궤적을 따라 호(arc)로 배치해 '여기로 점프하라'를 알리고, 색/빛/랜드마크로 진행 방향과 관심 지점을 가리킨다.

**왜 통하나.** Super Mario Bros. 분석(Crooked Pixels 'The UX of Super Mario Bros', GMTK) — 코인은 점프해야 할 곳, 관심 지점을 보여주려 전략적으로 배치된다. 코인 호는 점프 아크를 미리 그려주는 비언어적 가이드다(다만 '닌텐도가 의도적으로 설계'라는 귀속은 분석가 해석이며 1차 디자인 문서는 미확인). 길찾기 보조의 효과는 The Level Design Book wayfinding 페이지가 '% certainty'로 분류하되 스스로 'non-scientific estimate(비과학적 추정치)'라 명시한다 — 조명/색 ≈40%, 환경 스토리텔링 ≈50% 식이며, 'Left 4 Dead가 조명 배치로 경로를 암시한다'가 명시적 뒷받침 사례다. 'weenie'(먼 랜드마크로 시선을 끄는 장치)는 디즈니랜드 설계 개념을 Scott Rogers가 'Level Up!'에서 레벨 디자인에 차용·대중화한 것이다.

**구체 규칙(체크리스트).**
- [ ] 구덩이 위에는 점프 정점 높이를 따라 코인 3개를 호(arc)로 배치(가운데 코인이 가장 높음) — 점프 거리/타이밍 시각화.
- [ ] 다음 발판/진행 방향에 코인 1~2개를 '미끼'로 둬 시선을 끈다.
- [ ] 위험 직전 코인은 안전한 도약 시작점 위에 둔다 — 코인을 먹으려 서면 자연히 올바른 위치.
- [ ] 큰 보상의 비밀 경로 입구에는 코인 1개를 단서로 노출(LD-SECRET 유도).

**우리 엔진 적용 — super-runner는 이미 이 패턴 사용 중.**

```js
// 구덩이 [27,29] 위 코인 아치 — 가운데(col28)가 r7로 가장 높아 점프 궤적을 그림
{ t: 'o', c: 27, r: 8 }, { t: 'o', c: 28, r: 7 }, { t: 'o', c: 29, r: 8 },
// 신규 구덩이마다 동일하게 코인 3개 호를 강제하는 헬퍼
function coinArc(features, startCol, groundRow) { // 폭3 구덩이 기준
  features.push({ t: 'o', c: startCol,   r: groundRow - 4 });
  features.push({ t: 'o', c: startCol+1, r: groundRow - 5 }); // 정점(점프 아크 안)
  features.push({ t: 'o', c: startCol+2, r: groundRow - 4 });
}
```

is-rule: 'X IS WIN' 깃발(`f`)을 밝은 색/중앙 배치로 목표를 시그널, 밀어야 할 `text` 블록을 통로 시야선에. runeburst: 목표 색/블로커를 보드 중앙·상단에 모아 시선 유도.

**주의/안티패턴.** ❌ 코인을 장식으로 무작위 배치(잘못된 곳으로 점프 유도=안티-시그널). ❌ 구덩이 위 코인 호 정점이 실제 점프 최대 높이와 안 맞아 '먹으려다 죽음'. ❌ 신호가 과해 화면이 산만(진짜 위험 신호가 묻힘).

## 10. LD-RISK-PATH & LD-SECRET — 위험-보상 분기와 비밀 경로

**정의.** 메인 통로 외에 선택적 고위험-고보상 경로를 둔다. 위쪽 공중 발판처럼 떨어질 위험이 큰 대신 코인/파워업/숨은 보상을 주는 갈림길을 만들어, 실력과 욕심에 따라 위험 수준을 스스로 선택하게 한다. 일부는 숨겨 탐험 동기를 만든다.

**왜 통하나.** Super Mario World의 비밀 출구·숨은 영역 — 선택적 경로는 일부 진행을 열고 일부는 대체 보상을 준다. 고위험 경로는 고수에게 채널 상단의 도전을(LD-MASTERY-CEILING), 저위험 메인 경로는 초심자를 채널 안에 둔다 — 단일 레벨이 여러 실력대를 동시에 만족시키는 핵심 장치.

**구체 규칙(체크리스트).**
- [ ] 공중 발판 보너스 경로는 메인 지면 경로와 병행하되, 진입에 점프 정밀도를 요구하고 떨어지면 메인 경로로 복귀(즉사 아님).
- [ ] 고위험 경로의 보상은 메인보다 명확히 커야(코인 다발/파워업/지름길) 위험을 정당화.
- [ ] 비밀 경로 입구엔 미세 단서(어긋난 블록, 코인 1개, 색 변화)만 노출 — 너무 숨기면 발견 0, 너무 드러내면 비밀 아님.
- [ ] 고위험 경로 실패의 벌은 '시간 손해/보상 미획득'이지 죽음이 아니게(공정성).

**우리 엔진 적용.** super-runner의 공중 벽돌 플랫폼(`col 45~49 row6` + 위 코인 `row4` + 숨은 `'M'` 버섯 `col47`)이 이미 위험-보상 분기 — 떨어져도 지면 메인 경로로 복귀. 이 패턴을 레벨당 1~2개로 표준화하고 `'M'`(파워업)을 고위험 경로 끝에 보상으로. is-rule: `par`보다 적은 이동의 우아한 해법을 '숨은 고보상 경로'로(별 3개), 안전한 다수 이동 해법은 메인. runeburst: 위험한 연쇄(블로커 인접)를 노리면 큰 콤보 보상, 안전 매치는 적은 점수.

**주의/안티패턴.** ❌ 고위험 경로 실패가 즉사(위험-보상이 아니라 처벌). ❌ 보상이 위험에 비해 빈약(아무도 안 감). ❌ 비밀 단서 전무로 발견율 0 또는 너무 노골적이라 비밀 의미 상실.

## 11. LD-MASTERY-CEILING — 숙련 천장

**정의.** 기본 클리어는 누구나 가능하되, 숙련자가 더 잘 해낼 여지(스피드런 라인, 노미스, 모든 비밀 수집, 어려운 지름길)를 남긴다. 천장을 높여 반복 플레이와 자기 도전의 동기를 만든다.

**왜 통하나.** Maddy Thorson(GDC 'Designing Celeste') — 스피드러너를 위한 설계, 암벽등반에서 온 영감, 여러 플레이 옵션 제공으로 각 레벨이 '여러 방식으로 풀 수 있는 작은 스토리'다. Super Meat Boy의 40+회 리플레이 동시 재생(Refenes)도 마스터리 가시화 장치 — 자기 성장을 보여줘 천장에 도전하게 한다. 코요테/버퍼 같은 관용은 초심자를 돕지만(LD-FAIR), 정밀 라인은 고수에게 보상을 남긴다.

**구체 규칙(체크리스트).**
- [ ] 메인 클리어 외에 '타임 어택' 또는 '노데스' 같은 부가 목표를 레벨에 부여(가시 지표 제공).
- [ ] 숙련자만 닿는 지름길/연속 점프 라인을 비밀 경로로 심되 필수는 아니게.
- [ ] 수집물 100% 같은 완전 클리어 목표로 반복 동기 부여.
- [ ] 클리어 후 기록(시간/사망 수/수집률)을 보여줘 자기 개선을 가시화.

**우리 엔진 적용.** super-runner: 클리어 시 경과 시간·코인 수집률·사망 수를 기록/표시(마스터리 지표는 서버 ❌ → `localStorage` 로컬 베스트로 대체), `'M'` 버섯 + 모든 코인 100% 수집을 선택 목표로, 공중 경로를 끊김 없이 달리는 지름길 라인을 의도적으로 설계. runeburst: 별 3개(낮은 이동/높은 점수) 목표가 곧 천장 — `moves`를 빡빡히 줘 최적 플레이 보상. is-rule: `par` 이동수 달성=마스터리, `par` 미만의 '천재 해법'을 여지로.

**주의/안티패턴.** ❌ 기본 클리어조차 정밀을 요구해 천장이 곧 바닥(초심자 진입 차단). ❌ 마스터리 지표를 안 보여줘 도전 동기 부재. ❌ 숨은 천장 라인이 실은 불가능/버그성이라 좌절.

## 12. Worked example — super-runner LEVEL을 LD-* 로 재해석

현재 `games/super-runner/game.js`의 `LEVEL`을 시간축(`col`)으로 펼쳐 어떤 원칙이 어디에 박혀 있는지 표로 읽는다.

| col | 요소(스키마) | 비트(LD-4BEAT) | 적용 원칙 |
|---|---|---|---|
| 2 | `start{c:2,r:11}` | 도입 | 안전 스폰(LD-FAIR) |
| 6–10 | 코인·물음표(`o`,`?`) | 도입 | 위협 0 첫 등장(LD-TEACH) |
| 14–18 | 벽돌·버섯 클러스터(`B`,`?`,`M`) | 도입 | 파워업 첫 노출(LD-SIGNPOST) |
| 21 | 첫 적(`e`) | 도입 | 안전 거리 뒤 위협(LD-FAIR) |
| 23 | 파이프 `{c:23,top:10,h:2}` | 도입 | 낮은 장애물 예고(LD-FORESHADOW) |
| 27–29 | 구덩이 + 코인 아치(`r8/r7/r8`) | 도입→전개 | 점프 첫 시험·시선 유도(LD-SIGNPOST) |
| 39–42 | 4단 계단(`S`) | 전개 | 수직 이동 전개 |
| 45–49 | 공중 발판 + 코인 `r4` + 숨은 `M` + 적 `r5` | 전개 | 위험-보상 분기(LD-RISK-PATH) |
| 58–60 | 구덩이 + 적 무리(66,68) | 전개 | 강도 1파동(LD-PACING) |
| 70–72 | 물음표 3연속 + 5단 계단(75–79) | 비틀기 | 변형·정점 진입(LD-CURVE 봉우리) |
| 88–90 | 구덩이 | 비틀기 | 정점 챌린지 |
| 95–101 | 벽돌·적 2(`99,101`) | 마무리 | 종합 시험 |
| 104–105 | 폭2 구덩이 | 마무리 | 완화된 정점(톱니 하강) |
| 108–110 | 보상 코인 길 | 마무리 | 쉼표·보상(LD-REST/LD-REWARD) |
| 113–116 | 골 직전 돌계단 | 마무리 | 안도 연출(LD-PACING) |
| 124 | `goal{c:124}` | — | 클리어 카타르시스 |

**진단 시 사용법:** 레벨이 "단조롭다/억울하다"는 피드백이 오면 이 표로 (1) 위협 0 도입 구간이 있는지(LD-TEACH), (2) 봉우리 뒤 쉼표가 있는지(LD-PACING), (3) 구덩이 폭이 점프 아크 70~90% 안인지(§1), (4) 코인 호 정점이 실제 점프 높이와 맞는지를 점검한다.

## 13. 절차생성 주의 — 원칙을 생성 제약으로 코드화

WebGameForge는 CC0 절차생성을 표방하므로, 위 원칙을 **무작위 배치가 아니라 생성기의 제약(constraint)**으로 코드화해야 절차생성이 디자인 품질을 유지한다.

```js
// 절차생성 플랫포머 구간 생성기 — LD-* 를 제약으로 강제
function genSegment(rng, beat /* 'intro'|'develop'|'twist'|'final' */, groundRow) {
  var feats = [], pits = [];
  if (beat === 'intro') return { feats: feats, pits: pits }; // LD-TEACH: 도입엔 위협 0
  // 구덩이 폭: 점프 아크 이내로 클램프 (LD-FAIR / §1)
  var maxPit = (beat === 'twist' || beat === 'final') ? 5 : 4; // 90% vs 70%
  var w = 2 + Math.floor(rng() * (maxPit - 1));
  pits.push([10, 10 + w - 1]);
  coinArc(feats, 10, groundRow);          // LD-SIGNPOST: 구덩이 위 코인 호 강제
  if (rng() < 0.4) feats.push({ t: 'M', c: 6, r: groundRow - 3 }); // LD-RISK-PATH 보너스
  return { feats: feats, pits: pits };
}
```

**생성기 제약 체크리스트.**
- [ ] **도입 구간엔 위협 금지**(`beat==='intro'`는 적/구덩이 미생성).
- [ ] **구덩이 위엔 코인 호 강제**(생성 직후 `coinArc` 호출).
- [ ] **연속 구덩이 폭은 점프 아크 이내**로 클램프(도입·전개 70%, 정점 90%).
- [ ] **교착 방지**: 발판 간 최대 수직 간극 ≤ `hMax`, 다음 발판은 반드시 점프 아크 안.
- [ ] **시드 재현**: 같은 `seed`면 같은 레벨(서버 ❌ → 시드+`localStorage`로 베스트 기록). runeburst의 `seed` 필드가 같은 패턴.

## IP 안전 메모

레벨 디자인 **원칙·기법·메카닉**(4비트, 안전 도입, 코인 호 시선 유도, 톱니 곡선, 위험-보상 분기, 점프 관용)은 저작권 보호 대상이 아니므로 자유롭게 차용한다. 다만 **특정 상용 게임의 고유 레벨 레이아웃**(마리오 1-1의 정확한 블록 배치, 특정 Celeste 챕터 등)을 그대로 복제하지 않는다 — 기법만 가져와 절차생성/오리지널 배치로 재구성하고, 고유명(캐릭터·스테이지명)·에셋(스프라이트·BGM)은 PixelForge/ChipAudio 절차생성(CC0)으로 환기한다. super-runner가 '빨간 모자 러너'로 색 단서 1개만 남기고 나머지를 바꾼 방식이 표준이다. 상세는 [`ip-license-guard`](../../../ip-license-guard/SKILL.md). (법률 자문 아님 — 공개 분석·디자인 통념을 한글로 소화한 자료다.)
