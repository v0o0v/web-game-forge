# 레벨 디자인 인터뷰 (Deep Interview 적응판 · 탑다운 · 의도 주도)

> [`level-architect`](../SKILL.md)의 **'1) 의도 분석 + 인터뷰'** 단계를, **탑다운으로 모호성이 풀릴 때까지
> 끈질기게 묻는 1문1답 인터뷰**로 수행하는 플레이북.
> oh-my-claudecode `deep-interview`(Socratic 1문1답 + 약점 차원 타깃 + 챌린지 모드 + 준비도 게이팅)와
> web-game-builder [game-interview.md](../../web-game-builder/reference/game-interview.md)를 **레벨 설계**에 적응시켰다.
> 차이: 게임 인터뷰가 *어떤 게임을* 만들지를 캔다면, 이 인터뷰는 *이미 있는 게임에 어떤 레벨을* 왜 추가할지를 캔다.
>
> **언제 쓰나:** "레벨 하나 더", "더 어렵게", "재밌는 스테이지 추가해줘"처럼 요청이 모호하거나, 아래 차원이 비어 있을 때.
> 요청이 이미 구체적이면(목적·곡선상 위치·메카닉·난이도·개수가 다 적혀 있으면) 인터뷰를 건너뛰고 바로 설계한다.
>
> 자동 트리거 아님. SKILL.md '1) 의도 분석' 에서 **온디맨드 Read** 로 부른다.

---

## 0. 이 인터뷰의 3대 정신

1. **분석을 먼저 깔고 탑다운으로 내려간다.** 스킬 0단계(현재 게임 분석)가 끝난 상태에서 시작한다 — 장르·스키마·메카닉·기존 곡선을 이미 안다.
   그 위에서 **레벨의 목적(왜 이 레벨인가)** 부터 묻고 → 곡선상 위치 → 메카닉 → 난이도·페이싱 → 목표·예산 → 개수·삽입지점 순으로 *좁혀* 내려간다.
   위(의도)가 흔들리면 아래(난이도 수치)를 물어봐야 소용없다.
2. **Claude가 먼저 구체안을 제안한다(백지 금지).** 분석으로 얻은 정보 + `LD-*` 원칙으로 *이 게임의 이 자리에 어울리는 레벨 컨셉*을 매 라운드 먼저 제시하고 본인 의견을 밝힌다.
   사용자는 고르거나 비틀거나 자유 입력. "어떤 레벨 원해요?"가 아니라 "이 곡선이면 여기쯤 *얼음 블로커를 처음 소개하는 전개 레벨*이 비어 있는데, 이렇게 가는 건 어떠세요?"로 묻는다.
3. **모호성이 풀릴 때까지 끈질기게.** 한 라운드 한 질문. 추상적 답("그냥 어렵게")은 구체 사례로 되묻는다("어렵게 = 이동수를 18→14로 줄여 빡빡하게? 아니면 얼음 칸을 늘려 푸는 순서를 강제? 둘은 전혀 다른 어려움입니다").
   준비도 게이트(§6)를 통과하기 전엔 설계를 확정하지 않는다.

## 1. 핵심 원칙 (deep-interview에서 차용)

1. **1문1답.** 한 라운드에 질문 하나. 4개를 한 객관식에 욱여넣지 않는다. (L8 재미요소/비밀만 multiSelect 한 질문 허용.)
2. **약점 차원 타깃 + "왜 지금".** 매 라운드 가장 모호하거나 결정적인 차원 하나를 고르고, 왜 지금 이걸 묻는지 한 문장으로.
3. **가정을 드러낸다.** "뭘 원해요?" 대신 "무엇을 전제하나요?"를 묻는다. 추상적 답은 구체 수치/사례로 되묻는다.
4. **Claude가 먼저 참신한 컨셉을 제안.** 분석 정보 + [level-design/](./level-design/INDEX.md) 원칙 기반. 첫 옵션에 "(추천)" + 근거.
5. **안티패턴 가드.** [principles.md](./level-design/principles.md) §3 의 '섞지 말 것'(예: 사고형 퍼즐 + 시간압박, 즉사 + 화면밖 기습)을 내부 가드로. 충돌 의도면 절충 되묻기.
6. **준비도 게이트.** §6 차원이 구체화되기 전엔 설계 확정 금지.
7. **조기 종료 존중.** "알아서/그냥 추가해/충분해"라고 하면 즉시 멈추고, 분석 기반 추천 기본값으로 §7 설계안을 확정해 읽어준 뒤 진행한다.

## 2. 레벨 의도 차원 (탑다운 순서)

위에서부터 캔다(의도 → 위치 → 메카닉 → 난이도 → 목표 → 분량 → 재미·비밀). ✅=구체 확정 · ◻️=미정.

| # | 차원 | 무엇을 확정하나 | 비고 |
|---|---|---|---|
| **L1** | **분석 확인** | 스킬 0단계 분석(장르·스키마·메카닉·목표타입·난이도노브·기존곡선)이 맞는지 사용자 확인 | ★전제. 보통 묻기보다 *읽어주고 확인*. 틀리면 분석으로 회귀. |
| **L2** | **레벨의 목적 / 의도** | 왜 이 레벨인가 — 새 메카닉 소개? 난이도 정점? 휴식? 보스? 분량 확장? 특정 `FE-*` 강조? 리밸런싱? | ★★핵심. 모든 결정의 뿌리. |
| **L3** | **곡선상 위치** | 기존 곡선의 어디 — 도입(튜토리얼)/전개(중반)/정점(후반)/선택적 고난도. 앞뒤 레벨 대비 상대 난이도 | ★필수. LD-CURVE/LD-PACING 처방을 가른다. |
| **L4** | **도입·강조 메카닉** | 이 레벨에서 쓸 메카닉 — 기존 메카닉 조합 vs **신규 1개 도입**(LD-ONE-IDEA). 신규면 어떻게 가르칠지(LD-4BEAT) | ★필수. *없는 메카닉을 발명하지 않는다*(분석 목록 안에서). |
| **L5** | **난이도 · 길이 · 페이싱** | 얼마나 어렵게(이 게임의 난이도 노브로 *구체 수치*) · 한 판 길이(초/분·이동수) · 강도 곡선(꾸준/스파이크/완급) | 추상답 금지 → 노브 수치로. |
| **L6** | **목표 · 자원 예산** | 승리/실패 조건 타입(게임 스키마의 win 타입) + 자원 예산(이동수/par/시간/생명) | 매치3=moves·goal, 소코반=par, 러너=거리. |
| **L7** | **개수 · 삽입 지점** | 몇 개 레벨 · `LEVELS` 배열의 어느 인덱스에 삽입(기존 인덱스 시프트 영향) · 진행/해금 영향 | 1개 vs 미니팩. |
| **L8** | **재미요소 · 비밀** | 강조할 `FE-*`(연쇄/긴장/아하/위험보상 등) + 선택적 경로·비밀·보상(LD-SECRET/LD-RISK-PATH) | multiSelect 한 질문 허용. |

> 게임이 퍼즐이면 L4·L6 가 가장 무겁고(메카닉·해결가능성), 액션이면 L3·L5(곡선 위치·페이싱)가 무겁다.

## 3. 라운드 진행

각 라운드는 `AskUserQuestion` 한 번(질문 1개). 형식:

```
라운드 {n} | 타깃 차원: {L# 이름} | 왜 지금: {한 문장 근거} | 설계 진행: {✅개수}/8

{Claude의 제안·관점 1~2문장 — 분석 정보 + LD-* 근거 + 본인 비틀기·의견}

{질문}
```

- 답을 받으면 그 차원을 ✅로, **다음으로 가장 약한 차원**(보통 탑다운 다음 칸)으로.
- 답이 모호하면 같은 차원을 **구체화 질문**으로 한 번 더(추상→구체 되묻기).
- 안티패턴 충돌 감지 시 다음 질문은 **절충 되묻기**.

### 라운드 진행 리드아웃 (투명성)

매 라운드 끝에 한 줄로 상태를 보여준다:

```
설계: L1 분석확인 ✅ | L2 목적 ✅ | L3 위치 ◻️ | L4 메카닉 ◻️ | L5 난이도 ◻️ | L6 목표·예산 ◻️ | L7 개수·삽입 ◻️ | L8 재미·비밀 ◻️
다음 타깃 → L3(곡선상 위치): 목적이 '얼음 블로커 소개'로 정해졌으니, 이걸 곡선의 어디에 놓느냐가 난이도 처방을 결정합니다.
```

## 4. Claude의 제안 의무 — "분석 기반 구체안 먼저"

레벨 인터뷰의 강점은 **이미 게임을 분석했다**는 것이다. 그러니 매 라운드 *이 게임의 이 상황에 특정된* 구체안을 던진다.

- **구체적으로.** 카테고리가 아니라 그림이 그려지는 한 컷으로:
  - ❌ "난이도 어떻게 할까요?"
  - ✅ "현재 5번 레벨까지 이동수 20→16으로 줄며 색이 5→6으로 늘었는데, 6번은 *얼음 칸 8개를 처음 깔되 이동수는 20으로 넉넉히 줘서 '새 장애물 학습'에 집중*시키는 게 LD-TEACH에 맞습니다. 어렵게보다 '배우게' 설계하는 거죠. 이 방향 어떠세요?"
- **추천 + 근거 + 본인 의견.** 첫 옵션 "(추천)", "제 추천은 X입니다, 왜냐면 LD-~ 때문에".
- **분석과 모순되면 즉시 교정.** 사용자가 "더블 점프 레벨 만들자"는데 분석상 그 메카닉이 없으면 → "현재 게임에 더블 점프가 없습니다. (a) 단일 점프로 풀리게 재설계할까요, (b) 더블 점프를 새 메카닉으로 먼저 구현(platformer-game·level-designer)해야 하는데 그것까지 할까요?"

## 5. 챌린지 모드 (deep-interview Phase 3 적응 — 레벨용)

라운드가 쌓이면 관점을 바꿔 한 번씩 도발한다(각 1회). 설계를 날카롭게.

- **3라운드+ · Contrarian(반대로):** "정말 이 레벨이 *더 어려워야* 할까요? 곡선을 보면 직전 3레벨이 연속 상승이라, 여기서 한 번 *쉬어가는 보상 레벨*이 오히려 리텐션에 나을 수 있는데요(LD-REST)."
- **4라운드+ · Simplifier(덜어내기):** "이 레벨에 새 요소를 2개(얼음+확산) 넣으려는데, **하나만 남긴다면**? LD-ONE-IDEA상 한 레벨 한 개념이 학습에 좋습니다. 둘 다면 2개 레벨로 쪼갤까요?"
- **5라운드+ · Signature Moment(자랑할 한 컷):** "이 레벨을 클리어한 플레이어가 *어떤 순간*에 '오!' 하길 바라나요? 그 한 컷(대연쇄/아슬한 회피/규칙 발견)이 이 레벨의 정체성입니다."

각 모드는 한 번만 쓰고 일반 질문으로 복귀.

## 6. 준비도 체크 (게이트)

설계 확정 조건:
- **L1(분석) 확인** + **L2(목적)·L3(위치)·L4(메카닉)·L5(난이도) 구체화(✅)** — 각각 한 문장 + 구체 수치로 막힘없이 서술 가능.
- L6(목표·예산)·L7(개수·삽입)·L8(재미·비밀)은 ✅이거나, 미정이면 **분석·곡선 기반 추천 기본값**으로 확정(사용자에게 "이건 이렇게 갈게요" 고지).
- 안티패턴 충돌 해소(절충안 확정).

게이트 미달이면 가장 약한 차원으로 라운드를 더 돈다. 보통 **3~6라운드**면 충족된다(레벨은 게임보다 좁아 더 빨리 수렴).

### 라운드 수 가이드 / 조기 종료
- 2라운드+부터 "충분/그냥 추가해"로 조기 종료 가능 — 단, 필수(L2·L3·L4·L5)가 ◻️면 **추천 기본값을 채워 설계안을 완성**한 뒤 진행한다고 고지.
- 8라운드 soft 경고: "벌써 8라운드네요. 지금 설계안으로 진행할까요, 더 다듬을까요?"

## 7. 설계안 확정 & 빌드 라우팅

게이트 충족 시, **설계안을 한 화면으로 정리해 읽어주고 최종 확인**받은 뒤에만 레벨 데이터를 작성/위임한다.

### 설계안 형식

```
## 레벨 설계안: {레벨 이름} (대상 게임: {slug}, 삽입: LEVELS[{index}])

- **목적 (L2):** {왜 이 레벨인가 — 한 문장}
- **곡선상 위치 (L3):** {도입|전개|정점|휴식|선택적} / 직전·직후 레벨 대비 {상대 난이도}
- **메카닉 (L4):** {기존 조합 | 신규 1개: ___} / 신규면 학습법: {LD-4BEAT 도입→전개→비틀기→마무리}
- **난이도·페이싱 (L5):** {게임 난이도 노브의 구체 수치} / 길이 {초·이동수} / 강도 {꾸준|스파이크|완급}
- **목표·예산 (L6):** win:{타입} / 예산:{moves|par|시간|생명}
- **개수·삽입 (L7):** {N개} / {배열 위치 + 인덱스 시프트·해금 영향}
- **재미·비밀 (L8):** 강조 {FE-*} / 선택경로·비밀 {LD-SECRET/LD-RISK-PATH 여부}
- **적용 LD-* 근거:** {핵심 원칙 2~4개}
- **검증 계획:** {해결가능성|통과가능성|곡선 단조성 — 어떻게 확인할지}
- **빌드 라우팅:** 데이터 직접 수정({LEVELS 스키마}) | level-designer 위임({빌드 패턴}) + 제작요소 {juice-fx|game-ui-hud|chip-sound}
- **IP 안전 메모:** 고유 레벨 레이아웃 복제 회피, 기법만 차용
```

확정 후:
1. 대상 게임의 **레벨 스키마 그대로** 데이터를 작성한다(주석에 한 줄 디자인 노트 + LD-* 태그).
2. 빌드형이면 [`level-designer`](../../level-designer/SKILL.md)로, 데이터형이면 `LEVELS` 직접 수정.
3. **검증**(스킬 5단계)까지 마치고 결과를 근거와 함께 보고.
4. **확인을 받은 뒤에만** 작성한다.

## 8. 예시 (Good)

**라운드 1 — 분석 확인 후 목적부터**

```
라운드 1 | 타깃 차원: L2 목적 | 왜 지금: 분석은 끝났고(매치3, LEVELS 스키마, 이동수·색·블로커 노브, 5레벨까지 상승 곡선), 이제 '왜 이 레벨인가'가 모든 걸 결정하므로 | 설계 진행: 1/8

분석해보니 현재 runeburst는 5번 레벨까지 점수목표만 쓰고 블로커가 없습니다 — 곡선이 '점수 빡빡함'
한 축으로만 올라가요. 제 추천은 6번을 *첫 젤리(jelly) 블로커 소개 레벨*로 만들어 '새로운 풀잇감'을
주는 것입니다(LD-VARIETY + LD-TEACH). 그냥 더 어렵게보다 결이 다른 재미를 더하는 거죠.

이번에 추가할 레벨의 목적은 무엇인가요? (예: 새 블로커 소개 / 난이도 정점 / 휴식 보상 / 분량 확장)
```

**라운드 3 — 난이도를 추상답에서 구체 수치로 되묻기**

```
라운드 3 | 타깃 차원: L5 난이도·페이싱 | 왜 지금: 목적(젤리 소개)과 위치(전개 도입)는 정해졌으니, 이제 '얼마나'가 학습 성패를 가릅니다 | 설계 진행: 3/8

'적당히 어렵게'라고 하셨는데, 새 메카닉을 *처음 가르치는* 레벨은 LD-TEACH상 메카닉 외 난이도를
낮춰야 합니다. 제 추천: 젤리 1겹 6칸 + 이동수 22(넉넉)로 '젤리가 뭔지'만 체득시키고, 점수목표는
직전 레벨보다 낮춥니다. '어려운 젤리'는 다음 레벨로 미루는 거죠. 이렇게 갈까요?

이 레벨의 어려움을 어디서 만들까요 — (a) 이동수를 줄여 빡빡하게 (b) 젤리 양을 늘려 학습부하 (c) 둘 다(권장 안 함, LD-ONE-IDEA 위반)?
```
→ **반영:** "그럼 *젤리 6칸 + 이동수 22 + 점수목표 1800(직전보다 낮춤)*으로, 6번은 '젤리 입문' 레벨이 됩니다."
→ **검증+대안:** "이 방향 괜찮으세요? 아니면 젤리를 2겹으로 깔되 이동수를 더 줘서 '두 번 터뜨려야 한다'는 감만 주는 변형도 있는데, 어느 쪽이 끌리세요?"

**왜 좋은가:** 분석을 전제로 탑다운(목적 먼저), 약점 차원 하나만, "왜 지금" 명시, 추상답을 *이 게임의 노브 수치*로 되물음, LD-* 근거 제시, 안티패턴(LD-ONE-IDEA 위반=둘 다) 가드.

**Bad:** "레벨 몇 개 만들까요? 색은? 이동수는? 블로커는?"을 한 번에 — 의도(왜)를 건너뛰고 수치부터 물어 설계 근거가 없고(정신1 위반), 분석으로 이미 아는 걸 되묻고(정신2 위반), 4문항 객관식(정신3·1문1답 위반).

## 9. 최종 체크리스트

- [ ] 스킬 0단계 분석을 전제로 시작했는가(L1 확인)
- [ ] 탑다운: L2(목적)부터 묻고 아래로 내려갔는가
- [ ] 한 라운드 한 질문(1문1답) — L8만 multiSelect 허용
- [ ] 매 라운드 타깃 차원 + "왜 지금" 명시
- [ ] 매 라운드 **분석 정보 + LD-* 근거**로 구체안을 *먼저* 제안하고 본인 의견을 밝혔는가
- [ ] 추상적 답("어렵게")을 *이 게임의 난이도 노브 수치*로 되물어 구체화
- [ ] 없는 메카닉을 발명하지 않았는가(분석 목록 안에서만)
- [ ] 안티패턴 충돌(LD-ONE-IDEA 위반·사고형+시간압박 등)을 절충 되묻기로 해소
- [ ] 챌린지 모드(Contrarian/Simplifier/Signature)를 적절 라운드에 1회씩
- [ ] 준비도 게이트(L1 확인 + L2·L3·L4·L5 구체) 후에만 설계 확정
- [ ] 설계안을 한 화면으로 읽어주고 최종 확인 후 작성/위임
- [ ] 조기 종료("그냥 추가해") 시 추천 기본값으로 설계안 완성 후 진행
