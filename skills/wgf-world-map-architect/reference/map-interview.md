# 맵 설계 인터뷰 (Deep Interview 적응판 · 탑다운 · 의도 주도)

> [`world-map-architect`](../SKILL.md)의 **'1) 의도 분석 + 인터뷰'** 단계를, **탑다운으로 모호성이 풀릴 때까지
> 끈질기게 묻는 1문1답 인터뷰**로 수행하는 플레이북.
> oh-my-claudecode `deep-interview`(Socratic 1문1답 + 약점 차원 타깃 + 챌린지 모드 + 준비도 게이팅)와
> [game-interview.md](../../wgf-web-game-builder/reference/game-interview.md), [level-interview.md](../../wgf-level-architect/reference/level-interview.md)를
> **맵(진행 위상) 설계**에 적응시켰다.
> 차이: 게임 인터뷰가 *어떤 게임을* 만들지를, 레벨 인터뷰가 *어떤 레벨을* 추가할지를 캔다면, 이 인터뷰는
> *스테이지들을 어떤 위상·게이트·곡선으로 엮을지(맵)* 를 캔다.
>
> **언제 쓰나:** "맵 만들어줘", "월드맵 추가", "진행 구조 좀 재밌게", "무한 모드 넣어줘"처럼 요청이 모호하거나
> 아래 차원이 비어 있을 때. 요청이 이미 구체적이면(위상·게이팅·페이싱·영속이 다 적혀 있으면) 인터뷰를 건너뛰고 설계.
>
> 자동 트리거 아님. SKILL.md '1) 의도 분석'에서 **온디맨드 Read** 로 부른다.

---

## 0. 이 인터뷰의 3대 정신

1. **분석을 먼저 깔고 탑다운으로 내려간다.** 스킬 0단계(현재 진행 모델 분석)가 끝난 상태에서 시작한다 — 현재 위상·
   저장 모델·씬 흐름·게이트를 이미 안다. 그 위에서 **진행 판타지/목적(왜 맵을 손대나)** 부터 묻고 → 위상 → 게이팅 →
   거시 페이싱 → 내비 → 영속 → 분기·메타 순으로 *좁혀* 내려간다. 위(의도)가 흔들리면 아래(별 임계값)를 물어봐야 소용없다.
2. **Claude가 먼저 구체안을 제안한다(백지 금지).** 분석으로 얻은 정보 + `MAP-*` 원칙으로 *이 게임에 어울리는 위상·
   게이트·곡선*을 매 라운드 먼저 제시하고 본인 의견을 밝힌다. "어떤 맵 원해요?"가 아니라 "현재 runeburst는 선형 12레벨에
   진행감 표면이 없는데, *사가맵 + 4·4·4 액트 분할 + 별 게이트*로 가면 '여정'과 '재방문'을 동시에 얻습니다. 이 방향 어떠세요?"로.
3. **모호성이 풀릴 때까지 끈질기게.** 한 라운드 한 질문. 추상적 답("재밌게")은 위상·게이트의 구체 선택지로 되묻는다
   ("재밌게 = (a) 분기를 넣어 매 판 선택의 미학? (b) 액트·테마로 변주? (c) 무한·데일리로 자기경신? — 셋은 전혀 다른 재미입니다").
   준비도 게이트(§6)를 통과하기 전엔 설계를 확정하지 않는다.

---

## 1. 핵심 원칙 (deep-interview에서 차용)

1. **1문1답.** 한 라운드에 질문 하나. 4개를 한 객관식에 욱여넣지 않는다. (M8 분기·비밀·메타만 multiSelect 허용.)
2. **약점 차원 타깃 + "왜 지금".** 매 라운드 가장 모호하거나 결정적인 차원 하나를 고르고, 왜 지금 이걸 묻는지 한 문장으로.
3. **가정을 드러낸다.** "뭘 원해요?" 대신 "무엇을 전제하나요?"를 묻는다. 추상답은 구체 위상/수치로 되묻는다.
4. **Claude가 먼저 참신한 위상안을 제안.** 분석 정보 + [map-design/](./map-design/INDEX.md) 원칙 기반. 첫 옵션에 "(추천)" + 근거.
5. **안티패턴 가드.** [topologies.md](./map-design/topologies.md)·[principles.md](./map-design/principles.md)의 모바일
   부적합 위상(풀 허브·메트로배니아 연속공간)·다크패턴(과금/FOMO 게이트)·가짜 분기를 내부 가드로. 충돌 의도면 절충 되묻기.
6. **준비도 게이트.** §6 차원이 구체화되기 전엔 설계 확정 금지.
7. **조기 종료 존중.** "알아서/그냥 해줘/충분해"라고 하면 즉시 멈추고, 분석 기반 추천 기본값(보통 '선형/사가 베이스 +
   가벼운 분기/액트 + 데일리·무한 별도')으로 §7 설계안을 확정해 읽어준 뒤 진행한다.

## 2. 맵 의도 차원 (탑다운 순서)

위에서부터 캔다(목적 → 위상 → 게이팅 → 페이싱 → 내비 → 영속 → 분기·메타). ✅=구체 확정 · ◻️=미정.

| # | 차원 | 무엇을 확정하나 | 비고 |
|---|---|---|---|
| **M1** | **분석 확인** | 스킬 0단계 분석(현재 위상·저장 모델·씬 흐름·게이트·장르/세션)이 맞는지 확인 | ★전제. 보통 묻기보다 *읽어주고 확인*. 틀리면 분석으로 회귀. |
| **M2** | **진행 판타지 / 목적** | 왜 맵을 손대나 — 진행감 부재? 단조로움? 분량 확장? 리플레이? 무한 모드? 액트 서사? 재방문(별)? | ★★핵심. 모든 결정의 뿌리. |
| **M3** | **위상 선택** | 어떤 모양의 여정 — 선형/사가/그리드/분기 노드맵/액트 월드맵/허브/무한, 또는 조합 | ★필수. [topologies.md](./map-design/topologies.md) 선택표로 가른다. |
| **M4** | **게이팅 · 해금** | 무엇이 다음을 여나 — 클리어/별/키/능력. 하드 vs 소프트. 진행≠숙련 분리 여부 | ★필수. `MAP-GATE`·`MAP-STAR`·`MAP-LOCKKEY`. |
| **M5** | **거시 페이싱 · 난이도 분포** | 톱니 곡선·보스 케이던스(매 K)·휴식 배치·act 분할(몇 개·각 몇 스테이지)·정점 후 하강 | 추상답 금지 → 'act 4+4+4, 매 4번째 보스' 식 구체로. |
| **M6** | **내비 · 가독성** | 맵 화면 형태(세로 사가/노드 그래프/그리드)·현재위치·진척 가시화·thumb-zone·한 화면 노드 수 | 모바일 제약 반영. |
| **M7** | **영속 · 리플레이** | 영속 캠페인 vs 런 기반·데일리·메타 해금/NG+·기존 저장 마이그레이션 | runeburst면 rb-progress 보존 필수. |
| **M8** | **분기 · 비밀 · 메타** | 위험-보상 분기·시크릿/보너스·시퀀스 브레이킹·메타 통화·별의 이중 활용 | multiSelect 한 질문 허용. |

> 캐주얼 퍼즐이면 M3(위상)·M4(게이팅)·M7(영속)이 무겁고, 로그라이크 지향이면 M3(노드맵)·M8(분기·메타)이 무겁다.

## 3. 라운드 진행

각 라운드는 `AskUserQuestion` 한 번(질문 1개). 형식:

```
라운드 {n} | 타깃 차원: {M# 이름} | 왜 지금: {한 문장 근거} | 설계 진행: {✅개수}/8

{Claude의 제안·관점 1~2문장 — 분석 정보 + MAP-* 근거 + 본인 비틀기·의견}

{질문}
```

- 답을 받으면 그 차원을 ✅로, **다음으로 가장 약한 차원**(보통 탑다운 다음 칸)으로.
- 답이 모호하면 같은 차원을 **구체화 질문**으로 한 번 더(추상→구체 되묻기).
- 안티패턴 충돌 감지 시 다음 질문은 **절충 되묻기**.

### 라운드 진행 리드아웃 (투명성)

매 라운드 끝에 한 줄로 상태를 보여준다:

```
설계: M1 분석확인 ✅ | M2 목적 ✅ | M3 위상 ◻️ | M4 게이팅 ◻️ | M5 페이싱 ◻️ | M6 내비 ◻️ | M7 영속 ◻️ | M8 분기·메타 ◻️
다음 타깃 → M3(위상): 목적이 '진행감+재방문'으로 정해졌으니, 이걸 선형/사가/액트 중 무엇으로 담느냐가 게이팅·페이싱을 결정합니다.
```

## 4. Claude의 제안 의무 — "분석 기반 구체안 먼저"

맵 인터뷰의 강점은 **이미 게임의 진행 모델을 분석했다**는 것이다. 매 라운드 *이 게임의 이 상황에 특정된* 구체안을 던진다.

- **구체적으로.** 카테고리가 아니라 그림이 그려지는 한 컷으로:
  - ❌ "위상 어떻게 할까요?"
  - ✅ "현재 runeburst는 선형 12레벨 + `rb-progress` 정수 진행인데, 화면상 '진행 표면'이 없어 성취가 안 보입니다.
    제 추천은 *세로 사가맵*으로 같은 데이터를 '여정'으로 시각화하고(MAP-SAGA + MAP-PROGRESS), 12레벨을 4+4+4
    **액트**로 끊어 매 4번째에 종합시험 보스를 두는 것(MAP-ACT + MAP-BOSS)입니다. 데이터는 안 깨고 표현·구조만 얹는 거죠.
    이 방향 어떠세요?"
- **추천 + 근거 + 본인 의견.** 첫 옵션 "(추천)", "제 추천은 X입니다, 왜냐면 MAP-~ 때문에".
- **분석과 모순되면 즉시 교정.** 사용자가 "메트로배니아 맵 만들자"는데 모바일·짧은 세션·단일플레이면 → "풀 메트로배니아
  연속 공간은 작은 화면·1~3분 세션에서 길 잃기 쉽고 비쌉니다(MAP-NAV·MAP-MOBILE). (a) 능력 게이팅 감각만 살린 **노드맵
  하이브리드**(노드 잠금조건=능력)로 갈까요, (b) 정말 연속 공간 탐험이 코어라면 범위·세션 가정을 다시 잡을까요?"

## 5. 챌린지 모드 (deep-interview Phase 3 적응 — 맵용)

라운드가 쌓이면 관점을 바꿔 한 번씩 도발한다(각 1회). 설계를 날카롭게.

- **3라운드+ · Contrarian(반대로):** "정말 분기·노드맵이 필요할까요? 현재 콘텐츠가 12레벨뿐이면 *선형 + 사가 진행감*만
  살려도 충분하고, 분기는 합류·밸런스 비용이 큽니다(MAP-TOPOLOGY-CURVE). 분기는 콘텐츠가 더 쌓인 뒤로 미룰까요?"
- **4라운드+ · Simplifier(덜어내기):** "위상을 사가+액트+분기+허브 다 넣으려는데, **하나만 남긴다면**? 모바일은
  '선형/사가 베이스 + 한 가지 변주'가 안전합니다(topologies.md 기본값). 나머지는 별도 모드로 분리할까요?"
- **5라운드+ · Signature Moment(자랑할 한 컷):** "이 맵을 연 플레이어가 *어떤 순간* '오!' 하길 바라나요? 액트 보스를
  깨고 새 월드가 색을 바꾸며 열리는 순간? 분기에서 위험한 길을 골라 큰 보상을 먹는 순간? 그 한 컷이 이 맵의 정체성입니다."

각 모드는 한 번만 쓰고 일반 질문으로 복귀.

## 6. 준비도 체크 (게이트)

설계 확정 조건:
- **M1(분석) 확인** + **M2(목적)·M3(위상)·M4(게이팅)·M5(페이싱) 구체화(✅)** — 각각 한 문장 + 구체 선택/수치로 막힘없이 서술 가능.
- M6(내비)·M7(영속)·M8(분기·메타)은 ✅이거나, 미정이면 **분석·모바일 제약 기반 추천 기본값**으로 확정(사용자에게 고지).
- 안티패턴 충돌 해소(모바일 부적합 위상·다크패턴·가짜 분기 절충안 확정).

게이트 미달이면 가장 약한 차원으로 라운드를 더 돈다. 보통 **3~6라운드**면 충족된다.

### 라운드 수 가이드 / 조기 종료
- 2라운드+부터 "충분/그냥 해줘"로 조기 종료 가능 — 단, 필수(M2·M3·M4·M5)가 ◻️면 **추천 기본값을 채워 설계안을 완성**한 뒤
  진행한다고 고지.
- 8라운드 soft 경고: "벌써 8라운드네요. 지금 설계안으로 진행할까요, 더 다듬을까요?"

## 7. 설계안 확정 & 빌드 라우팅

게이트 충족 시, **설계안을 한 화면으로 정리해 읽어주고 최종 확인**받은 뒤에만 맵을 작성/빌드한다.

### 설계안 형식

```
## 맵 설계안: {이름} (대상 게임: {slug})

- **목적 (M2):** {왜 이 맵인가 — 한 문장}
- **위상 (M3):** {선형|사가|그리드|노드맵|액트|허브|무한 + 조합} / 적용 아키타입 {topologies.md §}
- **게이팅 (M4):** {클리어|별 N|키|능력} / 하드·소프트 배치 / 진행≠숙련 분리 여부
- **거시 페이싱 (M5):** {act 분할 N개·각 M스테이지} / 보스 케이던스 K / 휴식 배치 / 정점 후 하강
- **내비·가독성 (M6):** {맵 화면 형태} / 현재위치·다음노드 강조 / 진척 가시화 / thumb-zone·노드 수
- **영속·리플레이 (M7):** {영속 캠페인|런} / 데일리·메타해금·NG+ 여부 / 기존 저장 마이그레이션 계획
- **분기·비밀·메타 (M8):** {위험-보상 분기|시크릿|시퀀스 브레이킹|메타 통화} 여부
- **적용 MAP-* 근거:** {핵심 원칙 3~5개}
- **검증 계획:** {그래프 도달가능성·soft-lock·게이트 잉여·곡선 톱니·마이그레이션 — 어떻게 확인할지}
- **빌드 라우팅:** Map 씬 빌드({build-patterns.md} 패턴) | 노드 레벨 내용 → level-architect | 화면 연출 → game-ui-hud
- **데이터 스키마:** {MAP-SCHEMA 진화 단계 — v1→v2 마이그레이션 / 노드 정의 형태}
- **IP 안전 메모:** 고유 맵 레이아웃 복제 회피, 기법만 차용
```

확정 후:
1. 대상 게임의 **진행 모델을 마이그레이션**으로 보존하며 노드 그래프로 진화([build-patterns.md](./map-design/build-patterns.md) MAP-SCHEMA).
2. Map 씬을 Title↔Game 사이에 빌드(또는 game-ui-hud 위임). 각 노드의 레벨 내용·난이도는 [`level-architect`](../../wgf-level-architect/SKILL.md) 위임.
3. **검증**(스킬 5단계)까지 마치고 결과를 근거와 함께 보고.
4. **확인을 받은 뒤에만** 작성한다.

## 8. 예시 (Good / Bad)

**라운드 1 — 분석 확인 후 목적부터**

```
라운드 1 | 타깃 차원: M2 목적 | 왜 지금: 분석은 끝났고(runeburst=선형 12레벨, rb-progress 정수, Title→Game 직행,
맵 화면 없음, daily 모드 존재), 이제 '왜 맵을 손대나'가 모든 걸 결정하므로 | 설계 진행: 1/8

분석해보니 runeburst는 12레벨이 한 줄로 이어지는데 '진행 표면'(내가 어디까지 왔나·다음에 뭐가 있나)이 화면에
전혀 없어서 성취감·기대감이 약합니다. 제 추천은 (1) 같은 데이터를 *세로 사가맵*으로 시각화해 진행감을 주고
(MAP-SAGA+MAP-PROGRESS), (2) 12레벨을 액트로 끊어 마일스톤 보스로 리듬을 넣는 것(MAP-ACT+MAP-BOSS)입니다.

이번에 맵을 손대는 목적이 무엇인가요? (예: 진행감/성취 표면 추가 / 분량을 액트로 확장 / 리플레이(무한·데일리) 강화 / 매 판 다른 선택(분기))
```

**라운드 4 — 추상답을 구체 게이팅 선택으로 되묻기**

```
라운드 4 | 타깃 차원: M4 게이팅 | 왜 지금: 위상(사가+3액트)이 정해졌으니, 무엇이 다음을 여느냐가 캐주얼 이탈을 가릅니다 | 설계 진행: 4/8

'좀 도전적으로 잠그자'고 하셨는데, runeburst는 운+실력 섞인 매치3라 **진행 게이트와 숙련 게이트를 분리**하는 게
안전합니다(MAP-STAR): 다음 레벨은 *클리어(1성)*만으로 열고, *누적 별*로는 보너스 노드/액트 스킨만 잠그는 거죠.
순수 실력 게임이 아니므로 별로 진행을 막으면 '운으로 막힌' 좌절 이탈이 납니다(Woodbury 경고).

게이팅을 어떻게 할까요 — (a) 진행=클리어만, 별=보너스 전용(추천) (b) 액트 경계만 누적 별 하드 게이트(잉여 마진 크게) (c) 둘 다 없이 순수 선형 해금?
```
→ **반영:** "그럼 *진행=클리어(소프트), 액트 경계는 누적 별 N개 하드 게이트(접근 가능 총량의 ~40%)*로, 막힘 없이
가되 별 모으는 재방문 동기를 주는 구조가 됩니다."

**왜 좋은가:** 분석을 전제로 탑다운(목적 먼저), 약점 차원 하나만, "왜 지금" 명시, 추상답을 *이 게임의 위상·게이트
선택지*로 되물음, MAP-* 근거 제시, 안티패턴(순수 실력 아닌데 별 진행 게이트) 가드.

**Bad:** "위상 뭐로 할까요? 게이트는? 데일리 넣을까요? 노드 몇 개?"를 한 번에 — 의도(왜)를 건너뛰고 수치부터 물어
설계 근거가 없고(정신1 위반), 분석으로 이미 아는 걸 되묻고(정신2 위반), 4문항 객관식(정신3·1문1답 위반).

## 9. 최종 체크리스트

- [ ] 스킬 0단계 분석(현재 진행 모델)을 전제로 시작했는가(M1 확인)
- [ ] 탑다운: M2(목적)부터 묻고 위상→게이팅→페이싱으로 내려갔는가
- [ ] 한 라운드 한 질문(1문1답) — M8만 multiSelect 허용
- [ ] 매 라운드 타깃 차원 + "왜 지금" 명시
- [ ] 매 라운드 **분석 정보 + MAP-* 근거**로 구체안을 *먼저* 제안하고 본인 의견을 밝혔는가
- [ ] 추상적 답("재밌게/도전적으로")을 *이 게임의 위상·게이트 선택지*로 되물어 구체화
- [ ] 모바일 부적합 위상(풀 허브·메트로배니아)·다크패턴·가짜 분기를 절충 되묻기로 해소
- [ ] 챌린지 모드(Contrarian/Simplifier/Signature)를 적절 라운드에 1회씩
- [ ] 준비도 게이트(M1 확인 + M2·M3·M4·M5 구체) 후에만 설계 확정
- [ ] 설계안을 한 화면으로 읽어주고 최종 확인 후 작성/빌드
- [ ] 기존 진행 저장(rb-progress 등) 마이그레이션 보존 계획을 설계안에 포함했는가
- [ ] 조기 종료("그냥 해줘") 시 추천 기본값으로 설계안 완성 후 진행
