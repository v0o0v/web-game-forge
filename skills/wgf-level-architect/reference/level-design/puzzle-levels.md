# 퍼즐 레벨 디자인 (매치·머지 / 규칙조작·소코반)

> WebGameForge `level-architect`가 **퍼즐 장르 레벨**을 설계할 때 쓰는 처방전. 두 축을 다룬다 — (A) **매치·머지 보드**(`runeburst`의 `LEVELS` 스키마: shape/colors/moves/goal/win/블로커/seed)와 (B) **규칙조작·소코반**(`is-rule`의 `LEVELS` 스키마: par/ent 격자/texts 규칙블록). 공통 `LD-*` 원칙은 항상 [principles.md](./principles.md) 먼저, 색인은 [INDEX.md](./INDEX.md), 빌드 위임은 [`level-designer`](../../../wgf-level-designer/SKILL.md)·`puzzle-game`.
> 퍼즐 장르의 비-협상 규칙: **항상 풀린다(LD-SOLVABLE) · 자원에 무게가 있다(LD-BUDGET) · 한 레벨 한 아이디어(LD-ONE-IDEA) · 실패가 납득되고 회복이 공짜다(LD-FAIR)**.

## 한눈에 보기

| 축 | 코어 | 저장소 게임 | 대표 `LD-*` | 난이도 노브 |
|---|---|---|---|---|
| (A) 매치·머지 보드 | 스왑→소거→낙하→리필 캐스케이드 | `runeburst` | `LD-CURVE` `LD-BUDGET` `LD-SOLVABLE` `LD-FAIR` `LD-VARIETY` | moves · colors · goal/target · board shape · 블로커 |
| (B) 규칙조작·소코반 | 'X IS Y' 규칙을 밀어 다시 쓰기 / 박스 밀기 | `is-rule` | `LD-ONE-IDEA` `LD-SOLVABLE` `LD-BUDGET`(par) `LD-FAIR` `LD-4BEAT` | par · 신규 규칙 1개 · 통로 길이 · 규칙 상호작용 수 |

퍼즐은 액션과 달리 **'강도(intensity)'가 아니라 '통찰(insight)의 깊이'로 난이도가 매겨진다.** 톱니형 곡선(`LD-CURVE`)의 단위는 '더 빠른 적'이 아니라 '한 레벨 한 새 아이디어'(`LD-ONE-IDEA`)다. 두 축 모두 우리 엔진 제약(2D·단일플레이·모바일웹뷰·CC0/절차생성·Arcade 우선·서버 메타 ❌→localStorage/시드)을 그대로 따른다.

# 축 A — 매치·머지 보드 (`runeburst`)

`runeburst`는 매치3 스왑 캐스케이드를 **선언적 `LEVELS` 배열**로 인코딩한다. 레벨 설계 = 이 배열의 항목을 노브 1개씩 움직여 톱니 곡선을 그리는 일이다. 현재 스키마(`games/runeburst/game.js` 상단)를 정확히 인용하면:

```js
// games/runeburst/game.js — LEVELS[] (확인된 현행 스키마)
var LEVELS = [
  { name: '첫 별빛',   shape: 'square', colors: 5, moves: 20, goal: 1000,
    win: { type: 'score', target: 1000 }, seed: 1001 },
  { name: '성운을 걷어라', shape: 'cross', colors: 6, moves: 22, goal: 2000,
    win: { type: 'jelly' }, jelly: 1, seed: 1005 },
  { name: '별조각을 내려', shape: 'heart', colors: 6, moves: 24, goal: 2400,
    win: { type: 'ingredient', count: 3 }, ingredients: 3, seed: 1008 },
  { name: '마지막 한 수', shape: 'diamond', colors: 6, moves: 22, goal: 4200,
    win: { type: 'score', target: 4200 }, overload: true, ice: 6, seed: 1012 }
];
// win.type ∈ 'score'|'jelly'|'collect'|'ingredient'
// shape ∈ SHAPES 키(square/cross/diamond/hourglass/heart/star/ring) — 비유효 칸 마스크
// 블로커 필드: jelly / ice / spreaders / ingredients / overload
```

## 난이도 튜닝 노브 (축 A)

| 노브 | 범위 | 방향 | 효과 | 주의 |
|---|---|---|---|---|
| `moves` | 15~22 | ↓ = 어려움 | 이동수 예산(`LD-BUDGET`). 표준 15~20수 | par 미만 금지(가짜 난이도) |
| `colors` | 5~6 | ↑ = 어려움 | 색이 많을수록 목표색 매치 확률↓ | 도입 1~2레벨은 5 권장 |
| `goal`/`target` | 레벨당 +15~25% | ↑ = 어려움 | 점수·개수 압박 | 도입부 +37~60%는 너무 가파름 |
| `shape` | SHAPES 7종 | 비정형 = 어려움 | ring/hourglass = 가용 공간 축소 | 연속 레벨에 변주(단조 차단) |
| 블로커 | 0~2종/레벨 | 종/수↑ = 어려움 | jelly/ice/spreaders/overload | 4종 초과 = 가독성 붕괴 |

> **핵심 규율: 인접 두 레벨은 노브 1개만 움직인다.** `moves -2` 또는 `colors +1` 또는 `goal +15~25%` 중 **하나만**. 동시 다중 상향은 '난이도 절벽'을 만든다.

## A-1. `LD-CURVE` — 톱니형 난이도 곡선 + 복잡도 계단

**정의.** 난이도는 단조 상승이 아니라 '도전 도입 → 숙달 → 한 단계 어려운 변주'의 톱니(sawtooth)로 오른다. 신규 블로커/기믹은 한 번에 쏟지 않고 통과 레벨 수에 따라 **복잡도 계단(complexity staircase)**으로 하나씩 풀어준다.

**왜 통하나.** Jesse Schell은 너무 쉬우면 지루, 너무 어려우면 불안이며 둘 다 좌절로 수렴한다고 본다(도전과 실력이 함께 오르는 flow channel이 이상적). King(Candy Crush) 시니어 디자이너 John Davies는 신규 블로커를 '복잡도 계단'으로 도입하고, 어려운 레벨 뒤엔 일부러 가벼운 레벨을 둬 모멘텀을 살린다고 밝혔다(PocketGamer.biz).

**구체 규칙(체크리스트).**
- [ ] 인접 레벨 난이도 차 = 노브 1개 1단계. `moves -2` / `colors +1` / `goal +15~25%` 중 하나만.
- [ ] 예상 통과율 < 40%인 정점 레벨 직후엔 완화 레벨(통과율 70%+) 1개를 끼워 톱니를 만든다.
- [ ] `goal`은 레벨당 +15~25% 계단으로. 도입부 `1000→1600→2200→2800`(약 +37~60%)은 가파르니 도입은 +15~20%로 완만하게.
- [ ] 새 블로커/특수타일은 '계단 한 칸 = 한 종류'만. 같은 레벨에 신규 2종 이상 동시 도입 금지.

**우리 엔진 적용.** 현행 12레벨은 콤보→라인→코어→젤리→과부하→얼음→별조각→번식→폭발→수집→복합으로 이미 계단을 따른다. 새 항목을 push할 때 **직전 항목 대비 노브 1개만** 바꾸고, 정점(예: `moves 16`) 다음엔 `moves 20~22`의 완화 항목을 끼운다. `seed`는 레벨마다 고유값(현행 1001~1012)으로 고정해 결정론을 유지한다.

**안티패턴.** 여러 노브 동시 상향 → 난이도 절벽·이탈 급증 / `goal`만 키워 인내만 요구하는 '시간 끌기형' 가짜 난이도 / 완화 없이 정점 연속 배치 → flow channel 상단(불안)에 갇힘.

## A-2. `LD-FLOW-CHANNEL` — 몰입 채널(도전과 실력의 균형)

**정의.** 체감 난이도를 플레이어 실력 곡선에 붙여, 불안(너무 어려움)과 지루함(너무 쉬움) 사이 좁은 채널 안에 유지한다. 매치3에서는 **'이동수 여유'와 '목표 압박'의 비율**이 채널 조절기다.

**왜 통하나.** 도전과 실력의 균형이 boredom과 anxiety를 가르는 flow(몰입) 채널 개념은 Mihaly Csikszentmihalyi가 1970년대에 정식화한 flow 이론(1975년 'Beyond Boredom and Anxiety')에서 비롯되고, 'Flow: The Psychology of Optimal Experience'(1990)가 이를 체계화·대중화했다. (원본 1975 도식은 anxiety/flow/boredom의 단순 3구역이고, 흔히 인용되는 정식 도식은 1987년 Massimini·Csikszentmihalyi·Carli의 8채널 모델이다.) Jesse Schell은 이를 'tense and release(긴장과 이완)' 사이클 — 도전 상승→보상→완화의 반복 — 으로 실현하라고 처방한다(이는 일정한 flow 유지의 *대안*이 아니라 flow를 실현하는 방식 그 자체다).

**구체 규칙(체크리스트).**
- [ ] 도입/튜토리얼 레벨은 보드 위 메카닉 1~3종으로 제한.
- [ ] 목표 달성에 필요한 '이상적 이동수' 대비 지급 `moves` 비율로 채널 조절: 도입부 1.4~1.6배(여유), 정점 1.05~1.15배(빠듯)로 좁힌다.
- [ ] 정점 레벨은 '한 수 차로 아슬아슬 통과/실패'가 잦게 — 승리 시 잉여 이동수 0~2가 자주 나오게.
- [ ] `colors` 상향은 목표색 매치 확률을 낮춰 체감 난이도를 올리는 채널 노브로 쓴다.

**우리 엔진 적용.** `moves` vs `goal` 비율이 핵심 flow 노브다. 도입 '첫 별빛'(`moves 20`/`goal 1000`)은 여유롭게, 정점 '마지막 한 수'(`moves 22`/`goal 4200`+`ice`)는 빠듯하게 설정돼 채널 폭을 좁힌다. 신규 레벨은 `seed` 고정 보드를 10회 자가 플레이해 '승리 시 남은 moves'와 '목표 달성 %'를 기록(→ A-9 `LD-PLAYTEST`)하고, 남은 moves가 항상 5+이면 `moves -2` 또는 `goal +15%`로 상향한다.

**안티패턴.** 채널을 '어려움' 쪽으로만 좁혀 신규 유저를 불안 영역에 빠뜨림(초반 이탈) / 도입부터 `colors 6`이라 매치 확률이 낮은 '느린 시작'(도입 1~2레벨은 `colors 5` 권장, 현행 준수) / 여유를 너무 줘 긴장 없는 '무중력' 레벨.

## A-3. `LD-BUDGET` — 이동수 예산

**정의.** [퍼즐] 각 레벨에 유한한 `moves`를 배정해 모든 수에 의미를 부여한다. 예산은 '효율적으로 처리하면 통과, 낭비하면 실패'하도록 빠듯하되, 최적해(par)와 너무 멀지 않게.

**왜 통하나.** Candy Crush는 각 레벨에 유한 이동수와 점수판(현재/목표)을 줘 실시간 피드백을 만든다. 현대 매치3 표준 예산은 레벨당 15~20수로 좁혀졌다(과거엔 더 많았음, gamigion.com). 부스터 없이도 통과 가능을 기본으로 둔다(Fran Ruiz).

**구체 규칙(체크리스트).**
- [ ] 기본 예산 15~22수. 도입부 18~22, 정점 16~18로 좁힌다(현행 정합).
- [ ] win.type별로 par를 내부 추정하고 `moves = par × (1.05~1.6)` 범위에서 난이도별 배율 선택.
  - `score`형: `par ≈ goal ÷ (수당 기대점수)`
  - `collect`형: `par ≈ count ÷ (수당 평균 해당색 소거)` (예: 색 24개/18수)
  - `jelly`/`ingredient`형: 보드 위 블로커 개수·도달 난이도로 par 추정 (예: 별조각 3/24수)
- [ ] 점수 목표는 '평균 매치 1수당 기대점수 × 가용 이동수'의 60~80%에서 시작, 정점은 90~100%로.

**우리 엔진 적용.** `LEVELS[].moves`가 곧 예산. `seed` 고정 보드를 10회 자가 플레이해 '실제 소요 수'의 중앙값을 par로 삼고 배율을 곱해 `moves`를 확정한다. 부스터(`devUseItem`/`handleItem`의 망치·코어·스왑, game.js 905·849행)는 **예산 밖 추가 자원**이므로 '부스터 없이도 통과 가능'을 기본 보장한다(→ A-5 `LD-FAIR`).

**안티패턴.** 예산을 par 미만으로 줘 '최적 플레이로도 불가능한' 레벨 / 너무 후해 모든 수가 무게를 잃음 / `goal`만 키우고 `moves`는 그대로 둬 '운빨 캐스케이드 대기' 레벨.

## A-4. `LD-SOLVABLE` — 해결가능성·교착 방지(항상 풀리는 보드와 셔플)

**정의.** [퍼즐] 보드는 항상 합법 수가 존재하도록 보장하고(데드락 방지), 수가 사라지면 자동 셔플한다. 셔플 직후엔 자동 매치가 발생하지 않게(공짜 콤보 금지), 그리고 셔플 후에도 수가 존재하도록 재검증한다.

**왜 통하나.** Candy Crush는 가능한 수가 없으면 즉시 인지해 보드를 재배치하며, 재배치 시 3매치가 자동 성립하지 않게 한다. 데드락 미처리는 곧 강제 실패이므로 페어플레이의 전제다. 한 시도에서 셔플이 2회 이상이면 그 레벨은 '교착이 잦은 나쁜 보드'로 보고 색 분포/시드를 재조정한다(gamigion.com).

**구체 규칙(체크리스트).**
- [ ] 매 수 처리 후 합법수 존재 검사 → 없으면 즉시 셔플.
- [ ] 셔플 결과는 (1)즉시 매치 0개, (2)최소 1수 존재 두 조건을 동시에 만족할 때까지 재시도, 한도 초과 시 보드 재생성으로 폴백.
- [ ] 한 시도에 셔플 2회+ 발생 → 색 분포/시드 재조정.
- [ ] 미사용 보드 영역(목표/블로커가 닿지 않는 칸)은 마스크로 잘라내 무의미한 매치 공간을 줄인다.

**우리 엔진 적용.** `runeburst`가 이미 정석 구현이다 — `hasMove()`(game.js 790행), 매 수 후 `!hasMove()` 시 `shuffleBoard()`(285·756·900행), `shuffleBoard()`(809행)는 `do-while`로 `findMatches().matched.size > 0`(즉시 매치 없음) && `hasMove()`(수 존재)를 `attempt < 40`까지 보장하고 실패 시 `regenRunes()`로 폴백(821~822·827행). 보드 모양은 `SHAPES` 마스크로 유효 칸만 사용해 미사용 영역을 자동 배제한다. **신규 레벨 추가 시 이 4중 불변식(셔플→즉시매치 금지→수 존재 재검증→폴백 재생성)을 깨지 말 것.**

```js
// games/runeburst/game.js (809행) — LD-SOLVABLE 불변식 (현행 구현 발췌)
shuffleBoard: function (silent) {
  var attempt = 0;
  do {
    /* ...룬 재배치... */
    attempt++;
  } while (attempt < 40 && (this.findMatches().matched.size > 0 || !this.hasMove()));
  if (this.findMatches().matched.size > 0 || !this.hasMove()) this.regenRunes(); // 폴백
}
```

**안티패턴.** 셔플 후 즉시 매치 허용 → '공짜 점수'로 난이도 붕괴 / 데드락 재발 시 폴백 없이 무한 셔플 루프 / 비정형 shape에서 마스크와 낙하 로직이 어긋나 특정 칸이 영구 빈칸으로 남는 버그.

## A-5. `LD-FAIR` — 공정성·안티프러스트레이션(운빨 가짜 난이도·페이투윈 회피)

**정의.** 실패는 회피 가능하고 납득돼야 한다. RNG가 시스템 편에 서서 '될 일도 안 되게' 만드는 가짜 난이도를 금지하고, 결정론 시드로 같은 보드·같은 수를 재현 가능하게 한다. 부스터/결제 없이도 통과 가능을 기본값으로 둔다(페이투윈 아님).

**왜 통하나.** 플레이어는 시스템이 자신을 적대할 때를 감지한다 — RNG는 예측 불가하되 불공정하지 않아야 하고, 실패 사이클에 갇히지 않도록 소프트 보호가 필요하다(Room 8 Studio). F2P의 '+5 moves' 과금이 있어도 레벨 자체는 부스터 없이 풀리게 설계해야 공정하다(Fran Ruiz). 시드 고정은 'RNG 분산'을 제거해 난이도 평가를 신뢰 가능하게 한다.

**구체 규칙(체크리스트).**
- [ ] 모든 레벨은 결정론 시드 사용 — 같은 시드+같은 입력은 항상 같은 결과(재현·검증 가능).
- [ ] 색 드롭 확률 미세조정(±20~30%)은 플레이어가 인지 못하는 선에서 '소프트 보호'로만(시스템 유리하게 과용 금지).
- [ ] 부스터는 '있으면 쉬움'이지 '없으면 불가능'이 아니어야 한다 — par 검증은 부스터 0개 기준.
- [ ] '한 수 차 실패'가 운(캐스케이드 미발생)이 아니라 플레이어 선택 때문이도록, 정점 레벨도 par 내 결정론적 해를 보장.

**우리 엔진 적용.** `mulberry32(seed)`(game.js 76행)로 레벨별 결정론 보드를 생성한다(`LEVELS`의 `seed` 1001~1012, 데일리 시드는 오늘 날짜). 덕분에 같은 레벨은 누구에게나 동일 시작 보드 → 공정·검증 가능. `items`는 daily 여부에 따라 소량 지급되지만 win 판정은 부스터 비의존이다. 신규 시드 추가 시 그 보드를 **부스터 없이 par 내 통과하는 해가 존재**하는지 자가 플레이로 확인하고, 색 확률 조정은 도입하지 않거나 도입해도 미세하게 한다.

**안티패턴.** 난이도를 'RNG 운'으로 떠넘겨 같은 레벨이 어떤 판은 거저·어떤 판은 불가능 / 부스터 없이는 못 깨는 암묵적 페이투윈 / 색 확률을 시스템 유리하게 과조정해 '특정 색이 안 나와' 좌절 사이클 유발.

## A-6. `LD-VARIETY` — 승리조건·블로커 변주(반복 회피)

**정의.** 점수 한 가지만 반복하지 않고 젤리 제거/색 수집/별조각 내리기/주문 채우기 등으로 승리조건을 다양화하고, 블로커도 기능별(제거형/수집형/하강형/번식형/잠금형)로 변주해 같은 패턴의 지루함을 차단한다.

**왜 통하나.** 매치3 정설: '레벨에 요소 4종 초과 금지'(가독성)와 동시에 '같은 near-match 상호작용만 반복하면 금세 지루'(Room 8/RetroStyle). King은 블로커를 '순수 방해'에서 '흥미로운 선택을 만드는 것'으로 진화시켰고, 좋은 팀은 최소 50레벨 동안 같은 메카닉을 반복하지 않으려 한다.

**구체 규칙(체크리스트).**
- [ ] 승리조건 최소 4종 로테이션: `score`(점수)·`jelly`(셀 덮개 제거)·`collect`(특정 색 N개)·`ingredient`/order(아이템을 하단으로 낙하). 한 묶음(5~6레벨)에 같은 type 3연속 금지.
- [ ] 블로커 기능 분류로 변주(아래 표).
- [ ] 한 레벨의 '서로 다른 요소'는 4종 이하(룬 색 제외, 블로커+특수타일+목표 합산).
- [ ] 보드 shape도 연속 레벨에서 바꿔 시각적 단조 차단(square→cross→diamond…).

| 블로커 기능 분류 | 동작 | `runeburst` 필드 | 억제·상한 |
|---|---|---|---|
| 제거형 | 인접 매치로 해제 | `ice` | 횟수만큼 |
| 다겹형 | N회 매치로 제거 | `jelly`(2겹 성운) | 겹 수 |
| 하강형 | 바닥 도달 시 처리 | `ingredients`(별조각) | `count` |
| 번식형 | 매턴 확산, 인접 매치로 억제 | `spreaders`(암흑물질) | `MAX_SPREAD`=9 |
| 점수형 | 포함 매치 점수 ×2 | `overload` | — |

**우리 엔진 적용.** `win.type`이 이미 `score`/`jelly`/`collect`/`ingredient` 4종 + `overload`/`ice`/`spreaders` 블로커 변주를 갖췄다. `SHAPES` 7종으로 보드 모양도 로테이션. 신규 레벨은 `win.type`이 직전 2~3레벨과 겹치지 않게 고르고, 한 레벨 블로커는 1~2종으로 제한한다(현행 '마지막 한 수'의 `overload`+`ice` 복합이 상한선). 번식형(`spreaders`)은 `MAX_SPREAD`(game.js 32행)로 폭주 상한을 둔다. 새 블로커는 셀 오버레이 2D 배열 패턴(game.js 17행 주석)을 재사용한다.

**안티패턴.** 점수 목표만 반복해 12레벨이 사실상 같은 레벨 / 한 레벨에 5종+ 욱여넣어 가독성 붕괴(4종 규칙 위반) / 번식형에 확산 상한이 없어 보드가 메워져 데드락·불공정.

## A-7. `LD-TEACH` — 무텍스트 학습(안전한 환경에서 기믹 체험)

**정의.** 새 블로커/특수타일은 텍스트 설명이 아니라 위험이 낮은 보드 배치로 플레이어가 직접 만들고 효과를 보게 가르친다. 첫 등장 레벨은 그 기믹을 '쓸 수밖에 없되 안전하게' 설계한다.

**왜 통하나.** 게임은 몰입을 깨는 텍스트 튜토리얼 없이 메카닉을 가르칠 수 있다. Fran Ruiz의 jelly fish 레벨처럼 개방 공간에 기믹을 노출하고 제한 구역의 유일 해법으로 만들어 자연 학습을 유도한다. 닌텐도식 '안전한 도입에서 새 아이디어 체험' 원칙의 매치3 적용이다.

**구체 규칙(체크리스트).**
- [ ] 신규 특수타일 도입 레벨은 그것을 만드는 매치(4매치=라인, 5매치=코어, L/T=포장)가 쉽게 나오게 `colors`를 한 단계 낮추거나 보드를 여유롭게.
- [ ] 그 레벨 목표는 '신규 기믹을 한 번이라도 쓰면 달성'되게 낮게(점수 목표 완화).
- [ ] 신규 블로커는 보드 가장자리/소량으로 먼저 등장 → 다음 레벨부터 수량·중앙 배치 증가.
- [ ] 한 도입 레벨엔 신규 개념 하나만(→ B축 `LD-ONE-IDEA` 연동).

**우리 엔진 적용.** 12레벨이 이 원칙을 실행한다: '라인 블래스터'(L3)는 점수 2200으로 라인 특수타일을 만들며 익히게, '컬러 코어'(L4)는 5매치 코어 도입, '성운을 걷어라'(L5)는 jelly를 `moves 22`/`goal` 완화로 첫 학습. 신규 도입 레벨은 직전보다 `moves`를 늘리거나 `goal`을 낮춰 '안전한 첫 만남'을 만들고, `win.type`을 그 기믹과 직접 연결한다(예: 신규 블로커 도입 레벨의 win을 그 블로커 제거형으로).

**안티패턴.** 신규 기믹을 텍스트 팝업으로만 설명하고 보드에선 만들기 어렵게 둠 / 도입부터 목표를 빡빡하게 잡아 '배우기 전에 실패' / 한 레벨에 신규 개념 2개를 동시에 가르쳐 인지 과부하.

## A-8. `LD-4BEAT` — 도입→전개→비틀기→마무리(kishōtenketsu)

**정의.** 기믹 묶음(3~4레벨)을 4단으로 구성한다: 새 아이디어 도입(ki) → 안전한 전개(shō) → 예상 밖 비틀기(ten, 기존 메카닉의 새 적용/조합) → 정점 마무리(ketsu). 매치3에서는 보드 전개 단계(공간 개방·블로커 단계 해제)로도 표현된다.

**왜 통하나.** 닌텐도식 4단 레벨 구조(introduction→development→twist→resolution)를 명시적 설계 원리로 정식화한 주체는 디렉터 Koichi Hayashida이며(2012년 Gamasutra/Game Developer의 Super Mario 3D Land 인터뷰에서 kishōtenketsu로 직접 언급, 근원은 Shigeru Miyamoto의 4컷 만화 경험), Mark Brown의 GMTK 영상 'Super Mario 3D World's 4 Step Level Design'(2015)이 이를 4단계로 정리해 **대중화·해설**한 것이다('GMT가 정식화'는 과장 — 정확히는 Hayashida가 정식화하고 Brown이 대중화). 한 메카닉을 '가르치고-전개하고-비틀고-버리는' 자기완결 쇼케이스다.

**구체 규칙(체크리스트).**
- [ ] 기믹 묶음(3~4레벨)을 4비트로: 도입(여유)→전개(표준)→비틀기(그 기믹을 다른 블로커/목표와 조합)→정점(빠듯).
- [ ] 레벨 내부도 단계화: 초반 좁은 공간(블로커로 막힘)→중반 개방(블로커 해제로 콤보 여지)→후반 개방 공간서 정점 콤보.
- [ ] '비틀기'는 새 요소가 아니라 기존 메카닉의 신선한 적용(예: 라인 특수타일을 얼음 위에서 써야 효과).
- [ ] 마무리 레벨은 묶음의 모든 학습을 한 번에 요구(복합 목표/복합 블로커).

**우리 엔진 적용.** 12레벨을 3개 4비트 묶음으로 읽을 수 있다: `[L1 콤보도입→L2 캐스케이드전개→L3 라인비틀기→L4 코어정점]`, `[L5 젤리도입→L6 과부하전개→L7 얼음비틀기→L8 별조각정점]`, `[L9 번식도입→L10 폭발전개→L11 수집비틀기→L12 복합마무리(overload+ice)]`. 신규 묶음은 이 패턴으로 `LEVELS` 슬라이스를 구성한다. 레벨 내부 전개는 `SHAPES` 마스크(좁은 ring/hourglass=공간 제약)와 블로커 초기 배치로 '좁다→열린다' 흐름을 연출한다.

**안티패턴.** 모든 레벨을 평탄하게 만들어 '비틀기' 비트 부재 → 변별 없는 나열 / 비틀기에 진짜 새 요소를 넣어 도입과 구분 흐려짐 / 마무리가 정점이 아닌 또 하나의 표준 레벨이 돼 클라이맥스 상실.

## A-9. `LD-PLAYTEST` — 플레이테스트·계측 튜닝(봇 시뮬레이션과 셔플 빈도 지표)

**정의.** 난이도는 감이 아니라 실제 플레이/시뮬레이션 데이터로 조정한다. 봇/솔버로 통과율을 추정하고, 자가 플레이 N회로 잉여 이동수·셔플 빈도·목표 달성%를 계측해 노브를 미세조정한다.

**왜 통하나.** King은 봇으로 대량 플레이를 시뮬레이션해 출시 전 난이도를 추정한다(아웃라이어·통과율 예측에 강함). gamigion은 가중치 기반 봇(수당 칩 소거·목표 처리량으로 가중)으로 50~1000+회 반복해 평균 난이도를 잡고, 1k 완료가 신뢰선(어려운 레벨 ~10% 오차)이다. 자가 플레이 10회로 남은 목표/이동수를 기록하는 수작업 프로토콜도 표준이다.

**구체 규칙(체크리스트).**
- [ ] 신규 레벨은 시드 고정 보드를 최소 10회 자가 플레이 — '승리 시 남은 moves'와 '목표 달성 %' 분포 기록.
- [ ] '한 시도에 셔플 2회 이상'이면 색 분포/시드 재조정(교착 잦음 = 나쁜 보드).
- [ ] 봇 가중치는 수당 소거 칩 수·목표 직접 기여 수에 둬 '합리적 플레이어' 근사(랜덤 무브는 버그 탐지용일 뿐 난이도 예측에 부적합).
- [ ] 난이도는 레벨 단독이 아니라 인접 레벨 묶음의 지표 범위로 평가(고립 평가 금지).

**우리 엔진 적용.** `state()` 디버그 훅(game.js 293행)이 `moves`·`score`·`goal`·`objective`·`hasMove`·`over`를 노출한다 → 자동 봇/계측에 직접 활용. `devUseItem`(game.js 905행)·dev 훅으로 스크립트 플레이를 구동해 시드 보드별 통과 여부·잉여 이동수를 수집한다. `seed` 결정론 덕분에 동일 보드 반복 시뮬이 가능하다. 튜닝 루프: 시드 보드 10~50회 자가/봇 플레이 → 남은 moves 중앙값 5+이면 `moves -2` 또는 `goal +15%` → 셔플 2회+ 빈발 시 `colors` 분포/시드 교체 → 인접 레벨과 통과율 곡선 비교(`LD-CURVE` 톱니 검증).

**안티패턴.** 랜덤 무브 봇으로 난이도를 추정해 실제보다 어렵게 오판 / 단일 시드 1회 플레이로 난이도 확정(분산 무시) / 개발 극초기에 자동 DDA부터 구현(코어 재미·레벨 품질 먼저, 자동 조정은 나중).

## A-10. `LD-DDA` — 동적 난이도 조정(인지 불가 수준의 미세 보정)

**정의.** 플레이어가 특정 레벨에서 막힐 때, 인지하지 못하는 선에서 드롭 확률/보너스 생성 확률을 미세 조정해 좌절 사이클을 완화한다. '시스템이 봐줬다'고 느끼게 하지 않는 것이 핵심.

**왜 통하나.** gamigion: '어려운 레벨에서 잔여 이동수 < 40% & 목표 < 50%'이면 드롭 확률을 올려 보너스 생성을 돕는 트리거를 쓴다. 색 확률 ±20~30% 변화는 4~5색에선 플레이어가 인지 못한다. 단, 공정성(`LD-FAIR`)과 충돌하지 않게 '소프트 보호'로만 — DDA의 목적은 통과율을 flow channel 밴드로 되돌리는 것이지 '항상 이기게' 만드는 것이 아니다.

**구체 규칙(체크리스트).**
- [ ] DDA는 '실패 임박 + 명백한 운 부족'일 때만 발동(예: 잔여 이동수 < 40% & 목표 < 50%).
- [ ] 조정 폭은 색 드롭 확률 ±20~30% 이내, 또는 보너스 생성 칩 소량 주입 — 인지선 아래.
- [ ] 통과율을 목표 밴드(어려운 레벨 35~45%)로 끌어오는 보정에 한정.
- [ ] 코어 재미·정적 레벨 디자인이 검증된 뒤 도입(조기 도입 금지).

**우리 엔진 적용.** `runeburst`는 현재 정적 시드 보드(공정·결정론) 중심이라 **DDA 미탑재가 기본값으로 적절**하다(공정성 우선). 도입한다면 매 수 후 `state()`(293행)의 `moves`/`objective`를 읽어 '잔여 < 40% & 진행 < 50%' 트리거 시, 리필 단계의 색 선택 rng 가중을 목표색/보너스 생성 쪽으로 미세 상향한다. 단 `seed` 결정론을 깨므로 **'데일리 시드/검증 모드'에선 DDA off**로 두고 일반 플레이에서만 적용해 재현성을 보존한다.

**안티패턴.** DDA 과적용 → '아무리 못해도 이김'으로 성취감 소멸 / 결정론 시드와 DDA를 같이 켜 재현성 파괴 / DDA를 시스템 유리하게 써서 '안 도와주는' 방향으로 악용 → 가짜 난이도.

# 축 B — 규칙조작·소코반 (`is-rule`)

`is-rule`은 'NOUN IS PROPERTY' 단어블록을 밀어 규칙을 다시 쓰는 퍼즐(Baba Is You류)을 **선언적 `LEVELS` 배열**로 인코딩한다. 레벨 설계 = `ent` 격자와 `texts` 규칙블록으로 '한 통찰로 열리는 관문'을 짓는 일이다. 현행 스키마(`games/is-rule/game.js` 상단):

```js
// games/is-rule/game.js — LEVELS[] (확인된 현행 스키마)
// ent: 각 행 문자열 ('.'빈칸 '#'벽 'r'바위 'b'블롭 'f'깃발 'w'물)
// texts: [[r, c, 'WORD']] — WORD 블록을 밀어 'X IS Y' 규칙 구성
{ name: '규칙을 끊다', par: 12, cols: 9, rows: 7,
  ent: ['....#....', '....#....', '....#....', '.b..#..f.',
        '....#....', '....#....', '....#....'],
  texts: [[0,0,'BLOB'],[0,1,'IS'],[0,2,'YOU'], [0,6,'FLAG'],[0,7,'IS'],[0,8,'WIN'],
          [5,0,'WALL'],[5,1,'IS'],[5,2,'STOP']] }
// NOUNS = BLOB/ROCK/WALL/FLAG/WATER · PROPS = YOU/WIN/PUSH/STOP/SINK
// 전부 손검증된 풀이 존재 · undo 무제한(가설검증)
```

## 난이도 튜닝 노브 (축 B)

| 노브 | 범위 | 방향 | 효과 | 주의 |
|---|---|---|---|---|
| `par` | 6~18 | ↑ = 어려움 | 최적 이동수(`LD-BUDGET`). 솔버 검증값 | 손어림 금지 |
| 신규 규칙/속성 | 1개/레벨 | 도입 = 학습 | YOU/WIN/PUSH/STOP/SINK·정체성 전환 | 동시 2개 금지 |
| 통로 길이(`cols`·`ent`) | 7~11 | 길수록 어려움 | 선계획 깊이·possibility space | 캡스톤만 11열 |
| 규칙 상호작용 수 | 1~3 | ↑ = 어려움 | 끊기/짓기/전환 결합 | 4개+ = 조합 폭발 |

> **par 계단 권장: 도입 6~8 → 전개 10~12 → 비틀기/캡스톤 16~18.** `is-rule` 현행 12레벨이 이 범위를 따른다.

## B-1. `LD-ONE-IDEA` — 한 레벨 한 새 아이디어

**정의.** 각 레벨은 정확히 하나의 새 발상(메카닉, 규칙 조합, 메카닉의 새 적용법)만 가르치거나 탐구한다. 새 메카닉은 그 자체만 시험하고, 다음 레벨에서 기존 것과 결합한다.

**왜 통하나.** Jonathan Blow(IndieCade): '좋은 퍼즐은 매 레벨 플레이어에게 새로운 무언가를 가르치고 싶어한다 — 반복 변형을 피하라.' Arvi Teikari(Hempuli, Baba Is You): 'PULL, EMPTY, FALL, MORE 같은 새 단어를 순차적으로 하나씩 도입하고, 구현 직후 그 단어에서 나오는 가장 명백한 레벨 아이디어들을 먼저 소진한다.' Mark Brown(GMTK 'What Makes a Good Puzzle')도 같은 가르침-결합 진행을 강조한다.

**구체 규칙(체크리스트).**
- [ ] 한 레벨 = 새 속성/규칙 1개. 신규 PROP 도입 레벨은 그 PROP 단어를 **이미 완성된 규칙으로 배치**해 메카닉 자체만 체험시키고, 다음 레벨에서 단어를 분해/재조립 요구로 올린다.
- [ ] '처음 보는 것'은 최대 1개. 신규 도입 레벨의 `par`는 낮게(6~10) 잡아 메카닉 체험에 집중.
- [ ] 신규 도입 직후 1~2레벨은 같은 메카닉 변주(develop), 그 다음에야 기존과 교차(combine).
- [ ] 신규 요소 도입 레벨에선 다른 신규 변수 수치를 동시에 올리지 않는다.

**우리 엔진 적용.** 현행 12레벨 곡선(STOP→PUSH→규칙끊기→규칙짓기→YOU전환→WIN전환→SINK→복합)이 정확히 이 원칙이다. 신규 도입 레벨은 `texts`에 'NOUN IS PROP' 3블록을 미리 완성 상태로 배치(분해 불필요)하고, 다음 레벨에서 그 단어 중 하나를 떨어뜨려 플레이어가 직접 'X IS Y'를 밀어 만들게 한다.

**안티패턴.** 한 레벨에 새 메카닉 2개를 동시에 넣으면 어느 것이 해법 핵심인지 분리 학습이 안 된다 / 같은 아이디어를 미세 변형만 해 여러 레벨로 늘리면 `LD-VARIETY` 위반('소진'과 '반복'은 다르다).

## B-2. `LD-SOLVABLE` — 항상 풀리는 배치·데드락 방지

**정의.** 모든 퍼즐 레벨은 최소 하나의 해가 손검증(또는 솔버 검증)으로 보장돼야 하며, 플레이어가 비가역 수(corner push 등)로 '풀 수 없는 상태(deadlock)'에 빠지는 함정을 설계자가 미리 차단하거나 undo로 회복 가능하게 한다.

**왜 통하나.** Sokoban 데드락 이론(Sokoban Wiki/JSoko): 데드락은 '아직 플레이 가능하지만 더는 이길 수 없는 상태'. 두 핵심 유형 — (1)**Dead square**: 골이 없는 벽/구석에 박스를 밀어 영구히 못 빼는 칸, (2)**Freeze deadlock**: 박스가 양 축으로 막혀 동결(구석, 두 박스 상호 동결). 절차생성 연구(Taylor·Parberry, De Keyser)도 솔버로 해 존재를 보증한다.

**구체 규칙(체크리스트).**
- [ ] 모든 레벨에 손검증된 해 1개 이상 명시(현행 주석 '전부 손검증된 풀이 존재'가 모범). 가능하면 BFS/A* 솔버로 par 이하 해 존재를 자동 검증.
- [ ] 골 없는 구석/벽 끝에 밀 수 있는 박스가 도달 가능하면 그 칸은 dead square — 거기로 미는 것이 유일 진행처럼 보이지 않게 하거나 undo 무제한으로 회복 보장.
- [ ] 두 박스를 직각 인접 배치해 동시 동결되는 freeze 패턴을 비의도적으로 만들지 말 것. 박스 개수 = 골 개수(정합성 체크).
- [ ] 비가역 메카닉(SINK로 박스 소멸, 규칙 영구 파괴)을 쓰는 레벨은 undo/restart를 1탭 거리로 제공하고, '잘못된 한 수로 영구 교착'을 `LD-FAIR` 관점에서 텔레그래프.

**우리 엔진 적용.** 빌드 타임에 `ent`/`texts`를 파싱해 BFS 솔버로 par 이하 해 존재를 단위테스트화하면 레벨 추가 시 회귀를 막는다. SINK·규칙 파괴처럼 비가역 결과를 만드는 레벨은 undo 스택 무제한 유지(게임 헤더에 'undo 무제한(가설검증)' 명시 — 이 원칙의 직접 구현). (참고: `runeburst`는 같은 `LD-SOLVABLE`을 '교착 자동 셔플'로 구현한다.)

**안티패턴.** 절차생성/수동배치 후 솔버 검증 없이 출시하면 '풀리지 않는 레벨'이 새어나가 신뢰를 깬다 / undo가 없거나 비싸면 비가역 데드락이 곧 강제 재시작 = 강한 좌절 / 솔버가 의도보다 훨씬 쉬운 우회해를 찾는 경우가 흔하다 — '해가 있냐'뿐 아니라 '의도한 난이도로 풀리냐'까지 봐야 한다.

## B-3. AHA-게이팅 — 무엇을 할지는 명확, 어떻게는 불명확

**정의.** 좋은 퍼즐은 '무엇을 해야 하는가(목표)'는 즉시 읽히게 하되 '어떻게(해법 경로)'는 숨긴다. 해법은 한 번의 통찰(aha)로 갑자기 열리며, 그 통찰 전까지는 진행이 막혀(gating) 있다.

**왜 통하나.** Mark Brown(GMTK 'What Makes a Good Puzzle'): '좋은 퍼즐은 무엇을 해야 할지는 명백하게, 어떻게 할지는 명백하지 않게 만든다.' Jonathan Blow: 과도한 튜토리얼은 '에피파니와 발견의 기쁨을 죽인다' — 규칙을 말로 설명하지 않고 퍼즐 자체가 가르치게 둔다. Hempuli: Baba의 'aha'는 기대된 논리를 '깨뜨릴 때' 온다.

**구체 규칙(체크리스트).**
- [ ] 레벨 진입 시 골(`FLAG IS WIN` 등)이 한눈에 보이게 배치해 '목표'는 0초에 전달. 단, 직선 경로는 STOP/벽/물로 막아 '방법'을 가린다.
- [ ] 해법의 핵심은 단 하나의 비자명한 수(규칙 1개를 끊거나 짓거나, 정체성 1회 전환). 그 수를 깨닫기 전엔 모든 평범한 시도가 막히게.
- [ ] 통찰 후 실행은 짧아야 한다(par 대부분이 '깨달은 뒤 단순 이동'). 통찰형 레벨 `par`는 6~12 권장.
- [ ] 힌트는 텍스트가 아니라 공간 구도로(막힌 직선 + 옆에 분해 가능한 'WALL IS STOP' 단어쌍).

**우리 엔진 적용.** `ent`에서 `b`(블롭)와 `f`(깃발)를 같은 행 양 끝에 둬 목표를 즉시 보이게 하고, 가운데 `#` 벽 + 'WALL IS STOP' `texts`를 배치한다(레벨4 '규칙을 끊다'가 정석). 평범한 이동으론 못 가고, 'STOP' 단어를 밀어 규칙을 끊는 단 하나의 통찰만이 길을 연다. `par`를 그 통찰해의 최소 이동수로 타이트하게 설정해 '깨달음 = 해결'이 되게 한다.

**안티패턴.** 목표가 불명확하면 'aha'가 아니라 'huh?'(혼란) — 무엇을 할지는 절대 숨기지 말 것 / 해법 경로가 여러 평범한 변형으로 brute-force 가능하면 통찰이 무력화(possibility space를 작게) / 통찰 후 실행이 지나치게 길고 까다로우면 깨달음이 노동에 묻힌다.

## B-4. `LD-TEACH` — 무텍스트로 가르치기(안전한 환경의 직접 체험)

**정의.** 새 메카닉/규칙은 말이 아니라 안전한(실패할 수 없는) 환경에서 직접 한 번 해보게 함으로써 가르친다. 첫 등장은 '시험'이 아니라 '소개'다.

**왜 통하나.** 닌텐도 4단계 분석(Super Mario 3D World, kishōtenketsu): 1단계는 '실패할 수 없는 안전한 장소'에서 메카닉을 익히게 한다. Jonathan Blow: 규칙을 말로 설명하지 않고 퍼즐이 가르친다. Hempuli: 새 단어 도입 직후 '가장 명백한 레벨 아이디어'부터 보여줘 메카닉을 체득시킨다.

**구체 규칙(체크리스트).**
- [ ] 신규 메카닉 첫 레벨은 위협/페널티 제거: 함정·시간제한·실패 비용 없이 인과(밀면 움직인다, 물에 빠지면 메워진다)만 보이게.
- [ ] 메카닉을 '한 번 쓰면 골에 닿는' 최소 배치로 — 안 쓰면 못 풀게 해 자연 강제 학습. 예: PUSH 도입 레벨은 바위를 한 번 밀어야만 통과.
- [ ] 도입 레벨 `par`는 메카닉 최소 사용 횟수에 맞춰 짧게(6~10). 이후 develop(더 멀리 밀기)→twist(다른 규칙과 충돌)로 확장.
- [ ] 텍스트 설명창을 띄우지 말 것 — 색/구도/배치만으로 행동 유도.

**우리 엔진 적용.** 레벨3 '밀어내기'가 표준이다: 좁은 1행 통로에 바위 `r` 하나를 둬 '바위를 밀어야만' 깃발에 닿게 — PUSH를 무언으로 가르친다. 신규 PROP 도입 레벨은 `ent`를 단일 직선 통로로 단순화하고 방해 요소(추가 벽/물)를 0으로 둬 안전 학습을 보장한다. 이후 레벨에서만 통로 길이↑·교차 규칙↑.

**안티패턴.** 첫 등장 레벨에서 곧바로 실패 페널티/복잡도를 주면 '배우기 전에 벌받는' 불공정 / 도입 레벨에 다른 방해 요소가 섞이면 무엇이 새 메카닉인지 분리 학습 불가 / 텍스트 튜토리얼 대체는 발견의 기쁨을 죽인다.

## B-5. `LD-4BEAT` — 도입→전개→비틀기→마무리(kishōtenketsu)

**정의.** 한 메카닉(또는 한 챕터)을 4단 구조로 다룬다: (1)안전한 도입, (2)전개(더 어렵게), (3)비틀기(예상 밖 조합/반전), (4)마무리(숙련 확인) 후 그 메카닉을 '버리고' 다음으로.

**왜 통하나.** (A-8과 동일 근거 — 정식화는 Hayashida/Nintendo, 대중화는 Mark Brown의 GMTK 2015 영상.) '메카닉을 약 5분 안에 가르치고-전개하고-비틀고-버린다.' 발상의 근원은 Miyamoto의 4컷 만화 경험이다.

**구체 규칙(체크리스트).**
- [ ] 메카닉당 4레벨(또는 한 레벨 내 4구간): 도입(par 6~8)→전개(par 10~12, 같은 메카닉 더 길게)→비틀기(par 12~18, 다른 규칙과 충돌)→마무리(캡스톤, 결합).
- [ ] '비틀기'는 새 메카닉이 아니라 '같은 메카닉의 예상 밖 적용'(예: SINK를 '길 막기'가 아니라 '먼 박스를 미리 끌어와 메우기(선계획)'로 뒤집기).
- [ ] 마무리 후 그 메카닉을 한동안 쉬게(버리기) 해 `LD-VARIETY` 확보, 다음 묶음에서 새 메카닉으로 교체.
- [ ] 전체 게임은 이 4비트 묶음들의 연쇄로 `LD-CURVE`(톱니형)를 자연 형성.

**우리 엔진 적용.** 12레벨을 4비트 묶음으로 재독해 가능하다: SINK 묶음 = `8('물은 삼킨다', 도입)→9('돌로 메우기', 전개: 먼 박스)→11('뒤엉킨 규칙', 비틀기: 밀기+메우기+벽 결합)→12('마지막 한 수', 마무리: 넓은 통로 캡스톤)`. 새 게임 설계 시 `LEVELS`를 의도적으로 4개 단위로 묶고 `par`를 6→10→14→18로 계단 배치한다.

**안티패턴.** '비틀기' 단계에 완전히 새 메카닉을 들이면 4비트가 깨지고 `LD-ONE-IDEA`와 충돌 / 마무리 후에도 같은 메카닉을 계속 우려먹으면 반복 피로(throw it away를 지켜라) / 4비트를 모든 콘텐츠에 기계적으로 강요하면 오히려 예측 가능해진다.

## B-6. 엘레강스 — 최소 요소·레드헤링 제거

**정의.** 퍼즐은 필요한 최소의 공간과 요소만으로 구성한다. 모든 조각은 해에 쓰여야 하며, 쓰이지 않는 요소(레드헤링)는 제거한다 — 안 움직여도 되는 박스는 벽으로 대체하라.

**왜 통하나.** 'How to make a good puzzle'(Game Developer): '퍼즐이 동작하는 데 필요한 가장 작은 공간과 조각만 사용하라; 레드헤링을 제거하고, 대신 예상 밖 용도의 요소를 넣으라.' Sokoban 격언(games4brains): '모든 박스는 옮겨져야 한다 — 아니면 그냥 벽을 두는 게 낫다.' Jonathan Blow: red herring 없는 미니멀 퍼즐이 해를 더 또렷이 드러낸다.

**구체 규칙(체크리스트).**
- [ ] 레벨의 모든 박스/단어/지형이 해에 기여하는지 점검 — 안 하면 삭제하거나 벽으로 치환.
- [ ] 보드 크기는 해가 성립하는 최소 `cols`×`rows`(여백은 시야 정리용 최소만). 도입 레벨 7~9열, 캡스톤만 11열.
- [ ] possibility space(도달 가능 상태 수)를 의도적으로 작게 유지해 brute-force를 막되, 해는 비자명하게.
- [ ] 장식적 대칭/넓은 빈 공간은 trial-and-error를 유발하므로 지양.

**우리 엔진 적용.** `ent` 문자열에서 `.`(빈칸) 비율을 점검해 해에 무관한 큰 빈 영역은 통로를 좁혀 줄인다. `texts`의 모든 WORD가 해(규칙 짓기/끊기)에 쓰이는지 확인하고 안 쓰이는 단어쌍은 제거한다. `cols`/`rows`를 해 성립 최소치로 잡고 캡스톤 외엔 9열을 넘기지 않는다.

**안티패턴.** '어렵게 보이려고' 무의미한 박스/벽/넓은 공간을 추가하면 난이도가 아니라 노이즈만 늘어 brute-force를 부른다 / 단, 의도된 trapper(가짜 해를 암시하는 여분 공간)는 예외 — 레드헤링 제거와 'trapper 함정'은 목적이 다르다 / 지나친 미니멀화로 안전 도입 여지까지 깎으면 `LD-TEACH`와 충돌.

## B-7. `LD-BUDGET` — 이동수 예산·par 최적해

**정의.** 퍼즐에 최적해(par) 이동수를 부여해 무게를 준다. par는 '깔끔한 해'의 최소 수로, 플레이어가 낭비 없는 풀이를 지향하게 하고 설계자가 의도한 해를 계측한다.

**왜 통하나.** 'How to make a good puzzle': '난이도는 시작과 해 사이의 최소 단계 수로 측정한다.' Sokoban 솔버 연구(De Keyser): 최적해(push/move 수)는 퍼즐의 객관적 난이도·해 존재 지표다. par는 `LD-MASTERY-CEILING`(최소수 도전)과 `LD-BUDGET`(낭비 제한)을 동시에 구현한다.

**구체 규칙(체크리스트).**
- [ ] 모든 퍼즐 레벨에 `par`를 명시하고 솔버로 검증(현행이 이미 레벨마다 par 6~18 보유).
- [ ] `par`는 의도한 '깔끔한 해'의 이동수 — 솔버가 더 짧은 해를 찾으면 그게 진짜 par(설계 재검토 신호).
- [ ] par 초과 클리어는 허용하되(`LD-FAIR`), par 달성/이하를 별 보상/스피드런 목표로 가시화(`LD-MASTERY-CEILING`).
- [ ] 난이도 곡선상 par는 도입 6~8 → 전개 10~12 → 비틀기/캡스톤 16~18 계단(`LD-CURVE`).

**우리 엔진 적용.** 각 `LEVELS[].par`를 BFS/A* 솔버 출력으로 자동 산출·검증해 회귀 테스트화한다. UI에 '내 이동수 / par'를 표기하고 par 이하 달성 시 별·기록을 부여(가변비율 보상 `LD-REWARD`). (교차: `runeburst`는 par 대신 `LEVELS[].moves`가 동일 역할 — `moves`를 솔버 추정 최소 매치수의 1.2~1.5배로 잡아 긴장 유지.)

**안티패턴.** par를 솔버 검증 없이 손어림으로 잡으면 실제보다 후하거나 빡빡해 의도가 깨진다 / par 미달성에 과한 페널티(레벨 잠금)는 `LD-FAIR`/접근성 위반 — par는 '천장'이지 '관문'이 아니다 / 이동수 최적화만 압박하면 탐색·실험(undo 가설검증)의 즐거움이 위축된다.

## B-8. 규칙 상호작용으로 창발 만들기

**정의.** 여러 메카닉/규칙이 결합할 때 생기는 예상 밖 상호작용에서 가장 깊은 퍼즐이 나온다. 단일 메카닉 전시보다, 이미 가르친 규칙들의 조합으로 '깨뜨릴 수 있는 논리'를 설계한다.

**왜 통하나.** Hempuli(Baba Is You): '대부분의 레벨은 내가 가진 단어·시스템을 놓고 그들 사이의 놀랍고 재미있는 상호작용을 찾으려 하면서 나왔다 — aha는 기대 논리를 깨뜨릴 때 온다.' Jonathan Blow: 제약이 가능성을 제한하지 않고 새 가능성을 만든다. 규칙조작 장르(Baba/PuzzleScript rewrite rules)의 본질이다.

**구체 규칙(체크리스트).**
- [ ] 신규 메카닉을 충분히 가르친 뒤, 이미 아는 메카닉 2~3개를 한 레벨에서 교차시켜 비자명한 결합해 요구.
- [ ] 규칙조작: 'X IS Y'를 끊기/짓기/정체성 전환(NOUN IS NOUN) 조합 — 예: 'ROCK IS YOU'로 조종 대상을 바꾼 뒤 'ROCK IS WIN'으로 승리 조건까지 옮기는 2단 통찰.
- [ ] 상호작용 레벨 `par`는 결합 깊이에 비례해 높게(14~18). 단 '결합'은 최대 2~3개로 제한(인지 과부하 방지).
- [ ] 메타 규칙(YOU IS WIN, 자기 자신을 승리로)처럼 시스템 자체를 건드리는 수는 캡스톤급에만 1회 배치.

**우리 엔진 적용.** 후반 레벨 `texts`에 NOUN/PROP 단어를 분해 가능한 위치로 흩뿌려, 'WALL IS STOP'을 끊고 동시에 'FLAG IS WIN'을 지어야 하는 2규칙 동시 조작을 요구한다(레벨11 '뒤엉킨 규칙'이 밀기+메우기+벽 3종 교차). 레벨10 '나는 곧 목표'(YOU IS WIN 메타)처럼 시스템 자기참조 수는 단발 캡스톤으로 둔다.

**안티패턴.** 한 레벨에서 4개+ 규칙을 동시 조작 요구하면 통찰이 아니라 조합 폭발 → brute-force/포기 / 충분히 가르치기 전에 결합부터 요구(`LD-ONE-IDEA` 건너뜀)하면 불공정한 벽 / 메타/자기참조 규칙을 남발하면 시스템 신뢰가 흔들려 '무엇이든 가능'으로 느껴 탐색이 무의미해진다.

## B-9. `LD-FAIR` — 선계획 요구 + 공정한 회복

**정의.** 퍼즐은 즉흥 시행착오가 아니라 '미리 머릿속으로 수를 읽는 선계획'을 요구해야 한다. 동시에 잘못 읽었을 때의 회복(undo/restart)은 즉각·무비용이어야 공정하다.

**왜 통하나.** games4brains: 과도한 대칭은 '계획 대신 시행착오'를 유발하므로 지양 — 좋은 레벨은 선계획을 요구한다. Sokoban 비가역성: corner push 등 한 수가 영구 교착을 만들므로 미리 결과를 읽어야 한다. Blow/Brown/Hempuli 공통: 쉬운 리셋(undo)이 해법 도달의 필수 — 실험 비용을 0으로 만들어 가설검증을 장려한다.

**구체 규칙(체크리스트).**
- [ ] 해가 '특정 순서'로만 성립하게 설계(goal-area/parking-lot 기법): 박스를 채우는 순서가 하나로 강제되면 역순으로 계획하게 된다.
- [ ] 비가역 수(SINK 소멸, 규칙 영구 파괴)를 포함하되, undo 무제한 + 1탭 restart를 항상 제공(실패 비용 ≈ 0, `LD-CHECKPOINT`).
- [ ] 함정(trapper)은 '되돌릴 수 있을 때만' 사용 — 가짜 해를 시도해도 undo로 즉시 복귀 가능해야 `LD-FAIR` 충족.
- [ ] 기습(설명 없이 즉사하는 숨은 규칙) 금지 — 위협은 안전한 형태로 먼저 보여준다(`LD-FORESHADOW`).

**우리 엔진 적용.** undo 스택을 레벨 시작 상태까지 무제한 보장한다(이미 'undo 무제한(가설검증)' 구현). restart 버튼을 HUD 상시 노출. 선계획 강제는 `ent` 배치로: 좁은 통로 + 단일 순서로만 메울 수 있는 SINK 배치(레벨9 '돌로 메우기'가 먼 박스 선계획 요구). 비가역 결과 직전 상태를 undo로 항상 복원 가능하게 해 trapper를 공정하게 운용한다.

**안티패턴.** undo/restart가 느리거나 비싸면 선계획 요구가 곧 처벌이 되어 좌절 / 선계획을 요구한다며 정보(박스·골·벽 배치)를 화면 밖에 숨기면 불공정 — 모든 단서는 한 화면에 / 시행착오로도 우연히 풀리게 설계하면(possibility space가 크면) 선계획 의도가 무력화된다.

## 장르 메모 — 두 축 공통·차이

**(A) 매치·머지.** 난이도 노브는 4축(moves·colors·goal/target·board shape)이며 한 번에 한 축만 움직여 톱니를 만든다. 승리조건 4종(score/jelly/collect/ingredient) 로테이션이 장르 표준이고 `runeburst`가 이를 그대로 구현한다. 블로커는 기능별(제거형/다겹형/하강형/번식형/점수형)로 변주하되 번식형은 확산 상한이 필수다. **해결가능성이 장르 생명선** — 데드락 감지 후 자동 셔플 + 셔플 시 자동 매치 금지 + 셔플 후 수 존재 재검증 + 폴백 재생성의 4중 불변식을 깨면 안 된다. 공정성은 결정론 시드로 RNG 가짜 난이도를 제거하고, 부스터 없이 par 내 통과 가능을 기본값으로 둔다(F2P의 '+5 moves' 과금은 레벨 풀이 가능성과 분리). 색 드롭 확률 ±20~30% 미세조정은 4~5색에서 인지 불가하므로 소프트 보호/DDA 노브로 쓰되 검증·데일리 시드 모드에선 끈다. 튜닝은 시드 고정 보드 10회+ 자가/봇 플레이로 '잔여 이동수·목표 달성%·셔플 빈도'를 계측한다 — 한 시도 2회 셔플은 나쁜 보드 신호.

**(B) 규칙조작·소코반.** '액션 페이싱'이 아니라 **'학습 페이싱'**이 핵심 축이다. 톱니형 난이도는 '강도'가 아니라 '통찰의 깊이'로 측정되며, 한 레벨 한 새 아이디어(`LD-ONE-IDEA`)가 곡선의 단위다. 비-협상 규칙 4가지: (1)솔버 검증 — 모든 레벨은 손검증 또는 BFS/A* 솔버로 par 이하 해 존재를 보증(현행 주석 '전부 손검증된 풀이 존재'가 이 규율). (2)데드락 인지 — Sokoban류는 corner/freeze로 영구 교착이 가능하므로 undo 무제한이 사실상 필수 안전망('undo 무제한(가설검증)'). (3)무텍스트 학습 — 규칙을 말로 설명하지 않고 안전한 도입 레벨에서 체험. (4)aha 게이팅 — 진행이 '실력'이 아니라 '통찰' 하나로 열린다. 규칙조작 서브장르는 '규칙 자체가 퍼즐 조각'이라는 메타 층위를 더한다 — 가장 깊은 퍼즐은 단일 규칙 전시가 아니라 이미 가르친 규칙들의 예상 밖 상호작용(창발)에서 나온다. 현행 12레벨이 장르 원칙을 거의 교과서적으로 따르므로, 새 콘텐츠는 4비트 묶음(`LD-4BEAT`) 단위로 `LEVELS`를 확장하고 par를 6→10→14→18 계단으로 잡는 것이 일관성에 유리하다.

- **장르 스킬(빌드 위임):** 두 축 모두 `puzzle-game` + [`level-designer`](../../../wgf-level-designer/SKILL.md)가 빌드를 맡는다. `level-designer`는 본 문서의 `LD-*` 처방을 실제 `LEVELS` 데이터로 인코딩하는 메카닉(보드 마스크·셔플 불변식·undo 스택·솔버 게이트)을 제공한다.
- **제작요소 스킬:** 에셋은 VectorForge(룬·단어블록 절차 베이크)·ChipAudio(콤보 피치/미니멀 SFX)·MobileHarness(모바일 웹뷰 스케일/터치)로 생성한다. CC0 검증은 [`ip-license-guard`](../../../wgf-ip-license-guard/SKILL.md).
- **이웃 레벨 파일:** [platformer-levels.md](./platformer-levels.md)(super-runner) · [shooter-arena-levels.md](./shooter-arena-levels.md) · [runner-procedural-levels.md](./runner-procedural-levels.md) · [arcade-levels.md](./arcade-levels.md). 공통 원칙은 항상 [principles.md](./principles.md), 색인은 [INDEX.md](./INDEX.md).
- **인터뷰 → 설계 흐름:** 레벨 요구사항 추출은 [level-interview.md](../level-interview.md)로 시작해, 대상 게임(`runeburst`/`is-rule`)의 `game.js` 스키마를 0단계에서 분석한 뒤 본 문서의 노브 표·체크리스트로 곡선을 설계한다.
- **재미요소·DNA 색인:** 재미 조합(`FE-*`)은 [fun-elements.md](../../../wgf-web-game-builder/reference/game-dna/fun-elements.md), 게임 DNA 색인은 [INDEX.md](../../../wgf-web-game-builder/reference/game-dna/INDEX.md), 엔진 API는 [engine-api.md](../../../wgf-web-game-builder/reference/engine-api.md), Phaser 4 레퍼런스는 [phaser/INDEX.md](../../../wgf-web-game-builder/reference/phaser/INDEX.md).
