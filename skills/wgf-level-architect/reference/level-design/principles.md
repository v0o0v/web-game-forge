# 레벨 디자인 원칙 사전 (LD-*)

> WebGameForge가 "레벨을 어떻게 배치할지" 물을 때 쓰는 핵심 자료. 레벨 디자인 통념을 **재사용 가능한 원칙(LD-*)**으로 분해하고, 난이도 곡선·페이싱·안티패턴·추가 워크플로까지 한 파일에 담는다. 재미 요소(FE-*)가 "무엇을 만들지"라면, LD-*는 "그것을 어떤 순서·강도·배치로 가르치고 도전시킬지"다.
>

## 0. 우리 엔진 제약 (모든 원칙에 선적용)

이 사전의 모든 '엔진 적용'은 다음 제약을 전제로 한다. 어긋나는 처방은 채택하지 않는다.

| 제약 | 의미 | 레벨 디자인 함의 |
| --- | --- | --- |
| 2D · 단일플레이 | 협동 AI 디렉터·멀티 페이싱 불가 | L4D식 '팀 강도'는 '가장 위급한 단일 지표'로 번안 |
| 모바일 웹뷰 | 한 손·짧은 세션·작은 화면 | 1레벨 1~3분, 신호는 색+형태 이중부호화, 명도 대비 크게 |
| CC0 / 절차생성 | 고유 에셋·고유 레벨 복제 금지 | LEVELS를 손코딩 대신 곡선 생성기+시드로 |
| Arcade 물리 우선 | 정밀 강체는 Matter ⚠️ | 점프·임펄스는 단순 모델, 결정론 유지 |
| 서버 메타 ❌ | 온라인 랭킹·DDA 서버 불가 | localStorage 누적·시드 공유로 대체 |

세 데모 게임의 `game.js` 상단 선언적 `LEVEL(S)` 블록이 곡선의 **single source of truth**다. 본 사전은 이 블록을 직접 인용해 처방을 건다.

```js
// super-runner: 전역 LEVEL (플랫포머, 공간형 노브)
var LEVEL = {
  width: 132, rows: 14, groundTop: 12,
  pits: [[27, 29], [58, 60], [88, 90], [104, 105]], // [시작,끝] 구덩이
  features: [ { t: '?', c: 8, r: 9 }, { t: 'o', c: 6, r: 9 }, { t: 'e', c: 21, r: 11 } /* ... */ ],
  pipes: [ { c: 23, top: 10, h: 2 }, { c: 54, top: 8, h: 4 } ],
  goal: { c: 124 }, start: { c: 2, r: 11 }
};
// 난이도 노브 = pit 폭/연속 · 공중 발판 간격 · 적('e') 밀도 · 발판 길이
```

```js
// runeburst: 전역 LEVELS[] (매치3, 자원·확률형 노브)
var LEVELS = [
  { name: '첫 별빛', shape: 'square', colors: 5, moves: 20, goal: 1000,
    win: { type: 'score', target: 1000 }, seed: 1001 },
  { name: '성운을 걷어라', shape: 'cross', colors: 6, moves: 22, goal: 2000,
    win: { type: 'jelly' }, jelly: 1, seed: 1005 },
  { name: '얼어붙은 룬', shape: 'hourglass', colors: 6, moves: 20, goal: 2600,
    win: { type: 'score', target: 2600 }, ice: 8, seed: 1007 }
  // win.type: 'score'|'jelly'|'collect'|'ingredient'
  // 블로커: jelly / ice / spreaders / ingredients / overload
];
// 난이도 노브 = colors↑ · moves↓ · goal↑ · 보드 shape · 블로커 종류/수
```

```js
// is-rule: 전역 LEVELS[] (규칙조작 퍼즐, 인지형 노브)
var LEVELS = [
  { name: '밀어내기', par: 8, cols: 9, rows: 7,
    ent: ['.........', '.........', '#########', '.b.r...f.', '#########', '.........', '.........'],
    //   '.'빈칸 '#'벽 'b'블롭 'f'깃발 'r'바위 'w'물
    texts: [[0,1,'BLOB'],[0,2,'IS'],[0,3,'YOU'], [0,5,'FLAG'],[0,6,'IS'],[0,7,'WIN'],
            [6,1,'ROCK'],[6,2,'IS'],[6,3,'PUSH'], [6,5,'WALL'],[6,6,'IS'],[6,7,'STOP']] }
  // texts: WORD 블록을 밀어 'X IS Y' 규칙을 구성
];
// 난이도 노브 = 새 규칙 1개 도입 · par(최적 이동수) · 통로 길이 · 규칙 상호작용 수
```

## 1. LD-* 원칙 사전

각 원칙은 **정의 → 왜 통하나 → 구체 규칙(체크리스트) → 우리 엔진 적용 → 주의/안티패턴** 순으로 정리한다. 태그 표기(LD-CURVE 등)는 모든 파일이 그대로 쓴다.

### LD-FLOW-CHANNEL 몰입 채널 (도전과 실력의 균형)

- **정의:** 플레이어의 현재 실력(skill)과 게임이 요구하는 도전(challenge)을 거의 비등하게 맞춰, 불안(challenge>skill)과 지루함(skill>challenge) 사이의 좁은 통로 안에 플레이어를 계속 머무르게 한다. 실력이 시간에 따라 오르므로 도전도 함께 우상향해야 채널을 벗어나지 않는다.
- **왜 통하나:** 도전과 실력의 균형이 boredom과 anxiety를 가르는 flow(몰입) 채널 개념은 심리학자 Mihaly Csikszentmihalyi가 1970년대에 정식화한 flow 이론(1975년 저서 『Beyond Boredom and Anxiety: Experiencing Flow in Work and Play』)에 기반한다. 원본 1975년 도식은 challenge-skill 평면을 anxiety / flow / boredom의 단순 3구역으로 나눴고, 1990년 저서 『Flow: The Psychology of Optimal Experience』가 이를 체계화·대중화했다. (1987년 Massimini·Csikszentmihalyi·Carli가 이를 8가지 정서 상태로 세분한 'Eight Channel Model(8채널 모델)'로 발전시켰으므로, 흔히 인용되는 '3채널'은 1975년 원본 도식이고 정식 세분 도식 명칭은 8채널 모델이다.) 게임 적용은 Jenova Chen(thatgamecompany)의 MFA 논문 'Flow in Games'가 '재미=flow'로 정리하며 macro/micro flow를 구분했다.
- **구체 규칙:**
  - [ ] 각 구간에 '예상 클리어 시도 횟수' 목표를 잡는다: 도입 1~2회, 중반 3~5회, 정점 6~10회. 이 값이 채널 폭이다.
  - [ ] 실력 상승분을 가정해 난이도를 우상향: 스테이지 N의 핵심 노브를 N-1 대비 약 10~20%만 올린다(급경사 금지).
  - [ ] 한 노브만 크게 올리지 말고 분산한다(예: moves를 -3 하면서 colors는 그대로 → 다음 스테이지에서 colors +1 하면서 moves +2 보정).
  - [ ] 초반 3~5스테이지는 거의 100% 클리어 가능하게(skill>challenge 쪽으로 약간 치우치게) 두어 '실력이 자란다'는 감각을 먼저 심는다.
- **우리 엔진 적용:** 세 게임 모두 `game.js` 선언 블록의 노브로 채널을 제어한다. super-runner는 `pits` 폭/연속·발판 간격·`features`의 'e' 밀도를 스테이지 인덱스 함수로 약 15%씩 상향. runeburst는 `colors↑ / moves↓ / goal↑` 중 한 번에 하나만 크게 움직이고 나머지는 보정. is-rule은 `par`과 통로 길이를 점진 상향하되 새 규칙은 한 레벨에 1개(LD-ONE-IDEA와 결합). 엔진에 `stageDifficulty(i)` 헬퍼를 두고 노브를 곡선식으로 생성하면 채널이 일관된다.
- **주의/안티패턴:** 절대 난이도만 보고 곡선을 그리면 실력 상승을 무시해 후반이 지루해진다(곡선은 '상대 난이도=도전-실력'이어야). 여러 노브 동시 상향은 스파이크를 만들어 anxiety로 튕긴다. flow를 '항상 어렵게'로 오해하지 말 것 — 너무 쉬워도 채널 이탈(boredom)이다.

### LD-CURVE 난이도 곡선 (톱니형 tense-and-release 상승)

- **정의:** 전체 난이도는 우상향하되 직선이 아니라, 도전을 올렸다가(긴장) 다음 구간에서 살짝 낮춰(완화) 다시 올리는 톱니/계단 패턴으로 진행한다. 평탄한 직선 상승도, 갑작스러운 스파이크도 피한다. 또한 마지막 비트를 '최고 난이도'로 두지 않고, 정점 직후 하강(falling action)으로 마무리를 '필연적 승리'로 체감시킨다.
- **왜 통하나:** Jesse Schell은 『The Art of Game Design: A Book of Lenses』에서 flow를 도전 상승→보상→완화가 반복되는 'tense and release(긴장과 이완)' 사이클로 설명하며, 이 진동으로 플레이어를 flow 채널 안에 유지하라고 처방했다. (흔히 인용되는 'Oscillation Method'라는 명칭은 Schell 본인의 용어가 아니라 그의 flow-channel 논의를 해설한 2차 글에서 쓰는 라벨이다. tense-and-release는 Csikszentmihalyi flow의 '대안'이 아니라 그것을 실현하는 방식 그 자체다.) 클라이맥스 뒤 완화는 The Level Design Book이 Aristotle(Poetics)·Freytag(5막)·Campbell(영웅 여정)·McKee(Story)를 인용해 정리한 서사 구조와 맞물린다 — Dark Souls·Portal·Half-Life 2의 최종 보스가 의외로 단순·예고된 풀이를 갖는 이유다.
- **구체 규칙:**

| 구간 위치 | 상대 난이도 처방 | 비고 |
| --- | --- | --- |
| 묶음 첫 스테이지 | 직전 정점보다 약 -10% | 의도적 완화(숨 고르기) |
| 묶음 중반 | +12~15%씩 점증 | 한 번에 한 노브 |
| 묶음 끝(정점) | +20% 스파이크 | 스파이크는 묶음 끝에만 |
| 정점 직후 | 완화 후 다시 +15% | 톱니의 골은 이전 골보다 절대값↑ |
| 게임 최종 | 정점은 끝나기 '직전', 진짜 끝은 -완화 | falling action |

  - [ ] 연속 두 스테이지의 상대 난이도 차가 한 묶음 평균 상승폭의 2배를 넘지 않게.
  - [ ] 곡선을 데이터로 정의: `difficultyOf(i) = base*(1+0.12*i) + 톱니항(계단/주기)`을 만들고 LEVELS 생성에 주입.
  - [ ] 최종 보스/대미 도전은 '새 메카닉 도입'이 아니라 '학습한 메카닉의 집대성'으로.
- **우리 엔진 적용:** runeburst `LEVELS`에 톱니를 그대로 인코딩 — 보스급(colors=6, moves 빡빡, 블로커 다수) 다음 스테이지는 colors=5·moves 여유·블로커 1종으로. super-runner는 긴 pit 연속+공중 발판(정점) 다음 레벨에 `groundTop` 연속 지형+넓은 발판(완화). is-rule은 규칙 상호작용이 복잡한 고 par 레벨 뒤에 par 낮고 단일 규칙 레벨을 끼운다. 손코딩 대신 곡선 생성기+시드로 LEVELS를 뽑으면 톱니 일관성이 보장된다(절차생성 CC0와도 정합).
- **주의/안티패턴:** 톱니의 골을 너무 깊게 파면(급강하) 성취감이 깨진다. 스파이크가 묶음 중간에 불쑥 나오면 '벽'에 부딪힌 느낌→이탈(LD-FAIR 위반). 마지막을 역대 최고 난이도+신규 메카닉으로 두면 좌절로 끝나 카타르시스가 사라진다.

### LD-PACING 페이싱 (강도 intensity의 상승·하강 파동)

- **정의:** 레벨/세션 전체에서 강도(긴장·판돈·복잡도)를 시간축에 따라 봉우리(peak)와 골(valley)로 출렁이게 배치한다. 강도는 난이도(객관 사망률)와 다르다 — 서스펜스·스테이크를 포함한다. 좋은 페이싱은 다수 봉우리와 골이 이어지는 톱니형 램프이고, 봉우리:골 ≈ 1:1로 둔다.
- **왜 통하나:** The Level Design Book(저자 Robert Yang 등)에 따르면 Valve 디자이너들은 Half-Life 2: Episode Two와 Left 4 Dead의 레벨 페이싱을 위해 beat를 Explore/Combat/Choreo/Puzzle 4종으로 분류하고, X축=시간(분)·Y축=강도(intensity) 그래프로 설계했다(강도 척도는 '0-100%, 0-5, 또는 0-10' 중 택일, 값은 "플레이테스트 관찰에서 나오는 직감"이라 명시 — Valve 내부 실무 관행이며 1차 출처는 GDC China 2014 'Level Design Workshop: Pacing'의 White Forest Inn intensity graph). Dan Cox는 아니고 **Mike Stout**의 'Trinity, Part 6 — Intensity Ramps'(2015)가 강도를 '주관·게임 내부 상대값', 난이도를 '객관·게임 간 비교값'으로 구분하고 램프는 봉우리와 골을 모두 포함해야 한다고 본다.
- **구체 규칙:**
  - [ ] 세션을 시간으로 쪼개 강도 점수(0~10)를 매겨 그래프가 직선이 아닌 파형이 되게: 도입 2~3, 첫 봉우리 5~6, 중반 7~8, 클라이맥스 9, 직후 완화 3.
  - [ ] 낮게 시작(start low): 첫 구간은 저강도로 맥락을 잡는다.
  - [ ] 연속 상승은 최대 3비트, 4비트째에 하강. 고강도(boss·연속 위협)는 길게 끌지 않고 그 전에 회복 beat(LD-REST) 삽입.
  - [ ] beat 종류를 섞는다: 전투-탐험-퍼즐-연출을 번갈아 같은 활동의 반복을 피한다(같은 비트 3연속 금지).
- **우리 엔진 적용:** 모바일웹뷰 단일플레이라 '세션=스테이지 시퀀스'로 본다. super-runner는 한 레벨 `width`를 구간화해 고강도(pit 연속+적)와 저강도(평지+코인 줍기)를 번갈아 인코딩. 현재 `pits [[27,29],[58,60],[88,90],[104,105]]` 사이 간격이 곧 '쉼표' 후보다. runeburst는 스테이지 시퀀스에서 고강도(빡빡 moves·다중 블로커) 사이에 저강도(점수형 win, 여유 moves)를 끼워 파형을 만든다. is-rule은 고 par 레벨 뒤에 '아하' 가벼운 레벨. 엔진에 stage별 `intensityScore` 메타를 두고 시퀀스 빌더가 파형(저-고-저-고-정점-완화)을 강제하면 페이싱이 데이터로 보장된다. 페이싱은 '레벨 내'와 '스테이지 시퀀스' 두 스케일(Jenova Chen의 micro/macro flow)에서 동시에 설계한다.
- **주의/안티패턴:** 고강도를 계속 쌓으면 무뎌지고(numb) 피로로 이탈. 골(저강도)을 '버리는 구간'으로 취급해 지루하게 만들지 말 것 — 회복은 보상처럼 느껴져야 한다. 최종 보스를 최고 난이도로 두면 falling action이 사라져 탈진으로 끝난다.

### LD-REST 쉼표·완급 (고강도 뒤 회복)

- **정의:** 고강도 직후의 회복 구간(rest/lull)은 다음 봉우리를 '다시 강하게' 느끼게 만드는 대비 장치다. 강도는 절대값이 아니라 직전 구간 대비 상대값이라, 쉼을 깔지 않으면 봉우리가 새 기준선이 되어 더는 높게 느껴지지 않는다.
- **왜 통하나:** Mike Stout의 'Intensity Ramps' Principle #5 — "항상 11로 틀어놓으면 11이 새로운 5가 된다(If it's always 'turned up to eleven,' eleven becomes the new five)": 5→11 점프는 극적이지만 10→11은 미미하다. The Level Design Book도 '어떤 보스전도 10분 넘기면 슬로그가 된다 — 다운타임을 대비·입가심(palette cleanser)으로 쓰라'고 명시한다(Mad Max: Fury Road의 진흙 정체 장면이 같은 원리). 이는 LD-FLOW-CHANNEL의 boredom 하한과 anxiety 상한 사이를 진동시키는 마이크로 장치다.
- **구체 규칙:**
  - [ ] 강도 8 이상 봉우리 직후엔 강도 3 이하 회복 구간을 최소 1개 강제 삽입한다.
  - [ ] 회복 길이는 직전 봉우리 강도에 비례시킨다 — 큰 봉우리일수록 긴 쉼표.
  - [ ] 쉼표는 완전 무위가 아니라 '저강도 보상 활동'(코인 줍기, 안전한 탐험, 쉬운 수집)으로 채워 지루함을 막는다.
  - [ ] 다음 봉우리는 직전 봉우리보다 올려야 쉼표의 대비가 산다(5→쉼→7, not 7→쉼→7).
- **우리 엔진 적용:** super-runner는 구덩이·적 밀집(봉우리) 뒤 8~12타일을 평지+코인 아치('o' 위주, 'e' 0개)로. runeburst는 어려운 블로커(ice/spreaders/overload) 다수 스테이지 뒤에 '블로커 없음+moves 넉넉+goal 낮음'의 가벼운 점수 스테이지를 입가심으로. is-rule은 고 par 난해 레벨 뒤에 par 2~3의 짧은 '한 수 깨달음' 레벨을 회복 비트로.
- **주의/안티패턴:** 쉼표 없이 봉우리만 연달면 강도 인플레이션→체감 평탄화→이탈. 쉼표가 너무 길거나 완전 무자극이면 몰입 끊김(boredom). 쉼표 뒤 봉우리를 같거나 낮게 두면 회복의 의미가 사라진다.

### LD-4BEAT 4비트 레벨 구조 (도입→전개→비틀기→마무리, kishōtenketsu)

- **정의:** 한 레벨(또는 한 구간)을 새 메카닉 하나에 대한 4단 쇼케이스로 구성한다: ①기(起, 도입: 안전한 곳에서 소개) ②승(承, 전개: 같은 메카닉을 위험 상황에서) ③전(轉, 비틀기: 같은 메카닉을 새 관점으로 꼬아 보여줌) ④결(結, 마무리: 숙달 확인). 약 5분 안에 가르치고-발전시키고-비틀고-버린다. 갈등 누적이 아니라 '예상 밖 전환(轉)'이 드라마를 만든다.
- **왜 통하나:** 4단계 레벨 구조(introduction/development/twist/resolution)를 명시적 설계 원리로 정식화·진술한 것은 닌텐도의 디렉터 **Koichi Hayashida** 본인이다(출처: 그의 GDC 2012 발표 및 Christian Nutt의 2012-04-13 Gamasutra/Game Developer 인터뷰, 대상 게임은 Super Mario 3D Land — kishōtenketsu(起承転結)를 명시적으로 언급한 1차 출처). Mark Brown의 Game Maker's Toolkit 영상 'Super Mario 3D World's 4 Step Level Design'(2015-03-16)은 이 개념을 4단계로 정리해 **대중화·해설**한 것이며, 영상 스스로도 구조를 'according to the game's director Koichi Hayashida'라고 귀속한다. 즉 정확히는 'Hayashida가 정식화(2012)하고 Brown의 GMTK가 대중화(2015)했다'이다(Hayashida 본인은 만화 4컷 구조의 근원을 Shigeru Miyamoto에게 돌렸다). 도입을 항상 안전 환경에 두는 점이 LD-TEACH·LD-FAIR과 맞물려 무텍스트 학습을 가능케 한다.
- **구체 규칙:**
  - [ ] 도입(起): 신 메카닉을 죽지 않는 안전 지대에서 1회 노출(아래 함정 없음, 시간 여유).
  - [ ] 전개(承): 같은 메카닉에 위험 요소 1개 추가(아래 pit, 적, 이동수 압박).
  - [ ] 비틀기(轉): 메카닉을 조합/반전 — '같은 메카닉의 새로운 의미', 양적 증가가 아닌 질적 전환.
  - [ ] 마무리(結): 앞 3비트를 종합한 작은 도전으로 숙달 확인 후 메카닉을 '버리고' 다음 레벨로.
  - [ ] 한 레벨에 4비트가 어려우면 4개 연속 스테이지로 분산(스테이지 단위 kishōtenketsu).
- **우리 엔진 적용:** is-rule이 가장 잘 맞는다 — 새 'X IS Y' 규칙을 도입 레벨에서 데드존 없이 1회, 다음 레벨에서 위험 격자('w'/'r' 근접)와 함께, 그 다음 기존 규칙과 상호작용(轉), 마지막 par 빡빡한 종합 레벨. (현재 12레벨이 이미 YOU→WIN→PUSH→STOP→SINK를 하나씩 도입하는 구조라 정합.) super-runner는 `width`를 4구간으로 나눠 1구간=안전 점프 소개, 2구간=pit 위 점프, 3구간=공중 발판('B' col 45~49)+적 동시(轉), 4구간=goal 직전 종합. runeburst는 새 블로커를 묶음 첫 스테이지에서 소량·여유 moves로 소개 후 묶음 내에서 발전·조합.
- **주의/안티패턴:** 비틀기(轉)에서 '새 메카닉'을 또 넣으면 LD-ONE-IDEA 위반 — 비틀기는 같은 메카닉의 변주여야 한다. 도입을 위험 지대에 두면 학습 전에 죽어 좌절. 4비트를 모든 레벨에 기계적으로 강제하면 변주가 사라져 지루(LD-VARIETY와 충돌) — 일부 레벨은 복습/콤보 레벨로.

### LD-ONE-IDEA 한 레벨 한 개념

- **정의:** 각 레벨(또는 명확한 구간)은 정확히 하나의 새 메카닉/아이디어만 도입한다. 새 아이디어는 단독으로 가르친 뒤에만 기존 요소와 결합한다.
- **왜 통하나:** 닌텐도 4단 설계의 핵심 전제 — 각 스테이지는 '새 아이디어 1개의 자기완결형 쇼케이스'다(GMTK 정리). Super Mario Bros. World 1-1도 9개 게임 요소를 한 번에 하나씩 격리 도입(Goomba→블록→버섯→파이프→구덩이)해 변별 학습을 보장한다. 인지부하를 한 번에 한 개로 제한하는 것이 핵심.
- **구체 규칙:**
  - [ ] 레벨/구간당 신규 요소 정확히 1개(새 적, 새 블로커, 새 규칙 중 하나만).
  - [ ] 새 요소 도입 직후 같은 요소만 2~3회 변주(결합 금지 구간).
  - [ ] 결합(새+기존)은 '비틀기(轉)' 단계에서만.
  - [ ] 난도 노브는 한 번에 하나만(적 수↑ 했으면 구덩이 폭은 유지).
  - [ ] 새 아이디어가 없는 '복습 레벨'을 주기적으로 넣어 정착시킨다.
- **우리 엔진 적용:** runeburst `LEVELS`에서 한 레벨에 새 노브 1개만 — 'ice 도입' 레벨이면 colors·moves·shape는 직전과 동일 유지(현재 L7 '얼어붙은 룬'이 `ice: 8`만 새로 추가). super-runner는 단일 LEVEL 안에서 구간별 1요소(도입=점프, 다음=적 스톰프, 다음=공중 발판, 다음=구덩이 연속), 같은 화면에 첫 등장 요소 2개 금지. is-rule은 레벨당 새 PROPS 1개(현재 구조와 정합) — 새 규칙 도입 레벨엔 기존 규칙 상호작용 최소화.
- **주의/안티패턴:** '하나'를 욕심내 두 개 넣으면 어느 것이 실패 원인인지 못 가린다. 새 아이디어 도입 레벨을 동시에 어렵게 만들면 학습과 도전이 뒤섞여 좌절. 복습 없이 새 것만 쌓으면 정착 실패(LD-VARIETY와 균형).

### LD-TEACH 무텍스트로 가르치기 (안전 환경에서 직접 체험)

- **정의:** 튜토리얼 텍스트·팝업 없이, 안전한 레벨 배치(죽을 수 없는 구간)에서 플레이어가 메카닉을 직접 시도하며 배우게 한다. 먼저 연습시키고 그 다음에 판돈을 올린다(practice-then-raise-the-stakes).
- **왜 통하나:** Super Mario Bros. World 1-1(Shigeru Miyamoto 설계)이 원형 — 텍스트 한 줄 없이 이동·점프·적 밟기·아이템을 가르친다. 첫 적을 스톰프가 쉬운 Goomba로 만들고(Koopa 대신), 일부 구덩이엔 바닥을 둬 빠져도 안 죽게, 점증 높이 파이프로 점프 높이를 무텍스트로 가르친다. Anna Anthropy & Naomi Clark의 『A Game Design Vocabulary』(2014)는 좋은 디자인이란 텍스트 튜토리얼 대신 시청각·맥락 단서로 작동 방식을 전달하는 것이라 본다. Don Norman의 signifier 원칙(아래 LD-AFFORDANCE)도 '좋은 단서는 설명 텍스트를 대체한다'고 정리한다.
- **구체 규칙:**
  - [ ] 신 메카닉의 첫 등장은 실패해도 죽지 않는 배치로(아래 pit 없음, 적 1마리, 시간 압박 없음).
  - [ ] 필요 행동을 환경으로 강제: 통과하려면 그 메카닉을 반드시 한 번 써야 하는 구도로.
  - [ ] 성공 즉시 피드백(점수·이펙트·길 열림)으로 '맞게 했다'를 확인시킨다.
  - [ ] 텍스트 UI 대신 시각 신호(LD-SIGNPOST)와 행동유도성(LD-AFFORDANCE)으로 안내.
- **우리 엔진 적용:** super-runner는 첫 레벨 start 직후 평지에 코인·발판을 두고 첫 pit은 좁고 안전 착지 보장 — 점프를 안 죽고 익히게. 첫 적('e' col 21)은 멀리 두어 밟기를 여유 있게. runeburst는 신규 블로커가 처음 나오는 스테이지를 moves 넉넉·goal 낮게(현재 L5 '성운을 걷어라' moves 22). is-rule은 새 'X IS Y' 도입 레벨을 위험 엔티티 없이 규칙 조작만 연습(undo 무제한이 가설검증 학습을 지원). 엔진에 '교습 레벨' 플래그를 두고 실패 비용 노브(체크포인트·재시도)를 자동 완화하면 일관된 온보딩이 된다.
- **주의/안티패턴:** 신 메카닉을 처음부터 위험 상황에 두면 학습 전에 죽어 좌절(LD-FAIR 위반). 모바일웹뷰에서 텍스트 튜토리얼은 읽씹·이탈을 부른다 — 배치로 가르쳐라. '쓰지 않아도 통과되는' 선택적 도입은 학습이 안 일어난다.

### LD-SIGNPOST 시선 유도·신호·랜드마크

- **정의:** 색·빛·구도·움직임으로 플레이어의 시선을 다음 행동/목표로 유도한다. 텍스트 화살표 없이도 '여기로 가, 이걸 해'가 읽히게 한다. 멀리서 보이는 큰 랜드마크('weenie')로 플레이어가 스스로 향하게 만든다.
- **왜 통하나:** 사람의 눈은 대비(색·형태·조명·움직임)에 자동으로 끌린다. The Level Design Book의 wayfinding 페이지는 'Left 4 Dead가 조명 배치로 경로를 암시한다'를 명시적으로 뒷받침한다("path implied by light placement"). 'weenie'(원거리 시각 유인물) 개념은 Walt Disney/이매지니어링이 디즈니랜드 설계에 쓴 것으로, 게임 디자이너 Scott Rogers가 GDC 2009 강연과 저서 『Level Up!』(2010)의 'Everything I Learned About Level Design, I Learned from Disneyland' 섹션에서 레벨 디자인에 차용·대중화했다. (참고: 노란색=정답 경로 signposting은 Uncharted 4의 클라이밍 ledge, The Last of Us 사례로 '널리 인용되는 대표 사례'이지 wayfinding 페이지가 정리한 업계 정설은 아니다. wayfinding 페이지의 '% certainty' 수치는 저자가 직접 "non-scientific estimate"라 밝힌 추정치다.)
- **구체 규칙:**
  - [ ] 게임 전체에서 '상호작용/목표 색' 1개를 못박는다(고채도·고명도). 지형·배경은 저채도.
  - [ ] 점프해야 할 경로는 코인/아이템을 호(arc)로 깔아 궤적을 미리 그려준다.
  - [ ] 진행 방향·목표는 화면에서 대비가 가장 큰 지점에. 랜드마크는 구간당 1개로 제한하고 충분히 크게.
  - [ ] 한 화면에 고채도 시선 끌개를 3개 이하로(4개 이상이면 signposting 무력화).
- **우리 엔진 적용:** super-runner는 구덩이 위 코인 아치('o' col 27~29, 57~61)로 점프 궤적 안내 — 모든 점프 챌린지에 표준화. `goal`(깃대)을 멀리서 보이는 랜드마크 실루엣으로(카메라 패럴랙스). '?' 블록은 일반 블록과 다른 색. runeburst는 매치 가능 룬에 `RUNES[].glow` 네온 글로우를, 블로커는 저채도 회색조로 위계 분리. 보드형이라 'weenie'는 목표 진척 시각화(별조각 슬롯·젤리 위치)로 치환. is-rule은 `WORD_COL`(고채도 단어블록)과 `ENT_COL`을 색 계열로 분리, 벽('#')은 회색(#737d98)으로 죽인다(이미 정합).
- **주의/안티패턴:** 배경 절차생성이 목표보다 시선을 끄는 '대비 역전' — 배경 채도/명도를 항상 목표 아래로 클램프. 색만으로 신호하면 색각이상(남성 약 8%)이 놓침 — 색+형태/명도 이중부호화 필수. 모바일 소형 화면에서 미세 대비차는 사라지니 명도 대비를 데스크탑보다 크게.

### LD-AFFORDANCE 행동유도성·가독성

- **정의:** 플레이어는 '이건 밟을 수 있다/밀 수 있다/피해야 한다'를 텍스트 없이 형태·색·위치로 즉시 읽어야 한다. 같은 기능은 항상 같은 모습, 다른 기능은 항상 다른 모습.
- **왜 통하나:** Don Norman의 affordance(객체가 제공하는 가능한 행동)와 signifier(그 행동이 가능함을 알리는 지각 가능한 단서) 구분. 'signifier' 용어는 Norman이 2008년 ACM Interactions 칼럼 'Signifiers, not affordances'에서 처음 도입했고, 『Living with Complexity』(2011)를 거쳐 『The Design of Everyday Things』 2013 개정판에서 본격 확장·정착됐다(2013판에서 크게 확장된 것은 맞으나 최초 정식화는 2008년). '손잡이는 당기기, 슬롯은 끼우기' — 형태가 사용법을 암시한다. 게임에서 일관된 시각 어휘는 학습 비용 없이 가독성을 만든다.
- **구체 규칙:**
  - [ ] 한 기능 = 한 형태/색을 게임 전체에서 고정(밟기=평평한 윗면+그림자, 밀기=입체 큐브, 위험=가시 실루엣, 목표=글로우).
  - [ ] 밀 수 있는 것은 밀 수 있게 생기게, 막는 것은 각지고 평평하게.
  - [ ] 위험은 위험하게 생기게(pits는 바닥 텍스처를 끊어 '발판 없음'을 즉시 읽히게).
  - [ ] 상호작용 타일과 장식 타일을 명확히 분리(가짜 어포던스는 신뢰를 깬다).
- **우리 엔진 적용:** super-runner는 `features`의 t값('B'벽돌·'?'아이템·'S'계단·'e'적)마다 형태 규칙을 1:1 고정해 선언적 LEVEL이 곧 가독성 계약이 되게. runeburst는 `RUNES[].sym`(star/diamond/triangle/orb/hex/crescent)으로 6색을 형태로도 구분(색각 보조). is-rule은 ROCK을 둥글고 입체감 있는 색(#cf9a52)으로 PUSH 암시, WALL을 평평·각진 회색으로 STOP 신호 — 엔티티 형태와 단어블록 형태를 분리.
- **주의/안티패턴:** 가짜 어포던스(못 밟는데 발판처럼 생긴 장식) = 최악의 가독성 버그. 숨은 어포던스(밀 수 있는데 안 그렇게 생긴 블록) = signifier 부재로 풀이 불가 착각. 같은 형태에 다른 기능을 주는 일관성 위반은 학습을 매 레벨 리셋시킨다.

### LD-FORESHADOW 예고·복선 (안전한 형태의 선노출)

- **정의:** 새 위협/기믹을 본격 도전으로 쓰기 전에, 무해하거나 통제된 형태(antepiece)로 먼저 보여줘 플레이어가 그 존재·동작을 미리 학습하게 한다. 나중에 같은 요소가 위험으로 돌아온다.
- **왜 통하나:** 'Antepiece'는 TV Tropes에서 'Instructive Level Design'의 sub-trope로 정의되며, 레벨이 앞으로 올 기믹/장애물을 (흔히 위험 없는 안전한 형태로) 미리 예고·연습시키는 기법이다. 자주 인용되는 예시는 Mega Man X1(안전한 구덩이로 Wall Jump 연습), Jak and Daxter의 Geyser Rock, Valve의 Half-Life/Portal, Prince of Persia 1(헐거운 타일이 압력판을 작동시키는 원리를 Level 4에서 미리 보여주고 Level 6에서 활용)이다. 4단 구조의 '도입(起)'이 곧 복선 기능 — 위험을 안전하게 선노출한 뒤 전개·비틀기에서 위험화한다.
- **구체 규칙:**
  - [ ] 치명적 기믹은 첫 등장 시 '구경만 하는' 안전 거리/위치에(닿아도 안 죽는 배치).
  - [ ] 같은 기믹의 2번째 등장부터 실제 위험(접촉=피해)으로 전환.
  - [ ] 복선과 회수 사이 간격은 1~2 구간(같은 레벨/구간 안). 너무 멀면 학습이 휘발.
  - [ ] 위협 직전엔 텔레그래프(LD-TELEGRAPH)로 회피 가능성 보장.
- **우리 엔진 적용:** super-runner는 피라냐가 들어갈 파이프(`pipes`)를 처음엔 빈 파이프(col 23)로 노출, 두 번째(col 54)부터 위험 추가. 첫 적(col 21)을 평지 단독 배치해 관찰 후 비틀기 구간에서 적+구덩이 결합. runeburst는 `LEVELS` 배열의 '블로커 1종씩 순차 도입'(주석 명시)이 그대로 복선 스케줄 — 신규 블로커 첫 등장 레벨은 goal↓/moves↑로 안전 마진. is-rule은 SINK를 먼저 'WATER IS SINK + ROCK'으로 안전 시연(L8) 후 다음 레벨에서 응용(L9).
- **주의/안티패턴:** 복선 없이 신규 치명 위협을 기습 배치 = 기습 금지(LD-FAIR) 위반. 선노출이 너무 미묘하면 학습 효과 없음. '안전한 미리보기'가 실제로 죽이면 복선이 아니라 기습이다.

### LD-RISK-PATH 위험-보상 분기

- **정의:** 필수 경로 외에 '고위험 고보상' 선택지를 둬 플레이어가 자기 실력·욕심에 따라 위험을 택하게 한다. 한 레벨에 여러 난이도층을 공존시켜 flow 채널 폭을 넓힌다.
- **왜 통하나:** 자기결정이론(SDT)의 '자율성(autonomy)' 욕구 — Ryan·Rigby·Przybylski(2006) 'The Motivational Pull of Video Games'와 그 측정 도구 PENS는 '목표·전략에 대한 선택지'가 자율성 충족을 높여 즐거움·재플레이를 예측한다고 실증했다. Schell의 Lens of Reward와 결합하면, 선택적 위험경로는 '더 큰 변동 보상'을 자발적 도전과 묶어 내재 동기를 강화한다.
- **구체 규칙:**
  - [ ] 안전 경로(낮은 보상)와 위험 경로(높은 보상)를 분기하되, 안전 경로만으로도 클리어 가능해야(필수≠위험).
  - [ ] 위험 비용을 명시: 진입 전에 위협을 텔레그래프(LD-FORESHADOW)해 '알고 택하게'.
  - [ ] 보상 차등: 위험 경로 보상 가치를 안전 경로의 1.5~3배로(욕심을 정당화하되 인플레 방지).
  - [ ] 되돌릴 여지: 위험 경로 실패가 전체 진행을 날리지 않게(체크포인트·부분 보상).
- **우리 엔진 적용:** super-runner는 공중 벽돌 플랫폼(col 45~49 위 코인 'o' 3개)을 위험경로로, 바닥 안전 경로와 병행. 숨은 버섯('M')을 위험 점프 보상으로. runeburst는 overload 셀을 노릴지(×2 큰 점수, 그러나 재배치로 보드 흐트러짐) 안전하게 목표만 채울지 선택지로. is-rule은 par 클리어=안전, 최소 이동/노undo 클리어=위험-보상 별 보너스.
- **주의/안티패턴:** 위험 경로가 사실상 필수(안전 경로로 클리어 불가)면 자율성이 강제로 변해 좌절. 보상 격차가 너무 크면 안전 경로가 무의미, 너무 작으면 아무도 위험을 안 택함. 위험을 텔레그래프 안 하면 LD-FAIR 위반.

### LD-SECRET 비밀·탐험 보상

- **정의:** 숨은 길·수집물로 탐험 동기를 부여한다. 발견 자체가 보상이며, 메인 동선 밖을 살피게 만든다.
- **왜 통하나:** 숨김은 '보상'에만 쓰고 '처벌'에는 절대 쓰지 않는다 — 이것이 LD-FAIR과의 경계다. Disney의 breadcrumb(빵부스러기) 동선처럼, 수집물을 점선으로 배열하면 탐험을 자연 유도하면서 동시에 진행 방향을 신호한다(LD-SIGNPOST와 결합). 발견 보상은 SDT의 유능감·자율성을 함께 자극한다.
- **구체 규칙:**
  - [ ] 비밀은 '보이는 단서'에서 출발(살짝 이상한 벽, 닿을 듯한 코인) — 완전 무단서 비밀은 좌절.
  - [ ] 비밀 경로의 위험도 안전 버전으로 먼저 보여줘 risk-path 판단 근거 제공.
  - [ ] 비밀 보상은 진행 필수가 아니어야(놓쳐도 클리어 가능).
  - [ ] 발견 즉시 가시 피드백(특수 SFX·연출·카운터 증가).
- **우리 엔진 적용:** super-runner는 숨은 버섯('M' col 17, 47)이 천연 비밀 — 벽돌 클러스터/공중 발판 속에 숨겨 탐험을 보상. 절차생성 시 '메인 동선에서 1~2점프 벗어난 안전 지점'에 비밀 슬롯을 합성. runeburst는 보드형이라 비밀이 약하지만 '데일리 시드 숨은 고득점 루트'로 변주. is-rule은 par보다 적은 '의외의 풀이'가 곧 비밀(별 보너스).
- **주의/안티패턴:** 무단서 비밀은 탐험이 아니라 '운빨/공략 의존'이 된다. 비밀을 진행 필수로 두면 막힘. 숨겨진 곳에 즉사를 두면 LD-FAIR 정면 위반.

### LD-MASTERY-CEILING 숙련 천장

- **정의:** 진입 장벽(skill floor)은 낮춰 누구나 시작·클리어하되, 숙련 천장(skill ceiling)은 높여 고수가 더 잘할 여지(스피드런·노미스·최소이동·하이스코어)를 남긴다. '쉽게 배우고 어렵게 통달'.
- **왜 통하나:** 낮은 floor·높은 ceiling이 게임 디자인의 'sweet spot'이라는 통념(흔히 'Bushnell's Law'로 귀속되나 매체마다 귀속이 갈리므로 1차 출처 단정은 피한다). 높은 천장은 숙련 플레이어에게 사실상 무한한 개선 여지를 줘 장기 동기(SDT 유능감의 상한 없는 충족)를 유지한다.
- **구체 규칙:**
  - [ ] 클리어 조건과 통달 조건을 분리(클리어=쉬운 목표, 통달=별 3/노미스/par/타임어택).
  - [ ] 결과 가시화로 천장 노출(베스트 점수·최소 이동수·클리어 타임을 저장·표시).
  - [ ] 고급 테크닉은 선택, 모르면 안전 경로로 클리어 가능(천장이 바닥을 막지 않게).
  - [ ] 천장 지표는 실력 종속이어야(운/RNG에 좌우되면 숙련=무의미).
- **우리 엔진 적용:** runeburst는 `goal`=낮은 floor(클리어), 별 2~3 target·캐스케이드 하이스코어=천장. 데일리 시드+결과 이모지 공유가 경쟁 채널. super-runner는 클리어=골인, 천장=전 코인 수집·노데스·클리어 타임·숨은 버섯 전부. is-rule은 클리어=풀이 1개, 천장=par 이하 최소 이동/undo 0회. 세 게임 모두 결과 메트릭을 LEVELS 스키마에 `best` 필드로 누적(localStorage).
- **주의/안티패턴:** 천장만 높이고 floor가 높으면 신규 이탈. 천장 보상이 안 보이면 고수가 도전할 이유 없음. 통달 조건이 RNG에 좌우되면 숙련이 무의미해진다.

### LD-FAIR 공정성·안티프러스트레이션 (회피 가능하고 납득되는 실패)

- **정의:** 실패는 항상 플레이어가 사전에 인지·회피할 수 있어야 하고, 죽고 나면 '내 잘못이었다'고 납득돼야 한다. 보이지 않는 기습(off-screen 즉사, 예고 없는 함정, 랜덤 즉사)을 금지한다.
- **왜 통하나:** Game Developer 'The Fun and Frustration of Failure in Games'는 실패가 동기로 작동하려면 (1)플레이어 통제·주체성, (2)맥락에 맞는 재시도 비용, (3)도전과 인지 부하의 균형이 필요하며, 예고 없는 공격이나 게임이 '제 규칙을 깨는' 순간 좌절이 폭증한다고 정리한다. Schell의 flow 논의에서 anxiety와 boredom 둘 다 frustration으로 수렴한다. 공정성은 '쉬움'이 아니다 — Celeste처럼 매우 어렵되 공정할 수 있다(난이도를 낮추는 게 아니라 회피 가능성을 보장).
- **구체 규칙:**
  - [ ] 즉사 위협은 반드시 화면 안에서 예고하고 반응 시간을 준다(LD-TELEGRAPH/LD-FORESHADOW와 결합).
  - [ ] off-screen에서 날아오는 즉사 요소 금지 — 모든 치명 요소는 진입 전 시야에.
  - [ ] 실패 직후 원인이 화면에 남아 보이게(어디서 죽었는지).
  - [ ] 퍼즐 교착 시 자동 구제(LD-SOLVABLE). 랜덤성은 보상에만, 처벌에는 결정론.
- **우리 엔진 적용:** super-runner는 pit·적을 진행 방향 기준 항상 화면 진입 전에 보이도록 간격을 잡고, 즉사 pit 직전엔 시각 신호용 코인 아치('o')를 둔다(이미 27~29 구덩이 위 아치가 이 역할). runeburst는 moves 소진 실패를 보드 상태가 명확히 보이는 상태에서만 — 교착(가능한 매치 0)이면 자동 셔플(이미 구현된 '교착 자동 셔플'이 LD-FAIR 실현). is-rule은 undo·reset을 즉시 제공해 한 수 실수로 처음부터 다시 하는 좌절을 없앤다(전 레벨 손검증 풀이 존재=LD-SOLVABLE).
- **주의/안티패턴:** 난이도를 올린답시고 기습 즉사를 넣으면 anxiety가 아니라 분노로 직행→이탈. 실패 원인이 화면 밖이거나 운이면 통제감 상실. 시각 과부하(신호를 너무 많이 깔아 위협 신호가 묻힘)도 불공정이다.

### LD-CHECKPOINT 체크포인트·실패비용 최소화

- **정의:** 실패 후 재시도까지의 마찰(이동 거리·로딩·반복 콘텐츠·진행 손실)을 최소화한다. 체크포인트를 도전 직전에 두고, 재시도를 즉각·무료에 가깝게 만들어 '한 번 더' 루프를 살린다. 처벌 강도는 마지막 체크포인트까지의 거리에 비례하므로 그 거리를 짧게 유지한다.
- **왜 통하나:** Game Developer 'How Punishment Systems Hurt Gameplay'는 실패 시 이미 끝낸 콘텐츠를 반복하게 만드는 먼 체크포인트가 마찰·이탈을 키운다고 지적한다. 반대로 Angry Birds류는 '레벨 1분 미만, 즉시 재시작'으로 진행 손실이 미미해 실패가 관리 가능하게 느껴진다. 관용 메카닉(코요테 타임·입력 버퍼·관대한 히트박스)도 같은 '실패비용 완충' 계열 — Celeste는 도전을 낮추지 않고 좌절만 제거했다.
- **구체 규칙:**
  - [ ] 체크포인트는 '위험 구간 직전'에 — 어려운 점프/적 밀집 직전에 두어 그 도전만 재시도.
  - [ ] 재시도 즉시성: 사망→재시작 0.5~1.5초 이내, 메뉴 경유 없이.
  - [ ] 짧은 레벨=자연 체크포인트(runeburst·is-rule처럼 레벨 단위 재시도가 곧 저마찰).
  - [ ] 관용 메카닉: 코요테 타임 ~80~120ms, 점프 입력 버퍼 ~100ms, 피격 히트박스는 스프라이트보다 작게(받는 쪽 관대)·보상 판정은 크게(주는 쪽 관대).
  - [ ] 진행 손실 제한: 재시도 시 수집물·해금·메타진행은 보존.
- **우리 엔진 적용:** super-runner는 현재 `start:{c}`만 있으므로 `checkpoints:[{c}]` 노브 신설 제안 — pit·적 밀집 직전 좌표에 체크포인트를 두고 사망 시 가장 가까운 통과 지점에서 리스폰. 점프 처리에 코요테 타이머·입력 버퍼 변수 추가, 'M' 버섯을 라스트히트 완충(2단 체력)으로. runeburst/is-rule은 레벨이 곧 체크포인트 단위 — 실패 시 즉시 동일 시드 재시작 버튼을 1탭 거리에, best/별 진행은 localStorage 보존. is-rule의 undo 무제한은 사실상 무한 체크포인트.
- **주의/안티패턴:** 체크포인트 과다(매 타일)는 도전·긴장 소실. 체크포인트 직후 즉시 위협 배치 금지(리스폰 킬). 관용 과다(코요테 타임 100ms 초과)는 '의도 안 한 점프'를 유발한다. 메타진행까지 되돌리면 좌절.

### LD-REWARD 보상 스케줄 (가변비율 + 성취 가시화)

- **정의:** 성공·진행에 대한 보상을 고정 간격이 아니라 예측 불가한 가변비율(variable ratio)로 섞어 배치하고, 진행과 성취를 항상 눈에 보이게 만든다. 작고 잦은 보상(즉각 피드백)과 크고 드문 보상(마일스톤)을 층으로 쌓는다.
- **왜 통하나:** B.F. Skinner의 강화 스케줄 연구에서 variable-ratio가 가장 높고 지속적인 반응률을 낸다(보상 후 휴지 없이). 게임의 랜덤 루트 드롭·캐스케이드 보너스가 교과서적 적용이다. 다만 단일플레이·무과금 톤에서는 슬롯머신식 RNG 갈망 루프는 피로를 부르므로 가변성을 '연쇄의 우연' 같은 실력 연동 형태로 쓴다. 외적 보상(코인)은 내적 동기(숙달·성장)로 가는 다리로 쓸 때 건강하다(Schell의 intrinsic/extrinsic feedback loop).
- **구체 규칙:**
  - [ ] 확정 보상(클리어=다음 스테이지)과 가변 보상(랜덤 드롭·콤보 보너스)을 섞는다.
  - [ ] 진행 가시화: 진행바·별점·최고기록을 항상 화면에.
  - [ ] 보상을 도전 비례로(고위험 경로/선택 목표에 더 큰 보상, LD-RISK-PATH와 결합).
  - [ ] 동일 크기 보상을 4~5회 초과 반복하지 말고 종류를 교차(점수/특수타일/연출/해금).
  - [ ] 평균 보상 간격이 플레이어 1회 시도 길이를 넘으면 갈망이 좌절로 바뀐다 — 0보상 구간을 길게 두지 말 것.
- **우리 엔진 적용:** runeburst는 캐스케이드 깊이×점수(`MULT_CAP=9`)를 가변보상 코어로, `overload:true` 셀(×2 후 재배치)을 '드문 큰 보상'으로, 별점(목표 대비 점수)으로 성취 가시화. super-runner는 코인('o')을 고정 배치(확정)하되 숨은 경로(LD-SECRET)에 가변 대형 보상, goal 도달 시 시간/노미스 보너스. is-rule은 par 이하 클리어에 별 추가. 엔진에 `rewardSchedule`(확정/가변 비율)과 `progressMeta`(별·최고기록)를 표준 필드로.
- **주의/안티패턴:** 가변 보상을 도박 메커니즘으로 과하게 쓰면 윤리 문제·피로(CC0 캐주얼 톤과 불일치). 보상이 도전과 무관하면 성취감 희석. 진행 가시화 없으면 곡선을 잘 그려도 성장 인지 불가.

### LD-VARIETY 변주·반복회피

- **정의:** 동일한 도전·beat·배치가 반복되면 실력이 그대로여도 도전 인지값이 떨어져(skill>challenge) boredom으로 미끄러진다. 같은 메카닉이라도 맥락·조합·표현을 바꿔 '같지만 달라 보이게' 한다.
- **왜 통하나:** tense-and-release 자체가 '같은 과제를 도전을 바꿔 다르게 보이게 하라'는 변주 처방이다. The Level Design Book의 페이싱 논의도 같은 beat 연속을 피하고(전투-탐험-퍼즐 교차) numbness를 막으라고 한다. kishōtenketsu의 轉(비틀기)도 본질적으로 변주 장치다.
- **구체 규칙:**
  - [ ] 같은 메카닉 등장 사이엔 최소 1개의 다른 beat/맥락을 끼운다.
  - [ ] 반복이 불가피하면 변수를 하나 바꾼다(속도·배치·조합·제약).
  - [ ] 보드/지형 형태를 주기적으로 교체해 시각적 신선도 유지.
  - [ ] N스테이지마다 '변주 스테이지'(평소와 다른 규칙/형태)를 의무 배치.
- **우리 엔진 적용:** runeburst는 `shape`를 square→cross→diamond→hourglass→heart→ring→star로 순환시켜 같은 매치3라도 보드 형태로 변주(이미 지원). super-runner는 pit/발판/적 조합을 레벨마다 셔플하고 배경을 교체(이미 스테이지별 배경 지원). is-rule은 규칙 조합을 매 레벨 다르게(같은 'X IS Y'라도 다른 엔티티에). 절차생성(CC0)이라 시드별 배치 변주가 자연스럽다 — 시드 다양성을 곡선 제약 안에서 최대화.
- **주의/안티패턴:** 변주를 신 메카닉 남발로 오해하면 LD-ONE-IDEA·학습 부담과 충돌. 변주가 곡선(난이도)을 흔들면 안 된다 — 도전값은 유지한 채 표현/맥락만 바꾼다. 무작위 변주가 공정성·해결가능성을 깨면 본말전도(LD-SOLVABLE 우선).

### LD-SOLVABLE 해결가능성·교착방지 [퍼즐]

- **정의:** 퍼즐/매치류 레벨은 항상 풀리는 배치여야 한다. 제한 자원(이동수/발사수) 내에 목표를 달성하는 합법 수열이 적어도 하나 존재하고, 데드락·고립 타일 같은 trivial 실패를 제거한다.
- **왜 통하나:** 현대 매치3는 AI 봇·스크립트 솔버로 simulated-play를 돌려 solvability를 결정론적으로 검증하고 고립 캔디 같은 데드엔드를 배제한다(arXiv 2409.06349). 단, 정해진 무브로 목표 점수 달성은 NP-hard(arXiv 1403.1911 'Candy Crush is NP-hard')라 완전탐색은 비싸고 휴리스틱·몬테카를로 시뮬레이션을 쓴다. 해결가능성은 LD-FAIR의 퍼즐 버전 전제다.
- **구체 규칙:**
  - [ ] is-rule: 모든 레벨에 손검증된 풀이가 존재하고, par는 그 최적 풀이의 이동수. 솔버로 'par 이내 도달 경로 존재'와 '데드락(YOU 소실 등 회복불능) 없음'을 BFS로 자동 검증.
  - [ ] runeburst: 같은 시드로 몬테카를로 봇 N회를 돌려 '제한 moves 내 goal 달성 성공률'을 산출(0%면 불가능, 95%면 너무 쉬움).
  - [ ] 교착(no valid move) 발생 시 자동 셔플이 보장하는 진행성을 솔버로 확인(셔플 후에도 매치 가능 보드인지).
  - [ ] 솔버 봇 평균 성공률·잔여 무브를 난이도 프록시로 써 LD-CURVE 톱니 배열을 정렬.
- **우리 엔진 적용:** runeburst의 `board[r][c]=tile|null`과 `mulberry32(seed)`는 헤드리스 재현이 쉽다 — Node에서 게임 로직만 import해 같은 시드로 N회 봇 플레이를 돌려 클리어율을 뽑는 CI 검증을 붙일 수 있다. is-rule은 `ent` 그리드+`texts`에서 규칙을 파싱해 상태공간 BFS로 par·solvability를 검증(격자 작아 완전탐색 가능).
- **주의/안티패턴:** 솔버가 '풀 수 있음'만 보고 '재미있게/의도대로 풀림'은 검증 못 함 — 사람 플레이테스트 대체 불가. 매치3 완전탐색은 NP-hard라 큰 보드에서 타임아웃(시뮬레이션 근사). 솔버 봇이 인간이 안 쓰는 비직관 경로로 풀어 '인간 난이도'를 과소평가할 수 있다.

### LD-BUDGET 자원·이동수 예산 [퍼즐]

- **정의:** 이동수/발사수를 제한해 한 수의 무게를 만든다. 자원이 적을수록 한 수의 무게가 커지고, 최적해를 찾는 머리싸움이 보상된다.
- **왜 통하나:** 제약은 최적화 동기를 만든다(FE-CONSTRAINT). 별 1~3 판정은 클리어(낮은 floor)와 최적화(높은 천장)를 분리해 LD-MASTERY-CEILING을 실현하고, par는 '클리어는 쉽게, 최적화는 어렵게'의 직접 노브다. 예산은 동시에 LD-BUDGET 자체가 페이싱(자원 압박이 강도 누적→해소로 출렁임)을 만든다.
- **구체 규칙:**
  - [ ] 이동/발사 횟수를 카운터로 제한하고 잔여를 크게 표시.
  - [ ] 클리어 par(여유 있게)와 통달 par(빡빡하게)를 분리 — 별 1~3 판정.
  - [ ] 예산 압박은 한 노브씩(moves -2 또는 goal +200을 최소 단위로).
  - [ ] 예산이 너무 빡빡해 첫 수부터 불리하면 불공정(LD-FAIR) — 시드별 시작 가능수 검증.
- **우리 엔진 적용:** runeburst는 `moves`가 예산이고 `goal`이 목표 — moves↓/goal↑ 비율로 별 1~3의 무게추를 만든다(현재 L1 moves 20 / goal 1000부터 L12 moves 22 / goal 4200까지 산술 상향). is-rule은 `par`(최적 이동수)가 곧 예산이자 통달 지표 — par 클리어=안전, par 이하=별 보너스. super-runner엔 예산 개념이 약하지만 '시간/노데스'를 의사 예산으로.
- **주의/안티패턴:** 예산을 시간압박과 같이 걸면 최적화 사고 시간이 없어진다(둘 중 하나만). 예산이 무의미하게 넉넉하면 무게가 사라진다. RNG가 크면 같은 예산도 매번 운이라 최적해 학습이 안 된다.

### LD-TELEGRAPH 텔레그래프 [액션]

- **정의:** 공격/위협의 예비동작(wind-up)을 노출해 플레이어가 반응할 시간을 준다. 위협의 위험 영역을 형태·색·모션으로 명시한다.
- **왜 통하나:** 텔레그래프는 LD-FAIR의 액션 버전 핵심 도구 — 위협이 예비동작으로 노출되어야 회피 가능하다. Norman의 signifier 원칙의 역으로, 단서 없는 위협은 가짜/숨은 어포던스로 신뢰를 깬다. 모든 위협은 충돌 전에 시각적으로 읽혀야 한다.
- **구체 규칙:**
  - [ ] 모든 위협은 충돌 전에 읽히게 — 적·구덩이는 점프 반응이 가능한 거리에서 보이게(off-screen 즉사 배치 금지).
  - [ ] 위협의 위험 영역을 형태로 명시(예: 다음 확산 칸을 예고색으로, 낙하 목표 칸을 하이라이트).
  - [ ] 텔레그래프 시간은 모바일 입력 지연을 고려해 넉넉히(너무 짧으면 불공정, 너무 길면 긴장 소실 — 플레이테스트로 예비동작 프레임 튜닝).
  - [ ] 난도 상승은 신호 밀도 증가가 아니라 신호된 도전의 정밀도 요구로(화면을 신호로 도배하지 말 것).
- **우리 엔진 적용:** super-runner는 pits·'e'(적)를 `DESIGN_W`(384px) 가시 영역+점프 반응 시간을 고려한 최소 선행 거리 제약으로 배치, 카메라 lookahead로 진행 방향을 더 보여준다. runeburst는 spreaders(번식)의 다음 확산 칸·ingredient 낙하 목표 칸을 1턴 전 예고 오버레이로. is-rule은 즉사가 없고 undo 가능해 본질적으로 텔레그래프 부담이 낮다.
- **주의/안티패턴:** 오프스크린 기습(화면 밖에서 갑자기 진입하는 즉사)이 가장 흔한 불공정. 텔레그래프가 너무 길면 긴장이 죽고 너무 짧으면 불공정. 읽었는데 물리적으로 회피 불가(반응시간 부족)면 텔레그래프 시간 부족이다.

### LD-PLAYTEST 플레이테스트·계측 튜닝

- **정의:** 디자이너의 직감은 가설일 뿐이며, 난이도·명확성·재미는 '게임을 처음 보는 외부인'의 실제 플레이와 텔레메트리로 검증해야 한다. 측정→비교→조정을 반복하는 닫힌 루프로 곡선을 수렴시킨다.
- **왜 통하나:** Schell·The Level Design Book이 강조하는 '당신은 당신의 플레이어가 아니다' — 디자이너는 '지식의 저주'로 자기 게임의 진입장벽을 못 본다. Valve는 매주 외부 테스터를 로테이션하며 학습곡선을 다듬었고, Slay the Spire(Anthony Giovannetti, GDC 2019 'Metrics Driven Design and Balance')는 (1)선택지로 주어졌을 때의 픽률, (2)승리 덱 등장률 두 지표로 밸런싱했다. 텔레메트리는 '무엇(what)'만 알려주고 '왜(why)'는 못 주므로 정량·정성을 반드시 병행한다. 진행자는 입 다물고 관찰한다(침묵 관찰 — 개입은 데이터 오염).
- **구체 규칙:**
  - [ ] 신규 빌드 전 최소 3~5명의 '처음 보는' 테스터에게 무설명으로 플레이. 디자이너 본인 클리어는 검증으로 치지 않는다.
  - [ ] 각 레벨에 가설 1개를 적고(예: '여기서 ROCK IS PUSH를 스스로 발견한다') 참/거짓만 본다.
  - [ ] 막혀도 60~90초는 개입하지 않고 스스로 빠져나오는지 관찰('아하 모먼트' 도달 시간 측정).
  - [ ] 죽음/이탈 위치를 공간 집계(1D 죽음 히트맵)해 난이도 스파이크를 찾고, 의도 곡선과 겹쳐 본다.
  - [ ] 한 빌드에서 노브 1개씩만 조정하고 같은 시드/par로 재측정(회귀 방지).
- **우리 엔진 적용:** 단일플레이 모바일웹뷰라 서버 텔레메트리 대신 localStorage 누적+console 덤프로 1인 메트릭 루프. runeburst의 `state()`가 이미 score·moves·objectiveProgress·over를 노출하므로 게임오버/클리어 시 스냅샷을 append하면 레벨별 클리어율·잔여 무브 분포 산출 가능. super-runner는 death pit 인덱스·재시도 횟수를, is-rule은 (실제 이동수/par)·undo 횟수를 누적. 결정적 시드(mulberry32)라 외부 자동화 없이도 같은 레벨을 재현 — 검증 루프의 기반이다.
- **주의/안티패턴:** 디자이너가 테스트 중 힌트를 주면(데이터 오염) 실제 난이도를 영영 모른다. 친구·동료만 쓰면 '맥락을 아는' 편향. 소표본(<수십)에서 히트맵을 신뢰하면 노이즈를 신호로 오독. 텔레메트리 수치만 보고 '왜'를 추측하면 잘못된 수정.

### LD-DDA 동적 난이도 조정 (보이지 않는 미세조정)

- **정의:** 플레이어의 실시간 성과(연속 실패·체류·정확도·잔여 자원)에 따라 난이도를 위아래로 미세조정하되, '시스템이 봐주고 있다'고 느끼지 못하게 은밀하게 — 이상적으로는 시도 사이(between runs)에 — 적용해 flow 채널 안에 붙들어 둔다.
- **왜 통하나:** Resident Evil 4(2005)의 숨은 'Difficulty Scale'은 정확도·받은 피해·사망·체류시간·인벤토리를 추적해 적 공격성·데미지·드롭률·스폰 수를 조정, 대부분 플레이어가 눈치채지 못하게 flow를 유지했다. Left 4 Dead의 AI Director는 스트레스 지표로 스폰·페이싱을 조절한다(Michael Booth, 'The AI Systems of Left 4 Dead', GDC 2009): 강도 누적기로 빌드업→정점 유지→감쇠→이완 4단계를 돌리며, '팀 평균'이 아니라 '가장 위급한 단일 멤버의 최고 강도'로 구동하고, Relax 단계는 1차 슬라이드 기준 '30-45초'(또는 Survivor가 다음 세이프룸 쪽으로 충분히 이동할 때까지) 신규 위협을 금지한다. 단 '성공을 처벌해 숙달감을 뺏는다'(RE4 비판)는 위험이 있어 LD-MASTERY-CEILING과 균형이 필요하다.
- **구체 규칙:**
  - [ ] 추적 지표를 1~3개로 좁힌다(연속 실패, 평균 클리어 시도, 잔여 자원).
  - [ ] 조정은 작게·천천히(한 번에 노브 5~10%만), 그리고 드러나지 않게. 플레이 도중 가시적 하향 금지 — 시도 사이에 적용.
  - [ ] 쉬워지는 방향(구제)은 적극적으로, 어려워지는 방향(처벌)은 보수적으로 — 숙달감을 지킨다.
  - [ ] DDA 켜고 끄는 경계: 학습 레벨엔 강하게, 도전/마스터리 콘텐츠엔 끈다(speedrun·노미스 보존). 명시 난이도 설정을 덮어쓰지 않는다.
- **우리 엔진 적용:** 단일플레이라 '디렉터'를 경량 강도 누적기로 — engine 런타임에 intensity 변수를 두고 피격·아슬한 회피·연속 실패 시 +, 안전 경과 시 -감쇠. runeburst는 같은 난이도 등급의 시드 풀을 만들어 연속 실패 카운트(localStorage)에 따라 '관대한 시드'를 다음 판에 제공(보드 모델은 그대로라 구현 가벼움). super-runner는 재시도 시 pit 폭을 한 칸 좁히거나 중간 체크포인트 1개 추가(between-run). is-rule은 par 기반이라 난이도 조정보다 '힌트 게이트'(N회 실패 후 단어블록 강조)가 적합. `playerState{streakFail, attempts}`를 두고 LEVEL 생성기에 보정항을 주입하되 '도전 모드' 플래그면 보정 0.
- **주의/안티패턴:** rubber-band가 너무 노골적이면 '잘해도 보상 없다'고 느껴 숙달 동기를 죽인다(RE4 비판). 조정 폭이 크면 플레이어가 자기 실력 변화를 인지 못 해 곡선이 무의미. DDA로 곡선 설계 부재를 가리려 하면 안 된다 — DDA는 잘 만든 곡선의 미세보정용이다.

## 2. 난이도 곡선 설계법

LD-CURVE·LD-PACING·LD-FLOW-CHANNEL을 실무 절차로 합친 섹션. 곡선은 한 번에 완성되지 않으며 LD-PLAYTEST 루프로 수렴한다.

### 2.1 곡선의 두 축: 절대 난이도 vs 상대 난이도

플레이어 실력은 시간에 따라 오른다. 따라서 **체감 난이도 = 절대 난이도 − 실력**이다. 절대 난이도를 직선으로 올리면 후반에 실력이 추월해 boredom으로 흘러내린다. 곡선은 항상 '상대 난이도'를 톱니로 그린다.

```
강도/도전
 9 |            ▲(정점)
 7 |       ▲       ╲    ▲(다음 정점, 더 높음)
 5 |   ▲    ╲   ▲   ╲  ╱  ╲
 3 | ╱  ╲  ╱  ╲ ╱(쉼) ╲╱     ╲(falling action)
 1 |╱    ╲╱    ╲                ╲___끝
   +----------------------------------> 시간
   도입  봉우리-골 반복(매크로 우상향)   완화
```

### 2.2 곡선 모양 처방

| 곡선 모양 | 증상 | 처방 |
| --- | --- | --- |
| 평탄 직선(저) | 지루(boredom) | 봉우리를 세워 도전 점증, 변주(LD-VARIETY) 주입 |
| 평탄 직선(고) | 무뎌짐(numb)·피로 | 골(LD-REST)을 파 '5→11' 대비 복원 |
| 단조 우상향 | 봉우리가 새 기준선 됨 | 톱니화 — 정점 직후 -10% 완화 |
| 톱니(우상향) | 정답 | 유지, 정점은 묶음 끝에만 |
| 끝이 최고난도 | 탈진 마무리 | 정점을 끝나기 직전으로, 진짜 끝은 falling action |
| 중간 스파이크 | '벽'·이탈 | 스파이크를 묶음 끝으로 이동, 사이에 복선(LD-FORESHADOW) |

### 2.3 구간별 처방 (5스테이지 묶음 예시)

| 스테이지 | 역할 | 상대 강도 | 노브 처방 |
| --- | --- | --- | --- |
| 1 | 도입·완화 | 3 | 직전 묶음 정점보다 -10%, 새 메카닉 1개 안전 소개(LD-TEACH) |
| 2 | 전개 | 5 | 도입 메카닉에 위험 1개 추가(LD-4BEAT 承) |
| 3 | 변주 | 5~6 | 같은 도전, 다른 맥락/형태(LD-VARIETY) |
| 4 | 비틀기 | 7 | 메카닉 조합/반전(LD-4BEAT 轉) |
| 5 | 정점 | 9 | 묶음 종합 스파이크, 직후 다음 묶음 1로 완화 |

### 2.4 세 게임별 곡선 노브 요약

| 게임 | 곡선 성격 | 1차 노브 | 1차 계측 신호 |
| --- | --- | --- | --- |
| super-runner (플랫포머) | 공간적 | pit 폭/연속, 공중 발판 간격, 적 밀도, 발판 길이 | 죽음 위치·재시도 수 |
| runeburst (매치3) | 자원·확률적 | colors↑, moves↓, goal↑, 블로커, shape | 클리어율·잔여 무브·막힌 objective |
| is-rule (규칙 퍼즐) | 인지적 | 새 규칙 1개, par, 통로 길이, 규칙 상호작용 수 | 이동수/par 비율·아하 시간·undo 수 |

세 게임 모두 LEVELS를 손코딩하지 말고 `difficultyOf(i)` 곡선 생성기 + 시드(절차생성 CC0)로 뽑으면 LD-CURVE 톱니·LD-PACING 파형·LD-VARIETY를 데이터로 일관 보장할 수 있다.

## 3. 안티패턴 (섞지 말 것)

레벨 디자인에서 충돌하는 원칙 조합. 명확화 단계에서 사용자가 이 조합을 요청하면 그대로 만들지 말고 되묻는다.

- **단조 우상향 + 쉼표 없음:** LD-CURVE(우상향 추세)를 LD-REST 없이 직선으로만 올리면 봉우리가 매번 새 기준선이 되어 강도 인플레이션→체감 평탄화→피로 이탈. 우상향은 '추세'일 뿐, 국소는 반드시 톱니여야 한다.
- **중간 스파이크 + 복선 없음:** 난이도를 올린답시고 묶음 중간에 신규 치명 위협을 기습 배치하면 LD-FAIR·LD-FORESHADOW 동시 위반 — '벽'에 부딪힌 좌절로 재도전 의욕(LD-CHECKPOINT)이 꺾인다. 스파이크는 묶음 끝에, 위협은 안전 형태로 먼저 보여라.
- **한 레벨 다개념 + 동시 난도 상승:** LD-ONE-IDEA를 어겨 새 메카닉 2개를 동시에, 게다가 어렵게 도입하면 플레이어가 무엇이 실패 원인인지 못 가리고 학습과 도전이 뒤섞여 좌절. 새 개념은 1개씩, 도입 레벨은 난도를 낮춰라.
- **퍼즐 해결가능성 방치 + 강한 RNG:** LD-SOLVABLE을 검증하지 않은 채 매치3 시드/리필에 운을 크게 걸면, 첫 수부터 불리한 시드나 데드락이 LD-FAIR을 근본부터 깬다. RNG는 보상에만, 처벌·해결가능성에는 결정론. 교착 시 자동 셔플로 진행성을 보장하라.
- **DDA로 곡선 부재 가리기 + 가시적 하향:** LD-DDA를 '곡선을 안 그려도 되는 핑계'로 쓰거나 플레이 도중 적이 갑자기 약해지는 가시적 변화를 주면, 공정성 신뢰가 붕괴하고 숙달감(LD-MASTERY-CEILING)이 사라진다. DDA는 잘 만든 곡선의 미세보정용이고, 조정은 시도 사이에 은밀하게.
- **기계적 4비트 강제 + 변주 소멸:** LD-4BEAT를 모든 레벨에 똑같이 강제하면 LD-VARIETY가 죽어 패턴이 예측되고 기억에 안 남는다. 일부 레벨은 복습/콤보/순수 휴식 레벨로 비워, 비틀기(轉)가 진짜 비틀기로 느껴지게 하라.

## 4. 레벨 추가 워크플로 체크리스트

새 레벨/스테이지를 추가할 때 순서대로 통과시킨다. 각 단계는 해당 LD-* 태그로 검증한다.

### 4.1 설계 단계

- [ ] **이 레벨이 가르치는 새 개념은 정확히 하나인가?** (LD-ONE-IDEA) — 둘 이상이면 분할.
- [ ] **새 개념의 첫 등장이 안전한 무위험 배치인가?** (LD-TEACH, LD-FORESHADOW) — 도입은 죽지 않게.
- [ ] **레벨이 도입→전개→비틀기→마무리 4비트를 갖는가?** (LD-4BEAT) — 한 레벨이 어려우면 묶음으로 분산.
- [ ] **이 레벨의 상대 난이도가 묶음 곡선의 어느 위치인가?** (LD-CURVE) — 정점은 묶음 끝에만, 직전 묶음 정점 뒤면 완화로.
- [ ] **노브를 한 번에 하나만 움직였는가?** (LD-FLOW-CHANNEL) — 여러 노브 동시 상향은 스파이크.
- [ ] **고강도 봉우리 뒤에 회복 구간이 있는가?** (LD-REST, LD-PACING) — 봉우리:골 ≈ 1:1.

### 4.2 가독성·공정성 단계

- [ ] **다음 행동/목표가 색·빛·구도로 읽히는가?** (LD-SIGNPOST) — 고채도 시선 끌개 3개 이하.
- [ ] **상호작용 가능/위험 요소가 형태로 즉시 읽히는가?** (LD-AFFORDANCE) — 가짜·숨은 어포던스 없게.
- [ ] **모든 치명 위협이 화면 안에서 예고되는가?** (LD-FAIR, LD-TELEGRAPH) — off-screen 즉사 금지.
- [ ] **실패 후 재시도 마찰이 최소인가?** (LD-CHECKPOINT) — 위험 직전 체크포인트, 즉시 재시작.
- [ ] **[퍼즐] par 이내 합법 풀이가 존재하고 데드락이 없는가?** (LD-SOLVABLE, LD-BUDGET) — 솔버/손검증.

### 4.3 동기·천장 단계

- [ ] **보상이 진행에 비례하고 가시화되는가?** (LD-REWARD) — 진행바·별·최고기록.
- [ ] **선택적 고위험 고보상 경로가 있는가?** (LD-RISK-PATH) — 필수≠위험.
- [ ] **숨은 탐험 보상이 단서에서 출발하는가?** (LD-SECRET) — 무단서 비밀·숨겨진 즉사 금지.
- [ ] **클리어와 통달 조건이 분리되는가?** (LD-MASTERY-CEILING) — 낮은 floor, 높은 천장.
- [ ] **이전 레벨과 다른 맥락/형태인가?** (LD-VARIETY) — 같은 패턴 3연속 금지.

### 4.4 검증 단계

- [ ] **선언적 LEVEL(S) 블록만 수정했는가?** — 곡선의 single source of truth 유지. 가능하면 곡선 생성기+시드로.
- [ ] **'처음 보는' 테스터 3~5명에게 무설명 플레이시켰는가?** (LD-PLAYTEST) — 침묵 관찰.
- [ ] **레벨 가설(무엇을 배우는가/어디서 막히는가)이 참인가?** (LD-PLAYTEST) — 죽음 히트맵·이동수/par.
- [ ] **노브 1개씩 조정하고 같은 시드/par로 재측정했는가?** (LD-CURVE 검증 루프) — 회귀 방지.
- [ ] **[해당 시] DDA가 곡선의 보정용이며 가시적 하향이 없는가?** (LD-DDA) — 도전 모드엔 끄기.

## 5. IP 안전 메모

- **메카닉·원칙은 자유롭게 차용하되, 고유명·에셋·특정 레벨 레이아웃은 복제하지 않는다.** flow 채널·kishōtenketsu 4비트·tense-and-release·weenie 같은 레벨 디자인 통념은 누구나 쓰는 일반 원리이므로 적용은 자유다. 그러나 Super Mario Bros. World 1-1의 타일 좌표, Left 4 Dead의 맵 레이아웃, Slay the Spire의 카드 같은 특정 게임의 구체 콘텐츠를 그대로 옮기는 것은 금지한다.
- **출처가 있는 사례는 '원리 설명'으로만 인용하고, 우리 레벨은 절차생성 오리지널로 환기한다.** 'Mario 1-1처럼 안전 환경에서 가르친다'는 원리는 차용하되, 실제 배치는 우리 시드·곡선 생성기로 새로 뽑는다. 세 데모 게임의 `game.js` 주석이 명시하듯(runeburst: 'Bejeweled/Candy Crush 명칭·디자인 미사용', is-rule: 'Baba Is You 이름·스프라이트·레벨 미사용', super-runner: '닌텐도 마리오 에셋·이름·시그니처 미사용') 메카닉만 차용하고 에셋·레벨은 전부 CC0 절차생성이다.
- **이 문서의 수치·귀속은 디자인 참고이지 법률 자문이 아니다.** 인용된 GDC 발표·서적·블로그는 원리의 출처 맥락을 보이려는 것이며, 상업 배포 시 에셋·상표·구체 레이아웃의 독립성은 별도로 확인해야 한다.
