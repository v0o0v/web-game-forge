# 게임 청사진 인터뷰 (Deep Interview 적응판 · 탑다운 · 조합 주도)

> web-game-builder의 **'0) 요청 명확화'** 단계를, **탑다운으로 모호성이 풀릴 때까지 끈질기게 묻는 1문1답 인터뷰**로 수행하는 플레이북.
> oh-my-claudecode의 `deep-interview` 스킬(Socratic 1문1답 + 약점 차원 타깃 + 챌린지 모드 + 준비도 게이팅)을 **게임 설계**에 적응시켰다.
> 추상적 객관식 1회로 끝내지 말고, **사용자가 재미 요소를 직접 조합**해 *자기가 원하는 재미있는 게임*의 구체적 청사진이 나올 때까지 파고든다.
>
> **언제 쓰나:** 게임 제작 요청이 한 줄·모호("퍼즐 게임 만들어줘", "재밌는 거 만들어줘")이거나, 아래 차원들이 명시되지 않았을 때.
> 요청이 이미 구체적이면(플랫폼·코어·재미조합·아트·사운드·분량이 다 적혀 있으면) 인터뷰를 건너뛰고 바로 빌드한다.
>
> 자동 트리거 아님. SKILL.md '0) 요청 명확화'·`commands/make-game.md`·`puzzle-game/SKILL.md` 0번 레시피에서 **온디맨드 Read**로 부른다.

---

## 0. 이 인터뷰의 3대 정신

1. **탑다운으로 내려간다.** 넓은 맥락(누구를 위한·어디서 도는 게임인지)부터 묻고, 거기서 메카닉 → 재미 조합 → 감각(아트·사운드) → 운영(승패·분량·조작)으로 *좁혀* 내려간다.
   맥락이 메카닉을 프레이밍하고, 메카닉이 아트를 프레이밍한다. 위가 흔들리면 아래를 물어봐야 소용없다.
2. **재미 요소 조합은 사용자가 주도한다 (1순위).** Claude는 이미 game-dna로 수십 종의 재미 요소(`FE-*`)를 분해해 갖고 있다.
   그러니 **완성된 아키타입을 통째로 들이밀어 "이거 할래요?"로 가두지 말고, `FE-*` 팔레트를 펼쳐 사용자가 직접 고르고 섞게** 한다(§4). 추천은 디폴트로 제시하되 선택권은 사용자에게.
3. **모호성이 풀릴 때까지 끈질기게.** 한 라운드에 한 질문씩, 가장 약한 차원을 계속 캔다. 추상적 답은 구체 사례로 되묻는다.
   준비도 게이트를 통과(§6)하기 전엔 빌드를 시작하지 않는다. 목표는 *Claude가 만들기 편한 게임*이 아니라 **사용자가 원하는 재미있는 게임**이다.

기존 방식의 문제(개선 전): `AskUserQuestion` 1회(최대 4문항)로 아트/장르/테마/분량을 한꺼번에 묻고 끝냈다 → 질문이 추상적이라 청사진이 흐릿하고,
사용자가 재미 요소를 *조합할* 자리가 없고, Claude의 창의적 제안이 들어갈 자리가 없었다. 이 인터뷰가 그걸 고친다.

## 1. 핵심 원칙 (deep-interview에서 차용)

1. **1문1답.** 한 라운드에 질문은 하나. 4개를 한 객관식에 욱여넣지 않는다. (단, §4 재미 요소 조합은 multiSelect 한 질문 = 여러 *선택지*지만 여전히 한 *질문*이다.)
2. **약점 차원 타깃 + "왜 지금".** 매 라운드 가장 모호하거나 가장 결정적인 차원 하나를 고르고, **왜 지금 이걸 묻는지**를 한 문장으로 밝힌다.
3. **가정을 드러낸다.** "뭘 원해요?"가 아니라 "무엇을 전제하나요?"를 묻는다. 추상적 답("그냥 재밌게")이 나오면 **구체 사례로 되묻는다**.
4. **Claude가 먼저 참신한 컨셉을 제안한다.** 빈 객관식을 던지지 말고, game-dna 기반 검증 조합 + 본인의 창의적 비틀기를 구체 옵션으로 제시하고 **본인 의견을 밝힌다**(§5). 사용자는 고르거나 자유 입력.
5. **안티패턴 가드.** [game-dna/fun-elements.md](./game-dna/fun-elements.md) §3, [game-dna/puzzle/fun-elements.md](./game-dna/puzzle/fun-elements.md) §3의 '섞지 말 것'을 내부 가드로 적용.
   충돌 조합(연역+실시간가속, 우아한해+강RNG, 명상형+과한주스 등)을 고르면 그대로 만들지 말고 **"둘 다 살리려면 구간을 나눠야 하는데 어느 쪽을 코어로 할까요?"**로 되묻거나 절충안을 제안한다.
6. **준비도 게이트.** §6의 차원이 충분히 구체화되기 전엔 스캐폴딩 금지.
7. **조기 종료 존중.** 사용자가 "알아서/추천대로/그냥 만들어/충분해"라고 하면 즉시 멈추고, 현재까지 좁혀진 청사진 + 추천 기본값으로 §7 청사진을 확정해 읽어준 뒤 진행한다.

## 2. 게임 청사진 차원 (탑다운 순서)

위에서부터 순서대로 캔다(맥락 → 메카닉 → 재미 조합 → 감각 → 운영). 보통 이 순서가 약점 순서와 일치한다. ✅=구체 확정 · ◻️=미정.

| # | 차원 | 무엇을 확정하나 | 비고 |
|---|---|---|---|
| **C1** | **플랫폼 · 타깃 유저** | 모바일 웹뷰 / 데스크톱 / 둘 다 · 가로·세로 · 타깃 유저층(캐주얼·키즈·코어 퍼즐러·올드스쿨 레트로 팬 등) | ★맨 먼저. 난이도·세션 길이·조작·아트 톤·사운드를 전부 프레이밍. |
| **C2** | **코어 루프 / 장르** | 플레이어가 매 순간 *실제로 하는 행동* 한 문장 (game-dna 코어로 고정) | ★필수. 모든 메카닉의 뿌리. |
| **C3** | **재미 요소 조합 (`FE-*`)** | 사용자가 `FE-*` 팔레트에서 직접 고른 2~4개 + 그게 *어떤 순간* 터지는지 + 검증·대안 반영 | ★★**핵심. 사용자 주도(§4).** |
| **C4** | **아트 스타일 · 테마 · 출처** | 픽셀(`PixelForge`) vs 미려한 스무스/벡터(`VectorForge`) 택1 + 결(플랫/네온글로우/글래스/카툰) + 테마·마스코트 + **아트 출처(실제 에셋 소싱=`sprite-picker` vs 절차 생성)** | ★필수. 결과 인상 최대 좌우. 게임당 하나. 비주얼을 직접 고르려는 기색이면 `sprite-picker` 로. |
| **C5** | **사운드 · 음악 결** | BGM 무드(칩튠 8비트 / 앰비언트 / 리듬·비트 동기화) + SFX 톤(또렷·말랑·미니멀) | `ChipAudio` 기본, 결만 정한다. BGM은 오리지널. |
| **C6** | **승패 · 진행 · 분량 · 난이도** | 승리/실패 조건, 1레벨 vs 레벨팩(개수), 난도 곡선, 점수·별점·베스트·시드 공유 | 타깃 유저(C1)에서 기본값 도출 가능. |
| **C7** | **조작** | 입력(키보드/스와이프/탭/드래그) | 보통 C1(플랫폼)에서 파생 → 자동 확정. |

> 퍼즐이면 C2를 game-dna **7개 퍼즐 코어**(낙하/매치/병합/연역/공간/물리/규칙)로, 그 외 장르면 전역 game-dna 아키타입으로 고정한다.

## 3. 라운드 진행 (deep-interview Phase 2 적응)

각 라운드는 `AskUserQuestion` 한 번(질문 1개)으로. 형식:

```
라운드 {n} | 타깃 차원: {C# 이름} | 왜 지금: {한 문장 근거} | 청사진 진행: {✅개수}/7

{Claude의 제안·관점 1~2문장 — game-dna 기반 + 본인 비틀기·의견}

{질문}
```

- 답을 받으면 그 차원을 ✅로, **다음으로 가장 약한 차원**(보통 탑다운 다음 칸)을 타깃해 다음 라운드로.
- 답이 모호하면 같은 차원을 **구체화 질문**으로 한 번 더 판다(추상→구체 되묻기).
- 안티패턴 충돌이 감지되면 다음 질문은 **절충 되묻기**.

### 라운드 진행 리드아웃 (투명성)

매 라운드 끝에 한 줄로 청사진 상태를 보여준다:

```
청사진: C1 플랫폼·타깃 ✅ | C2 코어 ✅ | C3 재미조합 ◻️ | C4 아트·테마 ◻️ | C5 사운드 ◻️ | C6 승패·분량 ◻️ | C7 조작 ◻️
다음 타깃 → C3(재미 조합): 코어는 정해졌으니, 이제 어떤 손맛을 섞을지가 게임 성격을 결정합니다.
```

## 4. 재미 요소 조합은 사용자가 주도한다 (★ 이 인터뷰의 1순위 차별점)

C3 라운드는 단순 "재미요소 고르기"가 아니라 **사용자가 팔레트에서 직접 조합하고, Claude가 그 조합을 되비춰 검증·확장하는** 루프다.
사용자의 예시 그대로: *"이런 재미 요소들이 있는데 어떤 조합을 원하세요 → 이 조합이면 이런 류의 게임이 됩니다, 괜찮나요? → 혹시 다른 아이디어는?"*

### 4단계 루프

1. **팔레트 노출 (expose).** 코어(C2)가 정해지면, 그 코어에 잘 붙는 `FE-*` 재미 요소를 fun-elements 사전에서 **6~8개** 꺼내
   *각각 한 줄 정의*와 함께 펼친다. `AskUserQuestion` **multiSelect**로 사용자가 **2~4개를 직접 고르게** 한다.
   - 옵션 라벨 = 한글명+태그(예: "연쇄·콤보(FE-COMBO)"), 설명 = 정의 한 줄 + *언제 터지는지*.
   - 추천 조합에 "(추천)"을 달되, **고르는 건 사용자**임을 분명히("이 중 어떤 손맛들을 섞고 싶으세요? 2~3개 골라주세요").
   - 팔레트는 game-dna 사전이 출처: 퍼즐은 [puzzle/fun-elements.md](./game-dna/puzzle/fun-elements.md) §1(퍼즐 특화 8 + 공통), 그 외는 [fun-elements.md](./game-dna/fun-elements.md) §1.
2. **조합 반영 (reflect).** 사용자가 고른 조합을 받으면 → **"그 조합이면 *이런 류의 게임*이 됩니다"** 하고 **구체적인 한 컷(가상의 플레이 장면)으로 되비춘다.**
   막연한 카테고리("매치 퍼즐이 되겠네요")가 아니라 그림이 그려지게("같은 색을 밀어 모으다 한 수로 화면 절반이 도미노로 터지고, 콤보 숫자가 커질수록 글로우가 번지는…").
3. **검증 + 대안 (validate + alternatives).** 곧바로 되묻는다: **"이 방향 마음에 드세요? 아니면 제 다른 아이디어 — [대안 조합/비틀기] — 는 어떠세요?"**
   사용자가 미처 생각 못 한 조합을 *Claude가 제안*해 선택지를 넓힌다(여기서 본인 의견·참신함을 적극 개진).
4. **안티패턴 가드 & 확정.** 충돌 조합이면 절충 되묻기(§1.5). 사용자가 "이걸로"라고 확정할 때까지 조합을 **함께** 다듬는다.

> 조합이 코어를 바꿀 만큼 커지면(예: 매치에 '규칙 발견'을 얹고 싶다 → 규칙조작 코어로 이동) C2로 거슬러 올라가 코어를 갱신한 뒤 다시 내려온다. 탑다운은 한 방향 고정이 아니라 *위가 흔들리면 위로 돌아간다*.

## 5. Claude의 제안 의무 — "참신한 의견 개진"

조합 주도권은 사용자에게 주되, **매 라운드 Claude가 먼저 구체적인 컨셉/대안을 제시**한다(백지 금지).

- **출처:** [game-dna/](./game-dna/)의 장르별 분석 + 조합 레시피. 거기에 **본인의 창의적 비틀기**를 더한다.
- **구체적으로.** 카테고리 라벨이 아니라 **그림이 그려지는 한 컷**으로:
  - ❌ "매치3 퍼즐은 어떠세요?"
  - ✅ "비트마다 좌→우로 스윕 라인이 지나가며 *예약된 매치를 한꺼번에* 터뜨리는 **리듬 매치**는 어떨까요 — 스윕 직전 막판 스왑으로 군집을 키우는 도박이 손맛입니다. 제 추천은 이쪽인데, 차분한 사고형도 같이 올릴게요."
- **추천 + 한 줄 컨셉 + 왜 재밌나 + 본인 의견.** 첫 옵션에 "(추천)", "제 추천은 X입니다, 왜냐면 ~"으로 관점을 분명히(사용자가 반박·선택하기 쉽게).
- **다양성.** 코어를 묻는 라운드(C2)에선 서로 다른 코어/아키타입을 3~4개 고르게 섞어 노출.
- 요청에 이미 단서가 있으면 그 부분은 고정하고, 제안은 *그 안에서의 변주*로 좁힌다.

## 5.5. 챌린지 모드 (deep-interview Phase 3 적응 — 게임용)

라운드가 쌓이면 관점을 바꿔 한 번씩 도발한다(각 1회). 청사진을 날카롭게 만든다.

- **3라운드+ · Contrarian(반대로):** 기본 가정을 뒤집는다 — "정말 그 장르가 최선일까요? 같은 타깃 유저에게 *완전히 다른 코어*면 더 신선할 수도 있는데, 굳이 이 코어인 이유가 있나요?"
- **4라운드+ · Simplifier(덜어내기):** 최소 버전을 묻는다 — "고른 재미 중 **하나만 남긴다면** 무엇이 코어인가요? 나머지는 빼도 성립할까요?" (MVP 청사진 확보)
- **5라운드+ · Signature Hook(자랑할 한 컷):** 정체성을 묻는다 — "친구에게 30초로 자랑한다면 *어떤 순간*을 보여주고 싶나요? 그 한 컷이 이 게임의 정체성입니다."

각 모드는 한 번만 쓰고 일반 질문으로 복귀.

## 6. 준비도 체크 (게이트)

스캐폴딩 시작 조건:
- **C1(플랫폼·타깃) 확정** + **C2(코어)·C3(재미 조합)·C4(아트·테마) 구체화(✅)** — 각각 한 문장으로 막힘없이 서술 가능.
- C5(사운드)·C6(승패·분량)·C7(조작)은 ✅이거나, 미정이면 **타깃 유저 기반 추천 기본값**으로 확정(사용자에게 "이건 이렇게 기본값으로 갈게요" 고지).
- 안티패턴 충돌이 모두 해소(절충안 확정).

게이트 미달이면 가장 약한 차원으로 라운드를 더 돈다. 보통 **4~7라운드**면 충족된다.

### 라운드 수 가이드 / 조기 종료
- 3라운드+부터 "충분/그냥 만들어"로 조기 종료 가능 — 단, 필수(C2·C3·C4)가 ◻️면 **추천 기본값을 채워 청사진을 완성**한 뒤 진행한다고 고지.
- 10라운드 soft 경고: "벌써 10라운드네요. 지금 청사진으로 진행할까요, 더 다듬을까요?"

## 7. 청사진 확정 & 빌드 라우팅 (deep-interview Phase 4·5 적응)

게이트 충족 시, **청사진을 한 화면으로 정리해 읽어주고 최종 확인**받은 뒤에만 `games/<slug>/` 스캐폴딩을 시작한다.
(별도 spec 파일 없이 응답 안의 청사진 블록 + 확인으로 충분. 무겁게 하지 않는다.)

### 청사진 형식

```
## 게임 청사진: {제목} (slug: {kebab-slug})

- **플랫폼 · 타깃 (C1):** {모바일웹/데스크톱/둘 다 · 가로|세로} / 타깃 유저: {유저층}
- **코어 루프 (C2):** {플레이어가 매 순간 하는 행동 한 문장}
- **재미 조합 (C3):** {사용자가 고른 FE-* 2~4개 + 각각 언제 터지는지}
- **아트 · 테마 · 출처 (C4):** {PixelForge|VectorForge + 결} / {테마·마스코트} / 출처: {실제 에셋 소싱(sprite-picker) | 절차 생성} → render: {pixelArt 설정}
- **사운드 (C5):** {BGM 무드 + SFX 톤}
- **승패 · 진행 · 분량 (C6):** {승리/실패} / {1레벨|N레벨팩} / {난도 곡선} / {점수·별점·베스트}
- **조작 (C7):** {입력 방식}
- **차용 game-dna 레퍼런스:** {읽을 장르 파일 1~2개 + 채택/조립한 조합 레시피}
- **IP 안전 메모:** {상표 이름·원작 에셋 회피, 절차생성 오리지널}
- **빌드 라우팅:** 장르 스킬 → {platformer-game|topdown-shooter|arcade-classic|puzzle-game|endless-runner}
  · 제작요소 스킬 → {선택 FE-*별: juice-fx|chip-sound|game-ui-hud|level-designer · 아트: sprite-picker(실제 에셋 소싱)|sprite-forge|vector-graphics(절차 생성)}
```

확정 후:
1. 만들 게임과 가까운 **game-dna 장르 파일 1~2개를 Read**해 메카닉·재현 노트·IP 안전 메모를 반영.
2. SKILL.md "전문 스킬 라우팅"으로 코어 장르 스킬을, 선택된 재미요소별 제작요소 스킬을 잇는다.
3. 서버 라이브 메타·정밀 강체 물리가 섞이면 단일플레이 축소(로컬 베스트·고스트·시드 공유·단순 임펄스)로 만들 것임을 미리 고지.
4. **확인을 받은 뒤에만** 코드를 짠다.

## 8. 예시 (Good)

**라운드 1 — 탑다운: 맥락부터 (플랫폼·타깃 유저)**

```
라운드 1 | 타깃 차원: C1 플랫폼·타깃 유저 | 왜 지금: 누구를 위한·어디서 도는 게임인지가 난이도·아트·조작·세션 길이를 전부 프레이밍하므로 맨 먼저 정합니다 | 청사진 진행: 0/7

퍼즐은 타깃 유저에 따라 완전히 다른 게임이 됩니다 — 출퇴근길 한 손 캐주얼이냐, 진득하게 머리 쓰는 코어 퍼즐러냐에 따라
난이도·세션 길이·조작이 갈립니다. 제 데모 추천은 '모바일 웹 + 캐주얼'(스와이프 한 손, 30초~2분 세션)이지만, 정하기 나름입니다.

이 게임은 어떤 플랫폼·어떤 유저층을 위한 건가요?
```

**라운드 3 — 재미 요소 조합 (사용자 주도 팔레트 + 반영·대안)**

```
라운드 3 | 타깃 차원: C3 재미 조합 | 왜 지금: 코어(공간 밀기)는 정해졌으니, 이제 어떤 손맛을 섞을지가 게임 성격을 결정합니다 | 청사진 진행: 2/7

밀기 코어에 잘 붙는 재미 요소를 제 사전에서 꺼내왔습니다. 정답은 없으니 **마음에 드는 손맛 2~3개를 직접 골라** 섞어주세요.
제 추천 조합은 '수읽기 + 연쇄·콤보'(여러 수 앞을 설계해 한 번에 대연쇄)지만, 다르게 섞으셔도 제가 그에 맞춰 게임을 새로 조립합니다.

[multiSelect] 수읽기(FE-PLANNING) · 연쇄·콤보(FE-COMBO) · 최적화/별점(FE-OPTIMIZE) · 손맛/주스(FE-JUICE)
            · 제약(이동수 제한)(FE-CONSTRAINT) · 되돌리기 탐색(FE-TRANSFORM) · 아하·통찰(FE-AHA) · 공간 추론(FE-SPATIAL)

어떤 손맛들을 섞고 싶으세요?
```
→ (사용자가 고르면) **반영:** "그럼 *최소 이동 수 안에서 한 수로 대연쇄를 노리는 머리싸움 밀기 퍼즐*이 됩니다 — 막힌 보드에서 '아 이렇게 밀면 다 터지네!'의 아하가 핵심이죠."
→ **검증+대안:** "이 방향 괜찮으세요? 아니면 제 다른 아이디어 — 같은 밀기에 '규칙 발견'을 얹어 *무엇이 벽·승리인지 바꿔가며* 푸는 쪽 — 도 신선한데, 어느 쪽이 끌리세요?"

**왜 좋은가:** 탑다운(맥락 먼저), 약점 차원 하나만 타깃, "왜 지금" 명시, **재미 요소를 사용자가 직접 multiSelect로 조합**, Claude가 조합을 구체적 한 컷으로 *반영*하고 *대안*까지 던짐.

**Bad:** "매치3·2048·테트리스 중 뭐 할래요?"만 던지기 — 완성 아키타입을 통째로 들이밀어 조합 여지가 없고(정신2 위반), 맥락(타깃 유저)도 안 묻고 바로 메카닉으로 점프(정신1 위반).

## 9. 최종 체크리스트

- [ ] 탑다운: C1(플랫폼·타깃 유저)부터 묻고 아래로 내려갔는가
- [ ] 한 라운드에 질문 하나(1문1답) — C3 조합만 multiSelect 한 질문 허용
- [ ] 매 라운드 타깃 차원 + "왜 지금" 명시
- [ ] **C3에서 FE-\* 팔레트를 펼쳐 사용자가 직접 조합(multiSelect)하게 했는가**
- [ ] 조합을 받은 뒤 **구체적 한 컷으로 반영 + 검증 + 대안 제시**했는가
- [ ] 매 라운드 Claude가 game-dna 기반 참신한 컨셉/대안을 *먼저* 제안하고 본인 의견을 밝혔는가
- [ ] 추상적 답은 구체 사례로 되물어 구체화
- [ ] 안티패턴 충돌은 절충 되묻기로 해소
- [ ] 사운드(C5)도 명시적으로 물었는가
- [ ] 챌린지 모드(Contrarian/Simplifier/Hook)를 적절 라운드에 1회씩
- [ ] 준비도 게이트(C1 확정 + C2·C3·C4 구체 + 나머지 기본값) 후에만 빌드
- [ ] 청사진을 한 화면으로 읽어주고 최종 확인 후 스캐폴딩
- [ ] 조기 종료("그냥 만들어") 시 추천 기본값으로 청사진 완성 후 진행
