# 게임 청사진 인터뷰 (Deep Interview 적응판)

> web-game-builder의 **'0) 요청 명확화'** 단계를 **깊이 있는 1문1답 인터뷰**로 수행하는 플레이북.
> oh-my-claudecode의 `deep-interview` 스킬(Socratic 1문1답 + 약점 차원 타깃 + 챌린지 모드 + 준비도 게이팅)을
> **게임 설계 차원**에 맞게 적응시킨 것이다. 추상적 객관식 1회로 끝내지 말고, **구체적 게임 청사진**이 나올 때까지 파고든다.
>
> **언제 쓰나:** 게임 제작 요청이 한 줄·모호("퍼즐 게임 만들어줘", "재밌는 거 만들어줘")이거나, 핵심 차원(아래 5개)이
> 명시되지 않았을 때. 요청이 이미 구체적이면(코어 루프·아트·테마·분량이 다 적혀 있으면) 인터뷰를 건너뛰고 바로 빌드한다.
>
> 자동 트리거 아님. SKILL.md '0) 요청 명확화'·`commands/make-game.md`·`puzzle-game/SKILL.md` 0번 레시피에서 **온디맨드 Read**로 부른다.

---

## 0. 왜 이 인터뷰인가 (설계 의도)

기존 방식은 `AskUserQuestion` 1회(최대 4문항)로 아트/장르/테마/분량을 한꺼번에 묻고 끝냈다. 문제:
- 질문이 추상적("어떤 장르?")이라 사용자가 막연한 답을 고르고, 결과물 청사진이 흐릿하다.
- 한 번에 다 물어 각 답이 얕고, 서로 충돌하는 선택(안티패턴)을 거를 라운드가 없다.
- **Claude의 창의적 제안이 들어갈 자리가 없다** — 사용자는 주어진 보기에서 고르기만 한다.

이 인터뷰는 deep-interview처럼 **한 번에 한 차원씩 깊게** 파고, 매 라운드 **Claude가 game-dna 기반의 참신한 컨셉을 먼저 제안**하며,
**구체적 청사진**이 완성될 때까지 좁힌 뒤 빌드한다.

---

## 1. 핵심 원칙 (deep-interview에서 차용)

1. **1문1답.** 한 라운드에 질문은 하나. 4개를 한 객관식에 욱여넣지 않는다. (deep-interview: "Ask ONE question at a time — never batch")
2. **약점 차원 타깃.** 매 라운드 가장 모호하거나(또는 결과 인상을 가장 크게 좌우하는) 차원 하나를 골라 거기를 캔다.
   질문 전에 **"지금 왜 이걸 묻는지"**를 한 문장으로 밝힌다.
3. **가정을 드러낸다.** "뭘 원해요?"가 아니라 "무엇을 전제하고 있나요?"를 묻는다. 추상적 답("그냥 재밌게")이 나오면
   **구체 사례로 되묻는다**("재밌다 = 한 수로 대연쇄가 터지는 손맛인가요, 아니면 차분히 정답을 찾는 쾌감인가요?").
4. **Claude가 먼저 참신한 컨셉을 제안한다 (이 인터뷰의 핵심).** 빈 객관식을 던지지 말고, 매 라운드
   **game-dna에서 검증된 조합 + 본인의 창의적 비틀기**를 구체 옵션으로 제시한다(§3 참고). 사용자는 고르거나 자유 입력한다.
5. **안티패턴 가드.** [game-dna/fun-elements.md](./game-dna/fun-elements.md) §3, [game-dna/puzzle/fun-elements.md](./game-dna/puzzle/fun-elements.md) §3의
   '섞지 말 것'을 내부 가드로 적용. 사용자가 충돌 조합(예: 연역+실시간가속, 우아한해+강RNG, 명상형+과한주스)을 고르면
   그대로 만들지 말고 **"둘 다 살리려면 구간을 나눠야 하는데 어느 쪽을 코어로 할까요?"**로 되묻거나 절충안(시드 고정 모드 분리, undo 제한)을 제안한다.
6. **준비도 게이트.** §5의 5개 차원 중 **필수 3개(코어 루프·재미 손맛·아트/테마)가 구체적**이 되고 나머지 2개의 기본값이
   확정되기 전엔 스캐폴딩을 시작하지 않는다.
7. **조기 종료 존중.** 사용자가 "알아서/추천대로/그냥 만들어/충분해"라고 하면 즉시 멈추고, **현재까지 좁혀진 청사진 + 추천 기본값**으로
   §6 청사진을 확정해 읽어준 뒤 진행한다.

## 2. 게임 청사진 차원 (약점 타깃 대상)

매 라운드 이 5개 중 가장 약한 차원을 캔다. ✅=구체 확정 · ◻️=미정/모호.

| # | 차원 | 무엇을 확정하나 | 비고 |
|---|---|---|---|
| **D1** | **코어 루프 / 장르** | 플레이어가 매 순간 *실제로 하는 행동* 한 문장(예: "캔디를 한 칸씩 밀어 같은 색 3개를 연결해 소거") | ★필수. 모든 결정의 뿌리. game-dna 코어로 고정. |
| **D2** | **재미 손맛 (FE-\*)** | 가장 살리고 싶은 재미요소 2~3개(`FE-COMBO`·`FE-PLANNING` 등)와 그게 *어떤 순간에 터지는지* | ★필수. fun-elements 사전에서. |
| **D3** | **아트 스타일 · 테마** | 픽셀(`PixelForge`) vs 미려한 스무스/벡터(`VectorForge`) 택1 + 결(플랫/네온글로우/글래스/카툰) + 테마·마스코트 | ★필수. 결과 인상 최대 좌우. 게임당 하나, 섞지 않음. |
| **D4** | **승패 · 진행 · 분량 · 난이도** | 승리/실패 조건, 1레벨 vs 레벨팩(개수), 난도 곡선, 점수/별점/베스트 유무 | 기본값 제시 가능(예: 손제작 8~12레벨 + 난도 상승). |
| **D5** | **타깃 · 조작** | 모바일 웹뷰 포함 여부(기본 포함)·가로/세로, 입력(키보드/스와이프/탭/드래그) | 기본값: 모바일 포함, 코어에 맞는 입력. |

> 퍼즐이면 D1을 game-dna **7개 퍼즐 코어**(낙하/매치/병합/연역/공간/물리/규칙)로, 그 외 장르면 전역 game-dna 아키타입으로 고정한다.

## 3. Claude의 제안 의무 — "참신한 의견 개진" (이 인터뷰의 차별점)

**매 라운드, 질문과 함께 Claude가 먼저 구체적인 컨셉을 제안한다.** 사용자에게 백지를 내밀지 않는다.

- **출처:** [game-dna/](./game-dna/) (장르별 분석 + 조합 레시피)에서 검증된 조합을 가져오고, 거기에 **본인의 창의적 비틀기**를 더한다.
- **구체적으로.** 카테고리 라벨("매치 퍼즐")이 아니라 **그림이 그려지는 한 컷**으로 제안한다:
  - ❌ "매치3 퍼즐은 어떠세요?"
  - ✅ "비트마다 좌→우로 스윕 라인이 지나가며 *예약된 매치를 한꺼번에* 터뜨리는 **리듬 매치**는 어떨까요 — 스윕 직전 막판 스왑으로 군집을 키우는 도박이 손맛입니다(Lumines의 타임라인 소거 + 위험-보상). 제 생각엔 여기에 '큰 한 방'을 노리게 만들면 '한 판 더'가 강하게 걸립니다."
- **추천 + 한 줄 컨셉 + 왜 재밌나.** 각 옵션은 친근한 이름 + 한 문장 컨셉 + (가능하면) 어떤 재미요소가 터지는지. 첫 옵션에 **"(추천)"**.
- **본인 의견을 명시한다.** "제 추천은 X입니다, 왜냐면 ~"처럼 Claude의 관점을 분명히 밝힌다(사용자가 반박·선택하기 쉽게).
- **다양성.** 코어를 묻는 라운드에선 서로 다른 코어/아키타입을 3~4개 고르게 섞어 노출(퍼즐이면 7개 코어에서 고르게).
- 요청에 이미 단서가 있으면(장르·레퍼런스 언급) 그 코어를 고정하고, 제안은 *그 코어 안에서의 변주*로 좁힌다.

## 4. 라운드 진행 (deep-interview Phase 2 적응)

각 라운드는 `AskUserQuestion` 한 번(질문 1개)으로 진행한다. 형식:

```
라운드 {n} | 타깃 차원: {D# 이름} | 왜 지금: {한 문장 근거} | 청사진 진행: {✅개수}/5

{Claude의 참신한 제안 1~2문장 — game-dna 기반 + 본인 비틀기·의견}

{질문}
```

- `AskUserQuestion`의 옵션 = §3의 제안들(추천 첫 옵션 + 한 줄 컨셉). 사용자는 자유 입력으로 자기 아이디어를 낼 수도 있다.
- 답을 받으면 그 차원을 ✅로 갱신하고, **다음으로 가장 약한 차원**을 타깃해 다음 라운드로.
- 답이 모호하면 같은 차원을 **구체화 질문**으로 한 번 더 판다(추상→구체 사례 되묻기).
- 안티패턴 충돌이 감지되면 다음 질문은 **절충 되묻기**가 된다(§1.5).

### 라운드 진행 리드아웃 (deep-interview의 투명성 차용)

매 라운드 끝에 한 줄로 청사진 상태를 보여준다(딱딱한 점수 대신 체크리스트):

```
청사진: D1 코어 ✅ | D2 재미 ✅ | D3 아트·테마 ◻️ | D4 승패·분량 ◻️ | D5 타깃·조작 ◻️
다음 타깃 → D3(아트·테마): 결과 인상을 가장 크게 좌우하는데 아직 미정이라 다음에 캡니다.
```

## 4.5. 챌린지 모드 (deep-interview Phase 3 적응 — 게임용)

라운드가 쌓이면 관점을 바꿔 한 번씩 도발한다(각 1회). 청사진을 더 날카롭게 만든다.

- **3라운드+ · Contrarian(반대로):** 사용자의 기본 가정을 뒤집어 본다 — "정말 그 장르가 최선일까요? 같은 테마로 *완전히 다른 코어*(예: 푸시 대신 경로 잇기)면 더 신선할 수 있는데, 굳이 이 코어인 이유가 있나요?"
- **4라운드+ · Simplifier(덜어내기):** 가장 단순한 재미 버전을 묻는다 — "이 중에서 **하나만 남긴다면** 어떤 재미가 코어인가요? 나머지는 빼도 게임이 성립할까요?" (MVP 청사진 확보)
- **5라운드+ · Signature Hook(자랑할 한 컷):** 정체성을 묻는다 — "친구에게 30초로 자랑한다면, *어떤 순간*을 보여주고 싶나요? 그 한 컷이 이 게임의 정체성입니다." (이게 D1·D2를 한 문장으로 응축시킨다.)

각 모드는 한 번만 쓰고 일반 질문으로 복귀한다.

## 5. 준비도 체크 (게이트)

스캐폴딩 시작 조건:
- **필수 3개(D1 코어·D2 재미·D3 아트/테마)가 모두 ✅(구체)** — 한 문장으로 막힘없이 서술 가능.
- D4·D5는 ✅이거나, 미정이면 **명시적 추천 기본값**으로 확정(사용자에게 "이건 이렇게 기본값으로 갈게요"라고 고지).
- 안티패턴 충돌이 모두 해소(절충안 확정).

게이트 미달이면 가장 약한 차원으로 라운드를 더 돈다. 보통 **3~6라운드**면 충족된다.

### 라운드 수 가이드 / 조기 종료
- 3라운드+부터 "충분/그냥 만들어"로 조기 종료 가능 — 단, 필수 3개가 ◻️면 **추천 기본값을 채워 청사진을 완성**한 뒤 진행한다고 고지.
- 10라운드 soft 경고: "벌써 10라운드네요. 지금 청사진으로 진행할까요, 더 다듬을까요?"

## 6. 청사진 확정 & 빌드 라우팅 (deep-interview Phase 4·5 적응)

게이트 충족 시, **청사진을 한 화면으로 정리해 사용자에게 읽어주고 최종 확인**받은 뒤에만 `games/<slug>/` 스캐폴딩을 시작한다.
(deep-interview는 spec 파일을 쓰지만, 게임 빌더는 별도 파일 없이 **응답 안의 청사진 블록 + 확인**으로 충분하다. 무겁게 하지 않는다.)

### 청사진 형식

```
## 게임 청사진: {제목} (slug: {kebab-slug})

- **코어 루프 (D1):** {플레이어가 매 순간 하는 행동 한 문장}
- **재미 손맛 (D2):** {FE-* 2~3개 + 각각 언제 터지는지}
- **아트 · 테마 (D3):** {PixelForge|VectorForge + 결} / {테마·마스코트} → render: {pixelArt 설정}
- **승패 · 진행 · 분량 (D4):** {승리/실패} / {1레벨|N레벨팩} / {난도 곡선} / {점수·별점·베스트}
- **타깃 · 조작 (D5):** {모바일 포함 여부·가로세로} / {입력 방식}
- **차용 game-dna 레퍼런스:** {읽을 장르 파일 1~2개 + 채택한 조합 레시피}
- **IP 안전 메모:** {상표 이름·원작 에셋 회피, 절차생성 오리지널}
- **빌드 라우팅:** 장르 스킬 → {platformer-game|topdown-shooter|arcade-classic|puzzle-game|endless-runner}
  · 제작요소 스킬 → {선택 FE-*별: juice-fx|chip-sound|game-ui-hud|level-designer|sprite-forge|vector-graphics}
```

확정 후:
1. 만들 게임과 가까운 **game-dna 장르 파일 1~2개를 Read**해 메카닉·재현 노트·IP 안전 메모를 반영한다.
2. SKILL.md "전문 스킬 라우팅"으로 코어 장르 스킬을, 선택된 재미요소별 제작요소 스킬을 잇는다.
3. 서버 라이브 메타·정밀 강체 물리가 섞이면 단일플레이 축소(로컬 베스트·고스트·시드 공유·단순 임펄스)로 만들 것임을 미리 고지.
4. **확인을 받은 뒤에만** 코드를 짠다.

## 7. 예시 (Good)

**라운드 2 — 약점 차원 타깃 + Claude 제안 + 구체 되묻기**

```
라운드 2 | 타깃 차원: D2 재미 손맛 | 왜 지금: 코어(공간 푸시)는 정해졌지만 '무엇이 손맛인지'가 비어 있어 콘텐츠 톤이 안 잡힙니다 | 청사진 진행: 1/5

순수 Sokoban은 본래 콤보가 없는 정적 퍼즐입니다. 제 제안은 game-dna의 '미리 체인을 쌓아 한 번에 터뜨리는
선계획형 콤보' 노트를 빌려, **밀기 코어 + 매치 소거 캐스케이드**를 합치는 겁니다 — 같은 색 캔디를 밀어 3개+
연결하면 소거되고, 소거가 새 연결을 만들면 도미노 연쇄가 터집니다. 즉 "한 번의 밀기로 대연쇄가 터지게 여러 수에
걸쳐 배치를 설계"하는 게 손맛이 됩니다. 제 추천은 이 콤보(FE-COMBO) + 수읽기(FE-PLANNING) 조합입니다.

이 게임에서 가장 살리고 싶은 손맛은 무엇인가요?
```

**왜 좋은가:** (1) 약점 차원 하나만 타깃, (2) 왜 지금 묻는지 명시, (3) Claude가 game-dna 기반의 구체적·참신한 컨셉을
*먼저* 제안하고 본인 추천을 밝힘, (4) 추상이 아니라 "한 번의 밀기로 대연쇄"라는 그림이 그려지는 제안.

**Bad:** "장르? 아트? 테마? 분량?을 한꺼번에 고르세요" — 4개를 한 번에 묶고(원칙1 위반), 제안 없이 백지 객관식(원칙4 위반), 추상적이라 청사진이 안 잡힌다.

## 8. 최종 체크리스트

- [ ] 한 라운드에 질문 하나(1문1답), 4개 묶음 금지
- [ ] 매 라운드 타깃 차원 + "왜 지금"을 명시
- [ ] 매 라운드 Claude가 game-dna 기반 참신한 컨셉을 *먼저* 제안하고 본인 의견을 밝힘
- [ ] 추상적 답은 구체 사례로 되물어 구체화
- [ ] 안티패턴 충돌은 절충 되묻기로 해소
- [ ] 챌린지 모드(Contrarian/Simplifier/Hook)를 적절 라운드에 1회씩
- [ ] 필수 3개(D1·D2·D3) 구체 + D4·D5 기본값 확정(준비도 게이트) 후에만 빌드
- [ ] 청사진을 한 화면으로 읽어주고 최종 확인 후 스캐폴딩
- [ ] 조기 종료("그냥 만들어") 시 추천 기본값으로 청사진 완성 후 진행
